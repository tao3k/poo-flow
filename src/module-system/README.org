#+title: POO Flow module-system feature layout

* Boundary

This page describes the current implementation, not its target ownership.
The complete Core migration and deletion of this directory are audited in
[[file:../../docs/10-19-design/10.06-poo-module-system/core-module-system-ownership-audit.org][Core Module System ownership and migration audit]].

=src/module-system= currently houses the remaining POO Flow module adapters
and mechanisms awaiting Core migration. Product entrypoints are moving to
their feature owners;
Core owns the shared, parser-safe POO contracts and is becoming the sole
Module System mechanism owner.  The
dependency direction is POO Flow Core -> gerbil-parser -> POO Flow; Core
must not import POO Flow or a maintained product module.

Maintained product modules live in =modules/<module>/=.  In particular,
workflow implementation belongs to =modules/workflow/=.  Product module
observability contracts live in =core/observability/=; product UI, authoring,
testing, and build adapters live with their respective features. POO-native CLOS,
extension-graph operations, and module-schema contracts belong to Core.
The shared Sandbox object is owned by =modules/sandbox-core/shared-object.ss=,
not by the generic module system.

* Feature owners

| Feature | Public factor | Responsibility |
|---------+---------------+----------------|
| declaration | =declaration/interface.ss=; =src/user-interface/selection-flags.ss=, =module-selection-syntax.ss= | POO-native selection values and product user syntax/flag policy |
| descriptor | =descriptor/interface.ss= | module descriptor contracts |
| loader | =core/module-system/loader/objects.ss=, =core/module-system/loader/load-path.ss=, =loader/collection.ss=, =loader/tree.ss=; =src/authoring/module-imports.ss=, =source-registry.ss=; =src/user-interface/module-source-selection.ss= | Core lazy receipts and ordered LoadPath; product discovery, selection, and source policy |
| projection | =core/module-system/projection/option-objects.ss=, =option-validation.ss=; =src/user-interface/module-value-catalog.ss=; =projection/options.ss=, =runtime.ss= | Core option values and validation; product value catalog, descriptor and runtime projection |
| profile composition | =core/profile-composition/=; =src/scenario/composition-syntax.ss=, =profile-root.ss= | Core owns Profile selection, =use-module=, and ProfileBundle algebra; Scenario owns =user-composition= and root projection |
| object validation | =core/module-system/schema/validation.ss= | native POO Type/C4 contract evidence |
| contribution verification | =core/contribution/verification.ss= | direct Core import; the redundant product re-export was removed |
| semantic module policy | =src/authoring/semantic-module.ss= | POO Flow default authoring roles over Core semantic Module Contracts |
| observability | =core/observability/= | Core owns reusable observation primitives; feature adapters consume them directly |

The shared factors below are owned once by the =core/= Git submodule and
installed under the =core= Gerbil package namespace.  Do not
copy them back into =src/module-system= or import them through a POO Flow alias.

| Shared feature | Core public factor | Responsibility |
|----------------+--------------------+----------------|

| object family | =object-family/interface.ss= | hygienic POO object-family declarations |

| contribution contract | =contribution/objects.ss= | pure POO contribution values and capability admission |

Further extraction requires a real downstream consumer and a single source owner.
A source file is not eligible merely because it has no =:poo-flow/= import:
its exported semantics, source-owner qualifications, build targets, and tests
must also move atomically.  The shared lineage analysis is qualified in
Core; the POO Flow RFC45 test remains a consumer test.  In contrast,
=src/proof/composition-facts.ss= describes a POO Flow proof receipt and
=src/authoring/semantic-module.ss= defines only POO Flow default authoring roles over
Core-owned semantic Module Contracts and constructors.  Consumers import Core
directly beside the product policy.

The mechanism consumes =poo-flow-load-modules= directory discovery as its
maintained-module input.  It must not import maintained module implementations.
User profile and presentation composition belongs to =src/user-interface/=,
not to this directory.
