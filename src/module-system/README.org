#+title: POO Flow module-system feature layout

* Boundary

=src/module-system= owns the POO Flow module mechanism.  Its root contains only
package-level entrypoints; each implementation feature owns a directory with an
=interface.ss= public factor and focused implementation factors.  The separate
=core= package owns the shared, parser-safe POO contracts.  The
dependency direction is POO Flow Core -> gerbil-parser -> POO Flow; Core
must not import POO Flow or a maintained product module.

Maintained product modules live in =modules/<module>/=.  In particular,
workflow implementation belongs to =modules/workflow/=.  Loader
observability and POO Flow module admission live here; POO-native CLOS,
extension-graph operations, and module-schema contracts belong to Core.

* Feature owners

| Feature | Public factor | Responsibility |
|-
| declaration | =declaration/interface.ss= | POO-native selections and flags |
| descriptor | =descriptor/interface.ss= | module descriptor contracts |
| loader | =loader/interface.ss= | discovery, resolution, lazy loading |
| projection | =projection/interface.ss= | option and receipt projection |
| profile composition | =profile-composition/interface.ss= | functional composition values |
| object validation | =object-validation/interface.ss= | object contract evidence |
| composition | =composition/interface.ss= | public re-export of Core lineage and local proof facts |
| diagnostics | =diagnostics/interface.ss= | diagnostic and doctor receipts |
| semantic module | =semantic-module/interface.ss= | semantic module objects and types |
| observability | =observability/interface.ss= | module authoring and observation |

The shared factors below are owned once by the =core/= Git submodule and
installed under the =core= Gerbil package namespace.  Do not
copy them back into =src/module-system= or import them through a POO Flow alias.

| Shared feature | Core public factor | Responsibility |
|-
| type and contract evidence | =types.ss= | native classification and validation contracts |
| object family | =object-family/interface.ss= | hygienic POO object-family declarations |
| extension graph | =extension-graph/interface.ss= | ordered contributions and fixed-point resolution |
| module schema | =module-schema/interface.ss= | inherited field contracts and merge |
| POO CLOS | =poo-clos/interface.ss= | native MOP extension and method combination |
| composition lineage | =composition/lineage.ss= | pure cycle and productive-recursion analysis |
| core observability | =observability/debug.ss= | reusable POO/debug observation contracts |
| testing Case profile | =observability/testing-case.ss= | POO-native Case policy around the native test runner |

Further extraction requires a real downstream consumer and a single source owner.
A source file is not eligible merely because it has no =:poo-flow/= import:
its exported semantics, source-owner qualifications, build targets, and tests
must also move atomically.  The shared lineage analysis is qualified in
Core; the POO Flow RFC45 test remains a consumer test.  In contrast,
=composition/proof-facts.ss= describes a POO Flow proof receipt and
=semantic-module/= defines POO Flow admission and authoring roles.  Those
remain here until their contracts and qualification owners can be deliberately
transferred, rather than acquiring duplicate modules in both packages.

The mechanism consumes =poo-flow-load-modules= directory discovery as its
maintained-module input.  It must not import maintained module implementations.
User profile and presentation composition belongs to =src/user-interface/=,
not to this directory.
