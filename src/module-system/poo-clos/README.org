#+title: POO-native CLOS implementation status

* Status

This owner implements a POO-native CLOS metaprotocol extension.  The Common
Lisp HyperSpec supplies semantic conformance vectors, but it does not own the
runtime architecture.  Class precedence is the upstream Gerbil POO prototype
C3, projected back to the exact CLOS class metaobjects.  The extension remains
opt-in and is not part of the default module selection.

The implementation provides:

- POO-native generic-function, method, specializer, effective-method, invocation
  frame, and typed-failure values;
- =class=, =eql=, and universal specializers;
- multiple-dispatch applicability and =argument-precedence-order=;
- identity-preserving method addition, replacement, and removal;
- the standard =around=, =before=, primary, and =after= method combination;
- lexical next-method checks, including replacement-argument applicability.
- POO-native class, direct-slot, effective-slot, instance-state, and slot-cell
  metaobjects;
- native POO C3 class precedence with diamond, monotonicity, and upstream
  inconsistency handling;
- instance- and class-allocated slots, inherited option merging, initforms,
  initargs, default initargs, and shared initialization;
- slot value, bound-state, makunbound, missing, and unbound protocols;
- reader and writer methods that participate in the ordinary dispatch kernel.
- immutable lambda-list descriptors with required, optional, rest, key,
  allow-other-keys, supplied-p, and generic/method congruence;
- expansion-time =.defclass=, =.defgeneric=, and =.defmethod= declaration IRs with
  binding-aware grammar markers and source-located rejection;
- a POO-native parenthesized method head, lexical =call-next-method= and
  =next-method-p=, and an explicit generic-binding generation owner.
- POO method-combination and generic-protocol metaobjects, all nine ANSI simple
  built-ins, declarative short and long combination forms, qualifier groups,
  required/order checks, and lexical =call-method= execution;
- checked method bundles bound to an exact generic-protocol object, functional
  bundle composition through ordinary method admission, and the thin hygienic
  =.defmethod-bundle= projection;
- identity-preserving =change-class=, lazy obsolete-instance migration,
  dependent-class redefinition cascades, retained shared-slot cells, and both
  instance-update hooks;
- explicit generic bindings with atomic =ensure-generic-function=
  reinitialization and dispatch-generation invalidation;
- read-only class, slot, method, specializer, generic and generation readers.
- two-phase =make-load-form= and =make-load-form-saving-slots= protocols with
  cycle-safe reference resolution, bound-slot preservation, and no initform
  replay.

The public factor is =interface.ss=.  The functional kernel keeps an explicit
POO invocation-frame API for low-level construction, while ordinary
=.defmethod= bodies receive hygienic lexical =call-next-method= and
=next-method-p= bindings over the same runtime object.  There is no second
evaluator.

The closed authoring path is:

#+begin_example
ClosGenericProtocol -> ClosMethodBundle -> native define-type POO values
                    -> .defmethod-bundle -> existing generic admission/dispatch
#+end_example

The macro creates one ordinary =ClosMethodBundle= value.  Protocol identity,
method ownership, replacement, ordering and execution remain in the checked
runtime functions.  There is no CLOS CPL implementation: =classes.ss= maps the
upstream =compute-precedence-list!= result back to its exact class metaobjects.
=funcs.ss= retains only CLOS-owned indexing mechanics and reuses Gerbil std
=invert-hash<-vector= for position indexes and =stable-sort= for method
ordering.  The 40-sample Scenario under
=t/scenarios/performance/poo-clos-native-c3/= checks native order and =eq?=
metaobject identity while recording construction and warm-query latency.

* Scheme and POO adaptations

- ANSI class redefinition mutates the same POO class object, increments its
  generation, and retains layout history for lazy migration.  Class and
  instance object identity are both preserved.
- CLOS =eql= specializers use Scheme =eqv?= without serialization or numeric
  canonicalization.
- Keyword/initarg names accept native Gerbil keyword values and symbols.
- Multiple values are carried by the native Scheme values protocol.

The executable clause ledger and interpreted/AOT qualification are owned by
=t/qualification/poo-clos/=.  Its exhaustive 41-entry CLHS 7.7 manifest maps
every operator to a source-owned evidence fixture and currently has no open
required ANSI row.  Qualification still fails closed if any row becomes open,
if a fixture has no attributable assertions, or if interpreted and fresh-AOT
counts diverge.  Receipts retain =performance-claim? #f= until a user approves
a workload and SLA.

* Convergence boundary

The older =poo-method-combination/= module is migration input, not a second
standard.  New qualifiers, frames, effective-method rules, and public authoring
work belong here.  Reusable single-receiver behavior must converge into this
owner before the older module and its registry entry are removed.
