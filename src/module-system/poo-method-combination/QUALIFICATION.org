#+title: POO method combination qualification contract — v1

* Scope

This document records the stable qualification contract for the native
POO method-combination feature. It does not version an ignored run directory,
receipt count, content digest, local timing sample, or generated artifact path.
Those values are evidence for one invocation and remain under
=.data/qualification/=.

The qualified slice covers qualified method ordering, call-next-method frame
semantics, native POO contracts, the opt-in Observation adapter, bounded
performance checks, and Loader integration. It
does not claim a complete CLOS class system, production telemetry activation,
or full-package release acceptance.

* Entry points

From the project root:

#+begin_src sh
gerbil build
just test
#+end_src

The package's =build.ss= is the only build graph and =unit-tests.ss= is the
single upstream =:clan/testing= entrypoint.

* Acceptance contract

The focused slice must establish all of the following:

- semantic suites execute nonempty assertion sets;
- repeated native POO measurement receipts retain the expected checksum and method-plan
  identity and remain within the v1 smoke budget;
- statistical summaries consume those POO receipts directly and reject empty,
  duplicate, or inconsistent trials.

* Representative semantic witnesses

- Diamond primary order is =D B C A= and after order is =A C B D=; the shared
  ancestor contributes once.
- Repeated next calls can use original or replacement arguments while retaining
  the qualified method chain by descriptor identity.
- Primary replacement does not suppress the enclosing before/after methods.
- The real rejected SemanticModule observation retains the failing path and
  =prototype-mismatch= reason.
- The Observation renderer is opt-in, preserves default behavior, reuses its
  method plan, returns fresh summaries, and performs no output side effect.
- The default matrix contains 80 generic-chain trials plus five trials of that
  real Observation consumer against its equivalent pure functional renderer.
- Warm-path checks compare against the v1 functional-chain comparator and
  preserve exact results; the bounded threshold is a smoke guard, not a
  production latency claim.

* Evidence boundary

Passing the focused native tests admits only this package slice.  The build
system's generated files are not qualification-domain objects and are neither
rescanned nor promoted into a second manifest. Full-package release, installed
dependency provenance, and production performance admission remain separate
gates.
