#+title: Python Runtime Package

This package is the Python runtime consumer for POO Flow runtime bindings.

It does not own the ABI. The C surface lives under =bindings/runtime-c=.
Production code compiles and loads that binding through out-of-line CFFI API
mode so the package validates the same runtime handoff contract that Rust,
Marlin, or other runtime languages should consume.  The current installed
surface is ABI v0.1 and is not an ABI v1 freeze claim.

The package is managed by =uv=. It provides a Python API and a command-line
probe for the current C ABI. Future ALALEX validation runtime code should plug
into this package and consume the same =poo_flow_runtime= API.

Scheme owns flow composition, graph, policy-family and strategy-combinator
semantics. The installed runtime-v0 C ABI owns the control lane: negotiation,
sessions, arenas, mediation and evidence. It has no graph-plan handle API.

Python owns production scheduling, action IO, reducers, cancellation and durable
storage. =RuntimeGraphProgram.reference()= remains available with a local Python
domain receipt. Native programs require an actual runtime-v0 session plus a
=SemanticRuntime= context. The latter loads a compiler-produced Scheme AOT
library through out-of-line CFFI, admits the graph through existing POO objects,
and binds the full projection to a Scheme receipt before actions run. Static
successors come from Scheme graph algorithms. Conditional labels and dynamic
jump/send targets are resolved or checked by =graph.targets= against the same
immutable plan digest. A bare low-level executor uses reference mode; configured
native execution requires both the Scheme binding and a real control session.

=SemanticRuntime.call("temporal.solve", task)= evaluates the existing finite
ASCENT temporal semantics. =observe_model_answer(task, output)= parses inert
JSON and recomputes Scheme evidence, returning =consistent= or =contradicted=.
=predict_temporal_answer(task, predictor)= and its async counterpart pass only
the task to model IO and return its candidate with a fresh Scheme observation.
A contradiction is reported as evidence, without retry or effect authorization.
The historical prompted answer-supply experiment is withdrawn as design
acceptance; no-Prompt model integration and real-time teaching remain open.
Caller-declared source labels are not authenticated. Admission and answer
consistency do not grant effect authorization.

The finite hypothesis-family engine is a separate native profile.
=classify_temporal_family(task)= and =aclassify_temporal_family(task)= invoke
=temporal.family.classify=; =observe_temporal_family(task, candidate)= and its
async counterpart replay the whole current result through Scheme. The task
contains =profile: finite-hypothesis-family=, a model with =identity=,
=domains=, =observations=, =hypotheses=, =complete= and =mode=, and a query
with =identity=, =target= and =limit=. Wire objects are projections of existing
POO values, not an alternative engine. =limit: false= exhausts the finite
family; a positive integer permits an unexplored frontier. Model mode is
=exclusive-explanations= or =overlapping-mechanisms=. The native descriptor
publishes inventory bounds. Extra fields and unsupported profiles/relations
fail closed. Receipt classification is assumption-relative; source authenticity
and action authorization remain false. The exact supported projection and
local qualification are in [[file:../../modules/temporal-causality/design-audit.org][the engine delivery record]].

The semantic runtime has one process-wide lifetime and one owning thread,
bounded input and queue sizes, explicit native result ownership, and terminal
cleanup. Each artifact is checked against an expected SHA256 before loading.
The optional wheel producer bundles the AOT library and its closure manifest;
this adds semantic ABI v1 operations without declaring the whole v0 control
surface frozen.
The architecture correction and delivery gates are recorded in
[[file:../../docs/10-19-design/10.06-poo-module-system/python-scheme-runtime-foundation.org][Python/Scheme Runtime foundation]].

Runtime graph programs can return an execution trace for local debugging and
ALALEX validation. The trace is process-local observability; it does not replace
the C ABI receipt boundary.

Each reference graph execution carries its local domain receipt and plan digest
next to the local trace. These identify the reference plan, not native execution
or authenticated source data.

Run:

#+begin_src sh
uv run --project packages/python-runtime poo-flow-jsonschema-contract --help
uv run --project packages/python-runtime pytest packages/python-runtime/tests
#+end_src

* JSON Schema contract generation

Users can bring a JSON Schema file and generate a Scheme contract artifact for
a Funflow stage or profile:

#+begin_src sh
uv run --project packages/python-runtime poo-flow-jsonschema-contract \
  schemas/json/custom-stage.json \
  --name custom-stage \
  --object-key funflow/custom-stage \
  --output user-interface/custom/my-module/contracts/custom-stage.ss
#+end_src

The generated source defines =custom-stage-schema=,
=custom-stage-contract-artifact=, and =custom-stage-contract-receipt=. Python
only projects JSON into Scheme data; the Scheme bridge remains the semantic
owner for recursive map-value contracts such as
=stages.<stage_id>.tasks.<task_id>=, =profiles.<profile>.limits.<resource>=,
or =jobs.<job_id>=.
* Scheme load AOT warmup

Python runtime users can load Scheme user-interface fragments through the
package =load(...)= API. Repeated loads use an in-process projection cache, and
fresh Python processes can reuse Gerbil AOT runners when they have been
precompiled.

Precompile a user module explicitly during CI, install, or runtime warmup:

#+begin_src sh
uv run --project packages/python-runtime python -m poo_flow_runtime.scheme_load_aot \
  precompile packages/python-runtime/t/fixtures/funflow_user_module.ss \
  --cwd .
#+end_src

The command prints a single =poo-flow.scheme-load-aot.v1= receipt containing the
source path, workspace root, binary path, rebuild flag, and elapsed time. Normal
=load(...)= calls reuse a matching AOT runner when present but do not compile
one synchronously unless the caller passes =compile_aot=True= or sets
=POO_FLOW_SCHEME_LOAD_AOT_COMPILE=1=.

Run the exact AOT benchmark after precompile:

#+begin_src sh
uv run --project packages/python-runtime python -m poo_flow_runtime.benchmarks \
  scheme-load-aot --iterations 10 \
  --source packages/python-runtime/t/fixtures/funflow_user_module.ss \
  --cwd .
#+end_src

The benchmark emits =poo-flow.scheme-load-aot-benchmark.v1= receipts with
per-sample timings: =samples-us=, =min-us=, =median-us=, =mean-us=, =p95-us=,
and =max-us=. The default scenarios measure in-process cache hits,
in-process AOT reuse, and fresh Python process AOT reuse. Add
=--include-interpreter= only when an intentionally seconds-scale cold
interpreter baseline is needed.

For downstream users that should not install Gerbil, publish a preprojected
Scheme datum artifact from a Gerbil-enabled authoring/release lane:

#+begin_src sh
uv run --project packages/python-runtime python -m poo_flow_runtime.scheme_projection_artifact \
  export packages/python-runtime/t/fixtures/funflow_user_module.ss \
  --cwd .
#+end_src

The artifact is =SOURCE.poo-flow-projection.sexp= by default and stores the
normalized projection rows plus source/projection digests. Runtime =load(...)=
checks this artifact before AOT or Gerbil fallback, so an installed package can
run an already-published flow without =gxi= or =gxc=.

Benchmark the artifact path explicitly:

#+begin_src sh
uv run --project packages/python-runtime python -m poo_flow_runtime.benchmarks \
  scheme-load-aot --iterations 10 --include-artifact --preproject-artifact \
  --source packages/python-runtime/t/fixtures/funflow_user_module.ss \
  --cwd .
#+end_src

* Wheel build

The GitHub wheel workflow keeps this boundary explicit:

1. =projection-artifact= runs with Gerbil and =ccache=, builds the POO Flow
   package, exports real packaged projection artifacts, and uploads them.
2. =wheel= runs without Gerbil, downloads those artifacts, builds the Python
   wheel, installs it, and loads the packaged artifact from package resources.

Build the Python runtime wheel without requiring Gerbil after the generated
artifact has been placed next to its Scheme source:

#+begin_src sh
bazel build //bindings/runtime-c:runtime_c_shared
POO_FLOW_RUNTIME_V0_LIBRARY="$PWD/bazel-bin/bindings/runtime-c/libruntime_c_shared.dylib" \
  uv build --project packages/python-runtime --wheel \
    --out-dir dist/python-runtime-wheel
#+end_src

On Linux, use the corresponding =libruntime_c_shared.so= output.  The wheel
builder consumes this explicitly declared Bazel product; it never invokes Make
or discovers a source-tree =bindings/runtime-c/build= directory.

Install and smoke test the built wheel in a clean environment:

#+begin_src sh
python -m venv /tmp/poo-flow-runtime-wheel-smoke
/tmp/poo-flow-runtime-wheel-smoke/bin/python -m pip install \
  dist/python-runtime-wheel/*.whl
/tmp/poo-flow-runtime-wheel-smoke/bin/python -m poo_flow_runtime.scheme_projection_artifact --help
/tmp/poo-flow-runtime-wheel-smoke/bin/python -m poo_flow_runtime.benchmarks scheme-load-aot --help
#+end_src

The wheel build validates the downstream runtime package shape. Gerbil stays in
the authoring/release lane when source Scheme fragments need to be projected
into =*.poo-flow-projection.sexp= artifacts.
To ship built-in flows, generate each projection artifact before =uv build= and
place the source plus adjacent =*.poo-flow-projection.sexp= under the package
tree, for example =src/poo_flow_runtime/projections/=. Hatch includes those
package data files in the wheel. The no-Gerbil wheel CI lane must only consume
and verify these files; it must not generate real projection artifacts.

* Runtime graph checkpointing

The Python runtime package exposes the first process-local checkpoint surface
for human-in-the-loop graph execution:

#+begin_src python
checkpointer = MemoryRuntimeGraphCheckpointer()

try:
    program.invoke_thread("thread-1", {}, checkpointer, trace_key="trace")
except RuntimeGraphInterrupted:
    pass

execution = program.resume_thread(
    "thread-1",
    {"approved": True},
    checkpointer,
    trace_key="trace",
)
#+end_src

Inspect or edit a saved checkpoint before resuming:

#+begin_src python
checkpoint = checkpointer.inspect("thread-1")
checkpointer.update_state("thread-1", {"approved-by": "operator"})
history = checkpointer.history("thread-1")
previous = checkpointer.load_at("thread-1", history[0].checkpoint_id)
#+end_src

Checkpoints carry the validated graph plan digest.  Resuming with a changed
graph plan is rejected before execution continues.

The memory checkpointer is not a durable production store.  It fixes the
runtime API shape for thread-scoped interrupt/resume, while keeping durable
storage outside the C ABI boundary.

Use the file checkpointer when the Python runtime needs a local durable
snapshot:

#+begin_src python
checkpointer = FileRuntimeGraphCheckpointer("/tmp/poo-flow-runtime")
#+end_src

The file backend stores trusted Python runtime snapshots and uses hashed
thread-id filenames.  It is not a cross-language checkpoint protocol.

* Runtime graph subgraphs

Use ~RuntimeGraphSubgraph~ when a parent graph node should run a nested graph as
an action:

#+begin_src python
subgraph = RuntimeGraphSubgraph.from_parts(
    child_plan,
    child_actions,
    input_keys=("seed",),
    output_keys=("value",),
    trace_output_key="child-trace",
)

parent_actions = {"child": subgraph.as_action()}
#+end_src

Subgraphs are Python runtime strategy combinators.  The parent graph remains
the C ABI validation/materialization unit.

* Runtime graph store

Use runtime stores for cross-thread, namespace-addressed memory:

#+begin_src python
store = FileRuntimeGraphStore("/tmp/poo-flow-store")
store.put(("users", "alice"), "profile", {"name": "Alice"})
profile = store.get(("users", "alice"), "profile")
items = store.search(("users",))
#+end_src

Stores are separate from checkpoints.  Checkpoints capture thread-local graph
execution state; stores hold long-term runtime memory for actions.

* Runtime context

Actions can opt into runtime context by accepting a second argument:

#+begin_src python
runtime = RuntimeGraphRuntime(thread_id="thread-1", store=store)

def remember(state, runtime):
    runtime.require_store().put(
        ("threads", runtime.require_thread_id()),
        "value",
        state["value"],
    )
    return {"stored": True}
#+end_src

One-argument actions continue to work.  Runtime context is a Python runtime
surface for stores, checkpointers, thread ids, and metadata; it is not part of
the C ABI payload.

* Messages and tools

Use ~add_messages~ as the reducer for message state:

#+begin_src python
reducers={"messages": add_messages}
#+end_src

Use ~RuntimeGraphToolNode~ to execute tool calls from the last AI message:

#+begin_src python
tool_node = RuntimeGraphToolNode.from_callables({
    "add": lambda a, b: a + b,
})
#+end_src

This mirrors the common MessagesState/ToolNode graph shape without taking a
LangGraph or LangChain dependency.

* Scheme observations after model predictions

The optional semantic AOT artifact supports =temporal.observe=.
=SemanticRuntime.predict_temporal_answer(task, predictor)= passes a detached
task to caller-owned model IO. =apredict_temporal_answer= supports async IO.
No solved answer is supplied to the predictor. After IO, Scheme recomputes
against the current task and returns a digest-bound status/row difference.

The returned candidate and observation remain data. A contradiction supplies
current computation evidence, grants no effects and causes no model retry.
Provider inputs and any later feedback transfer remain the caller's explicit
IO. Model learning must be measured separately from receipt correctness.

* Runtime C ABI cache

The runtime C ABI probe shared library is cached outside the package-local
~build~ directory by default.  This keeps normal runtime use fast even when a
developer cleans local build artifacts.

Override the cache location when needed:

#+begin_src sh
POO_FLOW_RUNTIME_C_ABI_BUILD_DIR=/path/to/cache uv run poo-flow-runtime-probe
#+end_src

The runtime tests include gates for hot binding load, steady rebuild, repeated
program invocation, and resume-path binding reuse.

* MRR snapshot resource

=MrrSnapshotResource= connects an already projected =RuntimeGraphPlan= to the
trusted =mrr-data-poo-flow= worker for the bounded =poo-flow.static-edges.v1=
profile. The POO Flow runtime owner supplies the worker path, local protection
directory, environment, source, and revision. =protect= saves a snapshot locally;
=publish= requires remote acknowledgement; =pending_roots= and =sync_pending=
support replay after an offline period. =query_tool= fixes the snapshot scope
before exposing a no-argument tool to an agent.

This adapter checks worker receipts and transport bounds. It does not compile
MRR property queries, choose a physical plan, or admit semantic results. The
MRR Query layer owns those decisions; MRR Data supplies the snapshot and
physical storage interfaces. The static-edge profile is a separate legacy
runtime path, not the Healthcare GQL caller.

Typed Python runtime plans are materialized into C ABI graph handles before
validation or handoff. This keeps Python's execution model aligned with the
upstream ABI instead of creating a parallel graph protocol.

* Bound read-only model tool calls
=poo_flow_runtime.semantic_tools= exposes =temporal_tool_definition=,
=invoke_temporal_tool= and =ainvoke_temporal_tool=. The model submits a structured
function call for the caller's current task. The Library validates operation,
argument identity and exact task data before executing native =temporal.solve=.
Stale source generations, replacement facts, duplicate JSON keys and added
fields are rejected. The helper returns the actual engine result and artifact
digest, suitable for a paired provider =function_call_output=.

The installed-wheel real DeepSeek qualification passes 24/24 sync/async tool
roundtrips and 48/48 provider responses. Model final output preserves the actual
status, rows and source binding. This qualifies a forced read-only tool route;
unaided source prediction remains FAILED and autonomous tool choice is untested.
See [[file:../../t/qualification/semantic-abi/README.org][the bounded receipts and deadlines]].
