#+title: Python module testing

This package owns executable Python-side checks for POO Flow modules and
their compositions. Runtime-targeted cases load the repository's
=poo-flow-runtime= source; the optional =runtime= extra uses its built wheel
in an installed environment. The Runtime wheel does not carry model SDKs,
Scheme test workers, or case registrations.

* Case contract

Each =CaseSpec= has a stable identity, a mode (=unit=, =native= or =live=), and one or
more =(module, part)= targets. One module is a module case; two or more
distinct modules are a cross-module case. The check receives a =CaseContext=
with the repository root and optional source roots for externally pinned
modules. Registration rejects duplicate case identities and target pairs.

The [[file:src/poo_flow_testing/catalog.py][catalog]] currently registers an
inert Ascent candidate boundary, a native source-withdrawal check, a Python
Runtime graph check, a Runtime + Ascent candidate graph, and the POO Flow
evidence-assessment + Ascent qualification, and a native ASCENT plus
temporal-causality fixture check. These are actual checks, not
coverage placeholders. New module owners add a check near their domain and
register its target parts in the catalog.

From the repository root:

#+begin_src sh
uv run --project packages/python-testing --group dev pytest -q packages/python-testing/tests
uv run --project packages/python-testing poo-flow-test-cases list --module gerbil-ascent
uv run --project packages/python-testing poo-flow-test-cases list --composition cross
uv run --project packages/python-testing poo-flow-test-cases coverage
#+end_src

=coverage= discovers =modules/*/interface.ss= and shows the registered case
identities or an empty field for each uncovered module. It is an inventory,
not a claim that all 25 public POO Flow modules are covered. External
=gerbil-ascent= and =python-runtime= targets appear in =list=; their case
records are not counted as local =modules/*= files.

Native checks need a built or installed Gerbil package graph. For an isolated
checkout, pass exact source roots rather than relying on a sibling branch:

#+begin_src sh
uv run --project packages/python-testing poo-flow-test-cases run \
  --mode native --module gerbil-ascent \
  --module-root gerbil-ascent=/path/to/gerbil-ascent \
  --module-root gerbil-parser=/path/to/pinned-gerbil-parser
#+end_src

The evidence-assessment case invokes the root =just test-file= recipe. Its
receipt must include =MODULE-OK=, =HARNESS-OK=, final =OK=, and no harness or
overflow error marker. The Ascent candidate check uses a bounded persistent
Scheme worker for the two-source snapshot fixture. Other modules can
register checks that use their own semantic test owners; this framework
does not reimplement their logic in Python.

The =model-study.native-fixtures= case executes both Scheme owners, including
ASCENT's requested finite and founded receipt, and checks their outputs
against the pre-registered answer keys. It runs in
Ubuntu CI with the declared ASCENT pin and makes no model API request.

* Interactive model study

The optional =live= extra adds the official OpenAI Python SDK. The
[[file:docs/ascent-reasoning.org][Ascent study]] uses the existing Python
Runtime graph executor, an interactive user turn, and the same bounded
Scheme checker. It contains no stored model task prompt. The
[[file:docs/pilot-2026-10-01.org][pilot receipt]] covers two finite graph
snapshots and does not establish general model performance.

The fixed [[file:docs/model-study-baseline.org][baseline]] and
[[file:docs/model-study-typed.org][typed]] protocols separately test ASCENT
candidate evidence and POO Flow temporal classification with a real
model. Their [[file:docs/model-study-baseline-results.org][baseline]] and
[[file:docs/model-study-typed-results.org][typed]] results retain wrong
answers and boundary failures. The experimental Runtime output guard
in =temporal/authority.py= withholds model claims of release authority
when the native receipt denies it; it does not authorize any effect.
The [[file:docs/model-study-protocol.org][founded receipt protocol]] pairs the typed
observation with the newly verified ASCENT receipt on the same frozen
task and records the Runtime's guarded output separately from model
scores. The pinned Ascent package and the local checkout must identify
the same source head before a live founded-receipt result is admitted.
Its [[file:docs/model-study-results.org][bounded pilot]] found no score improvement on the fixed
corpus: both arms scored 15/15 on choice and 12/15 on boundary claim.
The guard withheld all six closed-cut release-authority claims.
That pilot sent JSON observations. The separate
[[file:docs/model-study-scheme.org][Scheme source pilot]] sends actual Gerbil Scheme
programs and scores returned S-expressions with a native Scheme reader;
its [[file:docs/model-study-scheme-results.org][nine-call result]] found no exact row-set answer on the fixed programs.
