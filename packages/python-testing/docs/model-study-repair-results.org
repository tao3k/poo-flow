* Protocol limitation and correction

The outgoing task listed the form =(relation NAME ARITY)= but did not
say that source relations were already supplied by each snapshot and
must not be redeclared. The first receipt sent back to the model only
contained =rejected= and =invalid= statuses, not the located
=duplicate-relation= diagnostic. Therefore this run does not isolate
the model's ability to repair a diagnosed error. After preserving the
raw run, the task contract was made explicit and the native tool was
changed to include diagnostic code/path pairs in its Scheme receipt.
The revised protocol needs a new committed-head preview and separate
authorization before any further paid calls. The earlier four-call
authorization is exhausted.

This fixed, tiny sample does not establish general Scheme literacy,
ASCENT tool usefulness, or deployed behavior. It does show that a
status-only native receipt is too weak for a meaningful repair test.
