* Claim and scope

This model explores a *declared* finite, exclusive family of candidate causes.
Its result is relative to the supplied observations, temporal constraints,
clock domain, family-completeness assertion and exploration bound.  An admitted
candidate is temporally consistent; it is not thereby an actual cause.  The
public Scheme contract consists of POO observations, hypotheses, constraints,
queries and receipts.  =Next= is an internal TLA+ relation over all eligible
candidate selections, not a fixed public action list or a learned causal law.

The model is decomposed by responsibility:

| File | Responsibility |
|------+----------------|
| =TemporalHypothesisFamily.tla= | Parser-admitted literal source and model data |
| =TemporalOrder.tla= | Reusable partial clock-order predicates |
| =TemporalFamilySemantics.tla= | Pure three-valued temporal consistency predicates |
| =TemporalFamilyExplorer.tla= | Nondeterministic bounded exploration and properties |
| =TemporalFamilyCase.tla= | Domain-neutral TLC instance and public property names |
| =TemporalFamilyCase.cfg= | Exhaustive two-candidate case |
| =TemporalFamilyBounded.cfg= | One-candidate bound and unexplored frontier |
| =TemporalDiscriminatingFamily.tla= | Later evidence refutes one candidate |
| =TemporalDiscriminatingCase.tla/.cfg= | Exhaustive unique-admissibility case |

* Formal interpretation

Let =O= be finite observations, =H= nonempty candidate hypotheses, and =C=
constraints.  An observation has identity, clock domain, natural position,
provenance and modality.  A hypothesis has identity, proposed cause and common
effect.  A constraint names a hypothesis and an ordered pair of observations.
The supported relations are strict =before= and non-strict =not-after=.  A
comparison is known only when both observations are present, observed, and in
the same clock domain.  Otherwise its value is =unknown=.  A failed known
comparison is =refuted=, and a satisfied known comparison is =admitted=.

Every hypothesis has an implicit strict cause-before-effect test in addition
to its declared constraints.  Its status is the conjunction in a three-valued
logic with =refuted= dominant, =unknown= second, =admitted= otherwise.  This
conservative order preserves uncertainty: a missing observation cannot be
silently interpreted as a passed temporal test.  It also makes an explicit
contradiction decisive even when another observation is unknown.

During exploration the candidate identities partition into disjoint sets
=R= (remaining), =A= (admitted), =F= (refuted), and =U= (unknown).  One step
selects any =h in R= while =|A ∪ F ∪ U| < EffectiveLimit=, removes it from =R=,
and adds it to the set matching its pure status.  The relation covers every
selection order within the bound.  A terminal state has =R= empty or reaches
the bound.  The query for target =t= is:

| Condition | Classification |
|-----------+----------------|
| =t in F= | =refuted= |
| =t in A=, =R= empty, =FamilyComplete=, =U= empty, =|A|=1= | =necessary= |
| =t in A= otherwise | =possible= |
| all other states | =unknown= |

=Necessary= therefore means unique temporal admissibility within the
caller-declared complete family after exhaustion.  It is not metaphysical
necessity or an intervention-based actual-cause judgment.  An incomplete
family or a bounded frontier cannot support that result.

* Properties and evidence

=InputInvariant= checks the finite instance's structural preconditions;
=PartitionInvariant= checks conservation and disjointness of the four sets;
=StatusInvariant= checks that every explored identity is in the set dictated
by the pure semantics; =BoundInvariant= checks the exploration cap; and
=TerminalAgreement= checks the expected terminal classifications for each
configuration.  TLC explores all reachable states of each *configured finite
instance*, including both candidate selection orders.  It does not prove the
properties for arbitrary cardinalities or all possible source programs.

=FairSpec= adds weak fairness for =ExploreAny=.  Under this explicit
assumption, =EventuallyTerminal= states that exploration reaches either
exhaustion or the bound.  This is a model scheduling assumption, not a
promise that the Scheme runtime or a distributed system will be fair.

Run =just check-temporal-family-tlc= from the repository root.  The two full
configurations use =ExplorationLimit=0=, deriving their effective bound
from the finite declared family.  The first expects =possible=; the bounded
configuration uses =ExplorationLimit=1= and permits =possible= or =unknown= according
to which candidate is explored first.  The discriminating configuration
exhausts the candidates and expects =necessary= for the sole temporally
admissible one.  The focused Scheme test
=t/qualification/tla-plus-interface/interface-test.ss= independently
constructs the literal POO model and compares its digest with the
source-to-POO projection.  It also projects the discriminating fixture and
checks the corresponding native classification.  These are fixture
correspondence checks, not a general refinement theorem or a typed TLC
receipt.

* Assumptions and open obligations

- The hypothesis family is finite and exclusive; completeness is a caller
  assertion, not inferred from evidence.
- Positions are natural numbers meaningful only inside one declared clock
  domain.  Event time, ingestion time, processing time and watermark order
  require distinct contracts before cross-domain inference.
- The source mapper accepts only five finite literal operators and rejects
  unsupported declarations or expression forms.  Parser acceptance alone is
  not semantic admission.
- A future correspondence theorem must relate the Scheme classifier's four
  sets and classification to the TLA+ terminal states for *all admitted model
  inputs and bounds*.  A TLC-to-POO receipt must bind source, grammar,
  semantic-model identity, configuration and checked result separately.
- Intervention semantics, structural causal equations, alternative-world
  generation, correction and retraction, and unbounded liveness remain outside
  this model.  A causally admissible claim requires additional evidence.

* Bitemporal revision submodel

=TemporalRevisionSemantics.tla= defines a finite set of evidence revisions
with predecessor and admission order, as-of visibility, maximal heads and
valid-time applicability.  =TemporalRevisionExplorer.tla= nondeterministically
appends any revision whose predecessor has been admitted.  Its append-only
transition relation is internal to the check.  The
=TemporalRevisionData.tla= case has an original assertion, two corrections
branching from it, and a retraction of only one correction branch.
Its valid-time fixture uses natural-number half-open intervals; the Scheme
time type also supports explicit open or closed endpoints.

At admission cut 15, =HistoricalCutInvariant= keeps only the original
assertion after it is admitted; later append steps cannot rewrite that cut.
=NoSilentWinner= requires an empty active set when multiple maximal revisions
remain.  =ActiveIsHead= forbids selecting a superseded revision.  Under weak
fairness of the append action, =EventuallyComplete= checks termination of
this *finite supplied revision set*.  =just check-temporal-revisions-tlc=
checks all predecessor-respecting orders of the case, not arbitrary journals.

The corresponding Scheme layer is =revisions/{types,objects,funs}.ss= and its
focused test is =t/temporal-revisions-test.ss=.  The Scheme receipt keeps a
canonical journal digest, an admission cut digest and a separate valid-time
projection digest.  The last binds the full valid-time instant row and result
buckets; a changed valid-time query cannot inherit the previous projection
merely because the admission cut is identical.  No executable, general
Scheme-to-TLA refinement relation exists yet: TLC and Scheme tests are
separate evidence.  Conclusion revision, watermark policy and effect
compensation remain outside this submodel; reverse-dependency scheduling is
the separate submodel below.
The Lean module =PooFlowProof.PooC4.TemporalEvidenceRevision= independently
proves future-append preservation for an abstract admission-time list filter;
it also proves the corresponding structural projection-key law.  It does not
bind the concrete Scheme and TLA+ representations or prove SHA-256 collision
resistance.

* Reverse dependency submodel

=TemporalInvalidationExplorer.tla= defines changed subjects, subject-to-
conclusion edges and conclusion-to-conclusion edges as finite input sets.
=Direct= selects immediate conclusions; =Closure= iterates dependency
propagation at most the number of declared conclusions.  =Advance= picks any
currently reachable unscheduled conclusion.  Cycles cannot reschedule an
element because the state is a set.  =ScheduledWithinClosure= excludes false
positives and =TerminalComplete= excludes missed dependents at a terminal
state.  =FairSpec= assumes weak fairness of =Advance= and checks
=EventuallyComplete= for the finite fixture.  The case contains two
independent subject branches, a conclusion cycle and a choice of scheduling
order.  Run =just check-temporal-invalidation-tlc=.

=ScopeChanged= adds a second finite fixture.  When the valid-time parameter
changes, =Direct= is the entire declared conclusion set, regardless of
subject edges or equal selected evidence buckets.  TLC checks
=ReprojectionScheduled= and completion for both configurations.  The
reprojection fixture has one reachable state because every conclusion is
scheduled initially; it checks the scope rule, not a runtime query-change
transition.

The Scheme =truth-maintenance/= module binds both admission cut and valid-time
projection identities and computes the same *mathematical*
transitive closure over POO derivations and emits an inert plan.  Its
=plan-from-cuts= path compares visible revision identities from two as-of
queries of one journal.  The Scheme entrypoint derives both snapshots
internally and rejects an index that differs from the replayed prior query;
the as-of owner reconstructs the journal digest from its revision inventory.
The test =t/temporal-truth-maintenance-test.ss=
checks chain, cycle, partial inventory, journal delta and cut identity cases.
It also checks full-inventory reprojection for the same cut and selected
revision under two valid-time coordinates, including a derivation with no
subject premise.  The Scheme plan carries a trigger so consumers cannot read
an empty changed-subject set as proof of no work.
LeanPoo's separate =TruthMaintenance= target proves
proof-obligation selection and certificate reuse for a typed patch.  Neither
the TLC fixture nor the Lean theorem proves a concrete Scheme/TLA/Lean
projection; that correspondence needs a canonical input map and an
implementation-level simulation or differential test over generated graphs.

* Conclusion selection race submodel

=TemporalConclusionSelection.tla= owns an abstract atomic pointer with
=selected= revision ID and natural-number =version=.  Each proposed change
names a new revision, predecessor, expected version and opaque proof
identity.  =Commit= is enabled only when both pointer fields match;
=Conflict= records a failed attempt without changing the pointer.  The
fixture offers a correction and a retraction from the same predecessor.
Both orders are explored.  Its invariants require disjoint committed and
conflicted sets, at most one commit, one version increment per commit and a
selected revision consistent with the committed set.  Under weak fairness
of =ResolveAny=, every finite proposal is eventually classified.  Run
=just check-temporal-conclusion-selection-tlc=.

The Scheme =conclusions/= module does not execute =Commit=.  It builds an
immutable conclusion journal, extends it without deleting old rows, and
prepares an inert =cas-ready= or =conflict= plan from
an externally observed pointer.  The test =t/temporal-conclusions-test.ss=
checks history preservation, branching, stale versions and counterfeit
journal rows.  The TLA+ action assumes an atomic runtime operation and says
nothing about capability admission, a durable pointer store, evaluator proof
validity or compensation after an already committed effect.  The independent
LeanPoo 4.34 target proves the parametric old-version staleness law for one
abstract successful commit; it does not establish runtime linearizability.

* Research basis

- Lamport, [[https://lamport.azurewebsites.net/pubs/time-clocks.pdf][Time, Clocks, and the Ordering of Events in a Distributed System]]:
  partial order motivates explicit clock comparability.
- Lamport, [[https://lamport.azurewebsites.net/tla/high-level-view.html][A High-Level View of TLA+]]:
  a specification denotes possible behaviors; checking one finite model is
  bounded evidence about that model.
- Lamport, [[https://lamport.azurewebsites.net/tla/hiding-and-refinement.pdf][Hiding, Refinement, and Auxiliary Variables]]:
  public POO observations and internal exploration state require an explicit
  observable/refinement relation.
- Halpern and Pearl, [[https://www.cs.cornell.edu/home/halpern/papers/actcaus.pdf][Causes and Explanations: A Structural-Model Approach]]:
  temporal consistency alone does not establish actual causation.
