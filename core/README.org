#+title: Core

* What Core owns

Core is the =core= Gerbil package: reusable POO-native mechanisms shared by
POO Flow, gerbil-parser, and other consumers. The package root is the module
root, so consumers import a precise owner such as =:core/module-system/config=.
There is no eager umbrella module or compatibility alias.

Core depends on Gerbil v0.19 and =gerbil-poo=; it does not depend on POO Flow,
ASP Scheme, or a product runtime. POO Flow includes Core as a Git submodule and
builds its sources before its own modules. It does not repeat that submodule as
a =gerbil.pkg= dependency.

* Responsibility map

| Area | Shared mechanism |
|------+------------------|
| =object-family/=, =types.ss= | POO object families and Types |
| =extension-graph/=, =composition/lineage.ss= | Extension fixed points and pure lineage analysis |
| =contribution/= | Contribution values, capability admission, receipt issuance and revocation |
| =module-system/= | Native Module values, schemas, inheritance, SourceRef, static Loader and Catalog |
| =profile-composition/= | Indexed Module Profile selection and pure ProfileBundle composition |
| =observability/= | Observations, feedback, slot presentation, memory sampling, testing Case |
| =poo-clos/= | CLOS-specific metaprotocols over native POO objects and MOP |

Within =module-system/=, =types.ss= and =objects.ss= own values and Contracts;
=funs.ss= and =graph/funs.ss= own pure operations; =config.ss= owns generic
interface construction. The =schema/=, =source/=, =loader/=, and =catalog/=
subdirectories separate their respective mechanisms. Consumers import these
leaf owners directly.

Semantic Module imports use native POO prototype composition. Gerbil POO's C4
orders and de-duplicates ancestors; the =contributions= slot rule places local
values before inherited values. Core does not add a general-purpose merge
evaluator. Removal, conflict admission, and extension fixed points remain
explicit, separately named policies.

The CLOS layer adds multiple dispatch, method combination, lifecycle, and
other CLOS semantics absent from the base MOP. Object identity, slot lookup,
Type validation, and C4 precedence remain owned by =gerbil-poo=. See
[[file:poo-clos/README.org][the CLOS implementation notes]] for its API and conformance boundary.

* Boundary with POO Flow

Core values are inert until a product owner admits or executes them. POO Flow
owns its Module branding, default authoring Profile, Loader selection, source
interpretation, Doctor presentation, Profiles, and runtime handoff. Core's
contribution verification can issue or revoke a host-trusted receipt; it does
not grant runtime authority or execute an effect.

The remaining POO Flow =src/module-system/= is being separated by ownership:
shared mechanisms move here, while product policy stays in POO Flow. A file's
location during migration is not a second permanent implementation contract.

* Build and test

Use Gerbil v0.19 with =gerbil-poo= available in an isolated =GERBIL_PATH=.
The Just recipes set the build parallelism and heap-fence tests before module
imports:

#+begin_src sh
just build
just test
just test-file t/module-interface-test.ss
#+end_src

Core's =t/= tests cover shared semantics. POO Flow retains product selection
and cross-package integration tests.
