   universe across POO and Data. Reject divergent pins, stale lock entries and
   duplicate producer revisions through =check_mrr_dependency_graph.py=.
2. Rebuild the native Scheme Library in CI. Download that exact run's semantic
   artifact and Runtime C producer, and verify semantic source/header/host hashes.
3. Compile original Rust MRR consumers before the execution deadline. Run the
   original result, support, rule, Derivation and policy tests serially through
   the five-second idle / 45-second total gate. Preserve actual Scheme oracles.
4. Install the Python Library consumer and replay those original Rust oracles
   against the same native artifact. Qualify correction, historical truth,
   current journal/catalog/policy guards and control-lane rejection. Required
   oracles must exist; an absent producer cannot turn into a passing skip.
5. Close the exact delivered-head CI, including the Python wheel. Report native
   consumer qualification separately from updated physical Data execution.

original emitted Scheme oracles are local or CI artifacts, never Git logs.

* Acceptance rules

Five seconds without genuine completed-work output is failure. Native execution
keeps the 45-second total bound. Build/dependency preparation, local semantics,
exact-head CI, real-model behavior and performance are distinct evidence.
No synthetic heartbeat, timeout widening, hidden retry or repair closes a gate.
New measurements and native qualification receipts use ASP Scheme's benchmark
API; receipt/ABI versions remain v1. Source control retains gates and bounded
structured summaries, not raw or compressed logs.
