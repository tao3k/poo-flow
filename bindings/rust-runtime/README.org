* Contract

Python runtime implementation and its Python qualification tools live under
=packages/python-runtime=. This directory owns the Rust consumer of the shared
C/Scheme ABI and Rust assertions for that consumer. Temporal semantics remain
in the POO/Scheme core. Python and Rust call the shared ABI as separate callers.

This Rust crate consumes =runtime-c/semantic.h=. Native POO/Scheme remains the
semantic owner. Supported operations are descriptor, temporal.solve/verify/observe
and temporal.family.classify/observe. Host registration, admission, publication
and arbitrary operation dispatch are not exposed by this read-only consumer.

=SemanticRuntime::open(path, expected_sha256, capacity)= checks a trusted host's
artifact digest, then opens it on one dedicated OS thread. Use an immutable
host-controlled artifact path: digest verification is not issuer authentication
and does not prevent a hostile filesystem rewrite during dynamic loading.
Artifact hashing streams through a 64 KiB buffer. Qualify the release build;
unoptimized debug hashing is not a deployment timing receipt. Optional
POO_FLOW_RUNTIME_TRACE records completed digest/load/open stages only.
Capacity must be 1..64, input bytes at most 1 MiB and consumed output at most
16 MiB. Pending queue saturation fails immediately. The queue holds at most
capacity pending requests plus one active request. Returned values are owned inert Scheme data;
native allocation is released on the owner thread before replying.

Native lifetime is process-global and thread-affine. =close= drains accepted
requests, closes once and joins the owner. Native code remains mapped for the
process lifetime, preserving Gambit's terminal-close contract. A second open
cannot reopen a closed native instance. Callers may share the Rust handle across
threads, including through Arc, but native pointers never leave the worker.
=Pending::wait_timeout= bounds only response waiting; it cannot interrupt native
execution. Close/drop may wait for a native call to finish. Read-only cancellation
is response abandonment, not solver interruption or a closed-frontier claim.

The =semantic_call= binary accepts one bounded Scheme datum object with exactly
=operation= and =payload= on stdin. The host supplies POO_FLOW_SEMANTIC_LIBRARY
and POO_FLOW_SEMANTIC_SHA256. It outputs only the original native Scheme datum object;
no Rust-created causal receipt, source authenticity or effect permit is added.

* Host source registration and current reads

=MrrObservationEvidence::register_current= builds source observations only from
the original re-admitted MRR result. The explicit =SourceRegistrationContext=
supplies the host's authority, subject and use scope. Registration goes through
the dedicated C control entrypoint on the same bounded owner queue; a semantic
or model operation cannot invoke that entrypoint. Native Scheme owns the source
digest and rejects generation rollback and conflicting same-generation state.

=RegisteredMrrSource::admit= checks the exact registered source version and
retains the original native proof receipt. =MrrFamilyAdmission::current= asks
Scheme to replay that proof and compare it with the independently registered
current source. The returned =current/stale= status concerns that read's host
snapshot. A corrected source does not overwrite the historical classification.
It must be queried, projected and admitted again. Unknown admissions, forged
current-state payloads and stale source handles fail closed. Native history is
bounded to 128 distinct admissions; an existing admission remains idempotent
at capacity, and no entry is evicted silently.

The host registration is an explicit trust premise, not provider authentication.
Current reads do not fence a later effect. Multi-source correspondence, durable
current pointers, conclusion predecessor journals, withdrawal/absence coverage,
atomic IFC publication and crash recovery require their separate gates.

* Acceptance

Run =packages/python-runtime/tools/differential.py= with the installed qualified Python wheel and
native artifact to generate a fresh oracle in its own process. The Rust native
test requires that artifact path/hash and POO_FLOW_RUST_DIFFERENTIAL. It compares
21 exact lens/family results across two vocabularies and open/budget profiles,
then checks errors do not poison future calls, queue saturation, concurrent
callers, terminal close and failed reopening. The CI wheel workflow runs this
against the same native producer artifact and installed wheel.

=just qualify-temporal-model PYTHON BINARY LIBRARY ORACLE ENV_FILE OUTPUT=
uses the ASP Scheme benchmark API to freeze four cases and artifacts, claim a
new output directory, measure each case once and emit native Scheme receipts.
At most eight real provider requests run with the five-second genuine-content
watchdog and zero retries. =packages/python-runtime/tools/deepseek_adapter.py= is only the provider HTTP
adapter: JSON exists inside that external service boundary; subprocess payloads,
oracles, native ABI and persisted records are Scheme data. Paid calls are never
repeated for p95 sampling. This runner checks task fidelity, real native output
and model consumption; it does not establish source authority or authorization.

=just benchmark-temporal-mrr= measures 20 complete native MRR test processes
through =:asp-gerbil-scheme/benchmark-api=. Set POO_FLOW_MRR_TEST_BINARY to the
release =mrr= integration executable and POO_FLOW_MRR_BENCHMARK_RECEIPT to a
new receipt path, plus the usual native artifact path/hash. Each sample runs all
semantic assertions. The subsecond gate includes process startup; it is not a
kernel throughput measurement. Rust tests remain the Rust FFI assertion owner;
ASP owns benchmark measurement and receipts. Its memory statistics describe the
Scheme harness process; child Rust/native peak memory is not measured by them.

* MRR boundary

This crate belongs to POO's runtime port. MRR continues to own query/catalog/
generation/result admission. MRR Data owns verified physical snapshot execution.
MRR result identity, source completeness, causal derivation, Temporal current
applicability and IFC flow authorization are distinct gates. No MRR generation
is converted into an integer Temporal generation by this transport.

* Native MRR result integration

Feature =mrr-transport= pins MRR =3ce31dac2dc58ab780ed06fa88103de501355692=.
=MrrObservationEvidence::verify= takes original native CandidateQueryResult and QueryResultAdmissionReceipt
values and calls MRR receiver-side candidate admission against the host's original CatalogBoundQuery. It retains the
original typed candidate and QueryResultAdmissionReceipt through =original()=.
No query/parser/catalog identity is regenerated by the adapter.

The initial projection accepts exactly two columns: =event= String and =position=
Integer, at most 128 nonempty unique event rows and 1 MiB of supported cell payload before digest computation or cloning.
Other shapes, null values, clock roles, implicit conversions and caller-supplied
observations are rejected. The host explicitly declares one event-time clock,
source identity, cut, projection, policy and separate integer Temporal generation.
The original content-addressed MRR generation stays unchanged. The correspondence
binds all upstream receipt identities and the host scope; its digest becomes
observation provenance so changed scope/generation cannot reuse model identity.

=classify= inserts only the re-admitted observations into a finite POO family and
calls the original native classifier. This is an operational native MRR -> Rust
host projection -> C/POO path. The MRR test fixture exports actual MRR typed
candidate values and receipts, then re-admits them and calls the real POO library.
It is not a physical DataFusion/S3 execution qualification, original GQL parser
receipt qualification, source authenticity proof or generalized row projection.
Coverage and action authorization remain false; family completeness is still
an explicit caller assumption. Original receipt result-digest semantics are
preserved separately from Temporal model/projection identity.

* ABI v1 direct migration

Only =poo_flow_semantic_v1_*= native entry symbols are loaded/exported. Descriptor
=abiVersion= is 1 and =wireFormat= is =scheme-datum-v1=. There is no legacy JSON
fallback. Artifact manifests and differential oracles use =.ss= files. Native MRR
values are passed directly; this adapter no longer calls MRR JSON transport.
See [[file:../runtime-c/semantic-wire.org][the bounded Scheme wire grammar]].

* Proof-bound Family revision and journal ABI

=MrrFamilyAdmission::revision_root= asks the Scheme owner to replay the original
admission and retain its proof-bound root. =MrrFamilyRevision::change= forwards
an original admission handle, predecessor handle, typed operation and
=FamilyRevisionFrontier=. Scheme reconstructs a native POO frontier, replays
both admissions and enforces the Library's Source/query/generation/cut rules.
No proof can be replaced by a caller-supplied string. A frontier's inventory
completeness and index digest remain caller declarations, not authenticated
reverse-dependency or provider evidence.

=MrrFamilyRevision::journal= replays every referenced original admission and
checks the supplied immutable graph inventory. The Scheme datum response
retains native revision fields plus per-entry classification, admission digest
and proof-bound revision digest. Branches and predecessors are retained; it
selects no current winner. Missing predecessors, duplicate revisions, unknown
handles and malformed fields reject. Native history is bounded to 128 distinct
revision handles; duplicate delivery remains idempotent at capacity. A journal
request contains 1--128 handles.

The descriptor advertises =temporal.family.revision.root=,
=temporal.family.revision.change= and =temporal.family.journal=. These use the
existing Scheme datum v2 transport and single owner thread. Handles live only
in that native process. The projected journal is a read-only receipt, not a
restartable proof archive. The archive API below transports and replays Family
premises; MRR Data authoritative persistence and pointer publication remain open.
=durable=, =runtimeExecuted=, =sourceAuthenticated= and =actionAuthorized= are
false. Current Source applicability is independently checked by =current=;
a historical revision/journal receipt never establishes current eligibility.

* Complete Family premise archive and detached replay

=MrrFamilyRevision::archive= exports a bounded native =PooFlowTemporalFamilyArchive=.
Its Scheme datum contains every admission Model/Query, original Source Model and
scope, Frontier, operation, predecessor and expected revision envelope. Native
POO constructors replay admissions and the whole graph before returning its
canonical digest. The exported archive fits a subsequent 1 MiB ABI replay request
and contains 1--128 revisions.

=MrrFamilyProofArchive::from_bytes= parses inert Scheme bytes and requires an
independently retained expected digest. It does not establish proof validity.
=replay= calls =temporal.family.archive.replay=: Scheme reconstructs all premises,
checks admission/proof/revision/journal/archive digests, and returns a read-only
receipt. Entry order is immaterial; duplicates, missing predecessors, cycles and
tampered premises reject. =temporal.family.archive.export= and =.replay= are
advertised by the native descriptor.

Replay uses local maps only. It registers no current Source, restores no handles,
and grants no authorization, effects or durability. The caller must retain the
expected digest through a trusted channel; accepting a payload's own digest as
that anchor establishes no authenticity. This archive is complete relative to
Family premises, not the original physical MRR candidate/receipt/provider binding.
MRR Context admission, MRR Data authoritative journal/CAS, provider authentication
and effect authority remain separate gates. The native and fresh-process Rust
receipts are in =t/qualification/temporal-family-proof-archive/=.

* Current MRR Context binding

The optional =mrr-context= feature enables the original pinned MRR Context owner
API. Registered Sources and their native Family admissions retain the original
re-admitted MRR candidate, receipt, limits and host correspondence. No receipt
is reconstructed from model text or a Context declaration.

=MrrFamilyAdmission::context_reference= returns an MRR =FactId= and one native
MRR String value containing the versioned Scheme receipt datum. The FactId is
computed by MRR from the exact payload bytes. The host declares a one-String
relation in its source catalog and includes that exact fact in the Context's
=temporal_receipts=; it must not substitute a claimed digest or free-form text.
The Context core retains its own native fact/dependency/manifest semantics.

=check_context= rechecks the admitted Context against the supplied current
bundle/snapshot, rebinds its query, re-admits the retained original MRR candidate
and compares the entire receipt. It requires the exact receipt fact in both the
contract and required closure, verifies its payload and policy mapping, then
asks the native Scheme owner whether the original admission's Source is current.
Foreign bundle/query/generation, substituted payload, missing reference, policy
mismatch and stale native Source reject before returning a check receipt.

=context_policy_digest= defines the explicit versioned correspondence: SHA-256
of the UTF-8 domain =poo-flow.mrr-context-policy.v1= followed by NUL, the policy
byte length as a big-endian u64, then the native policy token's UTF-8 bytes. This
binds a host policy identity; it neither interprets nor authenticates that policy.
Actor/task declarations and provider authenticity remain upstream responsibilities.

This is a point-in-time observation, not a reusable lease or atomic disclosure
transaction. A subsequent Source update invalidates applicability; consumers
must recheck before use. MRR Data durable append/current CAS must join that
recheck to its own transaction. Authority/effect/durability flags remain false.
Detached archive replay cannot produce a =MrrFamilyAdmission= or current Context
handle. The production adapter and executable receipts are documented under
=t/qualification/temporal-mrr-context-binding/=.

* Orgize source observation

The optional =orgize-source= feature adds =org_source::WorktreeOrgSelection=.
The Rust host supplies a WorkTree root and a bounded project/WorkTree/source-cut
key with a relative Org path. The adapter reads at most 8 MiB of UTF-8 source,
parses it with Orgize's Scheme-AOT parser, runs one maintained named Element
query, and retains the parser-owned source observation privately. A later
=recheck_file= reopens the file and compares the key, resolved root and file,
bytes, parse configuration, rule, scope and selected graph-local IDs/spans.
Only a successful recheck exposes an ephemeral selection to its caller.

The key and root are host declarations. This adapter does not authenticate Git
WorkTree state, access grants or a stable filesystem path under concurrent
mutation. Its file read is not an atomic WorkTree snapshot. It does not call
the Scheme Session policy, grant an effect, or publish a Session/Memory head.
The host must still obtain an authoritative cut and current grant, pass the
parser-owned candidates to Session policy, and conditionally publish through
the runtime's expected-head CAS. The current Scheme Session selector remains
fail-closed for caller-supplied Element graphs.

The =org_source= Rust integration tests exercise current rechecks and stale
bytes/configuration/cut/query, path escape, root replacement, non-UTF-8 and
oversized source rejection. The Python runtime wheel CI runs these tests with
the optional feature and checks explicit =ORGIZE-SOURCE-HOST-OK= markers. An
independent Ubuntu CI job checks this feature without waiting for the native
Gerbil matrix.

* Original MRR support identity projection

With =mrr-transport=, =mrr_support::MrrSupportProjection::admit= consumes original
MRR Derivation values and explicit =MrrSupportBinding= fact-to-subject/revision
correspondence. It retains the original values and projects original IDs through
the fixed Scheme ABI v1 =temporal.support.evaluate= operation. The identity digest
binds rule/generation/output/support IDs; it does not certify rule execution,
output content or provider authenticity. Missing, duplicate and unused bindings
reject. Scheme alone evaluates applicability from the declared journal.
The read-only result admits neither proofs nor publication or durability.

=MrrFactProjection::admit= requires the original admitted =RelationCatalog=.
It resolves the Fact's exact RelationId, runs the owner =validate_fact= field
and context checks, requires complete/valid context and projects integer/boolean
content without coercion. The evaluator relation name comes from the catalog's
predicate; there is no unchecked caller alias constructor. Support projection
also requires the catalog and validates each original Derivation output.
Both retain its exact owner digest, and =verify_content= / =evaluate= require a
matching supplied catalog before calling native Scheme. A caller must obtain
that catalog from its authoritative provider; a matching value alone is not
provider authentication or an atomic current-state read.

The supported catalog profile is at most 32 relations, unique ASCII alphanumeric
or underscore predicates of at most 256 bytes, and 1--32 nonnullable integer or
boolean fields per relation. Key/Unique/FD constraints and other field schemas
are rejected because this adapter does not validate cross-row constraints or
implement their semantics. Original catalog ordering is canonicalized by MRR.
The fact content digest and fixed Scheme ABI v1 payload remain unchanged;
the held catalog digest is a local owner admission condition, not a newly
verified Scheme proof field. =verify_content= compares content with the original
Scheme constructor through =temporal.fact.content=.

This does not admit the associated MRR rule or authenticate source provenance.
Native tests replay a typed owner Fact and Derivation fixture through actual
ASCENT proof roots and Temporal revisions. The Rust catalog qualification and
Python replay receipts are in
=t/qualification/temporal-library-basic/catalog-binding-v1/=.

The remaining integration sequence is:
1. Project original =mrr_logic::Rule= heads/bodies and catalog relation/column
   correspondence into the original Scheme evaluator, then check their exact
   correspondence against proof DAG rule applications. A RuleId is insufficient.
2. Expose the existing Scheme proof producer and isolated Host policy capability
   through dedicated control entries in ABI v1. Model calls must not register
   policy/clock state or manufacture admitted proofs.
3. Recheck current authoritative catalog, source, policy and clock at the effect
   boundary, and admit only conditional Data publication with the expected head.
