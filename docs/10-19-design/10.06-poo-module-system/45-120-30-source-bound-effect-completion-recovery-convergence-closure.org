#+title: Source-bound effect completion recovery-convergence closure
#+startup: overview

* Status

This RFC closes the next v1 proof boundary after
[[file:45-120-29-source-bound-effect-completion-crash-recovery-closure.org][45-120-29]].

It separates two claims that the previous recovery design did not yet
distinguish:

- recovery safety: no invalid transition, duplicate execution, stale
  generation, or duplicate committed key is accepted;
- recovery liveness: repeated recovery attempts eventually reach an absorbing
  committed state.

This remains a v1 stabilization.  It introduces no v2 schema, no recovery
journal, no second ledger owner, and no JSON representation in the core Lean
model.  Audit/Python/AXLE transport continues through the existing FFI boundary.

* Lean-discovered gap: safety does not imply convergence

The crash-recovery state machine permits an acknowledged effect to remain in
=executed-uncommitted= while publication is retried.  That self-loop is safe:
the physical effect is not executed again.  It does not, by itself, guarantee
that storage ever accepts the publication.

Define the infinite trace:

#+begin_src typst
$ tau(n) = "executed-uncommitted" quad "for every" n in NN $
#+end_src

Every adjacent transition is the safe =retry-publication= transition, but no
index is committed:

#+begin_src typst
$ (forall n, op("SafeTransition")(tau(n), tau(n + 1)))
  and not (exists n, tau(n) = "committed") $
#+end_src

Therefore:

#+begin_src typst
$ op("TransitionSafety")(tau)
  not=> op("RecoveryConvergence")(tau) $
#+end_src

This counterexample prevents the RFC from claiming eventual commit merely from
idempotency, fail-closed classification, or commit uniqueness.

* Decision

Model repeated recovery in four independent layers.

1. A transition relation describes the safe state graph.
2. Provider acknowledgement monotonicity prevents a later compatible probe from
   rewriting an acknowledged receipt into a negative result or a different
   receipt.
3. A natural-number recovery rank is the explicit liveness obligation.  Every
   non-committed step must strictly decrease it.
4. The existing completion-publication history remains the authority for
   uniqueness of committed idempotency keys.

The recovery trace reaches commit when:

#+begin_src typst
$ op("ReachesCommit")(tau) =
  exists n, tau(n) = "committed" $

$ op("Converges")(tau) =
  op("ReachesCommit")(tau)
  and op("CommittedAbsorbing")(tau) $
#+end_src

The additional progress contract is:

#+begin_src typst
$ forall n,
  tau(n) != "committed"
  => rho(n + 1) < rho(n),
  quad rho : NN -> NN $
#+end_src

There is no infinite strictly descending chain of natural numbers.  Lean
therefore proves:

#+begin_src typst
$ op("TransitionClosed")(tau)
  and op("StrictlyRanked")(tau, rho)
  => op("Converges")(tau) $
#+end_src

The rank is not a new stored counter and does not become a runtime ledger.  It
is a proof measure discharged by the actual liveness contract:

- crashes are finite within the recovery obligation;
- the recovery attempt is scheduled fairly;
- provider acknowledgement remains observable;
- storage eventually accepts one valid existing completion publication.

Without those external conditions, the RFC promises safety and fail-closed
behavior, not eventual success.

* Safe transition graph

#+begin_src mermaid
stateDiagram-v2
    [*] --> NotExecuted: "authoritative provider negative"
    NotExecuted --> NotExecuted: "safe wait / no physical execution"
    NotExecuted --> ExecutedUncommitted: "execute once / durable acknowledgement"
    NotExecuted --> Indeterminate: "authority unavailable or conflict"
    ExecutedUncommitted --> ExecutedUncommitted: "crash or retry publication / never re-execute"
    ExecutedUncommitted --> Committed: "existing atomic publication accepted / rank decreases to terminal"
    ExecutedUncommitted --> Indeterminate: "storage or observation becomes uncertain"
    Indeterminate --> NotExecuted: "new authoritative negative / current epoch+fence"
    Indeterminate --> ExecutedUncommitted: "stable acknowledgement recovered"
    Indeterminate --> Committed: "closed existing commit evidence recovered"
    Indeterminate --> Indeterminate: "still unknown / fail closed"
    Committed --> Committed: "absorbing / history uniqueness"
    Committed --> [*]: "recovery converged"

    note right of ExecutedUncommitted
      Safety permits this self-loop.
      Liveness requires a decreasing rank;
      otherwise convergence is not claimed.
    end note

    note right of Committed
      No new journal owns this state.
      Existing completion publication
      and history remain authoritative.
    end note
#+end_src

The edge labels distinguish safety from progress:

- a crash/retry self-loop is safe but does not decrease the liveness rank;
- a ranked convergence witness cannot remain on that self-loop forever;
- committed is absorbing;
- indeterminate remains fail closed until new authoritative evidence appears.

* Provider acknowledgement monotonicity

For compatible attempts in the same provider, idempotency key, epoch, and fence
domain, an earlier acknowledgement constrains every later attempt:

#+begin_src typst
$ i < j
  and op("Status")(a_i) = "acknowledged"
  => op("Status")(a_j) = "acknowledged"
  and op("Receipt")(a_j) = op("Receipt")(a_i) $
#+end_src

This is a provider-owned liveness and observation contract.  Lean proves its
consequences, including that a later attempt cannot become an authoritative
negative observation.  Lean does not manufacture the external fact.

* Generation invalidation

Recovery observations are valid only in the current runtime epoch and fence
domain:

#+begin_src typst
$ e_"old" != e_"current"
  or f_"old" != f_"current"
  => not op("ClosedRecoveryObservation")(
    e_"current",
    f_"current",
    o_"old",
  ) $
#+end_src

A generation advance invalidates the older recovery observation.  It does not
rewrite or migrate that observation into the new session.

* Existing history uniqueness

The convergence witness carries the existing
=SourceBoundEffectCompletionPublicationHistory=.  Its closure is still:

=SourceBoundEffectCompletionPublicationHistoryClosed=

and committed-key separation is reused directly from:

=closedCompletionHistorySeparatesCommittedKeys=.

#+begin_src typst
$ op("ClosedConvergenceWitness")(w)
  => op("PairwiseDistinct")(
    op("HistoryExecutedKeys")(w."history"),
  ) $
#+end_src

The convergence model therefore does not create a recovery journal or a second
uniqueness implementation.

* Authority separation

| Concern | Authority owner | Lean obligation |
|-
| Safe transition graph | core proof | reject invalid state changes |
| Stable acknowledgement and receipt | effect provider | acknowledgement monotonicity |
| Fair retry and finite-crash progress | runtime scheduler | strict recovery-rank decrease |
| Eventual atomic acceptance | existing completion storage owner | reach committed |
| Committed-key uniqueness | existing publication history | reuse pairwise key separation |
| Audit/Python/AXLE transport | existing proof FFI owner | transport only; no semantic authority |

The core module uses pure Lean inductives, functions, and propositions.  It adds
no JSON instances.  Audit transport may project declarations, but an audit value
does not establish provider monotonicity, scheduler fairness, or storage
availability.

* Proof findings

The Lean model exposes and closes these v1 design defects:

1. Safe repeated publication retries may form an infinite non-convergent trace.
2. Idempotency and at-most-one commit are safety properties, not liveness.
3. Eventual commit needs an explicit well-founded progress obligation.
4. A stable provider acknowledgement must remain acknowledged with the exact
   same receipt across later compatible attempts.
5. A later negative result after acknowledgement would reopen duplicate
   execution and is therefore rejected.
6. New epoch or fence ownership invalidates every older observation.
7. Committed must be absorbing.
8. Commit uniqueness must be inherited from the existing publication history,
   not reimplemented by a recovery journal.

* Next proof gap

This gap is continued in
[[file:45-120-31-source-bound-effect-completion-recovery-progress-evidence-closure.org][45-120-31]].

The rank proves convergence only after the runtime/provider/storage owners
discharge its decrease obligation.  The next proof must connect that abstract
rank to concrete bounded evidence:

- finite crash budget and retry-attempt sequence;
- provider read-after-write acknowledgement durability;
- storage admission/backpressure and eventual acceptance;
- cancellation and supersession by a newer epoch/fence;
- a receipt showing which owner discharged each decrease.

That connection must remain an evidence composition over existing owners, not a
new scheduler, journal, or persistence system inside the proof layer.
