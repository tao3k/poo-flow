#+title: Scale-Parametric Module Graph Safety and Executable Admission
#+startup: overview

* Status

Accepted semantic architecture.

This RFC proves the scale-independent semantic obligations required before POO
Flow may claim that hundreds or thousands of Modules, each exporting different
Profiles, can safely enter one final ~use-composition~ root.

The concrete ~gerbil-poo~ refinement relation and generated graph receipt
contract are specified separately in RFC 45-113; this RFC does not admit that
implementation.

It deliberately separates semantic proof from executable scale admission.
Passing Lean does not admit the concrete Gerbil implementation or its
performance envelope.

* Scope

This document owns:

- the Module-count-parametric Profile selection model;
- contributor soundness and exclusion of spurious Profiles;
- imports-closure soundness and completeness;
- capability attenuation across every participating Module;
- aggregate Profile responsibility completeness;
- bounded fixed-point outcomes and cycle observability;
- the single-root law for arbitrary finite Module counts;
- the semantic-versus-executable scale admission boundary; and
- required 100, 1,000, and 10,000 Module receipts.

It does not own:

- a second fixed-point implementation;
- physical Gerbil package installation;
- a new composition macro;
- a framework-specific Module language;
- unbounded recursion;
- a promise of performance without process-attributed receipts; or
- implementation admission from abstract proof alone.

* Central theorem

For any natural number ~n~, let ~Fin(n)~ index the participating Module
instances.  Each Module contributes a Profile selection and a capability
requirement.

#+begin_src typst
$ S_n(p) = exists i in "Fin"(n): S_i(p) $

$ A_n(a) = forall i in "Fin"(n): A_i(a) $

$ A_n subset.eq A_i quad "for every" i in "Fin"(n) $
#+end_src

The first equation says that a Profile appears in the composed selection only
when at least one Module contributes it.  The second says that effective
authority satisfies every participating Module requirement.  Increasing the
Module family therefore cannot amplify authority.

The theorem is parametric in ~n~.  It has no architecture-level constant such
as 100 or 1,000.

* Reachable closure theorem

Let ~reachable(p, d)~ mean that dependency ~d~ is reachable from selected
Profile ~p~.  The admitted closure satisfies both directions:

#+begin_src typst
$ d in C_n arrow.r.double
  exists i in "Fin"(n), p:
    S_i(p) and "reachable"(p, d) $
#+end_src

Consequences:

- every dependency in the closure has a selected-Profile witness;
- every reachable dependency of every selected Profile enters the closure;
- an unreferenced Module or Profile cannot leak into the closure;
- excluded subgraphs remain explicit negative evidence; and
- closure identity is deterministic for one root revision.

This is the semantic soundness/completeness contract.  Executable traversal and
backend projection remain separately tested.

* Aggregate Profile compression

The four current User Interface cases provide a small concrete witness:

#+begin_src typst
$ "low-level-profiles" = 14 + 5 + 7 + 11 = 37 $
$ "duplicated-current-references" = 2 dot 37 = 74 $
$ "aggregate-selections" = 4 $
#+end_src

Compression from 74 references to four aggregate selections is admitted only
when the closure receipt retains all 37 low-level identities, their
responsibilities, exclusions, capabilities, graph/loop/proof objects, and
handoff presence or absence.

The shorter surface is not itself a correctness proof.

* Fixed-point and cycle boundary

Recursive submodule imports may contain cycles.  For every admitted root:

- cycle identity remains observable;
- evaluation terminates normally or suspends/fails closed at an explicit
  demand budget;
- raw unbounded recursion cannot escape;
- the result is deterministic for one root revision;
- incremental reevaluation preserves stable identity; and
- continuable recovery remains owned by the existing POO Flow control plane.

This RFC introduces no new fixed-point evaluator.

* Single-root law

~user-composition~ does not enumerate the transitive Module graph.

For any finite ~n~, it receives one ordinary composed Profile value, projects
one stable root identity, and performs exactly one root instantiation.

Module count changes closure work.  It does not change the public macro shape
or multiply root instantiation.

alone.

* Admission criteria

Executable large-scale support may be claimed only when:

- [ ] the concrete Gerbil implementation refines the scale-parametric model;
- [ ] 100, 1,000, and 10,000 Module receipts are present;
- [ ] every closure member has a selected reachability witness;
- [ ] every selected reachable dependency appears in the closure;
- [ ] capability authority never expands as Modules are added;
- [ ] explicit Module instances remain distinct at every scale;
- [ ] cycles terminate, suspend, or fail closed at observable budgets;
- [ ] memory and time receipts identify the owning process and phase;
- [ ] backend projection is sound and complete for the admitted closure;
- [ ] one ~user-composition~ still creates exactly one root; and
- [ ] the 45-91 through 45-94 obligations remain satisfied.
