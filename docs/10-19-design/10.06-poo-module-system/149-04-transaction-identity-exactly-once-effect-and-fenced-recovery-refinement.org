#+title: RFC 149-04 — Transaction Identity, Exactly-Once Effect, And Fenced Recovery Refinement
#+language: en

* Status

This is a Lean-proven refinement of RFC 149-03.

RFC 149-03 proves the local admission-to-commit snapshot and atomic
outcome obligations.  A local commit closure does not by itself prove
global transaction identity, duplicate equivalence, complete rollback,
or exclusive crash recovery.

This refinement defines those missing mathematical obligations.  It
does not claim that the Marlin transaction registry, effect journal, or
recovery runtime has already landed.

* Discovered logical defects

** Individually valid commits do not imply transaction-ID uniqueness

Two distinct =PromotionCommitRequest= values can reuse the same
=transactionId=, choose different target states, and each satisfy the
RFC 149-03 local commit closure.

Lean proves:

#+begin_src text
individualCommitClosureDoesNotEnforceTransactionIdUniqueness
#+end_src

Transaction identity is therefore a registry-wide functional
dependency:

#+begin_src text
same transactionId -> same canonical PromotionCommitRequest
#+end_src

It cannot be inferred from one receipt at a time.

** A duplicate outcome does not prove a prior commit

RFC 149-03 requires a duplicate receipt to name the exact target state.
An orphan receipt can satisfy that equality even when the commit ledger
is empty.

Lean proves:

#+begin_src text
duplicateOutcomeDoesNotProvePriorCommit
#+end_src

A valid duplicate requires an authentic prior =committed= receipt for
the same canonical request.  Matching prior-receipt fields are still not
enough:

#+begin_src text
matchingPriorCommitFieldsDoNotProveCommitValidity
#+end_src

The prior receipt must satisfy the Marlin-owned =CommitReceiptValid=
relation.

** Runtime-state equality does not prove complete rollback

The RFC 149-03 receipt observes one runtime-state digest.  Two worlds can
have that same digest while an external effect, message, file, remote
mutation, or capability exercise remains uncompensated.

Lean proves:

#+begin_src text
runtimeDigestRollbackCanHideExternalEffect
#+end_src

Rollback must compare a complete effect observation, not only the local
runtime state.

** Missing durable intent makes crash histories indistinguishable

A crash before an effect and a crash after an unrecorded external effect
can project the same absent durable record and the same runtime digest.

Lean proves:

#+begin_src text
missingDurableIntentAndEffectObservationAreAmbiguous
#+end_src

The durable transaction record must therefore be persisted before the
effect can begin, and recovery must observe both the runtime state and
the effect journal.

** Matching fence numbers do not prove exclusive recovery ownership

Two workers can copy the same transaction ID, observed fence, and next
fence.  Both satisfy numeric field checks while remaining distinct
claims.

Lean proves:

#+begin_src text
matchingFenceFieldsDoNotProvideExclusiveOwnership
#+end_src

The transaction owner must perform an atomic fence acquisition and
validate exactly one claim for a given durable-record snapshot.

** Typed registry and durable-record fields do not prove owner authority

Lean also proves:

#+begin_src text
uniqueRegistryFieldsDoNotProveRegistryAuthority
matchingDurableRecordFieldsDoNotProveRecordAuthority
matchingRecoveryFieldsDoNotProveRecoveryAuthority
#+end_src

The closure retains independent =TransactionRegistryValid=,
=DurableRecordValid=, =RecoveryClaimValid=, and
=RecoveryReceiptValid= relations.

* Mathematical model

The derived mathematical presentation is Typst:

#+begin_src typst
$ Q = (t, a, C, d_"pre", d_"target") $

$ U(R) =
  forall e_1, e_2 in R:
  ((e_1)_"t" = (e_2)_"t") => ((e_1)_"Q" = (e_2)_"Q") $

$ E = (d_r, d_x, n_u) $

$ "Prior"(Q, L) =
  exists p in L:
  "CommitValid"(p)
  and (p_"outcome" = "committed")
  and "BindsCanonicalRequest"(p, Q) $

$ "EffectClosed"(Q, p, E_0, E_1, L) = cases(
  ((E_0)_"uncompensated" = 0) and ((E_1)_"uncompensated" = 1)
    & "if committed",
  "Prior"(Q, L) and (E_1 = E_0) and ((E_1)_"uncompensated" = 1)
    & "if duplicate",
  E_1 = E_0
    & "if rejected or rolled back",

$ D = (Q, phi, f, E_"pre") $

$ K = (t, w, f_"observed", f_"acquired") $

$ "ClaimMatches"(D, K) =
  (K_"t" = (D_"Q")_"t")
  and (K_"observed-fence" = D_"fence")
  and (D_"fence" < K_"acquired-fence") $

  forall D, K_1, K_2:
  (V(D, K_1) and V(D, K_2)) => (K_1 = K_2) $

$ "RecoveryClosed"(R, D, K, Z) =
  U(R)
  and "RegistryValid"(R)
  and "Registered"(R, D_"Q")
  and "DurableRecordValid"(D)

  and "Exclusive"("ClaimValid")
  and "ClaimMatches"(D, K)
  and "ClaimValid"(D, K)
  and "ReceiptBinds"(Z, D, K)
  and "Terminal"(Z_"phase")
  and "EffectClosed"(D_"Q", Z_"effect")
  and "RecoveryReceiptValid"(Z) $

=E= is a complete transaction-scoped effect observation:

- runtime-state digest;
- external-effect or effect-journal digest;
- uncompensated application count for this transaction.

The digest is meaningful only if the Marlin owner defines and validates
the covered external effect domain.  POO Flow must not claim rollback
closure for effects excluded from that domain.  RFC 149-05 provides the
normative coverage and compensation proof.

* Canonical transaction registry

One canonical request contains:

- transaction ID;
- admission receipt ID;
- complete RFC 149-03 commit subject;
- expected pre-state digest;
- target post-state digest.

The registry contract is:

#+begin_src text
for every two registered entries:
  equal transaction ID implies equal canonical request
#+end_src

=TransactionRegistryValid= proves that the registry snapshot came from
the owning transaction store.  Pairwise uniqueness over caller-supplied
entries is not authoritative evidence.

* Exactly-once duplicate contract

A duplicate is accepted only when all of the following hold:

- the current request equals the registry's canonical request;
- an authentic prior receipt has outcome =committed=;
- the prior receipt binds the same transaction, admission, subject,
  pre-state, and target post-state;
- =CommitReceiptValid= accepts the prior receipt;
- the complete effect observation is unchanged by the duplicate attempt;
- the transaction has exactly one uncompensated application.

A receipt with outcome =duplicate= is a conclusion of this proof.  It is
not the input that establishes the proof.

* Complete rollback contract

For =rejected= and =rolledBack=:

#+begin_src text
postEffectObservation = preEffectObservation
#+end_src

Equality includes runtime state, covered external effects, and the
uncompensated application count.  A local runtime digest cannot stand in
for this higher-order observation.

An irreversible effect that has no verified compensation cannot produce
a =rolledBack= receipt.  It must fail closed into an explicit unresolved
recovery state owned by the runtime.

* Durable write-ahead record

Before an effect begins, Marlin persists a
=DurableTransactionRecord= containing:

- the canonical request;
- phase;
- current fence token;
- complete pre-effect observation.

=DurableRecordValid= proves that the record is durable and owned by the
transaction store.  The permitted phases are:

- =prepared=;
- =applying=;
- =committed=;
- =rolledBack=;
- =rejected=.

Only the final three phases are terminal.

* Fenced recovery contract

A recovery claim contains:

- transaction ID;
- worker identity;
- observed fence token;
- atomically acquired fence token.

Numeric monotonicity is necessary but insufficient.  The owner relation
=RecoveryClaimValid= performs the atomic acquisition.
=recoveryClaimAuthorityExclusive= requires that two valid claims against
the same durable-record snapshot are equal.

The recovery receipt binds the acquired fence, source phase, exact
effect receipt, and one terminal phase.  =RecoveryReceiptValid= proves
that the transaction owner produced it.

* Recovery state machine

#+begin_src mermaid
stateDiagram-v2
  [*] --> Prepared: "state=prepared / canonical request + pre-effect observation durable"
  Prepared --> Applying: "state=applying / exclusive fence acquired before effect"
  Applying --> Committed: "state=committed / exact target + one uncompensated application"
  Applying --> RolledBack: "state=rolled-back / full effect observation restored"
  Prepared --> Rejected: "state=rejected / no effect applied"
  Applying --> RecoveryClaim: "state=recovering / crash or lease loss detected"
  RecoveryClaim --> RecoveryClaim: "fence=stale / old worker rejected"
  RecoveryClaim --> Committed: "fence=valid / prior application proven complete"
  RecoveryClaim --> RolledBack: "fence=valid / compensation proven complete"
  RecoveryClaim --> Rejected: "fence=valid / effect proven not started"
  Committed --> Duplicate: "same canonical request / authentic prior commit witness"
  Duplicate --> Committed: "state unchanged / no second application"
  Committed --> [*]: "terminal receipt valid"
  RolledBack --> [*]: "terminal receipt valid"
  Rejected --> [*]: "terminal receipt valid"
#+end_src

Every edge label states the evidence required for the transition.
=RecoveryClaim= is not terminal.

* Owner boundaries

- Marlin owns the canonical transaction registry, durable records,
  effect journal, atomic fence acquisition, compensation, and terminal
  receipts.
- Cedar, Lean, and Human Audit continue to own the admission evidence
  carried by the canonical request.
- Lean owns the abstract countermodels and proof obligations.
- POO Flow composes the resulting first-class evidence objects and fails
  closed when an owner validity relation is missing.
