#+TITLE: POO Flow Research Program for MRR and Ascent
#+DATE: 2026-09-25
#+STATUS: research proposal

* Question and first decision

Can the native POO fixed point carry the Ascent kernel inside POO
Flow while MRR retains the meaning and admission of facts?  The first work is
an executable mapping of relation declarations, rule refinements, recursive
dependencies, and demanded results onto =.o=, =.mix=, =self=, and =.ref=.
The existing MRR/Ascent evaluator supplies an independent oracle for the same
input snapshot.  POO Flow must not add a second generic fixed-point driver.

This distinction needs an explicit test.  The native POO fixed point ties
together *slot computations* across composed prototypes and evaluates demanded
slots lazily.  Ascent computes the *least relation closure* under rules.  A
directly self-referential slot is not automatically a semi-naive relation
engine: =object.ss= caches a slot only after its computation returns.
The research question is which relation algebra and laziness representation
make these two semantics coincide, and where a separate backend operation is
still needed.  The experiment must establish this with executable evidence,
not terminology alone.

* Ownership and executable path

| Step | Owner | Output or invariant |
|------+-------+---------------------|
| source snapshot and typed rule bundle | source owner and MRR | exact source identities, generation, validated RulePackId |
| strategy declaration | POO Flow | POO-native policy object and functional composition; budget, capability, cancellation, evidence requirement |
| request projection | POO Flow | inert, typed external evaluation request bound to the MRR bundle and organization epoch |
| fixed-point evaluation | POO-native kernel experiment, checked against MRR/Ascent | bounded candidate receipt; no live publication or identity allocation |
| semantic admission | MRR lineage and transition owners | complete, generation-bound, identity-bound admitted result or typed rejection |
| decision and handoff | POO Flow | policy decision over admitted evidence, followed by authorized runtime handoff |
| external effect and feedback | admitted runtime and source owner | effect receipt; observations return as proposals |

The POO Flow declaration must be an ordinary Gerbil POO object/prototype with
named functional combinators.  It must not add an alist rule DSL or duplicate
the MRR ReasoningBundle grammar.  The native experiment may evaluate candidate
relations, but MRR remains the independent semantic oracle and admission
owner.  POO Flow must not infer admission from a POO result or an Ascent
completion flag.  A result from a
cancelled, partial, expired, or mismatched generation cannot authorize a
handoff.  An admitted semantic result also cannot grant effect authority by
itself: the POO Flow decision and runtime effect remain separate claims.

* First vertical slice: native POO kernel mapping

1. Resolve the exact POO library dependency and prove with executable tests
   that later POO refinements can supply relation inputs to earlier rule slots,
   and that demand and memoization have the expected behavior.
2. Represent a small positive recursive program as native prototypes and
   functional relation operations.  Compare transitive closure, duplicate
   facts, multiple derivations, and a cycle with MRR/Ascent.  Record whether
   native slot demand alone reaches the least relation closure; if it does not,
   identify the minimum missing operation at the relation/backend seam.
3. Bind an exact MRR RulePackId and source generation to each candidate result.
   Keep rule/fact semantics, lineage, and admission in MRR.  Test completion,
   truncation, cancellation, stale generation, and source withdrawal before a
   candidate can enter a POO Flow decision.
4. Compose the existing policy and runtime handoff path over admitted results.
   Only separate POO Flow authorization may reach an external effect.

The first two steps measure whether the native POO fixed point is sufficient
for the selected relation fragment.  Later steps establish control and evidence
behavior.  A transitive-closure match alone does not prove general Datalog,
deletion maintenance, BYODS parity, or an Ascent replacement.

* Why search and reasoning matter to an Agent

An Agent must repeatedly choose what to inspect, what to believe, what to do
next, and when to stop or escalate.  These are different questions.  Search
finds source-bound candidates under an exact snapshot and selector; MRR can
derive consequences and preserve support; a model can make a bounded judgment
under uncertainty; POO Flow controls context projection, policy, capability,
and handoff.  The value is measured by better task outcomes with less
unsupported action, latency, and model cost, not by fixed-point throughput
alone.

The control path to study is:

#+begin_example
source-bound retrieval -> MRR admitted facts and derivations
  -> POO Flow bounded context -> model judgment proposal
  -> POO Flow authorization -> runtime effect -> new source observation
#+end_example

Concrete retrieval belongs to its source/search producer.  POO Flow does not
add a second text index, parser, or graph language.  A retrieved passage is
evidence only when its source identity, revision, selector, and coverage are
known.  MRR inference may show what follows from such facts; neither a search
hit nor a model score is semantic admission.

** Jev as a decision-model case

TypeSafe AI's [[https://docs.typesafe.ai/introduction][Jev documentation]]
describes one supplied state and independent typed questions returning Choice,
Score, or Noul values.  Its [[https://docs.typesafe.ai/confidence][confidence
guide]] delegates thresholds and action handling to application code.  Jev is
therefore a useful example of a fast *judgment provider*, not an authority for
source truth, derivation, or external effects.  Vendor speed and calibration
claims must be measured on our own tasks with independent labels.

For a model-routing or next-action Choice, POO Flow first removes options that
violate capability, budget, or dependency constraints.  It then projects a
compact, provenance-bound state and asks the model to rank the remaining
options.  The returned option, probability distribution, model version,
question criteria, and input-state digest form a judgment proposal.  MRR
admission and POO Flow authorization remain separate gates; a high score
cannot widen capability or repair missing evidence.  An explicit abstain,
request-more-evidence, or human handoff route is required when coverage or
confidence is inadequate.

** Scenarios and measurable value

| Scenario | Search and reasoning contribution | Model judgment and controlled action | Outcome to measure |
|----------+-----------------------------------+--------------------------------------+--------------------|
| coding Agent changes an API | locate exact definitions/callers/tests; infer transitive impact and invalidated assumptions | choose next test or reviewer route from allowed options; authorize edits/tests separately | task success, missed affected files, stale-source actions, tests per successful change |
| incident or security triage | join logs, topology, source versions, and competing causal paths; retain supporting and contradicting evidence | rank investigation or escalation route without turning a risk score into permission to remediate | time to correct diagnosis, false escalation, unsupported remediation, evidence recall |
| research or knowledge Agent | retrieve source passages and revisions; derive claim dependencies and contradiction/coverage gaps | choose what evidence to fetch next or when to abstain | grounded-answer accuracy, unsupported claims, retrieval cost, explanation fidelity |

Each scenario needs a frozen source snapshot, task, allowed actions, independent
outcome labels, failure cases, and a replayable trace.  A claim that an Agent
improved requires a task-level comparison, not only a model accuracy score.
At minimum compare a generative-model-only workflow, search plus model,
search plus Jev-style judgments, and the full MRR/POO Flow evidence path under
the same tools and budgets.  Report end-to-end success, coverage, calibrated
abstention, unauthorized-action rate, latency, token/model cost, and receipt
size.  Vendor model agreement may be a diagnostic; it is not ground truth.

* Research lanes after the first slice

** Source change and revocation

POO Flow controls snapshot selection, capability scope, expiry, cancellation,
and retry.  MRR decides which facts and derivations survive a source generation
change.  The cross-layer property is that no stale receipt can authorize a new
decision.  Incremental evaluation must be compared with full recomputation
after each insertion and retraction.

** Evidence-aware optimization

POO Flow may select an evaluation profile or physical plan under a budget.  MRR
must first define the rule semantics and complete evidence requirements; the
candidate engine may then try Ascent indexes, parallel evaluation, or BYODS.
Two plans are interchangeable only when they produce the same admitted
semantic result and required evidence for the same generation.  A faster plan
with a partial or weaker receipt is not an equivalent plan.

** Agent-facing explanation and action

MRR owns recursive provenance, WHY/WHY-NOT, and Impact meaning.  POO Flow owns
which admitted explanation is projected into a task's context and which actor
may act on it.  A model or tool observation remains a proposal until its source
and MRR admission paths accept it.  The control-plane proof obligation is
temporal: admission, authorization, and effect must occur in that order, with
revocation and generation changes invalidating stale work.

* Reading and research hypotheses

- [[https://s-arash.github.io/ascent/cc22main-p95-seamless-deductive-inference-via-macros.pdf][Ascent]] supplies a macro-compiled, semi-naive fixed-point baseline.
- [[https://kmicinski.com/assets/byods.pdf][BYODS]] supplies a relation-storage and compiled-join seam.
- [[https://arxiv.org/abs/2203.16684][DBSP]] motivates exact incremental maintenance across richer operations.
- [[https://www.cl.cam.ac.uk/~nk480/datafun.pdf][Datafun]] motivates static monotonicity and termination checks.
- [[https://effect.systems/doc/pldi-2023-egglog/paper.pdf][egglog]] demonstrates equality saturation plus Datalog; reuse its results
  before proposing another equality engine.

These works motivate experiments, not POO Flow semantic ownership over MRR or
a claim that a particular backend is already superior.

* Acceptance evidence for the first slice

- POO-native declaration and functional composition are inspectable before IO.
- Exact RulePackId, source generation, organization epoch, capability scope,
  bounds, and receipt schema survive request projection.
- Native POO tests demonstrate late-bound rule inputs and demand behavior on
  the resolved library dependency; recursive closure matches independent MRR/Ascent
  fixtures, or the precise missing relation operation is documented.
- A complete candidate receipt and one MRR-admitted result refer to the same
  source snapshot; replay fixtures cover failures.
- Truncation, stale generation, rejection, revocation, and cancellation cannot
  reach runtime handoff.
- Source/receipt/decision/effect identities remain independently visible in a
  trace; no single receipt is promoted into another owner's authority.

Subsequent algorithm work requires independent semantic and performance
evidence on recursive, multi-support, update-heavy workloads.  The first
slice's success is a control-plane result, not algorithm parity.
