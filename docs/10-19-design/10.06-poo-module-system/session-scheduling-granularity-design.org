* Decision

Refine [[file:session-org-id-subagent-scheduling-design.org][Session IDs and Org-backed scheduling]] so that scheduling, context,
retries and result admission have explicit independent units. This answers the
requested finer granularity. It does not assert facts about any external
MultiAgent V2 implementation. Session remains one independent Module;
AI Agentic-context owns content admission and composes Session.

The previous proposal allocated a new child Session for every Attempt. Replace
that rule: an Attempt belongs to a Session; it does not create one implicitly.
Create a child Session when an admitted delegation needs a distinct interaction
identity, scope or independently resumable lineage. Compatible Tasks may reuse
a Session, each with exact input and result bindings. Retry creates a fresh
Attempt and claim generation; Session reuse remains an explicit admission choice.

* Units and ownership

| Unit | Responsibility | Stable binding |
|------+----------------+----------------|
| Session | Interaction identity, actor/placement lineage, mailbox and recovery | Session ID and owner revision |
| Task | Logical work item with independent acceptance conditions | Task ID, specification revision and Org anchor references |
| Attempt | One execution of the Task under exact inputs | Attempt ID, Task revision, Session ID and claim generation |
| Turn | One provider interaction within an Attempt | Turn ID/revision, provider request and projection digest |
| Context slice | Minimal admitted content closure for an operation | Projection digest, source vector, restriction/profile and Demand |
| Artifact | Independently admitted output for a declared result port | Artifact identity/digest, port revision and producer receipt |

Task is the canonical work-item identity; do not add a second WorkItem ID.
A Task may span several Turns. One Session may execute several compatible Tasks
sequentially. The initial protocol permits one active provider Turn per Session;
parallel independent Turns require separately enrolled Sessions. A worker/process
may serve many Sessions while respecting aggregate resource budgets.

Content identity and work identity remain separate. One Org =:ID:= can anchor
several Tasks, such as evidence extraction, contract review and implementation.
One Task may depend on several admitted anchors. A heading does not impose the
Task size or an execution boundary. Changing a Task specification creates a new
revision; running Attempts retain their original specification and must be
cancelled, isolated or re-admitted explicitly.

* Task specification and acceptance

A native =SessionTask= proposal declares:

- objective, anchor references and specification revision;
- input ports and required admitted artifact/source revisions;
- output ports, contract and independent acceptance conditions;
- read/write/effect ownership and placement restrictions;
- time, token, resource and spawn budgets;
- dependency/join, retry, cancellation and failure policies.

Input ports name declared semantic roles, not arbitrary trusted payload slots.
An output port is a declared acceptance boundary such as =source-evidence=,
=contract-review= or =change-proposal=. Context composes the applicable Query,
Evidence and restriction contracts. Session schedules their admitted references.
No raw alist task DSL or second evaluator is introduced.

Split work only when the parts have independently checkable contracts and useful
parallelism or recovery boundaries. Batch work when input closure, placement and
acceptance contracts are compatible and batching saves measured overhead.
Each batched Task retains its Attempt, budget and receipt; partial failure does
not silently succeed the batch. Do not split every file, sentence or token into a
Task. The partition decision includes Context cost, dependency critical path,
provider latency, expected retry cost and ownership conflicts.

An agent may propose decomposition/refinement. Publication requires expected
schedule revision, admitted acyclic edges and budget reservation. A refinement
records supersession and routing for unstarted work; it cannot rewrite running
Attempt identities or remove cancellation obligations. Numeric split thresholds
are configuration proposals to qualify against workloads, not fixed RFC guesses.

* Context granularity and editable working content

Context constructs a Task/Turn projection from declared anchor Elements,
required predecessor artifacts, relevant policy and explicit uncertainty.
Each input carries exact source/parser/query/restriction/profile bindings.
Transcript history is an optional selected input with bounded relevance and
provenance, never the implicit entirety of the parent Session.

A projected view may share immutable admitted subvalues within the permitted
scope. A small delta is transport optimization: it names the expected base digest,
new digest, changed/replaced/deleted Elements and qualified dependency coverage.
The receiving boundary reconstructs and admits the new projection before use.
Unknown base, missing dependencies or incomplete coverage require a full fresh
projection or typed refusal. Sending a delta cannot bypass current disclosure
checks or authorize previously disclosed content in a new scope.

Working Context edits create source/projection proposals with expected revisions.
Context admits the result before the next provider Turn. Retained evidence,
contradictions and mandatory policy inputs stay addressable through lineage even
when excluded from the working view. Agents cannot edit scheduler receipts or
grants through a working Org document. A source edit invalidates exactly those
dependents covered by admitted dependency information; otherwise invalidate the
whole affected Scope. Byte spans alone do not establish dependency coverage.

* Incremental results and dependency ports

A provider stream or progress message is an observation. It is not a dependency
completion. Independently usable output requires an admitted Artifact receipt
for a declared port and revision. A dependent Task may start when its exact
required ports are admitted, even if other producer work remains unfinished.
The whole producer Task succeeds only when its own acceptance conditions close.

Artifact publication binds Task/Attempt/Turn, input projection, output port,
artifact digest, current guards and expected owner revision. The scheduler
updates subscribers of that port, not every Session. A replaced/corrected artifact
creates a new revision and invalidates dependent inputs; already dispatched
consumers enter cancellation/isolation or fresh admission. An existing result
receipt cannot silently retarget a running consumer to the new artifact.

Final publication and external effects remain separate commit protocols.
A proposed patch may be independently reviewed before execution; review does not
by itself authorize application. Contradictory branch outputs remain explicit
and cannot be resolved by arrival order or absence of other claims.

* Session reuse, routing and safe interruption

Reuse requires compatible organization/epoch, actor identity, project/worktree,
placement, visibility and interaction policy. Task-specific Scope fields are
bound anew per Turn projection; Session reuse cannot widen them. Reject reuse
when residual provider-visible history would disclose information excluded from
the next Task's scope. Use a fresh isolated Session/transport when that exposure
cannot be qualified. An idle worker is not proof of an empty provider context.

Commands and results route by Session ID, Task ID, Attempt ID, Turn revision
and command/request identity. A message addressed only to Session ID cannot be
silently assigned to whichever Task currently occupies that Session. Late
completion from an earlier Attempt stays bound to that Attempt and cannot
complete its replacement. Follow-ups allocate an explicit new Turn or enqueue
against the declared Task revision.

Cooperative interruption occurs between Turns or at qualified tool/worker safe
points. A running model/tool is not assumed preemptible. Cancellation request,
acknowledged termination, isolation and unknown external effect state remain
separate receipts. Snapshot pending obligations before migration/resume.
Parent control waits release execution slots; child execution and control
coordination use explicit capacity policies so a parent cannot starve its children.

* Scheduling mechanics and metrics

Keep the pure Session task/port/claim semantics independent of runtime queues.
Runtime indexes project admitted state into Task/Session/port subscriber maps,
ready lanes and timers. Local completion work scales with subscribers of the
changed port; its cost is reported, including broad dependency fan-out.

Fairness and limits apply per organization/root and Task class, with Session
capacity as a placement constraint. Scheduling only by Session would hide a
root's many queued Tasks. Coalesce redundant ready/invalidation events by exact
revision; never coalesce away cancellation or external-effect obligations.
Provider request batching preserves per-Task admission and publication identity.

Compare the same Task graph executed with a fresh Session per Attempt against
qualified Session reuse, full projections against admitted deltas, and whole-task
completion against independent artifact-port release. Hold model, resources,
source, contracts and acceptance gates constant. Measure task quality as well as
scheduler CPU/allocations, Session cold-start overhead, transferred Context bytes,
provider tokens/spend, queue latency, critical-path completion and retry scope.
Keep semantic controls for stale inputs, duplicate results and cross-scope reuse.
No performance claim is established by a smaller message or more agents alone.

* Source roles and next implementation gate

| Role | Refinement |
|------+------------|
| Session =types.ss= | Task/Attempt/Turn/port shape, routing and capacity invariants |
| Session =objects.ss= | Native task specification, artifact reference and schedule prototypes |
| Session =funs.ss= / =funs-*.ss= | Partition admission, port readiness, routing, claim and retry algorithms |
| Session =config.ss= | Reuse/partition/fairness Profiles and limits |
| Session =interface.ss= | Closed public role exports |
| Context =types/objects/funs= | Demand/slice/delta admission and Org/source dependency closure |
| Explicit runtime/provider | Queue projections, safe points and qualified dispatch |

Begin with textual Session IDs and admitted Org bindings from the prior plan.
Then implement pure Task/Attempt/port readiness and typed routing before building
runtime reuse or delta transport. Add finite Quint controls for wrong-attempt
routing, retry double-counting, early port release, incomplete delta, cross-scope
reuse and dropped interruption obligations; replay through native boundaries.

This is a proposed protocol refinement. Existing headline replay, Module closure
and source-role regression receipts do not qualify these scheduling capabilities.
