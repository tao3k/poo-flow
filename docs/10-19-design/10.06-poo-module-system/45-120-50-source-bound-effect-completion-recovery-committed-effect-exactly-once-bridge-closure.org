#+title: RFC 45-120-50 — Source-Bound Effect Completion Recovery Committed-Effect Exactly-Once Bridge Closure
#+startup: overview
#+options: toc:3 num:t

* Status

Accepted.

The independent Lean model, exactly-once owner extension, single-transaction
bridge core, and exact recovery-trace integration are implemented.

This RFC defines one normative contract for a =committed= transaction result.

* Ownership

- RFC47 owns the authorized recovery transaction, exclusive claim, active
  fence, and terminal recovery receipt.
- RFC49 owns the complete effect-domain witness and its binding to the
  materialization plan and recovery observations.
- =SourceBoundCompositionalEffectClosure= owns source-resolved composition
  objects, exact declaration ownership, execution-trace transaction identity,
  fence identity, registry identity, and the rule that every runtime event is
  declared.
- =CommittedEffectApplicationExactlyOnce= owns the additional completeness and
  multiplicity condition required by a committed result.
- This RFC owns only the bindings among those owners.

No new execution receipt is introduced. The existing source-bound execution
trace receipt is the execution evidence.

* Lean-discovered architecture gap

The existing source-bound owner proves:

#+begin_src typst
#align(center)[
  $
    forall a in T :
      op("effect")(a) in U
  $
]
#+end_src

where =T= is the execution trace and =U= is the declared effect universe. This
is a no-extra-events property:

#+begin_src typst
#align(center)[
  $
    op("image")(op("effect"), T) subset.eq U
  $
]
#+end_src

It does not prove the reverse coverage direction:

#+begin_src typst
#align(center)[
  $
    U subset.eq op("image")(op("effect"), T)
  $
]
#+end_src

It also does not constrain multiplicity. Therefore both of these traces satisfy
the existing declaration rule:

#+begin_src typst
#align(center)[
  $
    U = { "payment", "message" } \
    T_("omit") = ["payment"] \
    T_("duplicate") = ["payment", "payment", "message"]
  $
]
#+end_src

The first omits a declared effect. The second applies one effect twice.

Matching transaction ID, fence token, and registry digest do not repair this
gap; those fields bind the envelope of the trace, not the cardinality of its
events.

* Normative exactly-once owner

Let =count_T(e)= be the number of trace events whose effect identity is =e=.
The owner closure is:

#+begin_src typst
#align(center)[
  $
    op("ExactlyOnce")(U, T) =
      op("Unique")(U)
      and op("image")(op("effect"), T) subset.eq U
      and forall e in U : op("count")_T(e) = 1
  $
]
#+end_src

=Unique(U)= is required because the effect universe itself must not encode one
effect identity more than once.

The existing =SourceBoundEffectClosure= supplies the subset condition, source
resolution, declaration ownership, and receipt envelope. The new owner adds
only universe uniqueness and the =count_T(e)= obligation.

* Committed bridge

For a promotion request =R=, RFC49 effect witness =W=, source-bound evidence
=S=, and recovery receipt =Q=, the bridge is:

#+begin_src typst
#align(center)[
  $
    op("CommittedBridge")(R, W, S, Q) =
      op("EffectDomainBridge")_(49)(R, W, Q)
      and Q_"outcome" = "committed"
      and S_"request.transaction" = R_"transaction"
      and S_"request.plan" = R_"plan"
      and S_"fence" = op("RecoveryFence")(Q)
      and S_"universe" = W_"universe"
      and B_("observation")(Q_"post", S_"trace")
      and B_("provenance")(Q, S)
      and op("ExactlyOnce")(S_"universe", S_"trace")
  $
]
#+end_src

The observation-to-trace relation is explicit because an aggregate
=EffectObservation= cannot prove which individual execution events occurred.

The provenance relation binds the owner commitment, recovery receipt,
source-bound witness, and source-bound trace receipt. Equal digest fields do not
stand in for that relation.

* Result separation

=CommitOutcome= has four constructors:

- =committed=
- =duplicate=
- =rejected=
- =rolledBack=

This RFC applies only to =committed=.

- =rolledBack= is owned by RFC49.
- =duplicate= requires evidence that no new effect execution was appended and
  that the response refers to the prior committed execution closure.
- =rejected= requires evidence that no materialization effect was admitted.

Neither =duplicate= nor =rejected= may inhabit the committed bridge.

* Lean realization

- [X] Independent countermodel proves that declaration-respecting traces may
  omit an effect.
- [X] Independent countermodel proves that declaration-respecting traces may
  duplicate an effect.
- [X] Independent countermodel proves that matching transaction, fence, and
  registry fields do not imply exactly-once execution.
- [X] The owner reuses =SourceBoundEffectClosure= and its existing trace
  receipt.
- [X] The owner adds effect-universe uniqueness and per-effect occurrence count
  equal to one.
- [X] The core bridge binds request, plan, recovery fence, effect universe,
  post observation, and provenance.
- [X] The core bridge requires the actual =committed= constructor.
- [X] Source-bound evidence is packed as one first-class evidence value.
- [X] RFC49 trace evidence is packed as one first-class evidence value rather
  than exposing every registry and validator as a trace-closure parameter.
- [X] Every committed index of the RFC49 recovery trace supplies the committed
  bridge.
- [ ] The duplicate outcome is bound to a prior committed closure and proves
  that no new event was appended.
- [ ] The rejected outcome proves that no materialization event was admitted.

* Elaboration constraint discovered by Lean

The first bridge formulation repeated more than thirty dependent parameters in
each forwarding theorem. Its isolated elaboration exceeded ninety seconds.

The corrected formulation packages the twelve source-bound owner inputs and
their proof into =SourceBoundCommittedEffectExactlyOnceEvidence=. The core
bridge consumes that first-class evidence value. The focused build then
completed the owner in 4.4 seconds and the bridge core in 8.8 seconds.

Convenience theorems MUST NOT re-expand the full dependent parameter surface.
The structure projections and the compact owner theorem are the proof API.

An attempted exact trace extension exposed the same problem one level higher:
replaying RFC47 and RFC49's approximately seventy open registry and validator
parameters caused the focused trace-closure build to exceed ninety seconds.
That structure was rejected and is not part of this RFC's implementation.

Therefore RFC49 trace evidence itself MUST become a first-class evidence
package before RFC50 trace integration is accepted. Hiding the width behind an
arbitrary proposition is not sufficient because it would lose the exact RFC47
authorized-recovery type.

The accepted implementation now uses
=SourceBoundEffectCompletionRecoveryEffectDomainRollbackTraceEvidence=. Its
=AuthorizedRecoveryAt= projection is definitionally the complete RFC47 bridge,
and =EffectDomainBridgeAt= is definitionally the complete RFC49 bridge. The
package built in 7.4 seconds and the compact RFC50 trace closure built in 3.8
seconds.

* Trace obligation

For recovery trace =T=, the formal integration is:

#+begin_src typst
#align(center)[
  $
    forall i :
      T_i_"outcome" = "committed"
      arrow.r
      op("CommittedBridge")_i
  $
]
#+end_src

This is pointwise. The number of composed modules and profiles changes the size
of =U_i= and =T_i=, but not the exactly-once predicate.

The Lean structure
=SourceBoundEffectCompletionRecoveryCommittedEffectExactlyOnceBridgeEvidence=
implements this quantification. Its =committedBindings= field requires the
exact committed bridge for every recovery-required index whose actual recovery
receipt outcome is =committed=.
