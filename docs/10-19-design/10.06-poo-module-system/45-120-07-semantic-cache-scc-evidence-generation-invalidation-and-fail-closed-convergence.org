#+title: Semantic Cache, SCC Evidence, Generation Invalidation, and Fail-Closed Convergence
#+startup: overview

* Status

The architecture in this RFC is accepted.

This acceptance freezes evaluation and evidence semantics.  It does not
admit an implementation, storage backend, exported cache API, or public
debug macro.

* Scope

This RFC defines incremental evaluation and observability for recursive
Module authority closure.

It covers:

- the ownership boundary between =gerbil-poo= and POO Flow;
- immutable semantic evaluation-node identities;
- cache soundness and generation invalidation;
- strongly connected component evidence;
- rooted monotone convergence;
- unrooted and non-convergent cycles;
- typed evaluation budgets;
- bounded recovery choices.

* Central decision

The fixed-point and prototype composition algebra remains owned by the
pinned =gerbil-poo= dependency.  POO Flow does not implement a second
fixed-point algebra.

POO Flow owns the evaluator around that algebra:

- dependency discovery;
- incremental scheduling;
- semantic memoization;
- cycle and strongly connected component recognition;
- budget enforcement;
- immutable observations and actionable failure receipts;
- bounded recovery coordination.

Removing the cache may reduce performance, but it MUST NOT change the
semantic authority result.

* Semantic evaluation-node identity

Every closure evaluation node has an immutable semantic identity
derived from the evidence that can affect its result.  Depending on the
operation, that evidence includes:

- Module identity and generation;
- evaluation operation or projection identity;
- target Module and responsibility scope;
- capability and delegation evidence identities;
- active profile-policy identity;
- applicable Contract identity;
- dependency generation identities;
- evaluator semantic schema identity.

Wall-clock time, process identity, thread identity, memory address,
continuation handle, cache location, telemetry sequence, and storage
backend MUST NOT participate in semantic node identity.

Two nodes with different semantic evidence cannot share a result merely
because their printed values or runtime locations appear equal.

* Immutable semantic cache

A semantic cache entry records:

- the evaluation-node identity;
- the exact dependency identities;
- the derived semantic result or fail-closed result;
- the evidence supporting that derivation;
- the evaluator semantic schema identity.

The entry is immutable.  Cache insertion, eviction, persistence, and
physical placement are runtime concerns and do not become semantic
inputs.

A cache hit is admitted only when node identity, dependency evidence,
and evaluator semantics match.  An incomplete, ambiguous, stale, or
schema-mismatched entry is a miss, not an approximate answer.

* Generation invalidation and cross-generation reuse

A new Module, capability, delegation, profile, Contract, or dependency
generation naturally changes the affected semantic identity.  The old
entry remains historical evidence but cannot answer the new key.

POO Flow does not require a global mutable invalidation sweep for
semantic correctness.

Cross-generation reuse is permitted only when a derivation proves that
all result-affecting dependency identities are unchanged.  The reuse
produces an explicit reuse receipt linking the new evaluation request
to the earlier evidence.

Absence of that proof requires reevaluation.  Runtime heuristics,
timestamps, path similarity, object address reuse, and telemetry cannot
substitute for the proof.

* Dependency graph and SCC evidence

The evaluator records semantic dependency edges while expanding the
closure frontier.  A repeated active-frontier identity is graph
evidence, not an invitation to continue recursive host-language calls
until stack overflow.

The evaluator identifies a strongly connected component from stable
member and edge identities.  Its observation evidence includes:

- the component identity;
- its member evaluation nodes;
- internal and incoming dependency edges;
- reachable root capability evidence;
- the refinement sequence or convergence witness;
- consumed typed evaluation budget;
- the reason for convergence, empty authority, or denial.

Cycle detection MUST occur through evaluator graph evidence before
unbounded Scheme recursion or an operating-system resource failure
becomes the primary diagnostic.

* Convergence semantics

A rooted SCC may converge when every refinement is monotone in the
non-widening authority order and reaches an evidence-equal fixed point.

An SCC with no reachable explicit root capability yields empty
authority.  The cycle itself grants nothing.

The evaluator fails closed when:

- a refinement widens authority;
- refinements oscillate or do not stabilize within the typed budget;
- a dependency edge lacks complete evidence;
- an SCC result depends on evaluation order;
- a cache conflict would select different semantic results;
- the convergence witness cannot be reconstructed.

Heuristic widening MUST NOT grant authority to force termination.

* Typed budget separation

Closure evaluation budgets and recovery action budgets are distinct
semantic types.

Closure evaluation budgets may bound:

- newly expanded evaluation nodes;
- discovered dependency edges;
- SCC refinement steps;
- admitted semantic cache-entry production.

Recovery action budgets may bound retries, substitutions, continuation
invocations, aborts, or total recovery actions.

One budget type cannot be compared with, converted to, replenished by,
or spent as the other without an explicit separately admitted semantic
mapping.

Wall-clock duration, CPU time, RSS, allocation count, and I/O volume are
runtime observations.  They may trigger an infrastructure guard and an
actionable receipt, but they do not silently become deterministic
semantic closure budgets.

* Diagnostic and recovery boundary

A convergence or evaluation-budget denial produces an immutable
=ObservationEvent= containing the evaluation frontier, SCC evidence,
typed budget evidence, dependency identities, cache disposition, and
last admitted refinement.

Pure diagnostic projections may inspect that evidence without creating
a new semantic generation.

Actions that change evaluation semantics or resources require an
authorized =RecoveryDecision= and a successor generation.  Examples
include:

- allocating a larger typed closure-evaluation budget;
- substituting or removing a dependency edge;
- replacing incomplete capability or delegation evidence;
- resuming an admitted suspended evaluation;
- producing a terminal abort.

Raw continuations remain ephemeral coordinator-owned handles.  They are
never semantic cache values, SCC members, observation fields, or
persistent recovery receipts.

* Public and advanced extension boundary

The ordinary Module composition interface remains unchanged.

Advanced evaluators, cache policies, SCC projections, and recovery
policies are native POO values composed through the existing ownership
boundaries.  A later RFC may admit a hygienic macro only when necessary
syntax or phase semantics cannot be represented by ordinary functions
and native =gerbil-poo= objects.

No user-facing fixed-point DSL, cache clause language, cycle handler
macro, or raw continuation hook is introduced.

* Implementation admission checklist

- [ ] Reuse pinned =gerbil-poo= fixed-point, prototype, and object
  composition semantics.
- [ ] Do not implement a parallel fixed-point algebra.
- [ ] Derive evaluation-node identity only from result-affecting
  semantic evidence.
- [ ] Exclude runtime clocks, process data, addresses, handles,
  telemetry, and storage location from semantic cache keys.
- [ ] Keep cache entries immutable and removable without changing
  semantic results.
- [ ] Require exact dependency and evaluator identity for a cache hit.
- [ ] Require a derivation receipt for cross-generation reuse.
- [ ] Detect cycles through graph and active-frontier evidence before
  unbounded host recursion.
- [ ] Give every SCC a reconstructible member, edge, root, refinement,
  and budget explanation.
- [ ] Admit rooted convergence only through monotone non-widening
  refinements.
- [ ] Derive empty authority for an unrooted SCC.
- [ ] Fail closed on widening, oscillation, order dependence,
  incomplete evidence, conflict, or budget exhaustion.
- [ ] Keep closure-evaluation and recovery-action budgets as distinct
  semantic types.
- [ ] Keep runtime resource observations outside deterministic semantic
  budgets.
- [ ] Keep continuations ephemeral and outside cache and SCC evidence.
- [ ] Preserve the ordinary Module composition interface.
- [ ] Apply the structured diagnostic and exception-bridge boundary in
  [[file:45-120-08-structured-diagnostic-evidence-and-exception-bridge.org][45-120-08]].
