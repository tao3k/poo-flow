* 1. Decision scope

This RFC is the proof-substrate continuation of RFC 45-120-43 and RFC
45-120-44.  Those RFCs continue to own Cedar authorization lifecycle and
authorization-subject semantics.  This RFC owns only the missing source-level
assurance boundary: reconstructing and verifying their external Cedar/Lean
dependency closure without losing Lean module context.

It does not weaken either Cedar theorem, copy Cedar declarations into POO Flow,
or treat an installed =.olean= as source authority.

* 3. Normative source authority

For this assurance lane, a declaration range is an index into a source unit;
it is not independently compilable source.

#+begin_export typst
$
  C_root = transitive-closure(imports, owner-module(root))
$

$
  admitted(root) iff
    forall m in C_root, unique-source(m)
    and source-digest(m) = receipt-digest(m)
    and clean-build(C_root)
    and typed-interface(Cedar, C_root)
    and axle-verify(root, typed-interface(Cedar, C_root))
$

$
  warm-latency(export) < 5s
  and phase-latency(axle) <= 10s
$
#+end_export

The authoritative unit is a module source file plus its import edge identity,
toolchain identity, Lake dependency identity, and content digest.  Declaration
ranges remain useful for selecting the final proof frontier after the module
graph has elaborated successfully.

* 4. Required pipeline

#+begin_src mermaid
flowchart TD
  R[Root Cedar lifecycle declaration] --> E[Lean declaration export]
  E --> N[Native exporter executable]
  N --> K[Content-addressed closure cache]
  K --> M[Owner module and import graph closure]
  M --> S[Unique source-unit resolution]
  S --> D[Source, toolchain, and Lake digests]
  D --> C[Local clean Cedar elaboration]
  C --> P[Typed Cedar proof-base interface]
  P --> X[AXLE environment preflight]
  X --> V[Root theorem2sorry and proof verify]
  V --> Q[Source-bound Cedar assurance receipt]
  S -->|missing or ambiguous| F[Fail closed]
  C -->|module-context error| F
  X -->|capability missing or over 10 seconds| F
  V -->|proof rejected| F
#+end_src

The installed AXLE SDK exposes =merge(documents: list[str], ...)=, but the
measurements above make it unsuitable for request-time dependency closure.
Multi-document merge is not the runtime path for this RFC.

The operation order is normative:

1. Export the root declaration closure.
2. Close the actual Lean import graph, including modules needed for syntax,
   notation, attributes, instances, and elaborator extensions.
3. Resolve every module to exactly one source owner from project, Lake package,
   or active toolchain source roots.
4. Build Cedar locally from those bound source units.
5. Project the already elaborated Cedar boundary as a typed proof-base
   interface.
6. Preflight the selected AXLE environment and reject missing capabilities in
   seconds; never rebuild dependencies through =merge=.
7. Verify the named root theorem and emit one receipt binding all prior
   identities.

* 5. Runtime and ABI boundary

User-facing backend configuration names capabilities and runtime languages; it
does not name adapter files such as =script.py=.

| Layer | Public identity | Hidden implementation detail |
|-------+-----------------+------------------------------|
| Cedar decision engine | backend =cedar=, language =rust= | crate path, executable path |
| Lean assurance engine | backend =axle=, language =lean= | client process and transport |
| Optional orchestration bridge | language =python= | module filename and script path |
| POO Flow user surface | POO object plus functional combinators | proof packaging layout |

Python may implement an internal ABI adapter, but Python source paths are not
part of the declarative composition contract.  The same rule applies to Rust
and Lean artifacts.

* 6. POO-native composition surface

The user composes an authorization capability, not the proof toolchain.  The
following is the intended interface shape; the names remain subject to the
public API RFC:

#+begin_src scheme
(def cedar-guard
  (make-authorization-guard
   policy: enterprise-policy
   subject: current-authorization-subject
   runtime: cedar-rust-runtime
   assurance: cedar-source-bound-assurance))

(def secured-effect-flow
  (flow-compose
   authenticate-subject
   cedar-guard
   execute-declared-effect
   record-effect-completion))
#+end_src

This surface remains POO-native and functional.  It does not expose a raw
alist DSL, a Python callback, or a proof-script filename.

* 7. Reflection contract

Reflection must answer semantic questions without leaking packaging details:

- which =AuthorizationSubject= snapshot was admitted;
- which Cedar policy epoch and fence were evaluated;
- which Rust engine receipts agreed;
- which Lean root declaration was verified;
- which module-source graph and toolchain/Lake identities were bound;
- why admission failed, using a typed phase and reason.

The reflection result may expose source digests and logical module names.  A
local absolute path is diagnostic evidence only and is not stable ABI.

* 8. Simulated value

| Scenario | Old declaration-flattening result | Source-unit closure result | Value |
|----------+-----------------------------------+----------------------------+-------|
| Cedar changes a notation import | late projection errors | changed import/source digest | localizes drift |
| Lean toolchain source was absent | owner resolution failure | exact toolchain source owner | removes false missing-source blocker |
| Installed =.olean= differs from source | potentially hidden by environment | clean source build rejects mismatch | prevents stale-artifact admission |
| User selects Rust Cedar backend | proof packaging leaks into config | backend/language identity only | simpler stable composition |
| Operator inspects denial | generic AXLE failure | phase, module, digest, reason | actionable reflection |

The highest-value outcome is not merely making AXLE green.  It is making a
green Cedar receipt mean that the declared user composition, the Rust decision
runtime, and the Lean proof source graph refer to the same authorization
generation.

- [X] AXLE owner-source extraction advances beyond source resolution.

- [X] Warm declaration export completes in 3.80 seconds.

- [X] The actual import graph is closed at module-source granularity locally
  and projected through a source-bound typed proof-base boundary remotely.
- [X] Typed Cedar proof-base projection passes the ten-second AXLE budget.
- [X] Exact frontier projection contains the named lifecycle root and no
  unbound declarations.
- [X] Root declaration verification and exact canonical roundtrip are accepted;
  theorem-proof extraction is not applicable to the selected definition and
  structure roots.
- [X] RFC 45-120-43 and RFC 45-120-44 record the final source-bound receipts.
- [X] Focused Python tests and the project proof gate pass under the authorized
  testing boundary.

* 11. Non-goals

- Treating a longer timeout as a semantic repair.
- Rebuilding Cedar through request-time AXLE multi-document merge.
- Copying Cedar Lean declarations into POO Flow.
- Trusting compiled dependency artifacts without source identities.
- Publishing Python, Rust, or Lean filenames as user configuration.
- Adding more ad hoc namespace/string rewriting to declaration slices.

Performance generation, native multi-root reuse, and phase reflection are
owned by RFC 45-120-63 rather than extending this source-authority RFC.
