#+title: POO Profile-Only Fixed-Point and Recovery User Interface
#+author: POO Flow
#+language: en

* Status

Accepted.

* Context

POO Flow provides fixed-point progress evidence, recovery policy, continuable
resumption, capability-bounded coordination, receipt-backed idempotency, and
observability projection.  Exposing each responsibility as another public
configuration clause would create a large macro DSL and duplicate the semantic
POO object model.

The accepted public composition surface is already sufficient:

#+begin_src scheme
(use-composition production-system
  (compose profiles
    (use-module wendao-episteme production)
    resilient-production))
#+end_src

* Decision

All fixed-point, recovery, resumption, and observability policy enters ordinary
composition as first-class POO profile values.

The public surface remains:

- =use-composition= as a thin hygienic binding projection;
- =use-module= as a thin hygienic Module/profile-selection projection;
- =compose= as an ordinary pure function;
- =profiles= as a first-class native POO composition strategy.

No additional public macro or configuration clause is introduced for
fixed-point observation, recovery, continuations, budgets, receipts, or
telemetry.

* User composition relationship

#+begin_src mermaid
flowchart LR
  Core["poo-flow-core semantic prototypes"]
  Wendao["wendao-episteme Module binding"]
  Production["wendao-episteme production profile"]
  Resilient["Application-owned resilient-production POO profile"]
  Select["use-module"]
  Compose["compose profiles"]
  Bind["use-composition"]
  Runtime["POO Flow evaluator and coordinator"]
  Doctor["Doctor / CLI projection"]

  Wendao -->|"exports an already Gerbil-visible Module binding"| Select
  Production -->|"selects the package-owned profile value"| Select
  Core -->|"provides generic policy and Contract prototypes"| Resilient
  Select -->|"returns a first-class Module/profile contribution"| Compose
  Resilient -->|"adds application-owned restrictive policy refinements"| Compose
  Compose -->|"returns one pure composed profile value"| Bind
  Bind -->|"binds the value without adding runtime semantics"| Runtime
  Runtime -->|"projects capability-redacted evidence outside composition"| Doctor
  Doctor -.->|"never feeds rows, receipts, or telemetry back into profiles"| Compose
#+end_src

* Profile responsibility

A profile value may refine:

- fixed-point progress policy;
- recovery selection policy;
- resumption policy;
- observability projection policy;
- deterministic structural budget restrictions;
- runtime watchdog policy.

These refinements are native POO values and Contracts.  They are not new Module
responsibility slots.

A profile MAY:

- select among already-authorized recovery strategies;
- restrict available recovery or resumption behavior;
- reduce structural or recovery-action budgets;
- require stronger evidence, redaction, or progress Contracts;
- provide application-specific POO dispatch refinements.

A profile MUST NOT:

- grant or widen a capability;
- increase a budget without delegated authority;
- execute a recovery action;
- own a continuation handle;
- rewrite authoritative evidence;
- turn telemetry or alists into semantic input;
- trigger package installation, build, testing, or distribution behavior.

* Public macro boundary

=use-composition= MUST only bind the ordinary value produced by its expression.

=use-module= MUST only select an already Gerbil-visible Module binding and its
package-owned profile value.  It does not clone a Git source, install a Gerbil
package, import an unavailable binding, run a build, or execute a Module.

Neither macro may contain:

- fixed-point evaluation;
- profile merge policy;
- capability resolution;
- recovery dispatch;
- continuation capture;
- receipt creation;
- package, build, test, or deployment behavior;
- hidden registries.

* Advanced extension boundary

Advanced users extend native =gerbil-poo= objects, prototypes, Contracts, slot
operators, and pure functions.

An advanced policy value enters =compose profiles= directly.  It does not
require a host-language =if= in the composition, an infrastructure clause, or a
new macro.

The public interface may provide small convenience constructors only when they
return ordinary first-class POO values and satisfy the project macro governance
rules.  The POO object interface remains the unique advanced semantic
extension foundation.

* Ownership

** poo-flow-core

=poo-flow-core= owns generic:

- Module and profile composition semantics;
- policy and Contract prototypes;
- evidence and decision prototype relations;
- POO dispatch boundaries;
- coordinator and receipt semantics;
- observability projection contracts.

It does not own =wendao-episteme= package build, testing, distribution, or
release.

** wendao-episteme

=wendao-episteme= owns:

- its Gerbil package and bindings;
- its domain Module values;
- its package-owned profile values;
- its domain Contracts and evidence refinements;
- its build, tests, distribution, and release.

** Final application

The final application owns:

- which Gerbil-visible Module bindings it composes;
- application-specific profile refinements such as =resilient-production=;
- deployment-specific restrictions;
- final capability delegation and budget authority.

* Tooling exclusion

Git source pins, =gerbil.pkg= declarations, Gerbil-Bazel, Nix, and GSLPH are
outside the user composition value:

- Git pins source identity;
- =gerbil.pkg= manages Gerbil packages;
- Gerbil-Bazel builds;
- Nix supplies environment, build, and deployment composition;
- GSLPH is a development-only policy harness and build/test framework.

None of them becomes a POO profile clause.

* Conformance checklist

- [X] The accepted public composition form remains unchanged.
- [X] Fixed-point and recovery policies enter as first-class POO profile values.
- [X] No new public macro or configuration clause is introduced.
- [X] Profiles may restrict but cannot grant authority.
- [X] =use-module= selects an already-visible binding and does not manage
  packages or builds.
- [X] Advanced extensions use native POO objects and prototypes.
- [X] Doctor, CLI, receipts, and telemetry remain outside composition.
- [X] Core, package, and final-application ownership remain separate.
- [X] Git, =gerbil.pkg=, Gerbil-Bazel, Nix, and GSLPH remain outside the user
  composition interface.
- [ ] Concrete =compose=, =profiles=, =use-module=, =use-composition=, and
  ProfileBundle source owners have been resolved through parser-owned owner
  discovery.
- [ ] Implementation has been admitted after owner resolution.

* Rejected public forms

The ordinary interface MUST NOT grow forms such as:

#+begin_src scheme
(use-composition production-system
  (fixed-point-observability ...)
  (recovery ...)
  (continuations ...)
  (budgets ...))
#+end_src

It also rejects host conditional composition:

#+begin_src scheme
(compose profiles
  (if research-enabled?
      (wendao-episteme +research)
      wendao-episteme)
  production)
#+end_src

Conditional or higher-order selection belongs in first-class POO policy and
prototype refinement.

* Non-goals

- Designing another configuration language.
- Adding infrastructure or package-management clauses to composition.
- Making diagnostics or telemetry compositional inputs.
- Moving package ownership into =poo-flow-core=.
- Defining an implementation schedule.
