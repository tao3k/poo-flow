* Status

- RFC state :: Implemented proof-harness semantics; architectural composition theorem remains an explicit proof obligation.
- Schema family :: v1 only.
- Durable document format :: Org, with Typst mathematics and Mermaid state diagrams.

* Problem discovered by Lean and AXLE

The RFC 50 root is a Lean =structure=, not a theorem.  The previous AXLE
pipeline started =theorem2sorry= before it knew the root declaration kind.
That made every root look like a theorem proof obligation and rejected a
perfectly valid structure with:

#+begin_example
Theorem '...SourceBoundEffectCompletionRecoveryCommittedEffectExactlyOnceBridgeEvidence' not found.
#+end_example

The next run exposed a second ownership error.  The independently verified
proof base was projected as typed axioms and transparent type aliases, but its
49 interface declarations were then treated as source-owned declarations of
the one-declaration RFC 50 increment.  A proof-base interface is an assumption
boundary, not a source owner of the increment.

These are architectural defects, not adapter compatibility cases.

* Normative declaration universes

Let =B= be an independently verified proof base and =D= the current declaration
increment.

#+begin_src typst
#let B = $cal(B)$
#let D = $cal(D)$
#let I_B = $I_B = (M_B, Sigma_B, Delta_B, U_B, H_B)$

$ M_B $ is the ordered set of proof-base module identities.
$ Sigma_B $ is the exact set of exported constant names and types.
$ Delta_B $ is the set of transparent, non-lambda type definitions required
for definitional equality.
$ U_B $ is the universe-parameter environment.
$ H_B $ is the canonical digest of the complete proof-base interface.

$ "Own"(D) inter "Interface"(B) = emptyset $

$ "Environment"(D | I_B) = "Interface"(B) union "Own"(D) $

$ "Bundle"(D | I_B) =
  ("Own"(D), "Interface"(B), M_B, H_B, "SourceDigest"(D)) $
#+end_src

The two declaration sets MUST remain disjoint in the v1 bundle:

- =declarations= contains only source-owned declarations of =D=.
- =proof_base_declarations= contains only typed interface declarations of =B=.
- =proof_base_imports= binds the ordered local module identities.
- =proof_base_interface_digest= binds the complete canonical interface.
- dependencies of =D= may terminate at =Interface(B)=.
- no proof-base declaration may acquire a synthetic source owner.

* Root-kind obligation function

Exact extraction and canonical round-trip apply to every root.  Theorem
statement extraction and proof verification apply only to theorem roots.

#+begin_src typst
#let obligation(k) = {
  if k == "theorem" {
    [ExtractExact + RoundTrip + Theorem2Sorry + VerifyProof]
  } else {
    [ExtractExact + RoundTrip]
  }
}

$ "Obligation"(d) =
  cases(
    "declaration-roundtrip + theorem-proof", "kind"(d) = "theorem",
    "declaration-roundtrip", "kind"(d) != "theorem"
  ) $

$ "Accepted"(d) =
  "RoundTrip"(d) and
  ("kind"(d) != "theorem" or "ProofVerified"(d)) $
#+end_src

An empty or unavailable root kind is a fail-closed error.  A non-theorem root
MUST NOT call =theorem2sorry= or =verify_proof=.  Its receipt MUST explicitly
record =theorem_proof: not-applicable=; absence of a theorem proof is not a
successful theorem proof.

* State machine

#+begin_src mermaid

    CanonicalRoundTrip --> Rejected: declaration set or kind unavailable
    CanonicalRoundTrip --> KindDispatch: exact names and root kinds accepted
    KindDispatch --> TheoremObligation: kind = theorem
    KindDispatch --> DeclarationAccepted: kind != theorem
    TheoremObligation --> Rejected: theorem2sorry errors
    TheoremObligation --> ProofVerify: statement generated
    ProofVerify --> Rejected: proof failed
    ProofVerify --> DeclarationAccepted: proof accepted
    DeclarationAccepted --> BundlePartition: roundtrip = accepted

    BundlePartition --> Rejected: unclassified declaration
    BundlePartition --> BundleAccepted: disjoint sets + interface digest bound
    BundleAccepted --> [*]: v1 receipt emitted
#+end_src

* Assume-guarantee composition obligation

The current implementation validates =D= against the typed interface =I_B=.
It does not, by itself, prove that the interface digest came from a successful
independent proof run of =B=.  The composition theorem therefore remains
explicit:

#+begin_src typst
$ "VerifiedBase"(B, H_B)
  and "InterfaceOf"(B) = I_B
  and "ValidatedIncrement"(D | I_B)
  and "Disjoint"("Own"(D), "Interface"(B))
  ==> "VerifiedComposition"(B "compose" D) $
#+end_src

The final proof receipt MUST bind =VerifiedBase(B, H_B)= to the same
=proof_base_interface_digest= carried by the increment bundle.  Until that
receipt binding is implemented and checked, the harness MUST describe the
result as an accepted increment relative to a proof-base interface, not as a
standalone proof of the entire transitive base.

* Declaration-family semantics

Source ranges are provenance coordinates.  They do not define Lean declaration
families.

#+begin_src typst
$ "Family"(d) != { x | "Range"(x) subset.eq "Range"(d) } $

$ "Family"("inductive") =
  {"inductive"} union "Constructors"("inductive") $

$ "Dependency"("inductive") =
  "Constants"("Type"("inductive"))
  union union_(c in "Constructors"("inductive")) "Constants"("Type"(c)) $
#+end_src

Generated constructors project their signature dependencies into the atomic
inductive source declaration.  They are not emitted as independent
source-owned declarations merely because their ranges overlap.

* Performance evidence

The proof runs exposed three materially different closure costs:

| Model | Declarations | Owner sources | AXLE observation |
|-------+--------------+---------------+------------------|
| range-contained source-family fixed point | unresolved | unresolved | Lean export exceeded 165 seconds |
| dependency closure without declaration-family metadata | 9 | 6 | missing structure fields and types |
| monolithic constructor-signature closure | 1145 | about 58 | 217080-byte owner payload; extraction exceeded 60 seconds |
| proof-base interface plus RFC 50 increment | 49 + 1 | 1 source owner | owner extraction accepted; canonical round-trip accepted |

* Implementation closure

- [X] Replace range-containment declaration-family closure with Lean
  environment metadata and constructor signatures.
- [X] Export a typed proof-base interface with exact names, types, universes,
  and required transparent non-lambda type definitions.
- [X] Enforce one bounded Lean export deadline across build and export phases.
- [X] Parse the canonical declaration set before dispatching root-kind
  obligations.
- [X] Skip theorem operations for non-theorem roots and emit an explicit
  =not-applicable= receipt.
- [X] Partition source-owned declarations from proof-base interface
  declarations in the v1 independent bundle.
- [X] Bind =proof_base_imports= and =proof_base_interface_digest= in the
  canonical bundle manifest.
- [X] Reject overlaps and unclassified exact declarations.
- [X] Add a focused non-theorem root regression.
- [ ] Bind an independently verified proof-base receipt to the exact
  =proof_base_interface_digest=.
- [X] Prove the assume-guarantee composition theorem in Lean, with explicit
  digest-binding injectivity.
- [X] Run AXLE independently over both the composition theorem and the digest
  collision counterexample.

* Rejected semantics

- No compatibility fields, migration layer, legacy payload, fallback parser, or
  v2 schema exists.
- No source-range containment heuristic defines declaration ownership.
- No theorem operation is attempted speculatively before root-kind discovery.
- No proof-base interface declaration is assigned to the current increment's
  source owner.
- No accepted increment receipt is promoted to a standalone transitive proof
  without the proof-base receipt binding.
