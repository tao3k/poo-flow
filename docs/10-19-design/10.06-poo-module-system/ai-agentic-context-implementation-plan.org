* Accepted direction and inspected baseline

Implement [[file:agentic-ai-context-system-design.org][the AI Agentic-context Module design]] as a Context Module composed with an independent Session Module and an owned
Memory Feature, rooted in Orgize/Org-mode. This plan records source ownership
and executable gates. Ownership migration is delivered at =22c4b24c=; new
Session and Memory lifecycle contracts remain proposed. Their exact roles and
transitions are specified in [[file:ai-agentic-context-session-memory-contracts.org][the protocol contract]].

Implementation starts from POO Flow =2f7172b59fd088f687a3a8cfea143612c6cccc5f=.
The existing Feature system supplies descriptor construction, dependency
resolution, manifests and qualification. Session remains one independent Module
at =modules/session/=. Context composes its native descriptor through Module
imports. Memory ownership moves directly into the Context Feature tree; the
former standalone Memory selection is removed. Existing semantic laws and ABI
versions retain their declared evidence boundaries during this ownership change.

* Slice 1: core Module and a real Org Context

The first deliverable must combine an admitted Module/Feature manifest with a
source-bound Context projection. A descriptor-only shell is not this slice.

1. Declare =ai-agentic-context= through the existing module descriptor/interface
   contracts. Compose the independent =session= descriptor through native Module imports.
   Use the qualified Feature ID =ai-agentic-context/memory= to avoid global ID collisions. Represent the
   mandatory core in the same qualification bundle; selected optional Features
   require it. Feature activation never removes a core admission/use condition.
2. Add immutable Scope, Org source anchor, Demand, and Projection contracts.
   Freeze/copy mutable inputs at the boundary. Digests bind the exact canonical
   values, query/result/source/profile and restrictions. Replay reconstructs
   projections instead of trusting caller-supplied digests.
3. Use the existing source-headline Query as the first named finite profile.
   It qualifies single-document headline selection, not all Org objects or
   cross-document closure. Reject an unsupported required profile explicitly.
4. Build a real example from English Org bytes, selecting an open task, binding
   its source digest/spans/query, and producing a scoped immutable projection.
   Re-read/replay after an edit before accepting another use.
5. Wire parent Module presentation, declaration and Feature selection into the
   existing user interface. Any user-facing flags lower deterministically to
   native FeatureSelection values; they do not form a second activation truth.

Focused gates: core without active Session history or retained Memory; qualified optional selections;
missing core dependency; unsupported options; same content in another scope;
changed bytes/spans/query rule; forged rows; bounded-incomplete refusal.
Use =t/ai-agentic-context-core-test.ss= and
=t/ai-agentic-context-feature-test.ss= plus existing Query/Feature regression cases.

* Slice 2: native current-use ownership

Move the existing Host implementation and update =src/ffi/context-use.ss=,
=build.ss=, the native compiler module closure, and actual consumer imports in
the same owner-bounded change. Preserve its current fixed-v1 wire contracts and
the existing purpose/generation/expiry/terminal-retirement tests.

Introduce a separately declared full Context envelope for Scope, Org source and
projection bindings only after its fields and native replay are implemented.
Keep the original MRR six-field contract intact. Old observation semantics
cannot be relabeled as full scope/atomic disclosure qualification.
Dedicated trusted enrollment stays separate from model-callable read operations.

Gates: actual C ABI/installed Python use, extra-field rejection, purpose denial,
stale source, contract/epoch mismatch, expiry, retirement, no resurrection,
and exact same-artifact MRR typed consumer replay.

* Slice 3: independent Session Module integration

Session/Turn values refer to exact core Projection revisions. Pure transitions
bind expected Session revision, pending turn, input revision and current fences.
Preserve competing branches and record the actual consumed input of each output.
Handoff creates a new admitted projection for its recipient; cancellation has a
request and a confirmed terminal result. Checkpoint stores immutable references,
never process handles or a cached allowed observation.

Update Session declarations, user-interface syntax/presentation, loop-engine
consumers, qualified scenarios, proof projections, exports and test imports.
Preserve standalone Session registrations and source ownership.
Context imports the native Session descriptor as a dependency. The existing
Module closure resolves that edge; no duplicate resolver or Session Feature is added.

Gates: branch/handoff scope, source edit during turn, cancelled-result refusal,
competing completion CAS, closed Session, checkpoint/restart and epoch mismatch.
Retain existing native Session controls whose semantics still apply and add
combined Context consumption controls rather than copying unchanged tests.

* Slice 4: Memory Feature direct migration

Experience records reference original Org Content and Session receipts where
applicable. Recall produces a fresh core Demand and qualified projection.
Consolidation creates a new derived artifact with original lineage and unresolved
contradictions. Revisit emits a new assessment with evidence, scheduling and
retention axes kept independent. An Org promotion is a source-write intent with
expected revision, not a store insertion or an automatic truth upgrade.

Memory requires core Context. Session-turn capture additionally requires the
independent Session Module and its receipt; pure source recall does not require an active Session instance. Enforce the selected
operation's preconditions at profile/admission time rather than modifying the
generic resolver to create hidden conditional Features. Revisit and durable
retention require their explicitly selected Temporal/Backend capabilities.

Migrate store adapters, intents and recovery behavior that remain valid; retire
old memory-core selection/registration and duplicate policy owners. Data retains
durable storage and transactions; this Feature adds no alternative backend.

Gates: Memory enabled without an active Session instance, capture missing Session refusal,
stale recall, corrected preference suppression, retained contradiction,
review-complete without factual support, retention expiry, explicit promotion
race, and disabling Memory without disabling core checks.

* Slice 5: combined proof and consumption fences

Bind the implemented Scheme contracts to the combined Quint profile described
in the design. Catalog typecheck/model-check receipts and matched guard mutations.
Replay counterexamples through native Core/Session/Memory and original consumers.
Refresh Lean correspondence for laws impacted by identity/state projection moves.
Separate abstract verification, native execution and refinement evidence.

Implement the actual check/disclose or check/effect consumption fence under the
owner that executes it. Data publication rechecks inside its held transaction.
Point-in-time observations remain explicitly bounded until these race gates pass.

* Build, migration and qualification discipline

- Use captured workspace environments, package-managed build roots and the
  heap-fenced =just test-file= entrypoints. Focused Scheme tests run serially.
- Require genuine progress within five seconds, bounded total execution,
  MODULE-OK, HARNESS-OK, final OK and no failure markers. No synthetic heartbeat
  or relaxed watchdog makes a stalled test acceptable.
- Re-scan imports, module keys, flags, native closure, test/proof catalogs and
  installed-language exports at each migration slice. Change corresponding
  consumers directly; an unresolved import is a blocker, not a fallback route.
- Keep POO local/native CI, MRR typed integration and Data transaction evidence
  separate. Push immutable producer revisions before advancing consumer pins;
  verify exact-head required CI after delivery.
- Do not commit raw logs or describe a passed finite profile as the full system.

* First reviewable implementation result

A new =ai-agentic-context= Module constructs a qualified Org-based Context without
retained Memory or an active Session history, composes an independent Session
descriptor, exposes inert owned Memory Feature descriptors through the existing
resolver, and refuses old selection reuse after a source/query/scope change.
This is the first code milestone. The complete redesign additionally requires
the independent Session integration and direct Memory migration and combined consumption/recovery gates.

* Local implementation receipt: 2026-10-10

The delivered hierarchy is =ai-agentic-context= importing the independent
=session= Module descriptor, with Memory as its owned optional Feature. The
redundant =session-core= registration and source directory have been removed.
The Context descriptor passes the existing Module closure and activation gates;
Session remains selectable on its own. Public authoring carries the same native
descriptor and qualified Feature manifest. No Session Feature is declared.

Core Scope admission freezes its identity tuple. Org projection and replay use
the canonical source-bound Orgize Query profile. Replay rejects changed bytes,
foreign scope, forged retained Scope, changed restrictions, budgets, Feature
selection and claimed authority. Context Use Host code and its FFI/AOT imports
now belong to the Context core. Memory code and its consumers migrate directly
to =modules/ai-agentic-context/features/memory/= without forwarding facades.

|------------+--------|

| Context core, dependency closure and native activation | 8 cases passed |
| Existing public Module macro surface | 6 cases passed |
| Existing Memory Org selection | 6 cases passed |
| Independent Session with Context Memory durable authoring | 1 case passed |

Each Scheme gate used the serial heap-fenced =just test-file= entrypoint and
required MODULE-OK, HARNESS-OK, final OK, and absence of failure markers. The
isolated old SDK authoring macro cold compilation hit the 180-second package
and 120-second direct compiler limits. Those failures remain failed receipts.
Qualification-only authoring macro/test artifacts subsequently compiled with
the SDK-documented =CORCXXFLAGS_GAMBUILD= C optimization override, within the
same 120-second gate. This establishes semantic regressions, not optimized cold
build latency or performance. No repository compiler setting was relaxed.

This receipt does not close redesigned Session turn/CAS/checkpoint protocols,
new Memory experience/revisit/consolidation semantics, a combined native Scope
consumption envelope, downstream MRR/Data qualification, or remote CI. Those
remaining contracts and gates stay explicit in the slices above.

* Source role correction and next protocol contract

The core originally combined shape admission, Scope prototype and pure functions
in =scope.ss=, with profile values and resolution in =features.ss=. These
responsibilities now separate into =types.ss=, =objects.ss= and specialized
=funs-*.ss= sources. =config.ss= composes the native descriptor, while
=interface.ss= closes these standard roles through imports/exports only.
Existing public function/prototype identities and digest bindings are preserved.

[[file:ai-agentic-context-session-memory-contracts.org][The protocol contract]] specifies Session inputs, transition CAS, cancellation,
recovery obligations, Memory experience/assessment lineage and revisit claims.
It also names existing Session-to-Memory helper imports that must move into
Context adapter ownership. This correction does not claim those proposed
protocols are implemented or covered by existing finite proof models.

* Next design slice: identity, Org binding and scheduling

Follow [[file:session-org-id-subagent-scheduling-design.org][the Session identity and scheduling contract]] in this order:

1. Textual runtime Session ID admission and direct migration of symbol-ID owners.
2. Bounded Org property-ID Query/profile, unique source-backed bindings and replay.
3. Native Session task/attempt/schedule values and pure DAG/claim/budget transitions.
4. Context per-child input/disclosure and parent result-admission adapters.
5. Bounded event-driven runtime queues, joins, cancellation and recovery.
6. Matched Quint/native traces and controlled scheduler performance receipts.

The CLM paper is research input for editable working Context, not qualification
of this scheduler. Existing finite models, eight core tests and package-build
receipts remain baseline evidence with their previously declared scope.

* Scheduling granularity refinement

Follow [[file:session-scheduling-granularity-design.org][Scheduling Granularity and Incremental Context]] for independent Task
acceptance, Attempt/Turn routing, admitted output-port release and Context slices.
Implement pure readiness/routing before runtime reuse or delta transport. A
fresh Session per Attempt is not the default allocation rule; compatible reuse
requires scope/history admission and preserves each Attempt's exact receipts.

* Context Delta formal model gate

[[file:context-delta-lean-quint-model-design.org][Context Delta Lean/Quint Model Design]] defines structural reference admission,
coverage including new/deleted units and nonlocal Query dependencies, exact
consumer/current-use fences, finite interleavings and native trace correspondence.
Full-target differential admission precedes dependency-based incremental work.
Neither source-digest binding nor finite abstract traces alone prove semantic
refinement or qualify production Delta consumption.

* Delta reference implementation and next gates

The [[file:context-delta-lean-quint-model-design.org][Delta model design]] now records the delivered native full-reprojection
reference API, compiled Lean structural/rejection laws, pinned Quint safe and
matched fault cases, source binding and native source-backed controls. CI closes
the new native regression and Lean target through existing build/proof owners.
The next implementation gates remain dependency coverage, incremental equivalence
and concrete Session/Host/Backend consumption/refinement. Do not treat the
reference API's accepted receipt as authority to publish or execute.
