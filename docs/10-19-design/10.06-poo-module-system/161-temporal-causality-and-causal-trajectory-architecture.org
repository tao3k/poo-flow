* Decision and terminology

The module-local research contract is
=modules/temporal-causality/framework.org=.  It defines the broader temporal
type algebra, model/query separation, formal obligations and implementation
status.  =packages/proofs/tla/temporal-causality/model.org= specifies the first finite
TLA+ slice and its exact limits.

=Temporal Causality= is a POO Flow core module, not an SDLC-only algorithm and
not a Healthcare-only ontology.  =Impact Analysis= is one derived operation of
that module; it is not the module name.  Vertical contributors declare domain
events, relations, time observations and risk semantics; the core owns causal
event graphs, causal trajectories, counterfactual trajectories, snapshot-bound
closure, witness paths, incomplete-frontier handling and inert analysis
receipts.

** Core engine and vertical ownership

The public =modules/temporal-causality/= API is a reusable engine for POO Flow
users and ecosystem packages.  It accepts domain-neutral POO objects for
observations, clock domains, relations, constraints, hypothesis families,
interventions, bounds and questions.  Its pure Scheme operations admit,
compose, revise and query those objects; its receipts report assumptions,
witnesses, counterexamples and unknown frontiers.  A caller can introduce a
new domain vocabulary or hypothesis family through POO object/prototype
composition without changing the core implementation or supplying raw
transition code.

Lambda packages own fixed vertical scenarios.  A Healthcare Case may declare
prescriptions, administrations, clinical risk and its particular formal model;
an SDLC Case may declare revisions, builds and verification obligations.
Those declarations instantiate the same core contract.  They do not move
Healthcare or SDLC terms, fixed =.tla= actions, policy-specific thresholds or
provider credentials into the core.  GQL, ASCENT, TLA+, Lean and optional
decision Providers are projections or contributors around the POO semantic
owner; none becomes a mandatory public DSL for a basic temporal query.

The minimum reuse gate is two independently defined vertical fixtures with
different event vocabularies, both composed and classified through the *same*
core API and model projection contract.  The gate must demonstrate that
adding the second fixture requires no edit to =modules/temporal-causality/=,
and that changing a hypothesis or clock observation changes the bound model
identity and invalidates stale receipts.  Until this passes, the Healthcare
model is evidence for one integration, not evidence of a reusable engine.

These names follow established literature rather than introducing a new grand
term.  Temporal graphs are used for event ordering and temporal reasoning;
causal event graphs represent directed cause/effect relations; dynamic causal
graphs and patient trajectories are used for longitudinal healthcare; and
counterfactual trajectories describe bounded alternatives under an
intervention.  The architecture keeps these concepts distinct.

Terminology references:

- Xiong et al., [[https://aclanthology.org/2024.acl-long.563/][Large Language Models Can Learn Temporal Reasoning]], uses a
  temporal graph as the intermediate representation for temporal reasoning;
- Roy et al., [[https://doi.org/10.1609/aaaiss.v3i1.31204][Causal Event Graph-Guided Language-based Spatiotemporal
  Question Answering]], represents events as nodes and cause/effect relations
  as edges;
- Jensen et al., [[https://www.nature.com/articles/s41467-020-18682-4][Disease trajectory browser for exploring temporal,
  population-wide disease progression patterns]], uses patient/disease
  trajectories for longitudinal healthcare analysis.

Their relevance is narrower than the core contracts below: Xiong et al. is a
=medium= reference for graph-mediated question answering, not an LLM inference
requirement; Roy et al. is =medium= vocabulary for candidate event paths, not
causal admission; Jensen et al. is =vertical= context for Healthcare trajectory
views, not a generic Temporal Causality algorithm.  Their present code
correspondence is =modules/temporal-causality/funs.ss= for structural paths and
=packages/lambda-episteme/user-interface/scenarios/healthcare/= for vertical
interpretation.

The literature leaves an implementation choice open: which hypothesis families and
interventions are admissible for one query.  The core must record that choice
and its finite bounds.  TLC can refute or exhaust a declared model family; it
cannot invent a causal mechanism from observations alone.  Likewise, a
counterexample in one generated model does not refute every possible model.

The 2026 trajectory sources R14--R18 are expanded with research questions,
formal contrast semantics, negative controls and reproducibility gates in
[[file:../../../modules/temporal-causality/impact/research.org][the module-local Dynamic Impact research record]].  As of 2026-10-01,
no paper published after 2026 is available for validation; conference pages
and author manuscripts establish the stated source claims, while POO Flow has
not reproduced their reported model-training experiments.

The AI-facing R19--R22 map to the [[file:../../../modules/temporal-causality/evidence/model.org][module-local Evidence relation model]].
They address searches, short answers, extended work and autonomous research
through shared evidence and artifact relations.  R14--R18 address a narrower
numerical trajectory-effect question; their impact estimands must not be
silently substituted for the potential influence of an evidence change on
research artifacts.

** Open-hypothesis Temporal Causality target

The public POO contract is an immutable composition of observations, temporal
and causal constraints, candidate hypotheses, admissible interventions, query
goals and explicit exploration bounds.  It does not require a caller to supply
one closed action list or a =Next= method.  Scheme functions compose these
values and create identity-bound projections; GQL and optional rule derivation
contribute candidates; an admitted TLA+ model and TLC explore behaviors
permitted by the selected hypotheses.  Lean may later prove the projection
laws.  No
projection silently promotes candidate evidence to an observed or admitted
causal fact.

For a query proposition =q= and the admitted finite family of worlds =W=,
the result may claim =possible= only when a witness world satisfies =q=, and
=necessary= only when every explored world satisfies =q= *and* exhaustion of
the declared family is evidenced.  =refuted= needs the corresponding exhaustive
absence; otherwise return =unknown= with the open frontier, bounds, assumptions
and counterexamples.  An empty family is invalid input, not vacuous necessity.
These are model-relative classifications, not empirical causal conclusions.

** Dynamic POO model construction and formal correspondence

The Cedar analogy is useful at the projection boundary: a POO value can own
semantic identity while language source is composed and validated for an exact
instance.  The current Cedar path accepts =PooFlowCedarPolicy= objects with
=.cedar= source and projects them to a native engine; its Lean definitional
semantics and differential tests are separate evidence.  Dynamic Cedar source
does not mean that every newly supplied policy already has an instance-specific
Lean theorem.  Temporal Causality needs the same distinction.

The target is a first-class =TemporalModel= POO composition, built at runtime
from observation domains, candidate mechanisms, constraints, interventions and
query obligations.  One model input is native TLA+ source: Gerbil parses it,
and a *typed semantic projection* maps only supported model constructs to POO
objects.  POO objects can then be composed or extended through functional
Scheme helpers.  The parser-owned CST remains the syntax authority; the POO
projection represents admitted temporal meaning, not a copy of TLA+ syntax.
Admission assigns a semantic revision and digest and returns explicit
diagnostics for unsupported constructs, unbound variables, inconsistent
constraints, incomparable clocks and absent bounds.  A model version may add
hypotheses without editing the public API or the existing Healthcare =.tla=
files.  The public contract contains possible behaviors and their constraints,
not a caller-authored =Next= action list.

The checked-in Scheme-native parser is
=gerbil-parser/languages/tla-plus=; its core and layout identities come from
the corresponding grammar metadata.  The layout grammar admits column-sensitive
junction lists but does not claim the entire SANY grammar, PlusCal or TLAPS
proof syntax.  The semantic mapper must declare an even
narrower supported subset and reject unsupported CST kinds with a typed
diagnostic; byte-exact roundtrip does not establish TLA+ semantic coverage.
Full grammar expansion requires a separately admitted grammar identity.

This is initially a TLA+ source-to-POO path, not a promise of automatic
POO-to-TLA+ generation.  Later emission back to =.tla/.cfg= is useful for
composed models, but requires a defined semantic preservation law.  A single
optional model-source slot on the POO composition could retain the qualified
TLA+ document identity; individual Event or Hypothesis objects need not each
carry duplicate source bytes.  Slot shape and projection ownership should be
settled by an executable source-to-POO fixture before freezing the public API.

| Stage | Owner and current state | Required evidence for dynamic models |
|-------+-------------------------+--------------------------------------|
| POO composition | =modules/temporal-causality/{types,objects,funs}.ss= currently owns events, cuts and classification | admit immutable model instances, hypothesis families, time domains and obligations with stable identity; preserve rejected and unknown frontiers |
| TLA+ source admission | =modules/tla-plus/interface.ss= parses source and exposes the parser-owned CST; =checked-source-{types,objects,funs}.ss= binds the root source, configuration, local =.tla= inventory and parser-owned TLC run to an inert POO receipt | bind external TLA libraries and the complete toolchain, then map the admitted behavior subset to POO transitions and prove or differentially check its interpretation; finite TLC checking does not establish that refinement |
| Optional TLA+ emission | no dynamic source emitter exists | emit a composed POO model as native =.tla/.cfg= only after defining source-to-POO-to-source semantic preservation and parser/TLC checks |
| Optional Lean correspondence | =packages/proofs/lean/PooFlowProof/PooC4/TemporalCausality.lean= currently proves event/cut laws | later prove a generic interpretation/projection or trace refinement law; Lean is not required to build, query or model-check a TemporalModel instance |
| Provider binding | =packages/lambda-episteme/user-interface/scenarios/healthcare/formal-assurance-projection.ss= binds vertical receipts | retain POO model identity, admitted TLA+ source identity and TLC scope/result as distinct fields in a generic projection; optional Lean evidence has its own field; Healthcare remains a vertical consumer |
| Optional decision Provider | no Jev adapter is present | use typed scores only to rank or propose hypotheses and discriminating questions; retain the full question/option contract and never convert confidence into model-checking exhaustion or a causal fact |

Each dynamically admitted instance needs exact source/semantic identity binding
and finite TLC exploration when model-checking is claimed.  Unsupported
constructs fail semantic projection; syntax acceptance alone cannot admit
them.  Progress claims additionally bind fairness and environment assumptions.
If a later Lean layer is added, a reusable theorem should relate the POO model
interpretation to the TLA+ projection for all admitted constructs, then bind
each instance.  This is an optional proof-strengthening path, not a prerequisite
for the engine.  The present parser, TLC receipts and Lean theorems do not yet
establish that relation.

First executable slice, in dependency order:

1. Define POO-native observation-domain, constraint, hypothesis and query
   objects in =modules/temporal-causality/{types,objects}.ss=.  Preserve the
   existing event/cut APIs while establishing explicit clock comparability and
   hypothesis modality; avoid an alist or macro DSL as the public interface.
2. Add pure admission and bounded classification functions in
   =modules/temporal-causality/funs.ss= and focused cases in
   =t/temporal-causality-core-test.ss=: two admissible explanations, one
   discriminating observation, incomparable clocks, incomplete frontier and
   empty-family rejection.  Include Healthcare-neutral and SDLC-neutral
   fixtures through one public API; neither may import the other's Lambda
   package.  Exhaustion and bounds must appear in the receipt.
3. Admit one native TLA+ fixture through =modules/tla-plus/=, map its supported
   definitions, model variables and properties to the same POO model contract,
   and run TLC on that exact source/configuration.  The existing Healthcare
   models stay vertical examples; parser success is not semantic projection or
   TLC execution.  Start with a domain-neutral fixture before a vertical Case.
4. Add optional POO-to-TLA+ emission and Lean correspondence only after the
   source-to-POO semantics is executable.  Keep model exhaustion, Lean proof
   and runtime behavior as separate evidence.

The first core slice is now executable in =modules/temporal-causality/=: a
finite hypothesis family has POO clock domains, observations,
explicit order constraints, candidate causes, a bounded query and an
identity-bound receipt.  The family explicitly chooses exclusive explanations
or overlapping mechanisms.  It distinguishes admissible, refuted, unknown and
unexplored candidates; only an exhausted, caller-declared complete exclusive
family can yield =necessary= relative to that family.  =t/temporal-model-test.ss=
exercises distinct medication and software-release vocabularies, changed
evidence, overlapping mechanisms, incomparable clocks, incomplete families
and finite bounds.  This
slice does not infer causal mechanisms, compare different clock domains,
interpret a TLA+ action formula or claim TLC exhaustion.  Stage 3 now has a
first source-to-POO subset: =packages/proofs/tla/temporal-causality/TemporalHypothesisFamily.tla=
declares five finite literal operators; =modules/tla-plus/funs.ss= maps their
sets and tuples to the same POO model, while a projection binds source,
grammar and semantic digests.  Extra declarations and nonliteral expressions
fail closed.  The subset is not a general TLA+ evaluator.  The literal source
is now the data instance for the module-local, compositional TLC model in
=packages/proofs/tla/temporal-causality/=.  Its bounded exploration is separately
qualified by =just check-temporal-family-tlc=; a typed TLC-to-POO receipt and
general refinement proof remain future work.  The local =model.org= records
the formal contract, proof obligations, scope and checked configurations.
The focused interface test compares the projected model digest with an
independently constructed POO model for this fixture; it is a bounded
correspondence check for the literal subset, not a general refinement proof.

A second module-local slice now covers immutable bitemporal evidence
revisions.  =modules/temporal-causality/revisions/= separates a fact's valid
interval from its admission instant, preserves assertions, corrections and
retractions, and projects an explicit as-of cut.  Branching corrections yield
a conflict rather than a chosen latest value.  The cut digest remains stable
when later revisions are appended; =t/temporal-revisions-test.ss= checks this
replay law.  A distinct projection digest now binds the full valid-time query
and its selected result, preventing a shared admission cut from being reused
as a different valid-time answer.  The downstream dependency index and
conclusion revisions bind both identities.  =packages/proofs/tla/temporal-causality/TemporalRevision*.tla= explores a
finite revision set, with historical-cut and no-silent-winner invariants
checked by =just check-temporal-revisions-tlc=.  A third module-local slice,
=modules/temporal-causality/truth-maintenance/=, indexes POO derivations by
subject and conclusion premises and computes a cut-bound reevaluation plan
through the transitive reverse dependencies.  The finite TLA+ case checks
closure safety and fairness-qualified completion, and a separate Lean 4.34
target uses LeanPoo proof objects for changed-dependency scheduling and
certificate reuse.  A valid-time query change now has a distinct
=valid-time-reprojection= trigger: with no declared parameter-independence
proof, it conservatively schedules every indexed derivation even if the cut
and selected evidence are unchanged.  The second TLC configuration checks
this full-scope scheduling invariant.  The cut-delta and reprojection entrypoints
take query instants and replay snapshots from the canonical journal instead
of trusting caller-supplied snapshot fields.  The caller still owns the
lower-level explicit delta and inventory completeness assertions; no general
Scheme/TLA/Lean refinement or active
conclusion publication is claimed.  The module now also has immutable
conclusion revisions, a canonical journal and inert versioned CAS plans in
=conclusions/=.  A finite TLA+ race case checks two competing proposals;
runtime proof admission, pointer commit and effect authority remain separate.
The precise semantics and limits are in
=modules/temporal-causality/framework.org= and =packages/proofs/tla/temporal-causality/model.org=.

The current TLA+ literal profile has exactly these nullary operators:

| Operator | Literal value admitted by the mapper |
|----------+--------------------------------------|
| =ClockDomains= | set of =<<identity, clock-role>>= string tuples |
| =Observations= | set of =<<identity, domain, natural-position, provenance, modality>>= tuples |
| =Hypotheses= | set of =<<identity, cause-observation, effect-observation>>= tuples |
| =Constraints= | set of =<<identity, hypothesis, relation, left-observation, right-observation>>= tuples |
| =FamilyComplete= | =TRUE= or =FALSE=; a caller assertion about the declared alternative family |

The supported relations are =before= and =not-after=.  Only observations in
the same explicit clock domain are compared; a declared or missing observation
keeps the candidate unknown.  The mapper rejects all other declarations and
expression kinds rather than treating parser acceptance as semantic admission.

The first Healthcare application is a prescription correction.  If a medicine
order is wrong, the system must distinguish:

- *past*: administrations and observations already committed before discovery;
- *present*: an active order, current exposure and effects still in progress;
- *future*: scheduled administrations and obligations within an explicit
  horizon;
- *counterfactual*: bounded alternative traces under a corrected prescription;
- *unknown*: missing causal parents, unobserved administrations, incomplete
  inventory or effects outside the selected horizon.

These sets must never be collapsed into one =affected= list.  Structural
dependency, temporal reachability, clinical causality, risk and action
authority are independent dimensions.

* Authority model

The source of truth is an identity-bound POO =CausalEventGraph=.  It may contain
observed facts, declared future candidates, derived events, hypotheses and
counterfactuals.  An immutable =CausalCut= is a projection of only committed
events whose logical position is not later than its explicit =as-of-position=.
Future plans and counterfactual alternatives therefore cannot be mistaken for
facts that have already happened.  A complete Impact input binds at least:

| Field | Purpose |
|-------+---------|
| Scenario and Case identity | vertical and concrete situation boundary |
| subject identity | Patient or other protected enterprise subject |
| change-event identity | the corrected/revoked prescription or changed feature |
| graph and Profile revision | exact semantic dependency snapshot |
| causal-event-graph identity | exact fact and candidate inventory |
| causal-cut identity | admitted events and all known causal parents |
| observation identity | explicit time observation; never an implicit live clock |
| policy identity | rules under which Impact is evaluated |
| horizon | bounded prospective and counterfactual scope |

An Impact receipt contains witness paths and separates =past-effects=,
=present-exposures=, =future-obligations=, =counterfactual-traces= and
=unknown-frontier=.  Completeness is always qualified: complete relative to an
identified cut, selected relations and horizon is not global clinical
completeness.

* Evidence, use and artifact influence across AI workflows
:PROPERTIES:
:CUSTOM_ID: temporal-evidence-ai-engine
:END:

The generic engine exposes evidence and artifact relations.  Search, short
answers, long work and autonomous research supply different
queries, evidence sources and artifact policies over the same relations.
=EvidenceRetrieval= links a question to an immutable evidence version;
=EvidenceUse= links that version to a claim; a separate
=EvidenceAssessment= names the exact use digest, assessor, method, verdict
and basis.  =EvidenceDependency= links claims or artifact nodes.
The POO audit keeps retrieved-but-unused, cited-but-unretrieved, unreviewed,
attested-refuted and contested uses distinct.  A reverse dependency closure reports
the *potential* affected claims of a changed evidence identity, bounded by
the supplied relation inventory.

The module-local [[file:../../../modules/temporal-causality/evidence/model.org][research and formal model]] maps AI papers R19--R22 to

The second model explores independently supplied reviewer verdicts in either

reviewer accuracy.

** GQL, ASCENT and TLA+ candidate exchange

:END:

Temporal owns the immutable evidence cut, projection and source inventory,
their digests, the revision generation, and admission of conclusions.  A GQL
query may select source or graph-path candidates from its admitted
=SourceQueryReceipt=; its current receipt carries query/source/parser,
provenance and result digest/count/completeness, but no common materialized
row object.  An ASCENT finite relation program may derive candidate rows
from a declared relation snapshot and report program/source/result digests,
diagnostics and bounded support.  Neither candidate engine confers causal
truth, action authority, or publication authority.

#+name: dynamic-impact-semantic-levels
#+caption: Admissible result levels for the module-owned Dynamic Impact path.
| Result level | Implemented owner | Evidence required to advance |
|--------------+-------------------+------------------------------|
| Structural witness | =modules/temporal-causality/funs.ss= | A path is not time order or causal effect. |

For two supplied series =L= and =R= on the same ordered time grid, the new
pure POO kernel computes =Dᵢ=L(tᵢ)-R(tᵢ)= and, for =i>0=,
=(Dᵢ-Dᵢ₋₁)/(tᵢ-tᵢ₋₁)=.  The division uses exact values and the *actual*
interval length, so an irregular grid is not silently treated as equally
spaced.  The receipt is =descriptive-contrast= for two observed series and
=candidate-contrast= if either supplied series is predicted or
counterfactual.  Its causal-admission flag is always false.  This arithmetic
is not an implementation of the LMTP paper's population EIF, DoFlow's
generative SCM, CLEF's sequence editor or HEDRA's event representation.

The [[file:../../../modules/temporal-causality/trajectory/model.org][Trajectory contract]] is independent of Impact.  Impact imports Trajectory;
Trajectory does not import Impact.  The intervention-window audit requires a
candidate series and observed baseline, checks agreement before the declared
onset, and integrates the supplied difference over an on-grid window.  This
does not identify the effect of the intervention.

The separate multivariate scope audit checks that declared direct targets
and protected negative-control measurements appear in matched candidate and
observed inventories.  It flags prefix or protected-output divergence and
returns =unknown= when a required comparison has no sampled evidence.  A
non-target variable is not automatically protected, since it could be a
downstream consequence.  Even =consistent-with-declaration= remains a
candidate-level result; the caller has not supplied an identified causal
model, positivity evidence or a complete variable universe.

For late or corrected trajectory data, the delta keeps both versions and
reports added, removed and changed sample coordinates.  Impact refresh never
mutates the historical contrast: an unchanged pair reuses it; compatible new
versions produce a new contrast; mismatched cut/projection or grid returns a
blocked receipt without a revised contrast.  Even an identity-only change
requires a new Impact receipt.  This is pure local re-evaluation, not a
streaming retraction engine or full incremental view-maintenance algorithm.

The research programme tests estimand alignment, treatment or intervention
persistence, delayed onset, affected-variable scope, support, uncertainty,
late evidence and hidden-parent failure.  Author-reported paper scores have
not been reproduced here.  The reproducible local arithmetic gate appears
as the named Org Babel block in the module-local record.

* Standard trajectory and Impact contract

=PooFlowCausalTrajectoryContract= is the domain-neutral admission standard for
every vertical Case that presents a correct path beside an error path.  It has
two explicit layers:

| Layer | Slots | Admitted modality |
|-------+-------+-------------------|
| operational | =trigger-event-id=, =intended-event-ids= | trigger is committed =observed=; intended members are =observed=, =declared= or =derived= |
| operational | =error-event-paths= | uncommitted =counterfactual= only |
| Impact | =intended-impact-event-ids= | uncommitted =hypothesized= only |
| Impact | =error-impact-event-ids= | uncommitted =hypothesized= only |

Identity sets are disjoint.  The intended path is ordered from the trigger;
each error path branches from the trigger or intended path; and Impact members
must be causally reachable from their corresponding path.  Missing identities,
incomplete event graphs, broken paths and modality violations produce typed
=PooFlowCausalTrajectoryAssessment= diagnostics.  Assessment uses one adjacency
index and two multi-root traversals, so its bound is O(V + E + declared
trajectory members), not one graph traversal per member.

=OntologyCase= exposes only the declarative =trajectory-declarations= slot.  Its
composition receipt owns =trajectory-assessments= and
=trajectory-handoff-ready?=.  A rejected trajectory also blocks the overall
Governance handoff.  In particular, changing an error-path event from
=counterfactual= to =observed= cannot promote it into fact; admission returns
=trajectory-contract-rejected= before any effect handoff.

* Four-language responsibility

** Scheme and POO — semantic and receipt owner

Gerbil POO owns declarative Event, Decision, Effect, Observation, Profile,
Scenario and Case objects.  It validates identities, seals the event graph,
derives the committed causal cut, projects the finite graph and produces
deterministic witness paths.  It also
combines its native temporal classification with independently admitted TLC
and Lean evidence into one inert assurance receipt.  Content-bound GQL Sources
remain non-authoritative analysis contracts until the downstream MRR Rust
library executes them through gerbil-parser's native FFI and returns a separate
execution receipt.

Scheme must not infer a clinical causal fact merely because two nodes are
reachable.  Relations carry modality, for example =declared=, =observed=,
=derived= or =hypothesized=.  A hypothesized drug effect remains a candidate
for review until admitted evidence promotes it; graph reachability alone never
does so.

The existing =sdlc-change-impact= already demonstrates deterministic shortest
witness paths, selected-relation scope, recheck sets and partial/invalid
inventory states.  That operation should move under the POO Flow Temporal
Causality core and be reused by SDLC and Healthcare rather than copied into a
second vertical framework.

** GQL — snapshot-bound relation question

GQL selects candidate paths over the sealed graph:

- which administrations derive from the changed prescription;
- which observations occurred after those administrations;
- which active and scheduled orders depend on the revoked medicine;
- which Cases, Profiles, policies and verification obligations must be
  reassessed.

GQL returns graph witnesses, not causality, temporal safety or permission.  A
query is bound to the graph digest and causal-cut identity.  Empty results on
an incomplete graph are =unknown=, never proof of no Impact.  Gerbil-parser
syntax/roundtrip admission remains separate from execution admission.

** TLA+ and TLC — bounded transition and counterexample owner

The Healthcare model defines states such as =Ordered=, =Validated=,
=Administered=, =ErrorDiscovered=, =Revoked=, =Reassessed=, =Corrected= and
=Closed=.  TLC explores interleavings of administration, late evidence,
revocation, notification and correction within a finite patient/horizon model.

Required safety properties include:

- after =ErrorDiscovered= or =Revoked=, no new administration is committed
  from the old order;
- a committed past administration is never silently erased or rewritten;
- a late event creates a new causal cut or suspends evaluation;
- missing causal parents prevent a complete Impact receipt;
- correction requires a new prescription identity and a fresh authorization;
- a counterfactual trace never becomes an observed clinical fact.

Required liveness properties include eventual reassessment and notification
under explicitly stated fairness assumptions.  TLC establishes these only for
the bounded model it exhausts; it is not a general mathematical proof.

** Lean — invariant, refinement and non-overclaim proof owner

Lean proves the general contracts that every implementation and bounded model
must respect.  Existing proof families already supply important pieces:

- =ExplicitTemporalObservations=: no implicit live-clock evaluation; changed
  observations change evaluation identity;
- =EventIngressCausalCut=: immutable causal cuts, suspension on missing parents
  and no silent late-event mutation;
- =IncrementalFixedPointCacheCorrectness=: every reachable dependent is
  scheduled and an affected strongly connected component cannot partially
  commit;
- =ReceiptContextLineagePrefixClosure=: past/current lineage is published while
  a future position cannot be claimed as already published;
- =UseCompositionCedarInputIdentityTransitionLineageClosure=: prior, current and
  future authority-context positions remain distinct.

The Healthcare refinement must additionally prove that the Scheme projection
preserves prescription, administration and observation identity; an active
wrong-prescription blocker prevents Provider handoff; past facts remain
immutable; prospective results are horizon-qualified; and an unknown frontier
cannot be converted into an allow decision.

Lean does not prove that one medicine caused one real-world symptom unless the
premises contain admitted clinical evidence for that relation.  It proves the
correct handling of whatever evidence and modality the receipt actually binds.

** Lean module ownership mirrors POO Module ownership

Lean's native module, root and library-target model is the proof equivalent of
the Scheme PackageSpec boundary.  A proof-bearing =modules/<owner>= has one
Lake library named =PooFlowModule<Owner>Proof=.  Its =roots= are the public
proof roots for that owner, and Lake alone derives their import closure.

Scenario names do not own foundational proof libraries.  Healthcare composes
the =governance=, =temporal-causality= and =authorization= libraries; it does
not replace them with a =Healthcare= build graph.  Likewise, a module without
an admitted Lean contract receives no placeholder library.

The ordinary proof gates are therefore:

#+begin_src shell
lake build PooFlowModuleTemporalCausalityProof
lake build PooFlowModuleGovernanceProof
lake build PooFlowModuleAuthorizationProof
#+end_src

The repository-wide =PooFlowProof= root remains available only as an explicit
integration qualification.  CI isolates module libraries in separate matrix
lanes, so changing one POO Module cannot implicitly turn its local validation
into a build of every enterprise proof family.

   =C_t= at an explicit logical position.
2. The POO Graph projection binds =G_t=, =C_t=, Profile/policy revisions and relation
   modalities.
3. Scheme materializes deterministic structural witnesses and the unknown

5. TLC explores bounded present/future/counterfactual transitions.
6. Lean proves generic invariants and the Healthcare refinement boundary.
7. Scheme combines the native, TLC and Lean receipts without treating one as
   proof of another.
