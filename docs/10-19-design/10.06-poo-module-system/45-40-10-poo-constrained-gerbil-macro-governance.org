#+title: POO 核心约束下的 Gerbil 宏治理
#+subtitle: 公共宏准入、展开闭包与组合语义权力边界
#+startup: overview

* RFC 状态

- 状态 :: 讨论中
- 性质 :: 规范性设计模块
- 上位原则 :: Gerbil 宏治理必须由 POO 核心约束
- POO 实现 :: =github.com/mighty-gerbils/gerbil-poo@1c3225637525400341a09e958296962c10184ead=

本模块定义宏能够做什么，而不是定义另一套组合语言。POO 对象、原型和原生操作拥有语义权力；宏只在普通函数和 POO 对象无法表达必要的卫生绑定、表面语法或阶段语义时获得准入。

* 宪法级原则

#+begin_quote
宏只能提供 POO 语义的卫生语法投影，不能成为 POO 之外的另一套语义来源。
#+end_quote

默认抽象顺序是：

#+begin_src text
普通函数
→ gerbil-poo 对象与原型
→ 函数式组合器
→ 经准入审查的宏
#+end_src

“写起来更短”或“为初学者隐藏对象模型”不能单独构成宏准入理由。

* 三个权力平面

#+begin_src mermaid
flowchart LR
    U["用户组合表达式"] -->|"提供表面语法"| M["Gerbil 宏平面"]
    M -->|"卫生绑定与静态 provenance"| P["普通 POO 值"]
    P -->|"原生对象操作"| S["gerbil-poo 语义平面"]
    S -->|"组合图与求值需求"| F["POO Flow 求值平面"]
    F -->|"结果与因果关系"| E["Evidence 平面"]
    S -->|"限定宏可投影的语义"| M
    E -->|"要求调用点与展开来源可解释"| M
#+end_src

宏平面不拥有运行时 authority。POO 语义平面拥有对象、原型、slot、mix、priority、identity、imports、capability 和 fixed-point 的解释权。Evidence 平面证明表面语法展开成了哪些普通 POO 值以及使用了哪些原生操作。

* 宏准入契约

一个公共宏只有同时满足以下条件才可准入：

1. 普通函数、POO 对象和函数式组合器无法表达所需的卫生绑定、源码语法或阶段语义。
2. 展开结果完全归约为普通函数调用和原生 POO 值。
3. 展开结果不要求宏私有的中间语言、解释器或运行时分派。
4. 宏不隐藏求值顺序、依赖、capability、authority 或副作用。
5. 展开来源和错误能够投影回用户调用点。
6. 存在与手写 POO 表达的规范等价验证。
7. 公共宏不生成新的公共宏，不形成宏塔。
8. 宏属于小型、封闭、经过 RFC 审查的公共宏表面。

内部生成宏可以消除重复的 POO 对象族、contract projection 或 manifest 声明，但不得泄漏为用户扩展协议。

* POO 语义禁区

宏不得自行实现或发明：

- merge、override 或 priority 规则；
- fixed-point 求值或循环依赖处理；
- identity、imports 或 capability 的隐藏推导；
- Profile registry 或宏私有对象类型；
- 基于语法分支的运行时 feature dispatch；
- 绕过 =gerbil-poo= 原生操作的字段拼接；
- runtime authority、lease、continuation 或 resumption 的隐式授予。

这些能力必须首先作为普通 POO 对象、原型、操作符或函数式组合器存在。

* 当前公共接口裁决

** =user-composition=

=user-composition= 是当前获得准入理由的公共宏，因为它负责：

- 建立声明名称的卫生绑定；
- 捕获静态 source provenance；
- 检查自身的参数数量和表面语法；
- 将语法错误投影到调用位置。

它不得：

- 解析 =compose= 内部的 Profile operands；
- 在编译期强制求值 Profile；
- 执行 mix、priority、fixed-point 或 capability 语义；
- 建立全局 registry；
- 授予运行时 authority；
- 生成只有自身能够继续解释的表示。

下面仅描述概念性展开，不承诺具体实现名称：

#+begin_src scheme
(user-composition my-system
  (compose profiles
    wendao-episteme
    production))
#+end_src

概念上归约为：

#+begin_src scheme
(def my-system
  (make-user-composition
    (source-provenance ...)
    (compose profiles
      wendao-episteme
      production)))
#+end_src

=make-user-composition= 必须是普通函数或 POO 构造操作。语法失败属于宏展开；POO 语义失败属于普通组合求值及其结构化 evidence。

** =compose=

=compose= 是普通高阶函数，不是宏。它接收一个第一等 POO composition-strategy 对象以及普通 operands：

#+begin_src scheme
(compose profiles
  base
  wendao-episteme
  production)
#+end_src

=profiles= 是 POO strategy 对象，不是宏关键字、类型标签或封闭枚举。=compose= 不得通过 =case=、名称比较或隐藏 registry 识别它，只能使用 strategy 对象公开的 POO 能力。

高级 strategy 通过 POO 原型扩展产生，不通过新宏产生：

#+begin_src scheme
(def audited-profiles
  (.mix profiles audit-policy))

(compose audited-profiles
  base
  wendao-episteme
  production)
#+end_src

这里的 =.mix= 只表示必须采用 =gerbil-poo= 的真实原生对象操作；最终接口以已验证的 =gerbil-poo= 原语为准。

* 展开闭包

宏展开后的结果必须：

- 可由普通函数接收；
- 可参与原生 POO 操作；
- 可作为 Profile operand 继续组合；
- 可由高级用户直接扩展；
- 可在不重新依赖原宏的情况下检查、求值和解释；
- 保留调用点、展开身份和 POO semantic identity 之间的 provenance。

#+end_src

* 结构性预算

宏预算采用结构限制，而不是任意数量上限：

- 公共宏清单封闭并接受 RFC 审查；
- 一个公共宏只建立一层公共语法边界；
- 公共宏不得生成公共宏；
- 内部宏不得成为用户扩展协议；
- 编译期展开必须确定，不读取网络、可变环境或动态 registry；
- 每个公共宏必须保留可查看的规范展开；
- 每个公共宏必须证明函数与 POO 路径不足以承担其职责。

* 非目标

- 不复制 Doom Emacs、Centaur Emacs 或其他系统的表面语法。
- 不为每个领域创建一个便利宏。
- 不建立新的配置 DSL。
- 不建立兼容性迁移或废弃策略；这是全新架构。
- 不重新实现 =gerbil-poo= 已有的 POO 语义。
