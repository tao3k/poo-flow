#+date: 2026-09-24

* Decision

POO Flow has one semantic model across Scheme, Lean and TLA+.  Native POO
Objects carry slots and inheritance.  Entity and Element are roles of those
Objects, not alternate representations.  Relations reference their stable
identities.  Queries are bounded read-only POO values.  The current graph-read
model has one GQL semantics with two surfaces: Scheme authors its native POO
AST, while a pure projector emits standard GQL source.  Python and runtimes are
Providers or adapters around that model and never become a second semantic
authority.

The repository-wide programming rules are routed by
[[file:44-current-project-programming-style.org][Current Project Programming Style]].
Query/Relation authoring is owned by
[[file:44-current-project-programming-style/04-semantic-query-and-relation.org][Style 04]];
formal correspondence is owned by
[[file:44-current-project-programming-style/07-formal-assurance-correspondence.org][Style 07]].

* Vocabulary

| Concept | Semantic responsibility | Forbidden interpretation |
|---------+-------------------------+--------------------------|
| Object | Native POO carrier of identity, slots and behavior | Generic JSON/alist authority |
| Entity | Identity-bearing domain role of one Object | Copied domain record |
| Element | Entity, Relation or inert Value admitted into one observation space | Independent object store |
| Relation | Typed identity edge between admitted Elements | Embedded copies of endpoints |
| Contract | Shape, invariant, scope, visibility and admission boundary | Runtime executor |
| Query | Immutable bounded read projection | Mutation, proposal, authority or raw query string |
| GQL Provider | Execution of an admitted projected graph Query | Owner of Contract or causal truth |
| Native refinement | Typed bounded filtering of a GQL candidate set | A second Query language or unbounded evaluator |
| Receipt | Identity/provenance evidence returned across a boundary | Authority grant |

* Native POO surface

The ordinary surface contains noun-valued slots and native slot algebra:

#+begin_src scheme
(.def SemanticCase
  (contract ? BaseContract)
  (elements ? (.o))
  (relations ? (.o))
  (queries ? (.o)))

(.def (PrescriptionCase @ SemanticCase)
  (elements =>.+
    (.o prescription: Prescription
        patient: Patient))
  (relations =>.+
    (.o prescribed-for: PrescriptionPatientRelation))
  (queries =>.+
    (.o impact: PrescriptionImpactQuery)))
#+end_src

The Query object declares identity, a GQL-aligned POO program, result bounds,
completeness, evidence requirements, visibility request and result Contract.
Raw GQL strings, query alists and anonymous evaluator lambdas are not Query
objects.  The core pure projector deterministically renders the admitted AST;
a named Provider may execute the resulting GQL source.  The syntax prototypes,
structural validator and pure source projector are owned together by the
declared =gerbil-parser= revision.  POO Flow extends the parser-owned Program
prototype only with governance metadata and admission; it does not copy the
GQL syntax graph or renderer.

The canonical Query Module publishes a =languages= noun slot containing one
=gql= semantic language.  Its =authoring-surface= is =scheme-poo= and its
=source-surface= is =gql=: these are two representations of one Query, not two
peer languages.  =gerbil-parser= remains the parser owner.  The live gate must
prove that the pure projection is byte-equal to the maintained Case source and
that this source parses and roundtrips exactly.

* Capability and escalation boundary

GQL is selected because the current Healthcare queries are graph pattern
reads: typed path traversal, property equality and bounded projection.  It is
not the owner of causal truth, temporal proof, authorization or governance.

When a vertical needs more than GQL selection, the default pipeline is:

#+begin_src text
POO Query -> GQL candidate selection -> typed native refinement -> result admission
#+end_src

The refinement is a named, bounded POO/functional Contract over a typed domain
Schema.  It binds the original Query identity, semantic revision and candidate
receipt; it is not an anonymous predicate or a second language registry.  This
keeps domain filtering out of GQL while preserving one admission chain.

Only evidence from a real Case may justify either a versioned GQL extension or
another Provider.  Higher-order systems such as ASCENT consume admitted facts
above this pipeline and may be implemented in Scheme/POO; they delegate graph
candidate retrieval to GQL rather than redefining GQL semantics.

* Single authority flow

#+begin_export mermaid
flowchart LR
  P["POO Scenario/Profile"] --> C["Contract"]
  P --> E["Element space"]
  P --> R["Typed relations"]
  P --> Q["Bounded POO Query"]
  C --> A["Query admission"]
  E --> A
  R --> A
  Q --> A
  A --> G["Parser-owned pure GQL projection"]
  G --> X["MRR/runtime execution"]
  X --> NR["Optional typed native refinement"]
  NR --> SR["SourceQueryReceipt"]
  SR --> ER["POO evidence result"]
  ER -. "never grants" .-> AU["Action authority"]
#+end_export

Gerbil-parser owns the POO-native GQL syntax graph and pure projection, then
proves source parsing, syntax contract and byte-exact roundtrip.
The GQL runtime proves only its execution receipt.  POO Flow admits that
receipt against the original Query and Contract identities.  Graph witnesses
do not by themselves prove causality, temporal safety, authorization or
completeness.

The executable boundary is =modules/query/contracts.ss=.  Runtime output
first enters Scheme as a typed =PooFlowQueryExecutionCandidate=; it is not yet
admitted evidence.  The =QueryReceiptBindingExecutor x Provider x Query=
crossing uses the POO CLOS generic and an MRR-owned method bundle.  Binding
checks the prior Query admission, Provider and parser identities, semantic
revision, byte-derived GQL source identity, result bounds, completeness and
required evidence before producing =PooFlowSourceQueryReceipt=.  Neither the
candidate nor the admitted receipt carries mutation or action authority, and
the binding path never starts MRR or another runtime.

The native transport pre-admission is an executable Scheme function in
=modules/query/rust-ir.ss=.  =gerbil-parser= projects it into the versioned,
byte-stable IR under =bindings/rust-ir=, and =gerbil-scheme-rust-ir= typechecks
and lowers that source-owned function during the Rust consumer build.  It
deliberately avoids both a Query-specific C structure and a Rust-owned JSON
schema.  MRR's =QueryResultAdmissionReceipt= supplies the admitted row count,
result digest and bound-query identity evidence.  The adapter must pair that
receipt with the original POO execution binding to obtain query version,
semantic revision, parser, source-content and provenance identities.  It must
not infer those identities from a digest or create a second Query authority.

* Executable Scheme authoring Contract

=src/module-system/authoring/contracts.ss= is the source-admission owner.  A
public =query=, =queries=, =*-query= or =*-queries= slot initialized by a raw
string, list, vector or lambda is rejected as
=poo-query-must-be-native-object=.  The repair is
=bind-named-poo-query-or-provider-projection=.

This gate is intentionally syntax-bounded.  It does not infer duplicate
authority from names, execute a Query, parse GQL or prohibit pure functions in
=funs.ss=.  Runtime and semantic Contracts own those stronger claims.

* Lean correspondence

=PooFlowProof.PooC3.NativeSemanticQueryModel= uses one
=ObjectIdentity=.  =EntityRole= and =ElementSpace= reference that identity;
they do not copy an Object.  Its theorems establish:

1. Entity role projection preserves native Object identity;
2. closed Relations reference one Element space;
3. admitted Queries select only declared Elements;
4. evaluation binds the original Query identity and semantic revision;
5. Query results never carry action authority.

The focused gate is:

#+begin_src sh
just check-native-semantic-query-lean
#+end_src

* TLA+ correspondence

=NativeSemanticQuery.tla= owns the bounded transition model.  Contract binding,
Query admission, Provider execution and terminal quiescence are separate
transitions.  Terminal quiescence is explicit so deadlock checking remains
enabled rather than being suppressed in configuration.  TLC checks:

1. Query execution never changes =semanticRevision=;
2. Query execution never grants =actionAuthority=;
3. Provider execution requires an admitted, Contract-bound Query;
4. every result binds both the Provider and source semantic revision.

TLA+ closure has three independently visible parts: native source/config,
parser syntax plus byte-roundtrip receipt, and TLC state-space receipt.  Parser
and model-checker gates remain distinct; the aggregate gate joins them with the
Lean correspondence check:

#+begin_src sh
just check-native-semantic-query-tla
just check-native-semantic-query-tlc
just check-native-semantic-query-model
#+end_src

* Cross-language obligations

- Scheme Object identity, Lean =ObjectIdentity= and runtime receipt identity
  must refer to the same semantic subject.
- Provider output includes Query identity, Query version, source content
  identity, parser identity, provenance root and result digest.
- Python consumes the versioned receipt contract; it does not define Query
  semantics independently.
- Empty results over incomplete Element spaces are =unknown=, never proof of
  absence.
- A Query cannot apply a Proposal, mutate a Scenario, widen visibility or
  publish authority.
