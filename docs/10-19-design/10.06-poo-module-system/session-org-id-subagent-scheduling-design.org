* Decision and scope

Session owns persistent interaction identity and subagent scheduling semantics.
=ai-agentic-context= composes the independent =session= Module, admits Org-backed
content bindings and constructs each participant's Context projection. Memory
remains Context's optional retention Feature. This design extends
[[file:ai-agentic-context-session-memory-contracts.org][the lifecycle contracts]] without adding a Session core or scheduler Module.

A stable Session ID enables lookup, resume, child scheduling and receipt routing.
The product requirement is persistent interaction identity; this document makes
no claim about Codex's internal implementation. The new identity/Org binding and
scheduler contracts below are proposed, not delivered capabilities.

* CLM research input

The likely referenced paper is Shao et al., [[https://arxiv.org/abs/2609.37725][Context Language Models]],
arXiv:2609.37725v1, submitted September 29, 2026. Its central mechanism exposes
live context as an editable file; multiple such contexts support multi-agent
workloads. Its [[https://arxiv.org/html/2609.37725v1][Section 5.1.2]] also reports little extra benefit from subagents on
the tested single-repository benchmark. This motivates editable Context and
explicit parallelism qualification; it does not demonstrate POO scheduling
throughput. [[https://github.com/facebookresearch/context-language-models][The authors' repository]] is a research reference, not a runtime dependency.
The user confirmed this paper as the intended research reference.

Our design decision is to let agents propose edits to their working Org content
and Context selection. Each accepted edit creates a new admitted revision with
provenance. The next turn receives a fresh projection. Scheduler state, source
receipts and grants remain controlled by their owning protocols. Rewriting a
working Context cannot rewrite historical receipts or erase worker obligations.

* Identity vocabulary

| Identity | Owner and lifetime | Relation |
|----------+--------------------+----------|
| Session ID | Session; immutable for the interaction lineage node | Persistent lookup/resume key; independent of provider/process |
| Org ID | Org content; explicit local =:ID:= property | Stable content anchor resolved within an admitted organization/source catalog |
| Binding ID | Context; immutable association identity | Associates Session ID with Org ID, role and admitted source revision |
| Task ID | Session; stable logical unit of work | References an admitted content anchor and graph revision |
| Attempt ID | Session; fresh for each execution/retry | References task, child Session, exact input and claim generation |
| Worker ID | Runtime; identity of an execution endpoint | May change while Session ID remains stable |
| Provider conversation ID | Provider adapter; endpoint-specific | Transport metadata, never the canonical Session ID |

New runtime Session IDs are opaque, bounded UTF-8 strings allocated by an
injectable ID provider. UUID is the default proposed representation; admission
validates canonical representation, freezes bytes and rejects collisions within
the authoritative namespace. Equality is value equality, not Scheme symbol
identity. Organization and epoch are checked independently of ID lookup.
A fork/new child receives a fresh ID; resume preserves ID and advances revisions.
Closed identities and retired generations are never reused.

Existing Session values require symbol IDs and =poo-flow-session-by-id= uses
=eq?=. The runtime migration must update constructors, references, indexes,
fixtures and receipts together. Public textual IDs must not be globally interned
into symbols. Existing symbol-based authoring names become declaration names,
with one explicit lowering into runtime identity; they are not alternate runtime
identities or an indefinitely supported compatibility facade.

* Org association and resolution

The [[https://orgmode.org/manual/Property-Syntax.html][Org property syntax]] defines property drawers; the [[https://orgmode.org/manual/Handling-Links.html][link manual]] describes
links to =ID= and =CUSTOM_ID=. For this profile, only an explicit local =:ID:=
is the stable anchor. Inherited IDs and =CUSTOM_ID= values do not substitute for
that binding. Titles, paths and byte offsets are revision-local locators.

=POO_FLOW_SESSION_ID= is a proposed POO convention, an inspectable root/primary
association hint. It is not a standard Org property or a dispatch instruction.
One Session may consume several Org anchors; one anchor may participate in
several Sessions. The admitted binding index owns this many-to-many relation.
The optional root property cannot represent or authorize all participants.

A =SessionOrgBinding= binds organization/epoch, Session ID, explicit Org ID,
source identity and digest, parser/query identity, Element locator at that cut,
binding role, revision, restriction and admission receipt. Context owns Orgize
parsing and Query admission, then lowers an opaque content reference into the
Session contract. Session does not import Orgize or Memory to resolve it.

Resolution requires exactly one explicit ID in the admitted source catalog cut.
Missing, duplicate or unreadable IDs produce typed refusal; do not pick the
first match. Copying a subtree with its ID requires explicit reassignment before
new identity admission. A moved anchor retains its identity only through an
admitted source relocation/rebinding receipt; a different digest never silently
reuses old disclosure permission. Changing =:ID:= creates a new anchor and an
explicit supersession relation. Deleting an anchor invalidates its live bindings.

Org property edits are proposals admitted through expected document revision,
Orgize parse/Query roundtrip and current restrictions. Neither a forged Session
ID property nor copied bytes can enroll a worker, grant authority or resume a
closed Session. Binding receipt publication and an optional Org backlink write
may occupy different stores: record pending backlink intent and reconcile it;
do not claim cross-store atomicity. Operational enrollment requires the admitted
binding receipt, while backlink status remains independently inspectable.

* Task graph and child Sessions

Session owns a versioned =SessionSchedule= with tasks, dependency edges, join
conditions, placement constraints, resource budgets and cancellation policy.
Context compiles admitted Org plans into native Session proposals. Ordinary Org
hierarchy supplies content structure; scheduling edges require explicit admitted
relations. Editing a task headline does not itself spawn an agent.

A task graph is a DAG per admitted graph revision. Parent/child lineage,
dependency edges, message flow and evidence lineage are different relations.
Reject missing executable dependency targets and cycles before dispatch.
Existing report graph helpers treat missing parents as external roots; this
presentation behavior cannot qualify executable task dependencies.

Each admitted Attempt belongs to an enrolled Session and binds Task/Attempt IDs,
scope restriction, input projection references and budget allocation. A separate
child interaction receives a fresh Session ID and parent/root reference.
Compatible Tasks/Attempts may explicitly reuse that Session under the admission
rules in [[file:session-scheduling-granularity-design.org][Scheduling Granularity and Incremental Context]]. Retries create fresh
Attempts/claim generations and retain previous outcomes. A resumed attempt requires reconciled provider identity and
current enrollment, not a new blind dispatch.

| Coordination | Required contract |
|--------------+-------------------|
| Fan-out | Explicit task IDs, per-child scope/input/budget and admitted graph revision |
| Dependency release | Admitted predecessor result receipt, not provider completion alone |
| Join | Declared all/quorum/first-qualified-result policy, exact result revisions and failure handling |
| Message | Sender/recipient Session IDs, attempt/turn revision, payload digest, purpose and current disclosure fence |
| Follow-up | Explicit new turn and admitted inputs; deduplicate by owner command identity |
| Handoff | Fresh recipient projection and placement receipt; Session identity survives worker replacement |
| Graph change | Expected schedule revision; reconcile running attempts, never silently retarget them |
| Cancellation | Parent intent plus child request/acknowledgment or isolation receipts |

A quorum counts distinct admitted logical task results; retries cannot count
multiple times. A first-qualified-result join cancels or isolates remaining
attempts, preserving unresolved obligations. Disagreement and evidence lineage
remain explicit when results are consolidated. A child cannot auto-publish its
output into a parent's active Context. Context admits it under the parent's
current Demand and constructs a new projection for the next parent turn.

* Scheduler semantics and runtime boundary

Public Session scheduling values are native POO objects. Named pure functions
validate graphs, compute readiness, allocate budgets and produce dispatch/join/
cancellation intents. Runtime/Marlin executes provider work and conditional
publication. Scheduler state belongs to Session; physical storage belongs to the
configured Backend/Data adapter. No Bash scheduling/discovery wrapper is added.

Proposed task states are =waiting=, =ready=, =claimed=, =running=,
=awaiting-admission=, =succeeded=, =failed=, =cancelled= and =blocked=.
Attempt states and task states are distinct. Policy decides whether a failed
attempt makes the task ready for retry or terminally failed.

1. Admit graph and content bindings at explicit schedule/source cuts.
2. Release ready tasks only after dependency receipts satisfy the declared join.
3. Select eligible tasks under resource, placement, fairness and scope policy.
4. Claim with expected task/schedule revision, owner epoch, generation and lease.
5. Prepare exact child/input/target bindings without caching an allow decision.
6. Persist a dispatch intent with idempotency key before provider submission.
7. Recheck current Context disclosure permission at actual submission through
   the qualified coordinator fence; record the exact dispatch observation.
8. Record provider completion; admit the result against current fences.
9. Publish task outcome and release only affected successors after owner CAS.

Ready/claimed state does not authorize execution. Source, policy or predecessor
receipt invalidation marks dependent tasks for re-admission; admission of a
successor or join rechecks the exact dependency receipts and current Context.
An event can enqueue reconciliation but cannot replace this fence. Recovery of
an outbox intent rechecks current permission before any undisclosed retry.

Initial runtime uses one conditional publication owner per schedule. Provider
execution is concurrent; admission/claims have a defined linearization point.
A later sharded runtime must qualify cross-shard joins, budget reservations and
recovery before making throughput claims. Lease expiry prevents stale publication
but does not prove the old worker stopped. Re-dispatch effectful work requires
provider idempotency/reconciliation or confirmed termination/isolation.

* Performance design and qualification

Avoid reparsing Org, traversing every Session or serializing full Context on each
scheduler tick. Cache only immutable admitted values; keep freshness/authority
checks at actual consumption. Index keys include organization and owner revision.

| Mechanism | Proposed work bound / admission condition |
|-----------+-------------------------------------------|
| Session ID and Binding ID indexes | Expected constant-time local hash lookup; durable/provider costs reported separately |
| Org anchor index | Built once per admitted source cut; incremental update only with qualified changed-element coverage |
| Task graph admission | O(V+E) graph validation and predecessor/successor indexes |
| Dependency completion | O(out-degree) affected-successor updates; no full graph scan |
| Ready queues | Bounded FIFO lanes with per-organization weighted fairness and aging |
| Deadline/lease queue | O(log Q) local heap insertion/removal, explicit clock domain |
| Context sharing | Immutable revision references and structural sharing within admitted scopes |
| Provider submission | Bounded batch size, reserved capacity and idempotent pending intents |
| Wake-up | Completion/source/policy/lease events, with bounded recovery reconciliation |

These are intended local data-structure bounds, not measured end-to-end results.
A scheduling step also pays placement eligibility, current guards and durable
publication costs. Do not hide candidate scanning or cross-shard coordination
inside a constant-time claim. Queue/index updates are private runtime state
projections of the pure admitted schedule, never a new semantic authority.

Budgets bound global and per-root/organization concurrency, depth, fan-out,
queued tasks, retained Context bytes, token/provider spend and tool/effect
capacity. Reserve child budgets atomically against the parent allocation;
release them once per terminal attempt receipt. Admission failure, provider
backpressure and quota exhaustion retain pending work without hot retry loops.
Parent waiting must not hold an execution slot required by its children.

Use matched workloads: linear chain, wide fan-out, diamond dependencies, mixed
long/short tasks, fairness under a noisy root, source correction, provider stall,
lease expiry, competing completions and crash recovery. Measure scheduler CPU,
allocation, queue depth, p50/p95/p99 readiness-to-claim and completion-to-release,
durable CAS conflicts, cancellation acknowledgment latency, token/spend and task
quality separately. Compare equal workers, budgets, model and cache state against
the baseline. Provider speed is not scheduler throughput. Establish numerical
service targets from these measurements rather than inventing them in the RFC.

* Source roles and implementation order

| Owner role | Proposed content |
|------------+------------------|
| =session/types.ss= | Textual identity, schedule/task/attempt, claim and receipt invariants |
| =session/objects.ss= | Inert Session, Task, Attempt, Schedule and Budget prototypes |
| =session/funs.ss= and owned =funs-*.ss= | Graph readiness, transitions, joins and budget functions |
| =session/config.ss= | Scheduler policies, fairness and placement Profile composition |
| =session/interface.ss= | Public role closure, no execution logic |
| Context =types/objects/funs= | Org anchor/binding admission and per-child projection adapter |
| Explicit runtime/provider owner | Queues, timers, dispatch, conditional publication and reconciliation |
| Memory Feature | Optional retained experience/assessment from admitted Session results |

Implement identity and source-backed binding admission first. The current
=orgize/open-headlines-v1= Context profile does not expose the required property
ID relation. Qualify a new bounded Orgize/Query property profile and exact replay;
do not claim the existing headline tests cover anchor uniqueness or scheduling.
Then implement one-owner pure task graph/claims and child result admission,
followed by bounded runtime queues, joins, cancellation and durable recovery.
Module authoring admission must qualify role/import direction through the existing
Profile gate. No empty shell files, new public DSL or compatibility resolver.

Quint models use bounded Sessions, anchors, tasks, revisions, workers and claim
generations. Match controls for duplicate Org IDs, copied Session properties,
missing/cyclic dependencies, over-budget fan-out, stale claims, retry double-count,
source correction after dispatch, parent-close/child-spawn races and dropped
pending obligations. Replay each trace through native admitted contracts.
Fairness/liveness require explicit eventual-worker/clock assumptions; finite
safety checks cannot establish high performance or unconditional completion.

* Granularity refinement

[[file:session-scheduling-granularity-design.org][Scheduling Granularity and Incremental Context]] separates persistent Session
identity, independently accepted Tasks, execution Attempts, provider Turns,
Context slices and admitted artifact ports. Session reuse requires explicit
qualification; it is not an implicit new Session for every Attempt.
