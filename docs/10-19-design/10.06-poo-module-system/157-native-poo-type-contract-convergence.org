#+title: Native POO Type and Contract Convergence
#+language: en

* Status

STABLE.  The shared native foundation, observability vertical slice,
module-object field/transformer Type boundary, graph Contract family, sandbox
resource Contract, and session policy/tool-grant Contracts are present.  Loop
governor and human-audit Contracts also use the shared native schema owner.
JSON Schema and type-fact projections consume the same descriptors directly;
the legacy record-contract modules have been removed.

* Decision

POO Flow uses the pinned =gerbil-poo= meta-object protocol as its only generic
type and dispatch foundation.  A project Type or Contract is a native
prototype-derived Type descriptor.  It is not a record, symbolic value-kind,
predicate registry, object-kind tag, or alist schema.

The former utilities contract macro design is removed.  No compatibility
wrapper, dual lookup path, or translation registry is admitted.

The dotted value-to-contract edge records validation association only.  A
domain object never inherits contract obligations as object behavior.

* Generic operation boundary

Only behavior with an open specialization axis is generic:

- =poo-flow-type-classify= dispatches to =.classify=;
- =poo-flow-contract-obligations= dispatches to =.obligations=; and
- =poo-flow-contract-admit= dispatches to =.admit=.

Fixed accessors, constructors, pure helpers, and final projections remain
ordinary named functions.  The project reuses upstream =element?= and
=validate= and does not redefine them.

* First vertical slice

The observability slice is the first native convergence owner:

1. Diagnostic and receipt values are native POO objects extended from their
   domain prototypes.
2. Diagnostic and receipt Contracts are declared with upstream =define-type=.
3. Classification checks the POO responsibility shape.
4. Pure obligations validate the responsibility values.
5. Admission returns one POO validation-evidence value.
6. Boolean acceptance and report projection derive from that evidence.

The slice removes its dependency on =src/utilities/contracts.ss= and
=src/utilities/contract-syntax.ss=.

POO slot declarations must not use a same-named lexical binding on the right
hand side.  For example, =candidate: candidate= denotes a self-slot reference
inside =.o=, not the surrounding variable, and therefore creates an infinite
recursive lookup.  Constructors use hygienically distinct names such as
=candidate-value=; the runtime scenario guards this expansion boundary.

* Module-object vertical slice

Module fields and transformer contracts store native =gerbil-poo= Type
descriptors.  Constructors reject a symbol or any other non-Type value before
it can enter composition.  Field values and transformer arguments are admitted
with upstream =element?=; there is no permissive unknown-kind branch.

The ASP structural harness still receives its established =valueKind= symbol,
but that value is a one-way diagnostic projection from the native descriptor.
It is not read back into semantic dispatch.  Parameterized lists are expressed
as native =(List element-type)= descriptors while projecting the bounded
=List= vocabulary required by the harness.

The dedicated =//scheme:module_object_native_type_contract_test= exercises
valid object validation and the fail-closed symbolic-kind boundary without
depending on the aggregate unit-test loader.

* Graph vertical slice

Graph node, edge, aggregate, analysis, and loop-analysis contracts are native
=PooFlowContract.= descriptors.  Their slot schemas are ordinary POO objects,
and every slot holds a native Type descriptor.  Contract admission first
classifies the graph object's POO responsibility and then discharges required
slot and =element?= obligations.

The graph owner no longer imports =utilities/contracts.ss= or
=utilities/contract-syntax.ss=.  It contains no =defcontract-family= expansion
and exports no legacy record-contract constants.  Existing contract-report
functions remain final one-way projections for diagnostics and tests; those
alists do not participate in admission.

The dedicated =//scheme:graph_native_type_contract_test= proves descriptor
identity, valid admission, invalid slot rejection, projection shape, constructor
validation, and analysis receipt construction.

* Sandbox resource vertical slice

The sandbox resource owner stores filesystem, CPU, ports, memory, and timeout
constraints as native Type descriptors inside POO slot-schema objects.  Its
=PooFlowSandboxResourcesPrototypeContract= is a native =PooFlowContract.=
descriptor whose pure obligations reject missing required slots and values that
fail upstream =element?= admission.

The existing ASP object-validation harness remains a downstream diagnostic
consumer.  Its =valueKind= rows are one-way projections from the native slot
Types; neither the harness nor type-fact projections own resource semantics.
The owner no longer imports legacy utilities contracts or expands
=defcontract-family=.

The dedicated =//scheme:sandbox_resource_native_type_contract_test= proves
descriptor identity, valid resource admission, invalid CPU rejection, report
shape, and integration with the existing evidence-producing validation path.

* Session policy vertical slice

Session policy and tool-grant owners use the repository-wide functional native
composition owner, =module-system/contract-schema.ss=.  That module constructs
native value Types, POO slot-schema objects, pure slot obligations, and
=PooFlowContract.= descriptors.  Graph and sandbox resource contracts use the
same owner.  Policy objects use POO slot presence and lookup; tool-grant
authorization rows use their bounded row reader.  These paths therefore share
contract semantics without conflating their representation boundaries.

The two owners no longer import legacy utilities contracts or expand
=defcontract-family=.  Their existing manifest rows are final projections, and
session-specific performance workloads now measure native descriptor projection
instead of legacy type-fact record conversion.

The dedicated =//scheme:session_native_type_contract_test= proves native
descriptor identity, valid policy and grant admission, invalid policy and grant
slot rejection, projection shape, and constructor gates.

* Sandbox profile vertical slice

The agent-sandbox owner defines the canonical profile kind and one native
=PooFlowSandboxProfileContract=.  Its eight required slots cover profile
identity, backend selection, network policy, capabilities, resource policy, and
metadata.  The sandbox-core facade re-exports that owner without copying its
type semantics.

Public =poo-flow-sandbox-profile?= now performs native Contract admission.
Descriptor projection requires the same evidence before portability checks and
before the legacy runtime descriptor boundary.  Parent-profile derivation uses
the same predicate instead of a shallow kind-only check.  Invalid or incomplete
recipes therefore fail closed while still remaining inert POO values during
authoring.

The dedicated =//scheme:sandbox_profile_native_type_contract_test= proves
native Type identity, valid admission, invalid-slot rejection, missing-slot
rejection, and fail-closed descriptor handoff.  The sandbox UI gate also fixed
a previous false-positive fixture whose complete recipe had accidentally been
quoted as the profile name, leaving its resource rows untested.

* Loop governance vertical slice

Loop governor nodes, aggregate governors, and human-audit review objects use
the shared =contract-schema.ss= owner.  Their POO role objects remain the
semantic values; native Contracts classify those roles and discharge slot
obligations without executing loops or runtime work.

The loop owners no longer import the legacy utilities contract modules and no
longer expand =defcontract-family=.  Existing contract rows remain bounded
control-plane projections.  The dedicated
=//scheme:loop_native_type_contract_test= proves native descriptor identity,
valid governor and audit admission, projection shape, and invalid-slot
rejection.

* JSON Schema and proof projection vertical slice

The JSON Schema emitter maps normalized IR nodes directly to native Types,
POO slot schemas, and a =PooFlowContract.= descriptor.  Node =kind= remains an
IR dispatch key only.  The validator checks slot values through upstream
=element?= and cannot recover or invoke a predicate from a projected record.

Type-fact and Lean-fact owners read native Contract identity, owner, object
kind, slots, Type report metadata, and required polarity directly.  Their rows
are one-way proof handoff projections; they never reconstruct a semantic
Contract.  The legacy =utilities/contracts.ss= and
=utilities/contract-syntax.ss= modules are deleted without compatibility
wrappers.

Dedicated contract-schema, JSON Schema, and type-fact gates prove native Type
identity, valid and invalid admission, bounded projection, and proof-row
generation.

* Performance contract

Declaration and construction may perform complete validation once.  Repeated
consumers must reuse the immutable evidence until the object generation
changes.  A benchmark is meaningful only if it separately measures:

- descriptor construction;
- warm generic dispatch;
- successful and rejected admission;
- evidence reuse;
- final projection; and
- allocation and peak RSS.

Legacy alist projection measurements cannot qualify this architecture.
