#+title: Git Source, Gerbil Package, Binding, and POO Import Closure
#+startup: overview

* Status

The architecture in this RFC is accepted.

This acceptance freezes ownership boundaries.  It does not turn any
source checkout into a Gerbil package, admit a registry, or assign child
build, test, or distribution ownership to POO Flow.

* Scope

This RFC separates:

- Git source ownership and revision pinning;
- =gerbil.pkg= package availability;
- Gerbil source-level binding visibility;
- POO Module =imports= semantic closure;
- the thin =use-module= projection.

It also defines downstream initial integration for
=wendao-episteme= without requiring that repository to become a Gerbil
package.

* Central decision

A Git repository or submodule is source evidence.  It is not
automatically a Gerbil package.

=gerbil.pkg= manages actual Gerbil package dependencies.  It does not
define POO Module identity or project semantic closure.

Gerbil =import= and =export= make Scheme bindings visible.

The POO Module =imports= responsibility defines semantic Module
dependencies after ordinary bindings and POO values exist.

=use-module= hygienically selects an already visible native Module
binding.  It does not cross or collapse those ownership boundaries.

* Four distinct planes

| Plane                       | Owner                         | Provides                                      | Does not provide                                      |
|----------------------------+-------------------------------+-----------------------------------------------+-------------------------------------------------------|
| Git source pin             | source-owning repository      | repository identity and revision evidence     | package identity, binding visibility, semantic import |
| =gerbil.pkg=               | actual Gerbil package owner   | package acquisition and dependency availability | Module identity, active evidence closure, runtime     |
| Gerbil binding visibility  | downstream source module      | hygienic import/export binding resolution     | POO semantic dependency closure                       |
| POO Module =imports=       | native Module POO value       | recursive semantic dependency evidence        | source checkout, package installation, Scheme loading |

The planes may refer to one another through explicit evidence.  They
remain different contracts and failure owners.

* Git source ownership

A Git pin identifies repository origin and exact revision for source
evidence.  A parent repository may carry that pin without owning the
child repository's:

- Gerbil package declaration;
- build graph;
- test suite;
- publication;
- release lifecycle;
- deployment adapters.

The parent may verify the pinned revision and the narrow interface it
consumes.  It does not run integration or distribution policy on behalf
of the child unless a separate owner contract explicitly assigns that
responsibility.

A Git revision may participate in source-snapshot or implementation
evidence.  It does not automatically become a Module domain identity,
evidence schema identity, Gerbil package identity, or profile identity.

* gerbil.pkg boundary

=gerbil.pkg= is the Gerbil package-management layer.

It may declare and retrieve a package and its package dependencies when
the source owner has actually defined that Gerbil package.

It does not:

- project POO Module =imports=;
- derive active evidence closure;
- select profiles;
- materialize capabilities;
- run Module fixed points;
- define build or test policy;
- convert an arbitrary Git checkout into a package.

If =wendao-episteme= later becomes a Gerbil package, that change may
simplify source availability and binding import.  It does not change
its Module identity, profiles, semantic =imports=, authority, or
observability semantics.

* Gerbil binding visibility

The downstream source owner uses normal Gerbil module-system
integration to make native POO values visible.

The exported surface may include:

- the =wendao-episteme= Module POO value;
- its domain-owned profile values;
- explicitly admitted Contracts or advanced POO extension values.

Normal Gerbil source integration may use package-provided modules or
source modules available through the downstream build environment.
That choice remains a source/build concern.

Binding visibility is complete before =use-module= expands.  A missing
binding is a compile-time source-resolution failure with source mapping,
not a request for runtime discovery.

* Downstream initial integration

Initial integration means that the downstream source owner:

- pins or otherwise obtains the intended source revision;
- makes its Gerbil source module available to the build;
- imports the Module and profile bindings through normal Gerbil syntax;
- records the exact source and binding evidence;
- composes those ordinary values through the accepted public interface.

Initial integration is not an =initial= form, initialization phase,
registry mutation, package-install side effect, or runtime lifecycle.

* POO Module imports boundary

The Module =imports= slot contains semantic dependency evidence among
native Module values.

It may participate in:

- recursive reachability;
- capability and Contract closure;
- profile and responsibility resolution;
- fixed-point evaluation;
- cycle and SCC evidence;
- observability and recovery.

It does not load Scheme source, install a package, inspect a checkout,
invoke a build system, or search a global registry.

The word =imports= in the Module contract therefore denotes semantic
Module dependencies, not Gerbil source syntax.

* use-module boundary

=use-module= receives an already visible Module binding and admitted
profile selector.  It produces one ordinary native POO value for
composition.

It does not:

- search the filesystem or network;
- inspect Git submodules;
- read =gerbil.pkg=;
- install or update packages;
- import Gerbil modules dynamically;
- discover a global Module registry;
- evaluate the semantic =imports= closure;
- invoke build, test, or distribution tooling.

A missing or phase-invalid binding produces the structured,
source-mapped expansion diagnostic defined by the macro evidence RFC.

* wendao-episteme and poo-flow ownership

=wendao-episteme= owns its domain Module identity, profiles, Contracts,
exports, source integration instructions, tests, and publication
choices.

=poo-flow-core= owns generic POO Flow Module, composition, authority,
observability, and runtime boundary contracts.

The POO Flow parent may pin source and consume the generic core
interface.  It does not become the owner of
=wendao-episteme= build, test, integration, distribution, or release
policy.

The final downstream application owns final profile selection and
composition policy.

* Failure ownership

Failures remain with their exact plane:

| Failure                                           | Owner                                  |
|--------------------------------------------------+----------------------------------------|
| missing or wrong Git revision                    | source pin and source owner            |
| missing actual Gerbil package                    | package declaration or environment     |
| unresolved Scheme binding                        | downstream Gerbil source integration   |
| invalid =use-module= syntax or phase             | thin macro projection                  |
| incomplete semantic Module =imports= evidence    | Module evaluator                       |
| child build, test, or publication failure        | child repository owner                 |

No layer silently retries by crossing into another plane.

* Implementation admission checklist

- [ ] Keep Git pin, =gerbil.pkg=, Gerbil bindings, and POO Module
  =imports= as distinct contracts.
- [ ] Treat a Git submodule as source and revision evidence only.
- [ ] Require an actual package declaration before using =gerbil.pkg=
  package semantics.
- [ ] Keep package management separate from semantic Module closure.
- [ ] Use normal Gerbil import/export for binding visibility.
- [ ] Complete downstream binding integration before =use-module=
  expansion.
- [ ] Keep initial integration as a source-owner action, not an
  =initial= syntax form or runtime phase.
- [ ] Keep =use-module= free of discovery, installation, registry,
  import traversal, build, test, and runtime effects.
- [ ] Keep the Module =imports= slot semantic only.
- [ ] Preserve =wendao-episteme= ownership of its domain source, tests,
  build, distribution, and release decisions.
- [ ] Preserve =poo-flow-core= ownership of generic semantic contracts.
- [ ] Preserve final application ownership of profile selection.
- [ ] Produce source-mapped diagnostics for missing bindings.
- [ ] Add no global Module registry or active-evidence projection into
  =gerbil.pkg=.
