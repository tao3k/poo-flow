#+title: Contribution test ownership
#+date: 2026-09-12

* Scope and public syntax
A contribution repository owns its test cases. =:std/test= owns suite and
assertion primitives, while =:clan/testing= owns discovery and execution.
POO Flow does not add a test declaration macro or another testing framework.
Its package entry derives the ASP POO discovery Profile only to exclude the
independent top-level =lambda-episteme= package from clan's recursive result.
No POO Flow scanner or explicit test-file list is introduced.
Each test retains ASP's default 1024 MiB process budget unless its own scenario
derives a larger memory Profile. Legacy aggregate suites are split into their
clan-discoverable =*-test.ss= owners instead of raising memory for an aggregate.

#+begin_src scheme
;; t/sdlc/unit/profile-test.ss
(import :std/test)
(export profile-test)
(def profile-test
  (test-suite "SDLC profile contract"
    (test-case "native profile" ...)))
#+end_src

The =*-test.ss= basename and exported suite binding are identical, following
the clan/testing convention directly. Memory, performance, debug and trace
profiles are POO extensions supplied by =asp-gerbil-scheme=; POO Flow only
selects or derives those profiles for its scenarios.

* Layout
=t/<module_name>/<lane>/*-test.ss= is required. Lanes are =unit=, =source=,
=user-interface= and =integration=. Optional source checks whose dependencies
are outside the default package environment use =*-check.ss= and are therefore
not part of clan/testing's automatic unit-test set.
Non-executable qualification receipts can remain in =t/qualification/=.

There is no second filesystem catalog, layout validator, lane runner or gxtest
subprocess API.

Fixture code that intentionally violates this contract belongs outside the
contribution's runnable test tree. POO Flow keeps its negative harness fixtures
under its own fixture tree. This work migrates the contribution-related tests;
it does not rewrite the entire existing POO Flow test suite.

* Entrypoint

Each package uses the upstream-style =unit-tests.ss= entrypoint. Optional
source capabilities must not use the ordinary =*-test.ss= suffix unless their
dependencies are part of that package's default test environment.

* Qualification
Tests demonstrate contribution behavior through ordinary std/test suites. No
parent runtime or complete NASA assurance claim is inferred from them.
