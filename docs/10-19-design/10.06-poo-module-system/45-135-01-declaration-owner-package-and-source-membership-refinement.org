* Discovered logical defects

The accepted manifest separates:

- =ResolvedSourceIdentity(package_id, revision, source_tree_digest, ...)=; and
- =DeclarationIdentity(name, owner_path, owner_source_digest, ...)=.

There is no relation from a declaration to its owning package. Consequently,
two different enterprise responsibility assignments can have the same
unbound manifest projection.

Adding only =owner_package_id= is still insufficient. It proves that a package
name was selected, but it does not prove that =owner_path= and
=owner_source_digest= are members of that package's =source_tree_digest=.

These are evidence and accountability defects, not serialization details.

The compiled theorems establish:

- =unboundProjectionCannotDistinguishOwnerSwap=: swapping the package
  responsibility for two declarations is invisible after the current owner
  package field is erased;
- =boundProjectionDistinguishesOwnerSwap=: the corrected bound declarations
  distinguish those assignments;
- =foreignOwnerRejected=: a declaration owner outside the resolved package set
  violates ownership closure;
- =conflictingOwnersRejected=: the same declaration name cannot have two
  different package owners in one functional assignment;
- =packageBindingAloneDoesNotProveSourceMembership=: package binding can be
  closed while source-tree membership is false;
- =evidenceClosedProvidesResolvedOwner= and
  =evidenceClosedProvidesSourceMembership=: the strengthened closure entails
  both required witnesses.

* Mathematical model

Let =P= be resolved packages, =D= declaration identities, and =u= the package
owner assignment.

#+begin_src typst
$ u: D arrow P $

$ "erase-owner"(d, u(d)) = d $

$ A != "swap-owner"(A) $

$ "erase-owner"(A) =
  "erase-owner"("swap-owner"(A)) $

$ "OwnershipClosed"(P, D, u) =
  forall d in D, u(d) in P $

$ "OwnerFunctional"(D, u) =
  forall d_1, d_2 in D,
    "name"(d_1) = "name"(d_2)
    implies u(d_1) = u(d_2) $

$ "SourceMember"(p, d) =
  "includes"(
    "source-tree-digest"(p),
    "owner-path"(d),
    "owner-source-digest"(d)
  ) $

$ "EvidenceClosed"(P, D, u) =
  "OwnershipClosed"(P, D, u)
  and "OwnerFunctional"(D, u)
  and forall d in D, "SourceMember"(u(d), d) $
#+end_src

The current schema cannot state =u=. A schema containing =u= but no
=SourceMember= witness still cannot establish =EvidenceClosed=.

* Refined bundle contract

** Declaration identity

=DeclarationIdentity= must add:

#+begin_src text
owner_package_id : PackageId
#+end_src

The field participates in canonical serialization and bundle identity.

** Source membership witness

For every declaration the bundle must carry or deterministically derive:

#+begin_src text
SourceMembershipWitness
  package_id
  owner_path
  owner_source_digest
  source_tree_digest
  witness_scheme
  witness_payload_digest
#+end_src

The witness scheme may be:

- a Merkle inclusion proof owned by the resolved source manifest;
- a package-manager source manifest whose canonical digest is already bound by
  =ResolvedSourceIdentity=; or
- a local-workspace active-source manifest from which the recorded tree digest
  is recomputed.

A package name, Git revision, or aggregate digest without an inclusion relation
is not a membership witness.

** Required validation

Bundle construction and verification must reject:

- a declaration without =owner_package_id=;
- an owner package absent from =resolved_sources=;
- the same declaration name assigned to different packages;
- a witness whose package, path, source digest, or tree digest differs from the
  declaration and resolved source identities;
- an unsupported witness scheme;
- a missing or invalid membership proof.
