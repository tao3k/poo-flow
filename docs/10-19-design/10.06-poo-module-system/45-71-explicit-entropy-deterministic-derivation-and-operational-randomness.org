#+title: Explicit Entropy, Deterministic Derivation, and Operational Randomness
#+startup: overview

* Status

This RFC records the accepted treatment of deterministic derivation, semantic
entropy, and operational randomness in POO Flow.

It extends explicit temporal observations and deterministic replay. It forbids
hidden random-number generation inside pure POO fixed-point evaluation.

* Typst formalization: explicit entropy and deterministic derivation

The complete semantic cut determines the canonical result identity.  A
variation source that changes semantic output must enter the cut as an
immutable entropy identity with provenance; hidden live randomness is not
admitted during pure derivation.

#+begin_src typst
#let derivation-id(cut, entropy, purpose) = (
  cut,
  entropy,
  purpose,
)

$ evaluate(cut, entropy, purpose)
  = replay(cut, entropy, purpose) $

$ result-id(evaluate(cut, entropy, purpose))
  = derivation-id(cut, entropy, purpose) $

$ changes-semantic-result(source)
  ==> explicit-entropy-identity(source, cut) $

$ missing(required-entropy)
  ==> suspend(derivation)
  and not read-live-randomness() $
#+end_src

Purpose identity provides domain separation.  Operational randomness may
influence non-semantic choices such as retry jitter or worker selection, but it
cannot change semantic results or their cache keys.

#+begin_src typst
$ cut-a != cut-b
  ==> derivation-id(cut-a, entropy, purpose)
  != derivation-id(cut-b, entropy, purpose) $

$ entropy-a != entropy-b
  ==> derivation-id(cut, entropy-a, purpose)
  != derivation-id(cut, entropy-b, purpose) $

$ purpose-a != purpose-b
  ==> derivation-id(cut, entropy, purpose-a)
  != derivation-id(cut, entropy, purpose-b) $

$ operational-randomness(r)
  ==> not affects-semantic-result(r)
  and not affects-semantic-cache-key(r) $

$ observed-digest != expected-digest
  ==> quarantine(determinism-conflict) $
#+end_src

* Central decision

The same complete semantic cut must produce the same canonical result identity.

If a result is expected to vary, the source of variation must appear as an
explicit identity in that semantic cut.

Three distinct roles remain separate:

1. deterministic derivation;
2. semantic entropy;
3. operational randomness.

* POO semantic ownership

Entropy and derivation policy are ordinary higher-order POO objects. Native
prototype composition defines:

- deterministic derivation domains;
- entropy source admission;
- purpose separation;
- consumption policy;
- confidentiality projections;
- replay policy;
- operational-choice constraints.

The public extension interface remains POO-native. Randomness, seed, fallback,
and sampling must not become an unstructured macro token DSL.

Pure policy may consume an admitted immutable entropy observation. It must not
call an operating-system RNG, wall clock, process identifier, or scheduler
source implicitly.

* Deterministic derivation

Deterministic derivation supports:

- content identity;
- stable cohort assignment;
- cache keys;
- partition placement;
- idempotency identity;
- reproducible identifiers derived from semantic inputs.

Derivation uses:

- canonical input serialization;
- explicit purpose and domain separation;
- stable algorithm identity;
- deterministic hashing or another admitted pure derivation;
- exact input identity disclosure.

It is not semantic entropy.

For example, stable cohort assignment derives from:

#+begin_example
domain: rollout-assignment
+ rollout identity
+ admitted subject projection
+ assignment revision
#+end_example

The same admitted inputs produce the same assignment.

* Semantic entropy

Semantic entropy is used only when the domain meaning requires an unpredictable
or externally allocated choice.

Examples may include:

- a lottery;
- a security nonce;
- an explicitly randomized experiment;
- another policy that declares entropy as a semantic input.

Entropy enters pure evaluation as an immutable =EntropyObservation= containing:

- entropy source identity;
- purpose and domain identity;
- observation identity;
- allocation counter or identity;
- entropy commitment;
- acquisition or attestation receipt;
- confidentiality domain;
- consumption policy identity;
- replay policy identity;
- observation schema identity.

The raw entropy value may remain in a restricted projection. Public evidence
uses only the admitted commitment or redacted projection.

* Operational randomness

Operational randomness may influence:

- equivalent worker selection;
- queue tie-breaking;
- work stealing;
- replica read selection;
- non-semantic load balancing.

It may change placement, timing, and execution order.

It must not change:

- canonical pure result;
- semantic cache identity;
- graph-wide proof;
- slot-resolution result;
- SCC stabilization result;
- compatibility admission.

Different outputs for the same complete semantic cut produce determinism-
violation evidence.

* Canonicalization

Canonicalization is part of fixed-point correctness.

The implementation must ensure:

- unordered maps and sets are ordered by canonical identity before hashing or
  folding;
- graph traversal order does not determine meaning;
- SCC result does not depend on node visitation order;
- equal-priority resolution is permutation-invariant or fails closed;
- concurrent completion order does not select a winner;
- hash-table implementation order does not enter semantic identity;
- process addresses, thread identifiers, worker identities, and host names do
  not enter pure results unless explicitly declared as semantic inputs.

A convenient iteration order is not canonical evidence.

* Identity roles and UUIDs

Semantic identities prefer content identity or canonical derivation.

Execution identities such as attempts, receipts, leases, and reservations may
use opaque authority-issued UUIDs.

An opaque UUID:

- does not change semantic meaning;
- is not a causal clock;
- is not ordered lexically to infer event order;
- does not replace a logical version or fencing token.

If a generated identity affects pure behavior, its allocation observation
becomes an explicit semantic input.

* Entropy allocation and consumption

Entropy consumption is affine or linear according to its policy.

Every use binds:

- observation identity;
- purpose and domain;
- consumer demand identity;
- allocation counter or version;
- consumption receipt identity.

Accidental reuse across different semantic purposes is rejected.

Historical replay may reuse the recorded observation to reproduce the same
decision. A new live decision requires a new admitted allocation unless policy
explicitly defines deterministic reuse.

Concurrent allocation uses an authoritative version, counter, or receipt. A
worker must not duplicate an entropy allocation while retrying or delegating a
demand.

* Secret entropy

Raw secret entropy must not appear in:

- public cache keys;
- unrestricted traces;
- explanation receipts;
- low-authority proof projections;
- distributed work envelopes outside its confidentiality domain.

Evidence may retain:

- entropy commitment;
- source and purpose identities;
- consumption receipt;
- controlled reveal evidence when required.

High-authority entropy must not leak through cache hits, timing, descriptors,
or observability expansion.

* Cache identity

An entropy-dependent semantic result includes
=EntropyObservationIdentity= in its semantic cache key.

The raw secret value does not need to appear in a public key projection.

Different entropy observations must not reuse one proof accidentally.

Historical replay uses the recorded observation identity.

Operational scheduling randomness never enters the semantic cache key.

* Distributed evaluation

A remote demand requiring semantic entropy receives only the admitted entropy
projection for that worker confidentiality domain.

The worker returns an =EntropyUseReceipt= with its pure result.

Retry, worker loss, and lease expiry must not allocate new entropy silently.
The coordinator either reuses the same admitted observation for the same
historical decision or creates a new semantic proposal with a new allocation.

Worker completion order and placement remain operational and cannot select the
canonical result.

* Observability sampling

Sampling is operational when it affects only observability cost and does not
contribute evidence to a semantic or governance decision.

If sampled observations influence rollout, compatibility, admission, or
governance:

- sampling policy identity enters the evidence cut;
- entropy allocation enters the evidence cut;
- coverage and confidence evidence are explicit;
- omitted samples are not interpreted as absence of failures.

A sampled evidence set must not claim full observation coverage.

* Entropy suspension and recovery

Unavailable, untrusted, exhausted, or incorrectly scoped entropy produces
=EntropySuspension=.

Continuable recovery roles may include:

- acquire a policy-admitted entropy observation;
- wait for authoritative allocation;
- cancel the decision;
- form a new deterministic-fallback proposal when business policy allows it.

A fallback that changes entropy semantics creates a new proposal. It must not
rewrite the suspended proposal in place.

The runtime must not substitute time, process identifiers, memory addresses, or
low-quality implicit pseudo-randomness.

* Determinism violations

A determinism violation records:

- complete semantic cut identity;
- conflicting result identities;
- evaluator and worker identities;
- canonicalization policy identity;
- dependency manifests;
- entropy observation identity when present;
- execution-order evidence;
- comparison receipt.

Last-write-wins, fastest-worker-wins, and traversal-order selection are not
valid recovery.

Recovery uses authoritative reevaluation or a new explicitly admitted semantic
proposal.

* Failure taxonomy

The implementation must distinguish at least:

- hidden RNG use attempted;
- derivation domain missing;
- canonical serialization mismatch;
- unordered traversal affected output;
- entropy source rejected;
- entropy unavailable;
- entropy allocation exhausted;
- purpose or domain mismatch;
- duplicate entropy consumption;
- secret entropy disclosure denied;
- entropy-dependent cache-key mismatch;
- sampling coverage incomplete;
- operational randomness affected semantic output;
- same-cut result divergence;
- fallback changed semantics;
- entropy receipt incomplete.

* Required invariants

1. Same complete semantic cut produces the same result identity.
2. Deterministic derivation, semantic entropy, and operational randomness remain
   distinct.
3. Pure evaluation performs no hidden RNG call.
4. Semantic entropy enters as an explicit immutable observation.
5. Operational randomness never changes canonical pure results.
6. Canonicalization removes traversal and completion-order dependence.
7. Opaque UUIDs do not provide semantic or causal ordering.
8. Entropy consumption is purpose-bound and duplicate use is detected.
9. Raw secret entropy remains disclosure-scoped.
10. Entropy-dependent cache keys include observation identity.
11. Retry and delegation do not silently allocate new entropy.
12. Evidence-affecting sampling declares policy, entropy, and coverage.
13. Fallback that changes semantics creates a new proposal.
14. Divergent same-cut results fail closed.
15. Public entropy policy extension remains POO-native.
