#+title: Gerbil POO Native Projection Engineering Standard
#+startup: overview

* Status

- Status :: Normative V1 engineering standard
- Scope :: POO Flow object construction, presentation, projection, conversion, and persistence boundaries
- Source evidence :: Gerbil =:clan/poo= implementations in =.data/gerbil-poo/object.ss=, =mop.ss=, =io.ss=, =proto.ss=, and =.data/gerbil-persist/persist.ss=, =content-addressing.ss=
- Lean model :: =PooFlowProof.PooC4.NativeProjectionPipeline=

* Decision

POO Flow SHALL compose the public object model from Gerbil =:clan/poo=
primitives. Business modules SHALL NOT wrap =$constant-slot-spec= or
=$computed-slot-spec=, manufacture a parallel slot protocol, or maintain an
eager summary beside a lazy presentation with the same responsibility.

The =:clan/poo= layers are:

1. =define-type= and =.defgeneric= own stable domain types and method families.
2. =.o=, =.def=, =.mix=, and =.+= own genuine prototype declaration and override.
3. =object<-fun= owns a large demand-driven projection when keys are data.
4. =object<-alist= and =object<-hash= are boundary adapters, not the public DSL.
5. =json<-=, =<-json=, =string<-=, =<-string=, =bytes<-=, and =<-bytes= belong
   to Type-owned I/O or persistence boundaries.

* Lessons from gerbil-poo

** Native object cache

=object<-fun= converts a key projection into the =:clan/poo= internal =$thunk-slot-spec=
entries. =.ref= stores the result in the object's instance hash. A POO Flow
presentation therefore needs neither a custom computed-slot wrapper nor a
second per-slot cache.

Shared intermediate projections MAY use Gerbil =delay=/=force=. The promise
must be local to one returned object and pure with respect to the object's
semantic inputs. Live resources, deadlines, capabilities, and mutable global
state MUST NOT enter that promise.

** Prototype composition

=.mix= and =.+= are used only when inheritance or override is semantically
present. Splitting one flat slot set into artificial parents adds C4
instantiation work and is forbidden. Large data-keyed projections use one
=object<-fun= object; small stable domain prototypes use =.o= or =define-type=.

** Type-owned conversion pipelines

=gerbil-poo/io.ss= defines =methods.string<-json= by composing the existing
JSON methods:

#+begin_src scheme
(define-type (methods.string<-json @ [] .json<- .<-json)
  .string<-: (compose string<-json .json<-)
  .<-string: (compose .<-json json<-string))
#+end_src

This is the required pattern: a new representation reuses established Type
methods. It does not copy JSON traversal into a presentation or persistence
module. =TS= and =TJ= are typed read constructors at this outer conversion
boundary; they are not substitutes for native POO values inside the runtime.

* Lessons from gerbil-persist

=Persistent.=, =PersistentData=, and =PersistentActivity= keep Type methods,
transaction state, restoration, and storage conversion separate. POO Flow
adopts the same ownership rules:

- a presentation projects inspectable semantic data and performs no storage;
- a Type describes validation and reversible conversion;
- a persistence owner supplies transaction context and recovery;
- content identity is derived through the Type's byte projection;
- caches retain already-derived values but never redefine their semantics.

* Algorithm and complexity rules

| Operation                 | Required form                                      | Complexity target                              |
|---------------------------+----------------------------------------------------+------------------------------------------------|
| Repeated slot read | native object cache or one local promise | first evaluation plus O(1) cached lookup |
| Batch row projection | one traversal with precomputed field/index state | O(rows + emitted values) |
| Prototype override | =.+= or =.mix= only for real inheritance | composition outside the hot loop |
| Representation conversion | Type method composed from existing methods | one conversion pass per boundary |
| Materialization | =.alist=/JSON/string only at the outer boundary | proportional to demanded output |

Linear =assq=/=member= scans inside a repeated key or row loop require an
explicit bounded-size argument or a benchmark. A constant-factor improvement
does not justify a new object, cache, scheduler, or conversion protocol.

* Presentation V1 contract

The loop-engine-only and workflow-CI-focused presentations SHALL:

- expose one public constructor each;
- use =object<-fun= for the large data-keyed slot vocabulary;
- use Gerbil promises only for intermediate values shared by several slots;
- preserve =.slot?=, =.all-slots=, and =.ref= observations;
- keep runtime execution false and perform no persistence or serialization;
- materialize JSON/string only through a future Type-owned outer adapter.

The mixed facade MAY use =object<-alist= while it remains an eager outer
boundary. It MUST NOT be described as a reusable domain type until a real
=define-type= contract and round-trip conversion Scenario exist.

* Executable evidence

Every optimization changes a fixed Scenario, not its sample count or hard
limit. Admission requires semantic checks plus P50, P95, maximum, input shape,
and memory evidence. A green P50 with a red P95 remains a red gate and is
reported as such.

The =user-interface-presentation-batch-projection= Scenario fixes 20 samples
and eight real loop-engine declarations. The first native =object<-fun=
implementation recorded P50 =2.670049 ms= and P95 =23.614168 ms= under the
existing 100 ms ceiling. The preceding artificial =.mix= split recorded P50
=11.957884 ms= and P95 =115.020991 ms=, proving that inheritance without an
override relation is harmful here.

The =workflow-presentation-native-projection= Scenario fixes 20 samples and a
real Funflow CI/CD config with three manifests and one handoff ABI. The eager
aggregate projection recorded P50 =58.512927 ms= and P95 =156.503915 ms=. The
source-owned demand projection recorded P50 =1.682997 ms= and P95 =20.166874
ms= under the unchanged 100 ms ceiling. This proves that laziness must begin
at the workflow owner; a lazy UI slot around an eager aggregate is not a lazy
pipeline.

* Lean correspondence

The Lean model proves three implementation-independent facts:

- composing conversion stages is associative;
- a sound cache returns the same observation as the uncached projection;
- composing JSON and string round trips preserves the domain value.

The proof does not claim a runtime cost bound. Timing and allocation remain
Scenario obligations, while Lean fixes the semantic conditions under which a
cache or composed conversion may be admitted.

* Audit gates

New code fails review when it:

- imports =$constant-slot-spec= or =$computed-slot-spec= outside a =:clan/poo=
  compatibility, qualification, method-combination, or low-level object owner;
- exports =/summary= or =/fast= beside a constructor with the same contract;
- uses =make-object= where =.o=, =define-type=, or =object<-fun= expresses the
  same public semantics;
- serializes a native POO object inside a hot semantic loop;
- changes benchmark samples, input size, or threshold to obtain green status;
- introduces a cache without an identity scope and semantic-equivalence test.
