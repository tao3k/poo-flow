* Problem

RFC 54 proves that a receipt is accepted only when its issued validation
context equals the current authority-owned context.  Exact equality rejects a
receipt while the current context differs, but equality alone does not prevent
the authority state from returning to an earlier context value.

The sequence:

#+begin_src typst
#align(center)[
  $
    C_0 arrow.r C_1 arrow.r C_0
  $
]
#+end_src

causes a receipt issued at the first =C_0= to become acceptable again at the
last =C_0=.  For policy and revocation state, this ABA rollback cannot be
classified as harmless idempotent replay.

Adjacent control-plane RFCs already use monotone generations to prevent ABA.
This RFC binds that principle directly to =ReceiptValidationContext= and the
receipt-DAG admission lineage.

* Valid context transition

For two contexts on one authority path:

#+begin_src typst
#align(center)[
  $
    "ValidTransition"(C_i, C_j)
      "iff"
    A(C_i) = A(C_j)
      and
    g(C_i) < g(C_j)
  $
]
#+end_src

The authority identity is stable within one lineage.  The generation strictly
increases for every published successor context.  A generation is never
reused, even when policy, authorization, and revocation snapshots later become
semantically similar to an earlier state.

Wall-clock time is not part of the proof.  The generation is an
authority-owned anti-ABA fence.

* Lineage model

An authority context lineage is a function from an authority-owned position to
a complete validation context:

#+begin_src typst
#align(center)[
  $
    L : NN arrow.r C
  $
]

#align(center)[
  $
    i < j
      "implies"
    g(L(i)) < g(L(j))
      "implies"
    L(i) != L(j)
  $
]
#+end_src

Therefore a receipt accepted at =L(i)= is rejected at every later =L(j)=:

#+begin_src typst
#align(center)[
  $
    i < j
      and
    "AcceptedAt"(r, L(i))
      "implies"
    not "AcceptedAt"(r, L(j))
  $
]
#+end_src

This theorem is stronger than comparing a receipt with one current context.  It
proves that no later position in the authority lineage can reuse an earlier
context value.

* Transition locality does not prove publication uniqueness

Strict advancement on each individual transition is still insufficient:

#+begin_src typst
#align(center)[
  $
    "ValidTransition"(C_0, C_l)
      and
    "ValidTransition"(C_0, C_r)
      and
    g(C_l) = g(C_r)
      and
    C_l != C_r
  $
]
#+end_src

Both successor transitions advance from the same generation, yet they publish
different policy, authorization, or revocation snapshots at one next
generation.  This is a same-generation fork.

Publication must therefore be single-valued for each authority and generation:

#+begin_src typst
#align(center)[
  $
    "Published"(C_l)
      and
    "Published"(C_r)
      and
    A(C_l) = A(C_r)
      and
    g(C_l) = g(C_r)
      "implies"
    C_l = C_r
  $
]
#+end_src

The lineage function plus strict generation growth establishes this fork-free
publication rule.  Transition-local validation alone does not.

* Local lineage validity does not prove cross-view consistency

Two verifiers can each receive a locally monotone lineage and still observe
different contexts for one authority and generation:

#+begin_src typst
#align(center)[
  $
    "LocalValid"(L_l)
      and
    "LocalValid"(L_r)
      and
    A(L_l(1)) = A(L_r(1))
      and
    g(L_l(1)) = g(L_r(1))
      and
    L_l(1) != L_r(1)
  $
]
#+end_src

Local lineage validity is therefore not a proof of global publication
consistency.  Each admitted context must carry membership evidence for the same
authority-owned publication domain =D=:

#+begin_src typst
#align(center)[
  $
    "Member"(D, C_l)
      and
    "Member"(D, C_r)
      and
    A(C_l) = A(C_r)
      and
    g(C_l) = g(C_r)
      "implies"
    C_l = C_r
  $
]
#+end_src

The publication domain is a semantic interface.  This RFC does not select a
database, transparency log, or consensus mechanism.  An implementation must
provide evidence that both contexts were checked against the same
authority-owned fork-free domain.

* Lean-discovered countermodel

The Lean model constructs two different contexts =C_0= and =C_1= and a receipt
issued at =C_0=.  Exact equality establishes:

#+begin_src typst
#align(center)[
  $
    "AcceptedAt"(r, C_0)
      and
    not "AcceptedAt"(r, C_1)
      and
    "AcceptedAt"(r, C_0)
  $
]
#+end_src

The first and last propositions are identical.  Without a lineage invariant,
the validator cannot distinguish initial use from rollback replay.

* Ownership boundary

- The acceptance authority owns the lineage position and generation.
- Publication is single-valued for each authority identity and generation.
- Every verifier checks publication membership against the same
  authority-owned fork-free domain.
- A context successor preserves the authority identity and strictly advances
  the generation.
- Policy, authorization, or revocation state publication occurs inside a new
  context generation.
- Audit JSON records an authority-issued context and generation; it does not
  advance or select the lineage.
- The receipt-DAG verifier consumes the authority's current lineage position
  and never restores an earlier context from receipt bytes.
- Separate authority paths remain separate lineages and are not unioned.

* State machine

#+begin_src mermaid
stateDiagram-v2
  [*] --> ContextZero: authority publishes generation g
  ContextZero --> ReceiptAccepted: receipt issued at C0
  ReceiptAccepted --> ContextOne: authority publishes generation g plus 1
  ContextOne --> OldReceiptRejected: exact context and generation differ
  ContextOne --> ForkDetected: same generation carries different context
  ForkDetected --> SharedDomainRequired: local views disagree
  SharedDomainRequired --> RevalidationRequired: common membership evidence missing
  ContextOne --> RollbackRejected: attempted C0 generation reuse
  RollbackRejected --> ContextTwo: publish a new strictly greater generation
  ContextTwo --> OldReceiptRejected: lineage position is later than issuance
  RevalidationRequired --> [*]: authority lineage repair required
  OldReceiptRejected --> [*]: revalidation required
#+end_src

* Architectural consequence

RFC 54 exact equality remains necessary, but it is not a complete rollback
defense.  Receipt admission additionally relies on an authority context lineage
whose generation is strictly monotone and never reused.

The resulting rule is:

#+begin_src typst
#align(center)[
  $
    "Admit"(r, L(j))
      "requires"
    "issued"(r) = L(j)
      and
    "LineageValid"(L)
  $
]
#+end_src

This closes rollback replay without wall-clock freshness heuristics and without
allowing receipt transport to control authority state.
