#+title: Submodule Observation-Budget Delegation
#+startup: overview

* Status

Accepted design.

This document refines the convergence-observation budget defined by
[[file:45-20-fixed-point-convergence-observation-budget.org][45-20]] for nested
POO modules.  It defines delegation, consumption, reconciliation, and replay.
It does not introduce a scheduler, a shared mutable counter, or a second
fixed-point evaluator.

* Decision

An observation budget is an immutable POO Capability.  A parent delegates
attenuated budget Capabilities to child module instances while retaining an
explicit parent allocation.

For every delegation generation:

#+begin_example
sum(child allocations) + parent retained allocation
  <= parent granted semantic units
#+end_example

The inequality is a conservation rule over semantic observation units.  It is
not a wall-clock limit and it is not derived from evaluation order.

* Delegation identity

Each delegated child budget has a canonical causal identity derived from:

- the parent budget identity;
- the child's canonical causal instance identity;
- the delegation generation;
- the contributing convergence-policy identity.

Runtime scheduling order, module path spelling, object address, and the time at
which a child is first demanded are excluded from this identity.

A child receives an independent immutable Capability.  It may consume its own
allocation, attenuate it, or delegate a bounded part of it to descendants.  It
cannot widen the grant.  A sibling cannot borrow, mutate, or replenish another
sibling's allocation.

* Consumption evidence

Every semantic observation consumes one unit from the allocation that
authorizes that observation and produces an immutable consumption receipt.
The receipt binds:

- the delegated budget identity and generation;
- the consuming module-instance identity;
- the semantic observation identity;
- the predecessor and successor allocation state;
- causal provenance.

Receipts form the evidence chain used to establish remaining allocation.
There is no hidden mutable balance, process-global counter, scheduler-owned
ledger, or ambient budget registry.

* No implicit return or borrowing

Unused child units do not automatically return to the parent.  Automatic
return would make the available budget depend on termination timing,
continuation scheduling, or demand order.

Cancellation also does not transfer the remaining allocation.  It records the
child's terminal state while preserving the allocation and consumption
evidence of that generation.

Redistribution requires explicit reconciliation authority.  Reconciliation:

1. revalidates the parent grant and all relevant delegation and consumption
   receipts;
2. closes the selected allocations for the current generation;
3. creates a successor delegation generation;
4. issues a new conserved allocation topology.

It never mutates an existing Capability or receipt.

* Exhaustion and extension

Child exhaustion is local to the child's delegated allocation.  It does not
consume a sibling allocation and does not silently draw from the parent's
retained allocation.

The exhausted child produces the convergence condition defined by 45-20,
carrying its allocation identity, generation, observation evidence, and causal
provenance.  An authorized parent policy may then decline, terminate, or
explicitly reconcile and extend through a successor generation.

Extension authority is separate from the existing budget Capability.
Possession of a consumption receipt, an unused remainder, or a child
continuation does not grant authority to issue more semantic units.

* Runtime boundary

The budget graph is evaluated as ordinary POO data and Capability refinement.
The runtime may execute demands and preserve receipts, but it does not decide
allocation policy.  The harness may validate conservation and replay evidence,
but it is not a budget provider.

No new scheduler, local fixed-point implementation, promise system, or
provider-order fallback is introduced here.  Native =gerbil-poo= demand-lazy
evaluation remains the sole POO evaluation mechanism.

* Replay

Replay reconstructs the historical allocation topology from immutable grants,
delegations, consumption receipts, reconciliation receipts, and successor
generations.

Replay must not:

- ask a live parent policy for a replacement decision;
- reallocate unused units implicitly;
- depend on the order in which sibling receipts are loaded;
- convert historical authority into authority for a live extension;
- resume captured continuations.

The replay result is valid only when every generation satisfies conservation
and every consumption receipt advances the allocation state it names.

* Implementation checklist

- [ ] Represent parent and delegated observation budgets as POO Capabilities.
- [ ] Derive child budget identity from canonical causal inputs only.
- [ ] Enforce conservation when constructing a delegation generation.
- [ ] Emit immutable consumption receipts for semantic observations.
- [ ] Keep sibling and parent-retained allocations isolated.
- [ ] Prevent implicit return, borrowing, replenishment, and cancellation
      transfer.
- [ ] Require explicit authority and receipt revalidation for reconciliation.
- [ ] Create a successor generation for every redistribution or extension.
- [ ] Preserve local exhaustion as a continuable convergence condition.
- [ ] Replay allocation topology without live policy calls or continuations.
- [ ] Test nested delegation, sibling isolation, exhaustion, cancellation,
      reconciliation, stale receipts, widening attempts, and replay.
- [ ] Verify that Mermaid edges describe the relevant state or transition
      without mechanical label prefixes.
