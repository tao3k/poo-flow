#+title: Observation Event Prototype Family and POO Dispatch
#+author: POO Flow
#+language: en

* Status

Accepted.

* Context

Authoritative semantic observation must remain open to new evidence domains
without turning the module system into a central tagged-record registry.
Cycle, budget, cache, capability, macro-expansion, and runtime-receipt evidence
share identity and causal requirements, but each domain has different facts and
Contracts.

The project already defines the semantic relation:

#+begin_example
Type
  = identity
  + pure classification evidence

Contract
  = Type prototype refinement
  + contextual obligations

ObjectType
  = Type refinement
  + responsibility-slot contracts

ModuleType
  = ObjectType(identity, imports, capabilities, profiles)
#+end_example

Observation is not Module composition.  It therefore must not enlarge
=ModuleType= or its four responsibility slots.

* Decision

=ObservationEvent= is an independent =ObjectType= prototype family.

The base prototype owns the common immutable evidence responsibilities:

- observed subject identity;
- evaluation generation;
- causal evidence identities;
- Contract-validated facts;
- provenance evidence;
- disclosure classification.

Disclosure classification describes the visibility requirement of evidence.
It does not contain, create, delegate, or grant a capability.

Domain observations refine the base prototype with domain-specific
responsibility-slot Contracts.  Recovery policy interpretation uses native POO
dispatch over prototype lineage.  It does not use a central kind switch or tag
registry.

* Base responsibility contracts

** Observed subject

The observed subject MUST be identified by semantic identity.  A pointer,
printed object, process-local address, or presentation row is not sufficient.

** Generation

Generation MUST identify the evaluation generation in which the facts became
valid.  A successor recovery action produces evidence in a successor
generation; it does not mutate the originating event.

** Causal evidence

Causal edges MUST reference authoritative evidence identities.  They MUST NOT
reference presentation rows, telemetry records, raw stack strings, or runtime
continuations.

** Facts

Facts MUST be immutable and validated by the domain observation Contract.
Facts describe what was observed.  They do not encode the recovery policy that
will interpret them.

** Provenance

Provenance MUST identify the semantic producer, phase, provider, and derivation
or runtime receipt required to justify the facts.

** Disclosure classification

Disclosure classification MUST support capability-scoped redaction and
audience-safe projection.  It is descriptive evidence only and MUST NOT be
treated as authority.

* Domain refinements

A domain observation refinement:

- inherits base evidence identity and causal responsibilities;
- introduces only facts unique to its evidence domain;
- refines Contracts without weakening inherited obligations;
- participates in POO dispatch through its prototype lineage;
- remains valid without doctor, CLI, telemetry, or rendering consumers.

The initial semantic families are:

- =CycleObservation= for SCC, path, and recursive dependency facts;
- =BudgetObservation= for typed limit and consumption facts;
- =CacheObservation= for semantic key, generation, hit, and invalidation facts;
- =CapabilityObservation= for requested, visible, delegated, and denied
  authority facts;
- =ExpansionObservation= for phase-aware macro and provider facts;
- =RuntimeReceiptObservation= for effect identity, outcome, and receipt facts.

This list is extensible through prototype refinement.  It is not a closed
enumeration.

* Dispatch governance

Recovery policies MUST dispatch through native POO prototype relations or named
POO-native dispatch helpers.

They MUST NOT:

- use an expanding central =cond=, =case=, or tag-to-handler registry as the
  ordinary extension mechanism;
- require modification of the base observation owner for every new domain;
- infer authority from the observation prototype;
- execute the selected recovery action;
- receive fields hidden by disclosure policy.

A general policy may handle =ObservationEvent=.  A more specific policy may
refine handling for a domain prototype.  The normal POO lineage determines the
applicable behavior.

* Module boundary

=ObservationEvent= MUST NOT inherit =ModuleType=.

It has no Module =imports=, =capabilities=, or =profiles= responsibilities.
A Module evaluation may emit an observation, but the observation is evidence
about that evaluation, not another Module.

No observation prototype may add a fifth responsibility slot to =ModuleType=.

* Conformance checklist

- [X] =ObservationEvent= is an independent =ObjectType= refinement.
- [X] =ModuleType= remains exactly identity, imports, capabilities, and
  profiles.
- [X] Common evidence responsibilities live in the base observation prototype.
- [X] Domain evidence uses Contract-preserving prototype refinement.
- [X] Recovery interpretation uses POO dispatch.
- [X] The observation hierarchy is open without a central tag registry.
- [X] Disclosure classification does not grant authority.
- [X] Events remain immutable across recovery generations.
- [ ] The concrete semantic evidence source owner has been resolved through
  parser-owned owner discovery.
- [ ] Implementation has been admitted after owner resolution.

* Non-goals

- Turning observations into Modules.
- Adding observability as a fifth Module responsibility slot.
- Defining a central tagged-record or handler registry.
- Encoding policy decisions inside observed facts.
- Carrying raw continuations or executable runtime handles.
- Replacing upstream =gerbil-poo= dispatch, object, type, or Contract
  foundations.
- Defining an implementation schedule.
