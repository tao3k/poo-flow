#+title: Repository, Module, Profile, and Governance-Language Namespaces
#+startup: overview

* Status

This RFC records the accepted namespace separation among the
=wendao-episteme= source repository, the =poo-flow-core= profile projection,
the exported profile binding, and a possible future Wendao governance language.

It fixes naming and ownership. It does not claim that conceptual future Gerbil
modules or language packages are already implemented.

* Typst formalization: non-substitutable namespace roles

Repository/source identity, projection module namespace, exported profile
binding, and governance-language namespace answer different questions.  They
are not aliases and cannot substitute for one another.

#+begin_src typst
#let namespace-roles = (
  "repository-source",
  "projection-module",
  "profile-binding",
  "governance-language",
)

$ forall(source in namespace-roles, target in namespace-roles,
  source != target
  ==> not substitutes(source, target)
) $

$ repository-source("wendao-episteme", commit)
  ==> provenance-evidence(commit)
  and not provides-module-path(commit)
  and not provides-package-identity(commit)
  and not provides-lexical-binding(commit)
  and not provides-governance-language(commit)
  and not provides-runtime-capability(commit) $
#+end_src

The projection module namespace states that =poo-flow-core= owns the thin
projection implementation.  It remains a proposed contract until a real Gerbil
module is implemented and verified.  Its exported binding names a first-class
semantic profile value; =compose= performs no repository, module-path,
package-manager, or global-registry lookup.

#+begin_src typst
$ projection.status = "proposed-contract"
  ==> not claim-importable-module(projection) $

$ projection.status = "implemented-and-verified"
  ==> may-claim-importable-module(projection) $

$ core-owned(projection)
  ==> not occupies-child-owned-wendao-namespace(projection)
  and not occupies-governance-language-namespace(projection) $

$ exported-binding(binding)
  ==> first-class-poo-profile(binding.value) $

$ compose(strategy, profiles)
  ==> not lookup(repository-name)
  and not lookup(module-path)
  and not lookup(package-manager-state)
  and not lookup(global-registry) $
#+end_src

A possible future =#lang= path is permanently a governance-language namespace,
not a generic =lang= alias and not a namespace for the current core-owned
projection.  This RFC reserves that role but does not claim an implementation.

* Central decision

Four names remain distinct:

1. repository and source identity;
2. projection module namespace;
3. profile semantic binding and identity;
4. governance language namespace.

A repository name, module path, lexical binding, and =#lang= path answer
different questions and must not substitute for one another.

* Repository and source identity

The source repository identity is:

#+begin_example
tao3k/wendao-episteme
#+end_example

The parent repository also records an exact Git submodule commit.

Together they provide source ownership and provenance evidence.

They do not provide:

- a Gerbil module path;
- a Gerbil package;
- a Scheme lexical binding;
- a governance language;
- a runtime capability.

* Projection module namespace

The current thin projection is owned by =poo-flow-core=.

Therefore its proposed owner-first Gerbil module path is:

#+begin_src scheme
:poo-flow/profiles/wendao-episteme
#+end_src

The path communicates:

- module code owner: =poo-flow-core=;
- surface role: profile projection;
- semantic subject: =wendao-episteme=.

The projection must not use a child-owned namespace or a language namespace to
hide its real owner.

The path remains a proposed implementation contract until a real Gerbil module
is implemented and verified.

* Rejected ambiguous module names

The following names are not accepted for the current projection:

#+begin_example
:wendao/episteme
:wendao/lang
:poo-flow/wendao
#+end_example

They obscure one or more of:

- code owner;
- module role;
- semantic subject;
- language purpose.

The core-owned projection must not occupy a future child-owned =:wendao/...=
namespace.

* Profile binding

The projection module exports the ordinary lexical Scheme binding:

#+begin_src scheme
wendao-episteme
#+end_src

The binding names the semantic profile that users compose.

The module path answers who owns the projection code.

The exported binding answers which semantic profile value is being composed.

These roles remain distinct even when both contain the text
=wendao-episteme=.

* User import and composition

The intended user surface is:

#+begin_src scheme
(import :poo-flow/profiles/base
        :poo-flow/profiles/wendao-episteme
        :poo-flow/profiles/production)

(user-composition my-system
  (compose profiles
    base
    wendao-episteme
    production))
#+end_src

The module paths are owner-scoped lexical imports.

The operands are ordinary first-class Scheme values.

=compose= performs no module-path, repository, package-manager, or global
registry lookup.

This example is a normative naming target, not evidence that the modules are
already implemented.

* Profile semantic identity

The text name =wendao-episteme= is not the complete profile identity.

The semantic identity includes:

#+begin_example
profile anchor and revision
+ exporting module identity
+ POO construction identity
+ source provenance identity
+ contract projection identity
#+end_example

Version and revision do not normally appear in the ordinary user binding.

Names such as =wendao-episteme-v3= or =wendao-episteme-2026= must not replace
canonical revision evidence.

When multiple revisions must coexist, normal module export and import rename
provide lexical disambiguation.

* Governance language namespace

A genuine governance language must state its purpose in its namespace.

The accepted future language target is:

#+begin_src scheme
#lang :wendao/governance
#+end_src

It denotes a governance language, not the source repository and not a generic
profile module.

The following language names are rejected:

#+begin_example
#lang :wendao/episteme
#lang :wendao/lang
#+end_example

=episteme= names a project or semantic subject, while =lang= does not identify
the governance responsibility.

* Governance language responsibility

A future =#lang :wendao/governance= may own:

- governance declaration syntax;
- hygienic expansion;
- compile-time contract projection;
- generation of ordinary POO governance objects;
- syntax provenance;
- bounded diagnostics.

It must not:

- execute runtime effects;
- issue capabilities;
- register global providers;
- hide quorum or authority;
- replace =compose profiles=;
- turn every profile setting into a governance DSL.

The language exists only when language-level reader, expander, and compile-time
semantics are actually needed.

Ordinary profile composition remains normal Gerbil Scheme code and does not
require this =#lang=.

* Ownership of future namespaces

The current Git submodule does not make =:wendao/...= a currently available
Gerbil namespace.

The current core-owned projection:

- may use =:poo-flow/...=;
- must not claim child ownership;
- must not claim the future governance language exists.

If =wendao-episteme= later becomes a Gerbil package, a new ownership contract
defines:

- child-owned module namespaces;
- exported profiles;
- governance language ownership;
- compatibility with the core-owned projection;
- package, build, and verification responsibilities.

The child must not take over the =:poo-flow/...= namespace, and core must not
occupy child-owned =:wendao/...= paths without an explicit contract.

* Module path is not authority

Owning or importing a module path does not provide:

- resource capability;
- governance role;
- trust-anchor status;
- runtime ownership;
- effect authority.

Module namespace expresses lexical code ownership.

Live authority remains capability-scoped and separately admitted.

* Failure taxonomy

The implementation must distinguish at least:

- repository name used as module identity;
- core projection placed in child namespace;
- profile binding confused with module path;
- profile text name treated as complete semantic identity;
- governance language confused with profile import;
- ambiguous generic =lang= namespace used;
- conceptual module treated as implemented;
- conceptual governance language treated as installed;
- core attempted child namespace ownership;
- child attempted core namespace ownership;
- module import treated as live authority.

* Required invariants

1. Repository, module, profile, and language names remain distinct.
2. Source identity uses =tao3k/wendao-episteme= and the exact pin.
3. The core-owned projection uses an owner-first =:poo-flow/...= namespace.
4. The exported semantic binding remains =wendao-episteme=.
5. Complete profile identity is evidence-based, not name-based.
6. A governance language explicitly uses =governance= in its path.
7. =:wendao/episteme= and generic =:wendao/lang= are rejected.
8. Ordinary profile composition does not require a governance language.
9. Future namespaces are not presented as current implementations.
10. Core and child do not occupy one another's namespaces implicitly.
11. Module import never grants live authority.
12. Public semantic extension remains POO-native.
