* Decision and proof boundary

Context Delta is an admitted transformation between exact immutable Context
projections. It must reconstruct the target projection produced by the declared
source/Query contract and must not confer permission to consume it. This refines
[[file:session-scheduling-granularity-design.org][Scheduling Granularity and Incremental Context]] and the
[[file:ai-agentic-context-session-memory-contracts.org][Session/Memory lifecycle contracts]].

Lean proves pure value/operation laws and the declared dependency model.
Quint explores finite interleavings of preparation, publication, invalidation,
disclosure, result admission and recovery. Native replay qualifies their relation
to Scheme contracts and concrete source bytes. Each has a separate evidence
boundary; none alone proves the complete runtime or its performance.

Current =modules/ai-agentic-context/funs-projection.ss= supports full bounded
headline projection/replay and the restricted local incremental path documented
below. General Query dependency certificates remain unimplemented. Existing Lean Session/WorkTree laws and finite Quint Session
controls are baseline evidence, not this Delta qualification.

* Contract vocabulary and initial restrictions

A =Projection= contains admitted binding metadata, an ordered collection of
content units, required obligations, completeness and its semantic commitment.
A content unit has stable identity, kind, version, value and source/evidence
references. Org IDs anchor content identity; parser-local locators and byte spans
remain bound to their source cut. Query rows/artifact ports require their own
identity scheme; an Org ID cannot identify every derived unit.

A =Delta= binds contract version, expected base projection commitment/revision,
target source vector and commitment, fixed scope/contract bindings, replacement
metadata, insert/replace/delete operations, target order and a coverage proposal.
Target metadata includes parser/Query/restriction/profile identities, budgets,
completeness and the dependency cut. It is admitted independently of payload.

The first profile requires the same organization/epoch, actor, project/worktree,
task, Session/Turn, destination, purpose, Query, parser, restriction and Feature
profile. Declared source-cut fields advance through explicit admitted lineage;
all other Scope fields remain equal. Source vector/revision changes are explicit.
Authority/grant generation is checked at use, not copied as an allow bit.
A different Query, scope, parser or policy/profile requires full reconstruction
and fresh admission. A new Turn must rebind/re-admit its projection; a Delta
cannot bypass that transition.

Patch keys are unique and operations disjoint. Insert requires absence in the
base, replace requires the expected existing unit version, and delete requires
presence at that version. No operation overwrites an identity silently. Target
order lists every surviving/inserted unit exactly once and no absent unit.
Unknown base, duplicate key, wrong expected version, truncated payload, missing
order entry or budget overflow causes typed refusal. No partial reconstruction
is exposed for provider use.

* Pure reference semantics

#+begin_src text
project(sourceCut, contract) -> admitted full Projection or typed rejection
apply(base, delta) -> reconstructed candidate or typed rejection
admitDelta(base, delta, currentSource, contract) -> admitted target or rejection
publish(expectedHead, admittedTarget) -> intent for owner CAS
consume(currentState, exactTarget, consumerBinding) -> fenced use intent
#+end_src

These are proposed named pure functions over POO-native boundary values.
=project= is the independently specified full semantic reference. =apply= checks
patch domain, versions, metadata and ordering. =admitDelta= reconstructs and
qualifies content/source bindings. Runtime executes publication/consumption
intents through existing Host/Backend protocols; it never treats =apply= success
as an allow decision.

Initial admission computes =project= at the target source cut and requires
structural equality with the reconstructed candidate, then recomputes the
canonical commitment. This validates transport and establishes a differential
baseline. It does not claim to avoid parse/Query work. A target digest supplied
by the sender cannot replace that independent equality check.

* Lean data model and theorem obligations

Use finite identity maps plus explicit order, exact binding records, structured
patch operations and typed rejection. Public Scheme values remain native POO;
Lean values are proof projections of their admitted facts. Propose the following
modules within the existing =packages/proofs/lean-poo/= Lake workspace:

| Proposed proof source | Obligation |
|-----------------------+------------|
| =PooFlowContextProof/DeltaTypes.lean= | Projection, Delta, operation, binding and rejection definitions |
| =PooFlowContextProof/DeltaApply.lean= | Executable reference apply/admission and structural laws |
| =PooFlowContextProof/DeltaCoverage.lean= | Restricted Query dependency semantics and coverage theorem |
| =PooFlowContextProof/DeltaUse.lean= | Publication/use guards, exact consumer binding and rejection laws |
| =PooFlowContextProof/QuintCorrespondence.lean= | Concrete abstraction and bounded action relation |
| =PooFlowContextProof/AxiomAudit.lean= | Theorem/assumption inventory and prohibited proof shortcuts |

Add a library target to that workspace when these sources are implemented; the
names above do not create a delivered target merely by appearing here.

| Theorem | Required conclusion, not an assumed equality |
|---------+---------------------------------------------|
| =apply_preserves_unique_domain= | Successful apply has no duplicate unit identity |
| =apply_exact_domain= | Result domain equals base minus deletes plus inserts |
| =apply_frame= | Untouched units retain exact value, version and evidence references |
| =apply_target_order= | Successful result order is precisely the admitted target order |
| =apply_rejects_wrong_base= | Unequal base commitment/revision yields typed rejection |
| =admit_equals_full_projection= | Accepted initial admission equals independently computed target project |
| =coverage_sound= | Constructive coverage premises establish all changed semantic dependencies |
| =incremental_equals_full_projection= | Qualified incremental project equals the full project at the same cut |
| =publication_preserves_obligations= | Mandatory obligations persist or have explicit discharge/supersession receipts |
| =consume_binds_current_input= | Success implies exact consumer/Attempt/Turn, current source and current guards |

For =coverage_sound=, prove the dependency semantics from the supported Query
operators; do not encode full-target equality itself as a coverage premise.
Prove failure branches, including fresh source units absent from the base and
removed rows. A coverage Boolean from a caller is never a proof witness.

Ordered composition is conditional: if delta A is admitted from P0 to P1 and
B from that exact P1 to P2 under compatible contracts, sequential reconstruction
agrees with P2. No unconditional commutativity: edits to different units may
still affect ordering or nonlocal Query results. Even disjoint structural patches
need qualified dependency independence and common target-cut admission before
parallel composition. An idempotent delivery acknowledgment does not make a
patch valid against a different base.

Hashes are commitments, not authentication or a Lean-proved SHA-256 injectivity
claim. Use structural equality and explicit source/admission evidence in semantic
proofs. Document cryptographic commitment assumptions and native serialization
correspondence separately. Do not introduce =sorry=, unrestricted axioms or
unproved "coverage complete" predicates to obtain the main closure theorem.

* Coverage model: additions, removals and nonlocal queries

Coverage must include direct source references, derived artifact lineage,
parser/Query dependencies, ordering, required policy/obligations and negative
information dependencies. New matching Elements can alter a result although no
old row refers to them. Removal of a previously absent/missing relation can also
change a query's interpretation. Aggregate, limit/top-k, ordering, negation and
join operators require whole relevant domains or separately proved certificates.

Begin with a bounded local selection profile whose membership and field
projection are functions of each source unit. Cover the complete admitted unit
domain at both cuts and prove selected-unit additions/removals/value changes.
A parser edit can change Element identity or structure outside an edited byte
span; the changed-element set must itself come from a qualified parser/source
boundary. Byte ranges alone cannot qualify it.

Until those premises are available, full reparse/reprojection is the reference
path. Unsupported operators or uncertain changed-set coverage require full
admission or refusal. A guard cannot default unknown coverage to unchanged.
This restriction remains explicit in the Feature/Profile and typed receipt.

* Quint state and bounded profiles

Propose =packages/proofs/quint/ContextDelta.qnt= and matched case wrappers,
registered through the existing proof-case catalog and runner. Split the initial
checks into patch/publication and disclosure/recovery profiles to keep domains
bounded; add a combined profile to qualify their shared invariants.

State includes immutable projection/cut fixtures, selected heads/revisions,
pending delta proposals, reconstructed candidates, coverage references, consumer
Session/Task/Attempt/Turn bindings, source/policy epochs, grant/claim generations,
worker requests, durable intents, cancellation obligations and historical receipts.
Use independently specified fixture values/reference patch semantics rather than
accepting arbitrary target digest labels as semantic truth.

Initial domain proposal: two Sessions/workers, two tasks, two source cuts, up to
three content units, two competing proposals, revision/generation cap four and
a bounded event log. Include insert, replace, delete, ordering and rejected
coverage cases. Caps guard transitions; no coordinate wraparound. State-space
measurements may require smaller independent profiles, with scope stated in
receipts. Exhaustion prevents further transitions; it is not evidence of progress.

| Action | Required model effect |
|--------+-----------------------|
| Prepare/reconstruct | Preserve exact base, target and consumer bindings; candidate remains unusable |
| Admit | Validate independent target fixture/reference semantics and declared coverage profile |
| Publish | Match expected selected-head revision and target source cut; advance owner CAS |
| Source/policy change | Advance cut/epoch and dirty affected dependents without deleting history |
| Queue/disclose | Persist exact request intent, then current-use fence at actual submission |
| Provider completion | Record immutable observation under original request/Attempt |
| Result consumption | Current exact input/consumer/grant/claim fence and one conditional outcome |
| Duplicate/reordered delivery | Deduplicate exact command identity or reject incompatible base |
| Cancel/acknowledge | Separate request from observed termination/isolation obligations |
| Crash/recover | Restore durable pending references, re-enroll guards and reconcile requests |

Invariants inspect publication/use receipts with the authoritative state snapshot
at their linearization point. Later source correction does not make a previously
valid historical receipt false. It makes future use require fresh admission.
Avoid a permanent =allowed= Boolean or an invariant that requires all historical
receipts to equal today's source cut.

| Safety invariant | Matched broken guard |
|------------------+---------------------|
| ExactBase | Ignore expected base commitment/revision |
| ExactReconstruction | Omit delete/order/expected-unit-version check |
| CompleteCoverage | Treat unknown coverage or newly matching unit as unchanged |
| ExactTargetCut | Admit a target against a different current source cut |
| OnePublication | Ignore selected-head CAS for competing proposals |
| ExactConsumer | Ignore destination/purpose/Session/Attempt/Turn binding |
| CurrentConsumption | Reuse admission as a future allow after source/grant change |
| NoLateAttemptOverwrite | Accept old claim generation or route to current Session task |
| NoDuplicateOutcome | Count duplicate delivery or retried task twice |
| RecoveryPreservesPending | Restore cached allow or erase unresolved request/cancellation |

Every mutant must be reachable and violate its named invariant under the same
bounded profile; merely enabling a mutation is not a negative receipt. Specify
trace bounds, checked invariants, search method and seed/exploration counts.
Finite safety checks do not prove unbounded fairness, liveness, runtime timing or
cryptographic security. Separate eventual-provider/clock/storage assumptions.

* Lean/Quint/native correspondence

Define an abstraction from admitted native projections/receipts to Lean values
and bounded Quint state. Each concrete publication, invalidation and consumption
step must refine a declared action or an explicitly justified stuttering step.
Map typed native refusals and source/cut identities; preserve exact input routing.
Do not hide a disclosure/effectful transition as stuttering.

The existing =packages/proofs/quint/source_binding.py= checks retained source
digest and invariant inventory. Reuse its freshness discipline, but a matching
hash does not prove semantic refinement. The new correspondence target must
prove value/guard preservation separately and audit its assumptions.

Counterexample replay carries actual Org bytes at both cuts, parsed Element/Query
values, patch operations, budgets, bindings and expected refusal. Replay actions
through native APIs, compare reconstructed targets with independent full native
projection, and retain cancellation/provider observations. Abstract cut/token
fixtures without concrete source replay cannot qualify parser or Query behavior.
Rust/Data consumers own transport/transaction replay once their ABI supports the
new envelope. Existing six-field Context Use receipts do not carry this Delta
contract and cannot close it by unchanged ABI tests.

* Source roles, delivery order and acceptance gates

Context =types.ss= owns Delta/binding/coverage/rejection shapes; =objects.ss=
owns inert native proposals and receipts; =funs.ss= and specialized =funs-delta*.ss=
own pure apply/reference admission functions. =config.ss= selects the supported
profile, and =interface.ss= closes public exports. Host/runtime owns current
use; Session owns Attempt/Turn/CAS; Data owns durable conditional publication.

1. Implement structural reference apply and full-target differential admission;
   prove domain/order/frame/rejection laws in Lean. No incremental speed claim.
2. Implement finite Quint publication/disclosure profiles and reachable matched
   mutations; replay concrete wrong-base, competing publication and stale-use traces.
3. Implement a restricted dependency profile and prove changed-domain coverage
   including new/deleted units; compare incremental versus independent full native
   projection on matched source transformations and negative coverage controls.
4. Add combined Session/claim/invalidation/recovery model and explicit
   correspondence. Qualify actual Host/Backend fences and each wire consumer.
5. Benchmark Delta encoding, reconstruction, parser/Query work, current guards,
   allocations and end-to-end latency separately against equal full projections.

Completion requires compiled Lean theorems and axiom audit, pinned Quint gates,
matched native controls and exact consumer receipts. This document designs those
gates; it does not report them as executed or passed.

* Reference implementation receipt

The core now exports native =AiAgenticContextDelta.= and
=AiAgenticContextEdit.= proposals and a declarative Delta Type.
=funs-delta.ss= owns =delta-between=, =delta-apply= and =delta-admit= public
functions under the =poo-flow-ai-agentic-context-= prefix. Patch admission
checks exact base, expected old units, duplicate identities and complete target
order. Source admission replays the original bytes, constructs the target from
current bytes and compares both content and recomputed target commitment.
It returns freshly constructed values with =coverage=full-reprojection= and
source-authenticated/action-authorized/durable flags false. Source-owner replay
errors retain their existing exception boundary; patch refusals use typed reasons.
Source-cut labels may change in the proposed envelope; current lineage/authority
qualification is a separate Host/consumer obligation.

=packages/proofs/lean-poo/ContextDelta.lean= implements ten named pure laws for
exact replacement, deletion, frame preservation across edit sequences, differential
admission and rejection. All compile, with an audit of 19 total theorems including
generated declarations using only standard Lean axioms. These are abstract
value laws, not a proof of native serialization, Query coverage or runtime refinement.
The Lake workspace declares =PooFlowContextProof= and CI builds that target.
Local qualification compiles the standalone core-only source through
=just check-context-delta-lean= without claiming a fresh LeanPoo dependency build.

The pinned Quint =context-delta= group has one safe fixture model (422 distinct
states) and five reachable matched controls: publication CAS, target cut, omitted
deletion, consumption cut and revoked grant. Controls violate their respective
invariants at 54, 15, 26, 41 and 42 distinct states. The first run stopped under
the existing five-second no-output watchdog during backend compilation; an
unchanged full retry passed six cases. Limits were not widened. Source-digest/
invariant-inventory binding to Lean is checked and remains metadata freshness.

Nine native cases exercise real Org changes, structural insertion/deletion/
replacement/order, wrong base/old unit, duplicate edits, incomplete order, forged
target, cross-scope/profile substitution and original-byte replay failure.
The first native run exposed a POO lazy-slot parameter/name collision in receipt
construction; corrected binding names passed the same heap/memory/watchdog gates.
Qualification test artifact compilation retains the previously recorded local
O0 override; repository production compiler settings remain unchanged.
Six proof-runner admission/freshness tests also passed.
The corrected production Delta module was recompiled with default compiler
settings, the normal PackageSpec build completed, and the eight existing core
cases passed under the unchanged watchdog. Both native suites contain
=MODULE-OK=, =HARNESS-OK= and final =OK= without failure/overflow markers.

At this reference milestone, remaining gates were dependency-coverage soundness
and incremental equivalence, combined Session/Attempt/recovery controls, automated concrete trace projection,
Lean/native semantic correspondence and actual Host/Backend/wire consumption
fences. Quint publication/consumption controls currently qualify the abstract
model; they do not assert those runtime fences are implemented. No incremental
speedup or complete Delta consumer qualification is claimed.

* Restricted local Query and Session Attempt implementation

The new =org-project-incremental= and =delta-admit-incremental= functions use
only the fixed canonical =orgize/open-headlines-v1= single-node Query.
Orgize still parses the entire target source and admits its complete headline
domain. Every node, including nonmatching nodes, contributes byte start/end,
title and TODO classification to the local input snapshot. Reuse requires exact
snapshot equality; inserted or shifted nodes are evaluated. Removed nodes are
excluded by enumeration of the complete current domain. Global Element IDs and
source digest cells are rebuilt from the current parser output for every row.
A global TODO directive change is observed through parser-produced classification.
The implementation trusts neither an old selected-row domain as coverage nor
caller-supplied cache slots: base byte replay reconstructs fresh cache values.

The incremental receipt uses =coverage=local-query-complete-domain=.
Full projection remains available and remains the reference for unsupported
Query operators; the incremental entrypoint accepts no custom Query program.
This is a semantic reuse path, not an incremental parser. Historical base replay
still performs full parsing and selection, including repeated defensive replay at
layer boundaries. No end-to-end performance improvement is claimed.

=ContextDelta.lean= adds six named laws for exact unchanged inputs, incremental
projection equality, insertion, removal, nonmatching-to-matching transitions and
global binding reconstruction. The audit now inventories 28 theorems including
generated declarations. The theorem uses complete source maps and equality of
actual local Query inputs, not full-target equality as a coverage assumption.
It abstracts parser correctness, ordering/serialization and native compiler
correspondence; the generic theorem does not prove those implementations.

=ContextCoverage.qnt= exhaustively checks two local keys, each absent,
nonmatching or matching. Its safe instance has 90 distinct states. Omitted
insertion, removal and negative-information changes violate equality at 12,
28 and 21 distinct states. =SessionAttempt.qnt= independently checks claim,
exact-generation completion, recovery with pending obligation, reconciliation
and closure through generation cap three. Its safe instance has 50 distinct
states; wrong-generation routing, dropped recovery obligation and closed resume
controls fail at 5, 5 and 10 states. These two models do not constitute a combined
Context/grant/source/publication refinement or a liveness qualification.

See [[file:session-attempt-implementation-receipt.org][the Session Attempt receipt]] for native ownership and recovery boundaries.
The current Delta suite includes matched real-byte incremental/full comparisons,
append reuse with newly rebound global IDs, forged cache replacement and the
source-replayed Context-to-Session input proposal. Local Lean compilation,
source/invariant metadata freshness and the six existing proof-runner admission
controls passed. Native and production qualification is recorded in that receipt.

Remaining full-system gates are parser-backed Org property ID anchor admission,
automated concrete trace projection, Lean/native correspondence, the combined
Session/Attempt/source/grant model, current-use Host publication/disclosure fences,
versioned wire/consumer changes, durable recovery and downstream MRR Data
qualification. Neither a Session transition intent nor a typed input reference
resolves producer authority or performs dispatch, CAS or durable publication.
