#+title: POO Lazy Slot Resolution Observability
#+language: en

* Status

IMPLEMENTED as an opt-in development boundary in
=src/module-system/observability/slot-debug.ss=.  It diagnoses lazy slot recursion before
unbounded heap growth while preserving upstream POO caching and exception
semantics.  It does not modify the vendored reference sources under =.data=.

* Source evidence

The failure is below ordinary Module behavior.  Upstream
=.data/gerbil-poo/object.ss= resolves a missing instance slot through
=hash-ensure-ref=.  The slot is inserted only after its initializer returns.
If the initializer re-enters the same receiver and slot, the cache is still
empty and resolution allocates again without a cycle verdict.

The upstream roadmap already names this gap:
=.data/gerbil-poo/doc/TODO.md= asks for circular-definition detection through
a suitable =hash-ensure-ref= variant.  This is therefore a known meta-object
protocol limitation, not evidence that every observed Module is malformed.

Upstream =trace-poo= cannot close the gap by itself.  Its inherited-slot
wrapper invokes =superfun= before checking whether the resulting value is a
procedure and before =traced-function= starts.  A lazy self reference can
therefore exhaust memory before a trace event exists.  The generic
=traced-function= also prints raw arguments and results, so applying it to live
POO values would not form a redaction boundary.

* Decision

POO Flow adds a distinct guarded receiver rather than patching global =.ref=
behavior.  Every inherited slot is replaced by an upstream
=$computed-slot-spec= whose resolver first performs a pure, typed admission
decision.  The public surface remains native POO: policies and receipts are
validated Contract values, and the returned subject is an ordinary composed
POO object.

#+begin_src mermaid
stateDiagram-v2
  [*] --> Inspect: wrapper slot requested
  Inspect --> RejectedCycle: receiver and slot already active
  Inspect --> RejectedDepth: active depth reaches policy maximum
  Inspect --> Admitted: edge is new and within budget
  Admitted --> Resolving: push receiver and slot edge
  Resolving --> Resolved: inherited resolver returns
  Resolving --> Raised: inherited resolver raises
  Resolved --> Cached: upstream wrapper caches private value
  Cached --> [*]
  Raised --> [*]: rethrow identical exception
  RejectedCycle --> [*]: typed anomaly
  RejectedDepth --> [*]: typed anomaly
#+end_src

The active path is dynamically scoped per Scheme thread.  An edge is
=(receiver-symbol . slot-symbol)=, not just a slot name: =outer.value= may
legitimately depend on =inner.value=.  Only symbols are retained, so the debug
path cannot keep receivers, slot values, resolver closures, or exceptions
alive.

* Trace and receipt boundary

For an admitted edge the adapter may call Clan's =traced-function=, but it
passes a zero-argument closure that returns only =resolved=.  The actual result
remains lexical and becomes the computed-slot result after tracing finishes.
The upstream printer therefore sees a symbolic label, no arguments, and one
closed result symbol.

Each phase also has a native =PooFlowDebugSlotReceiptContract= value:

| Outcome | Accepted | Stable reason |
|---------+----------+---------------|
| =admitted= | yes | =slot-resolution-admitted= |
| =resolved= | yes | =slot-resolved= |
| =raised= | no | =slot-resolution-raised= |
| =rejected-cycle= | no | =recursive-slot-resolution= |
| =rejected-depth= | no | =maximum-slot-depth-exceeded= |

Contract obligations bind depth to path length, accepted polarity to outcome,
reason to outcome, and cycle/depth outcomes to their actual boundary
conditions.  A caller cannot forge an accepted cycle receipt merely by
changing =accepted?=.

* Ownership and composition

- =types.ss= owns slot policy and receipt Contracts and their pure
  obligations.
- =func.ss= owns pure construction and the closed S-expression projection.
- =slot-debug.ss= owns computed-slot installation, dynamic path state, Clan
  debug handoff, and typed anomaly propagation.
- =debug.ss= is the stable development facade.

This separation keeps the effectful adapter independent from the existing
Module observation model.  It does not add slots to SemanticModule, replace
the strict =src/module-system/observability/module-presentation.ss= presentation owner, or make
debug output semantic evidence.

* Authoring and performance path

The supported path is deliberately phase-separated:

#+begin_export mermaid
flowchart LR
  A["Authoring: reader-only diagnostics"] -. "repair advice; no execution" .-> B["Construction: guarded POO proxy"]
  B -->|"first .ref"| C["Cold demand: admission and inherited resolver"]
  C -->|"upstream cache fill"| D["Warm demand: cached .ref"]
  C -. "emit? true" .-> E["Trace projection: bounded symbolic receipts"]
#+end_export

Authoring diagnostics do not claim runtime evidence.  The existing POO slot
authoring gate rejects same-name dynamic initializers such as
=construction-us: construction-us=: =.o= introduces declared slot names in
initializer scope, so that spelling recursively resolves the slot rather than
capturing the lexical value.  The standard repair is a distinct lexical name,
for example =construction-us: construction-us-value=.  The prototype rule
similarly advises resolving a stable =Contract.proto= once before repeated
construction instead of embedding =(.ref Contract 'proto)= in every =.o=
super clause.

The performance scenario under
=t/scenarios/performance/poo-observability-slot-guard/= measures those phases
without nesting the workload in an outer repetition count.  It prebuilds fresh
cold and traced batches, warms a separate guarded object once, and asserts
semantic checksums plus one-time evaluation.  Inline and bound prototype
times are diagnostic fields, not a relative-speed acceptance condition.

* Explicit limits

- The proxy is opt-in.  Unwrapped objects retain upstream behavior.
- The proxy does not patch =hash-ensure-ref= or install process-global hooks.
- Slot values that are themselves POO objects are not recursively wrapped;
  callers assign them explicit receiver labels and wrap them separately.
- =.all-slots= discovers topology without forcing slot values, but creating a
  proxy may still surface upstream precedence errors.
- Input prototype code remains trusted.  The guard detects active-edge cycles
  and bounded dependency depth; it is not a sandbox or a termination proof.
- The in-band guard begins only after its module loads.  A native Gambit
  =max-heap= limit remains mandatory for test and diagnostic launchers, while
  the ASP process guard remains an independent outer defense.
- Source authoring gates, runtime slot admission, memory receipts, and heap
  ceilings are complementary evidence and must not be reported as substitutes
  for one another.

* Verification contract

The framework gate must prove:

1. forged slot receipts fail Contract validation;
2. a zero-depth policy fails Contract validation;
3. a normal lazy slot evaluates once and its private value is absent from
   output;
4. a raised resolver preserves exception identity without disclosing it;
5. a direct self reference is rejected at the first repeated edge;
6. equal slot names on distinct receiver labels remain valid; and
7. a dependent slot crossing the configured depth fails before invocation;
8. repository constructors contain no direct stable prototype lookup in a
   =.o= super clause; and
9. performance receipts use distinct lexical value names rather than
   self-referential slot initializers.

The existing upstream debug-admission suite remains responsible for proving
raw =DDT= / =trace-poo= behavior and demonstrating that upstream output is not
a redaction boundary.  Full acceptance also requires the module-system source
authoring gate, native process heap ceiling, observability regression suites,
and the pinned ASP project-policy scan.
