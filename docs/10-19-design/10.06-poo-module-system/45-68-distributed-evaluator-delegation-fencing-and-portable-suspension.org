#+title: Distributed Evaluator Delegation, Fencing, and Portable Suspension
#+startup: overview

* Status

This RFC records the accepted execution protocol for evaluating pure POO
demands across processes and hosts.

It extends incremental fixed-point evaluation and distributed cache admission.
It does not place live execution work into the ordinary distributed cache.

* Typst formalization: fenced pure-demand delegation

The distributed unit is an immutable pure demand envelope.  It contains
semantic identities and an observation cut, but never live action authority or
a raw Gerbil VM continuation.

#+begin_src typst
#let demand-envelope(root, input, dependency, cut, policy, demand) = (
  root: root,
  input: input,
  dependency: dependency,
  cut: cut,
  policy: policy,
  demand: demand,
  pure: true,
  action-authority: none,
)

$ envelope(e)
  ==> pure(e.demand)
  and e.action-authority = none
  and immutable(e) $

$ worker-result(r) ==> candidate(r) and not direct-publish(r) $
#+end_src

Delegation is fenced by coordinator identity and a current, non-revoked fence.
A portable suspension stores resumable data and a resume token; resumption
requires the same demand identity, observation cut, policy identity, and a
current fence.

#+begin_src typst
#let fence-valid(f) = f.current and not f.revoked

#let resume-valid(s, current) = (
  s.demand == current.demand
  and s.cut == current.cut
  and s.policy == current.policy
  and fence-valid(current.fence)
)

$ admit-worker-candidate(r)
  ==> fence-valid(r.fence)
  and local-admission-checks(r)
  and coordinator-owned(r.commit) $

$ portable-suspension(s)
  ==> s.vm-continuation = none
  and s.action-authority = none
  and resumable-data(s) $

$ coordinator-commit(receipt) ==> receipt.commit-count = 1 $
#+end_src

* Central decision

The default distributed unit is an immutable pure demand envelope.

It is not a raw Gerbil VM continuation.

A raw continuation may capture process-local VM state, ports, threads, locks,
addresses, authority-bearing tokens, and undisclosed environment values. It
remains process-local unless a separately verified portable representation
proves otherwise.

Distributed execution must not change canonical POO semantics or transfer live
action authority to a pure worker.

* POO and functional ownership

Scheduling and delegation policy are ordinary higher-order POO objects and
pure functional combinators.

They may compose:

- locality preference;
- worker capability requirements;
- confidentiality placement;
- cost policy;
- retry budget;
- SCC placement;
- checkpoint policy.

The public semantic extension interface remains POO-native. Scheduling must not
become an enum-like =#:remote=, =#:retry=, or =#:checkpoint= macro DSL.

Funflow may provide functional execution composition. It must not become an
alternative POO semantic system or hidden authority channel.

* Demand envelope

An immutable =DemandEnvelope= identifies:

- semantic cut identity;
- demanded object and slot identities;
- dependency manifest seed;
- graph and SCC identities;
- pure input projection;
- evaluation policy identity;
- delegated budget;
- confidentiality domain;
- attempt identity;
- lease and fencing identities;
- coordinator return-channel identity;
- envelope schema identity.

The envelope contains the minimum input and disclosure projection required for
the demand.

It does not carry publication, activation, effect-commit, migration,
reclamation, or consumer-isolation authority.

* Coordinator ownership

The canonical evaluation coordinator owns:

- demand graph identity;
- SCC partition and ownership;
- parent evaluation budget ledger;
- cancellation tree;
- worker delegation;
- attempt lease and fence versions;
- dynamic demand admission;
- candidate result admission;
- graph-wide proof assembly;
- execution observability receipts.

Coordinator ownership is execution ownership. It does not replace pure POO
definition identity.

* Worker ownership

A remote pure worker may:

- evaluate the admitted POO demand;
- record the dependency manifest actually demanded;
- report value, proof, violation, or suspension candidates;
- report resource and budget consumption;
- propose newly discovered pure dependencies.

A worker must not:

- execute live effects;
- publish an active head;
- activate a consumer;
- mutate a persistent resource;
- increase its delegated budget;
- widen its disclosure or capability scope;
- mutate the canonical demand graph directly.

* Budget conservation

Delegated budgets are conserved across:

- retries;
- worker migration;
- sub-demand expansion;
- duplicated execution;
- checkpoint resumption.

A worker receiving a budget allocation cannot recreate the same allocation for
each retry or child demand.

All reservations and consumption belong to one parent budget ledger.

Worker disconnection does not automatically restore reserved budget. Release
requires reconciliation evidence proving that the reservation cannot still be
consumed or published.

Child budget scopes may narrow parent resources. They must not amplify them.

* Cancellation narrowing

Cancellation follows the demand ownership tree.

- parent cancellation may cancel a child scope;
- child cancellation cannot cancel its parent or siblings;
- one waiter cannot cancel work still owned by other waiters;
- cancellation advances the attempt fence;
- a late result cannot modify the fenced attempt.

Cancellation does not erase an already produced immutable pure result. Such a
result may be reconsidered only as a separately admitted cache candidate.

* Lease and fencing

An execution lease identifies the current worker assignment for one attempt.

Lease expiry allows the coordinator to reschedule the same semantic demand.
It does not change demand identity.

A late worker result after fencing:

- cannot update the current execution attempt;
- cannot consume new parent budget;
- cannot regain live delegation authority;
- may enter distributed cache admission as an untrusted candidate when it is a
  complete pure result.

Fencing applies to execution ownership, not semantic truth.

* Dynamic demand expansion

A worker discovering a new dependency emits a pure
=DemandExpansionProposal= containing:

- parent demand identity;
- exact causal dependency edge;
- requested projection;
- predicted budget;
- confidentiality requirement;
- SCC relationship;
- proposal identity.

The coordinator admits the proposal before adding the edge to the canonical
demand graph or delegating the new work.

This prevents recursive workers from silently expanding resource budgets,
disclosure scope, or graph reachability.

Rejected expansion produces suspension or violation evidence according to the
evaluation policy. It does not disappear as a generic worker failure.

* SCC placement

Independent SCC frontiers may evaluate concurrently.

A cyclic SCC has one joint evaluation owner responsible for:

- internal demand coordination;
- incoming evidence identity;
- stabilization;
- oscillation evidence;
- cycle paths;
- SCC budget;
- final SCC result identity.

The scheduler must not distribute cyclic nodes independently and allow them to
deadlock while waiting on one another.

The SCC owner may parallelize internal projections only after their
independence is proven.

Owner failure recovers from an immutable SCC checkpoint or reevaluates from the
original demand. Residual distributed wait relationships are not semantic
evidence.

* Process-local continuations

A raw Gerbil continuation is process-local by default.

It may capture:

- VM stack and register representation;
- live ports;
- locks and threads;
- process-local addresses;
- authority-bearing objects;
- private environment state.

Worker loss causes the pure demand to be reevaluated from immutable inputs and
evidence. The runtime must not pretend that an opaque VM continuation is
portable.

* Portable logical suspension

A separately defined pure checkpoint may be represented as a portable logical
suspension.

It contains:

- semantic cut identity;
- demand path;
- dependency manifest identity;
- pure intermediate value identities;
- remaining budget receipt;
- suspension reason;
- runtime and checkpoint schema identities;
- confidentiality domain;
- suspension receipt identity.

It must not capture live ports, locks, capability tokens, effect handles,
process addresses, or other non-portable resources.

Resumption verifies:

- semantic cut unchanged;
- dependency assumptions unchanged;
- runtime and checkpoint schemas compatible;
- confidentiality domain admitted;
- budget and resume capability valid.

If these checks fail, a new pure evaluation attempt begins. The old suspension
remains diagnostic evidence.

A portable logical suspension is not automatically equivalent to a
=call/cc= continuation.

* Duplicate execution and result convergence

Duplicate pure execution is allowed.

Equivalent admitted results converge by content identity.

Different result identities for the same complete semantic key produce
determinism-violation evidence. Worker priority, completion time, lease
ownership, and host identity must not select a winner.

Scheduling order and worker placement must not affect the canonical pure
result.

* Confidentiality and placement

Delegation projects only the data authorized for the worker confidentiality
domain.

Worker placement admission verifies:

- host and runtime identity;
- confidentiality domain;
- required pure evaluator capability;
- allowed data projection;
- network and storage policy;
- attestation evidence when required.

A scheduler performance preference cannot override confidentiality placement.

Remote result receipts disclose only the projection admitted for their
consumer.

* Receipts

A =DemandDelegationReceipt= records:

- demand and envelope identities;
- worker and coordinator identities;
- delegated budget;
- narrowed capability and disclosure scope;
- lease and fence versions;
- placement-policy identity.

A =RemoteEvaluationReceipt= records:

- actual dependency manifest;
- budget consumption;
- worker runtime identity;
- candidate result identity;
- suspension, violation, or completion evidence;
- lease and fence observations.

A =ResultAdmissionReceipt= records:

- expected and returned identities;
- dependency validation;
- budget reconciliation;
- lease and fencing result;
- confidentiality projection;
- acceptance, cache-candidate, rejection, or isolation reason.

Receipts carry evidence, not worker action authority.

* Failure taxonomy

The implementation must distinguish at least:

- demand envelope malformed;
- worker placement rejected;
- confidentiality projection denied;
- delegation budget unavailable;
- worker lease expired;
- worker lost;
- demand expansion rejected;
- recursive budget exhausted;
- SCC ownership lost;
- SCC checkpoint incompatible;
- raw continuation non-portable;
- logical suspension schema incompatible;
- suspension semantic cut changed;
- fenced late result;
- duplicate result converged;
- determinism violation;
- result admission incomplete.

* Required invariants

1. Distributed evaluation delegates immutable pure demands by default.
2. Raw VM continuations remain process-local unless portability is proven.
3. Workers receive no live action authority.
4. Coordinator owns canonical demand graph and SCC execution.
5. Delegated budgets are conserved across retries and child demands.
6. Cancellation narrows through the ownership tree.
7. Lease loss changes execution ownership, not semantic identity.
8. Fenced late results cannot modify current attempts.
9. Dynamic dependencies require coordinator admission.
10. Cyclic SCCs retain one joint evaluation owner.
11. Portable suspensions contain no live authority-bearing resources.
12. Scheduling order and placement do not change pure results.
13. Duplicate divergent results fail closed.
14. Confidentiality placement overrides performance preference.
15. Public semantic extension remains POO-native.
