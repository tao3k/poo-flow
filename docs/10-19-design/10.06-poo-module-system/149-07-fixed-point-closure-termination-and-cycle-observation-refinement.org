#+title: RFC 149-07 — Fixed-Point Closure, Termination, and Cycle-Observation Refinement
#+language: en

* Status

This is a Lean-proven refinement of RFC 149-06.  It reuses the
cycle/progress/budget/watchdog semantics of RFC 45-120-21, the relation
separation of RFC 45-120-22, and the profile-only interface boundary of
RFC 45-120-23.

The proof owner is the top-level enterprise scope:

#+begin_src text
packages/proof/lean/PooFlowProof/Enterprise/
  CompositionalFixedPointClosure.lean
  SourceBoundCompositionalFixedPointClosure.lean
  SourceBoundCycleObservationClosure.lean
#+end_src

=Enterprise= is not a child of =PooC3=.  Enterprise proofs may import
generic POO-C3 composition, policy, and authorization theorems, but the
enterprise model is owned by =PooFlowProof.Enterprise=.

This refinement defines evidence obligations.  It does not introduce a
second fixed-point runtime beside =gerbil-poo=, and it does not claim
that the current profile-composition runtime already emits these
receipts.

* Public interface remains unchanged

The user still writes:

#+begin_src scheme
(use-composition
  base-profile
  wendao-episteme-mix
  production-profile)
#+end_src

No fixed-point macro, worklist DSL, recovery form, or raw receipt alist
is added to the public Scheme surface.  =compose= remains pure;
=profiles= remain first-class POO values; =use-composition= remains the
shallow root-selection interface.

A profile may select an owner-valid progress policy and may limit
semantic, scheduling, or watchdog budgets.  It cannot grant retry
authority, own a continuation, or convert an observation into a
resumption command.

* Discovered logical defects

** A stable flag and empty pending list do not prove closure

The countermodel =fakeStableRootReceipt= contains all visible
=use-composition= roots, reports =stable=true=, and has no pending work.
It omits the nested notification workflow.

Lean proves:

#+begin_src text
stableFlagAndEmptyPendingDoNotProveLinkClosure
#+end_src

A closure receipt must independently prove that every link leaving a
visited object ends at another visited object.

** A link-closed candidate need not be the least fixed point

The set containing every possible node is closed under every link.  It
can nevertheless contain an unreachable orphan.

Lean proves:

#+begin_src text
closedCandidateNeedNotBeLeast
#+end_src

Therefore a receipt needs both directions:

- every reachable node is visited;
- every visited node is reachable.

Root inclusion plus link closure proves the first direction.  A separate
minimality witness proves the second.

** Least reachability does not prove registry membership

=Reachable.root= admits every selected root independently of registry
membership.  Therefore roots included, link closure, and minimality can
all hold for a ghost root in an empty registry.

Lean proves:

#+begin_src text
rootLinkMinimalityDoNotProveVisitedRegistration
#+end_src

Every visited entry must independently belong to the exact registry
subject set.  Registry owner validity cannot remain the only place where
this obligation is implicit, because the abstract least-fixed-point
theorem otherwise proves closure over an unmaterializable root.

** String visited identities collapse distinct object revisions

The original receipt stored =List CompositionNodeId=.  Two source-bound
objects can share that string identity while differing in revision,
source tree, object content, and effect contract.  One visited string
then appears to name both subjects.

Lean proves:

#+begin_src text
identityOnlyVisitedCannotDistinguishSourceRevision
#+end_src

The same pair exposes a termination-accounting defect.  Discovering the
second revision is not fresh in a string set, but it is a fresh semantic
subject and must consume another unit of finite registry capacity.

Lean proves:

#+begin_src text
sameNameDifferentRevisionIsFreshSubjectDiscovery
freshSourceBoundDiscoveryConsumesFiniteRegistryCapacity
#+end_src

The corrected receipt stores complete =CompositionObjectSubject=
values.  Its roots, visited set, pending work, links, minimality proof,
registration proof, object-binding evidence, and source-resolution
receipts all use the same subject.

** Finite discovery and scheduling are different obligations

A fresh semantic discovery adds one previously unseen registered node.
When the resulting visited list is a sub-permutation of the finite
registry, its length is bounded by the registry length.

Lean proves:

#+begin_src text
freshDiscoveryConsumesFiniteRegistryCapacity
#+end_src

This bounds semantic discovery.  It does not bound repeated dequeue,
dispatch, retry, or watchdog activity.  Those actions consume distinct
scheduling or runtime budgets.

** One scalar budget cannot identify the exhausted owner

Two observations can both report zero remaining units while one belongs
to semantic discovery and the other to scheduling dispatch.

Lean proves:

#+begin_src text
oneScalarBudgetCannotIdentifyExhaustionOwner
#+end_src

Semantic, scheduling, and runtime-watchdog budgets must have independent
owners and receipts.  Merge precedence is not a progress measure and
cannot settle any of these budgets.

** Oscillation requires a structural history witness

An opaque =semanticOscillation : SubjectProgressEvidence -> Prop= hook is not
enough to establish oscillation.  A contract could return true for an empty or
strictly monotone fingerprint history.  The v1 closure therefore requires both:

1. a canonical history witness in which the same fingerprint occurs twice with
   at least one different fingerprint between those occurrences; and
2. the domain contract's =semanticOscillation= predicate.

The typed history witness still needs a logical content identity.  A nonempty
provenance string does not bind checkpoint content, and an arbitrary digest can
map different canonical roots to the same string.  The stable v1 refinement is
specified in
[[file:45-120-25-source-bound-fingerprint-content-address-closure.org][45-120-25 source-bound fingerprint content-address closure]].

$ R(H) = (H."historyId", I_"last") $

$ "DigestReceipt"."canonicalRoot" = R(H) $
#+end_src

** Raw fingerprint history does not bind a transition

The oscillation witness over =List SemanticFingerprint= proves a repeated
string pattern but not source ownership or transition endpoints.  Lean
constructs a history that satisfies the repeat pattern while omitting the
evidence's current fingerprint entirely.

The v1 repair treats the raw list as a projection of
=SourceBoundSemanticFingerprintHistory=.  Typed checkpoints bind subject,
registry, generation, sequence, fingerprint, obligations, and provenance.
Closure additionally requires exact projection, previous/current endpoints,
current generation, and unique history coverage for every progress subject.

The complete model and proof map live in
[[file:45-120-24-source-bound-fingerprint-history-closure.org][45-120-24 source-bound fingerprint history closure]].

** Opaque progress hooks do not determine one classification

The same source coordinates and subject evidence can satisfy both =advancing=
and =regressing= when independent contract hooks overlap.  Per-subject mutual
exclusion alone is also insufficient for a heterogeneous SCC because different
subjects may support different exceptional classes.

The v1 repair adds:

1. =SourceBoundProgressContractCoherenceClosed= for per-subject semantic and
   obligation consistency;
2. an explicit injectively ranked
   =SourceBoundProgressClassificationPolicy=;
3. maximal supported-candidate selection; and
4. a uniqueness theorem for equal maximal ranks.

The mathematical model, risk-first default, Mermaid state graph, and Lean proof
map live in
[[file:45-120-23-source-bound-progress-classification-coherence.org][45-120-23 source-bound progress classification coherence]].

** Bare remaining values do not close deterministic budget evidence

=SourceBoundProgressReceipt= exposes semantic and scheduling remaining values,
but neither it nor =SourceBoundFixedPointReceipt= identifies the budget plan,
owner, original limits, consumption, or conservation proof.  Therefore
=remaining = 0= alone does not prove that the authorized budget for this
fixed-point evaluation was exhausted.

The v1 repair introduces an independent
=SourceBoundDeterministicBudgetEvidenceClosed= owner and composes it with
=SourceBoundProgressEvidenceClosed=.  A separate runtime-separation proof gives
a matching-coordinate watchdog counterexample: threshold exceedance can coexist
with positive semantic and scheduling remaining values.

The complete mathematical model, Mermaid state graph, ownership table, and
implementation checklist live in
[[file:45-120-22-source-bound-deterministic-budget-closure.org][45-120-22 source-bound deterministic budget closure]].

** A cycle observation is evidence, not retry authority

=CycleDetectedObservation= binds:

- registry digest;
- generation;
- strongly connected component members;
- causal path;
- provenance digest;
- consumed semantic and scheduling budgets;
- continuation identity.

Lean proves:

#+begin_src text
cycleObservationDoesNotAuthorizeRetry
#+end_src

The continuation identity makes the suspension observable.  It does not
make the observation executable.  Retry still requires the existing
runtime-local, single-use =RetryCapability= and its owner-valid
admission.  A profile and a cycle receipt cannot mint that capability.

** Matching cycle fields do not prove structural cycle closure

The initial cycle structure stored SCC members and causal paths as string
identities.  It also lacked an explicit closing edge.  Two distinct
source-bound revisions with the same string identity therefore collapse
into one apparent SCC member.

Lean proves:

#+begin_src text
identityOnlyCycleCannotDistinguishSourceRevision
#+end_src

Matching registry digest and generation are also insufficient.  A cycle
observation can name a ghost SCC and ghost path while satisfying both
fields.

Lean proves:

#+begin_src text
matchingCycleFieldsDoNotProveVisitedSubjectClosure
#+end_src

The corrected =SourceBoundCycleDetectedObservation= records complete
subjects and an explicit closing edge.  Its structural closure requires:

- nonempty SCC members;
- every SCC and path subject is in the fixed-point visited set;
- every path subject belongs to the SCC;
- every adjacent path pair is a real source-bound composition link;
- the path starts and ends at the same complete subject;
- the final path edge equals the explicit closing edge;
- the closing edge exists in the exact registry.

Lean proves:

#+begin_src text
completeSourceBoundCycleEvidenceCloses
closedSourceBoundCycleMemberIsReachable
sourceBoundCycleMembersAreReachable
sourceBoundCycleObservationDoesNotAuthorizeRetry
#+end_src

The final theorem retains the existing authority boundary: a complete,
source-bound cycle observation still cannot authorize retry.

** A closed causal path does not prove that every named SCC member belongs to the cycle

The first source-bound refinement still admitted one false classification.
Roots may legitimately contain two disconnected components.  If one
component contains a real cycle and the other component is a separately
reachable, registered root, then roots-included, link-closed, minimal, and
registered fixed-point evidence all remain true.  Merely requiring every
named SCC member to be visited nevertheless permits the disconnected root
to be inserted into =sccMembers= even though it is not mutually reachable
with the causal cycle.

Lean proves the complete counterexample:

#+begin_src text
pathClosedCycleCanIncludeDisconnectedSccMember
#+end_src

This is an SCC-classification defect, not a reason to create a second
declaration-closure protocol.  The correction strengthens
=poo-flow.lean-declaration-closure.v1= with the internal relation
=SourceBoundSccReachableWithin=.  Every source and target in the named SCC
must have a finite composition-link path whose intermediate subjects remain
inside that same SCC.  =cycleObservationSubjectClosed= now requires both the
existing path/closing-edge evidence and =sccStronglyConnected=.

Lean proves the positive source-bound SCC:

#+begin_src text
sourceBoundCycleSccStronglyConnected
completeSourceBoundCycleEvidenceCloses
#+end_src

Strong connectivity alone still does not establish a canonical SCC member
sequence.  The list =[A, B, A]= is strongly connected but repeats one
complete subject, so it cannot own a stable SCC identity or a one-to-one
per-subject evidence projection.

Lean proves:

#+begin_src text
strongConnectivityDoesNotProveCanonicalSccMembership
#+end_src

The v1 correction therefore requires =sccMembers.Nodup= in addition to
pairwise SCC-internal reachability.  This is a stronger internal proof
obligation for the existing declaration-closure path, not a new schema.

** Progress coordinates do not bind a complete subject or justify a classification

The initial =ProgressReceipt= binds only registry digest, generation, one
semantic fingerprint, one remaining-obligations digest, and a
=ProgressClass= label.  Registry and generation coordinates do not identify
which complete source-bound SCC was classified.  A single payload also
contains no before/after relation capable of distinguishing =converged= from
=regressing=.

Lean proves both counterexamples:

#+begin_src text
progressCoordinatesCannotBindCompleteCycleSubject
identicalProgressPayloadCanCarryContradictoryClassifications
#+end_src

The source-bound v1 refinement introduces proof-internal
=SubjectProgressEvidence= for each exact SCC subject.  Each entry carries the
complete object subject, previous/current semantic fingerprints, fingerprint
history, and previous/current remaining-obligation digests.
=SourceBoundProgressEvidenceClosed= requires:

- an independently owner-valid pure =SourceBoundProgressContract=;
- an independently owner-valid progress receipt;
- an already closed source-bound cycle observation;
- exact registry, generation, and cycle-observation identity binding;
- exact, duplicate-free coverage of the canonical SCC subject list;
- classification evidence supplied by the domain contract.

Classification is no longer accepted as a label.  Convergence requires
semantic equivalence and completed obligations for every governed subject.
Advancement requires every subject to be equivalent or monotonically improved
and at least one actual improvement.  Stall, regression, incomparability,
oscillation, and deterministic budget exhaustion each have separate
sufficient evidence.

Lean proves:

#+begin_src text
completeSourceBoundProgressEvidenceCloses
closedProgressEvidenceSubjectIsVisited
closedProgressClassificationHasOwnerEvidence
#+end_src

** A watchdog identifier is not runtime evidence

The initial progress receipt carries only an optional
=watchdogObservationId=.  The identifier can be present while no observation
exists.  Even when an observation with that identifier exists, identity alone
does not bind registry, generation, cycle observation, continuation, runtime
owner, phase, metric, unit, threshold, or provenance.

Lean proves:

#+begin_src text
watchdogObservationIdDoesNotProveObservationExists
matchingWatchdogIdDoesNotProveCoordinateBinding
#+end_src

A scalar process-tree RSS value is also not attribution.  Summed RSS can
double-count shared pages and cannot identify the owning phase or largest
process.  A memory watchdog receipt therefore records tree RSS, largest
process identity and RSS, and at least one PSS or platform-footprint
measurement.

Lean proves:

#+begin_src text
scalarTreeRssExceedanceDoesNotProveMemoryAttribution
#+end_src

The v1 refinement separates two owner relations:

- =SourceBoundProgressEvidenceClosed= owns semantic classification;
- =SourceBoundRuntimeWatchdogBindingClosed= owns runtime observation
  reference, exact coordinates, metric/unit compatibility, threshold
  exceedance, and metric-specific attribution.

=SourceBoundRuntimeWatchdogEvidenceClosed= composes the two relations in
Lean.  AXLE verifies their independent roots plus the consequence-level
composition, avoiding a false requirement that one owner source closure
materialize both complete proof implementations.

Lean proves:

#+begin_src text
closedWatchdogReferenceBindsRuntimeCoordinates
completeSourceBoundRuntimeWatchdogBindingCloses
independentlyClosedProgressAndWatchdogEvidenceCompose
completeSourceBoundRuntimeWatchdogEvidenceCloses
#+end_src

A matching watchdog observation still cannot decide the semantic
classification and cannot authorize retry.

#+begin_src text
matchingWatchdogObservationDoesNotDetermineSemanticClass
runtimeWatchdogObservationDoesNotAuthorizeRetry
#+end_src

** Matching fields do not prove owner validity

Lean proves:

#+begin_src text
matchingFixedPointFieldsDoNotProveOwnerValidity
#+end_src

Digest, generation, stable state, and empty pending work remain data.

* Corrected closure

The proof transport for this refinement stabilizes
=poo-flow.lean-declaration-closure.v1=.  Source ranges, generated-declaration
normalization, phase timing, and bounded root sharding are v1 implementation
refinements only.  This RFC does not authorize a v2 declaration-closure
schema, a second closure identity, or a competing proof path.

The completed v1 proof run did not admit root sharding.  All four root
theorems, including =completeFixedPointEvidenceCloses=, close within the
30-second per-operation AXLE budget after correcting two defects in the
original proof transport:

1. Environment constant closure alone omitted constructor-carried source
   dependencies such as reducible field aliases.
2. AXLE document reserialization was incorrectly treated as canonical source,
   expanding the largest canonical payload from 16606 bytes to 24568 bytes.

The repaired fixed point alternates environment dependency closure with
Lean-owned source-family expansion.  Only inductive or structure anchors and
constructors act as additional dependency carriers; recursors,
=noConfusion= declarations, derived instances, and declarations without a
source range remain traversal evidence rather than independent source assets.
Canonical source is the deterministic projection of Lean-owned ranges and
owner-source digests.  AXLE validates that source and its quotient identity.

The proof is formalized by:

- =environmentClosureAloneDoesNotImplySourceReplayClosure=, which preserves the
  concrete counterexample;
- =sourceFamilyAndEnvironmentClosureImplyReplayClosure=, which proves the
  repaired sufficiency condition;
- =nonSourceBearingTraversalNodeIsAbsentFromReceiptProjection=, which separates
  internal traversal constants from receipt declarations.

All three theorems live in
=PooFlowProof/Export/DeclarationClosureModel.lean=.  The four AXLE receipts are
green with empty Lean errors, Lean warnings, and failed-declaration sets.

=FixedPointEvidenceClosed= requires:

- the effect witness plan and roots match the promotion request;
- the composition registry and effect witness are owner-valid;
- the fixed-point receipt is owner-valid;
- receipt registry, roots, and effect universe match the witness;
- the receipt is stable and has no pending work;
- every root is visited;
- the visited set is closed under composition links;
- every visited node is reachable from the roots;
- every visited identity is registered in the exact registry;
- the progress receipt and pure domain Contract are independently
  owner-valid;
- progress binds the same registry, generation, exact cycle-observation
  identity, and duplicate-free complete SCC subject sequence;
- every accepted progress classification has before/after fingerprint and
  obligation evidence sufficient under that Contract;
- every cycle observation is owner-valid, binds the same registry, and
  does not name a future generation.

Lean then proves:

#+begin_src text
closedReceiptContainsEveryReachableNode
closedReceiptIsLeastFixedPoint
completeFixedPointEvidenceCloses
#+end_src

The least-fixed-point theorem is the correction to the weaker
=stable=true= design.

The source-bound refinement strengthens that theorem with:

- complete subject roots, visited entries, pending entries, and links;
- unique complete subjects in the registry;
- explicit visited-subject registry membership;
- owner-valid whole-object binding evidence for each visited subject;
- a matching owner-valid package, revision, and source-tree resolution
  receipt for each visited subject.

Lean proves:

#+begin_src text
sourceBoundClosedReceiptContainsEveryReachableSubject
sourceBoundClosedReceiptIsLeastFixedPoint
sourceBoundClosedVisitedSubjectHasUniqueObject
sourceBoundClosedVisitedSubjectHasBindingAndResolution
completeSourceBoundFixedPointEvidenceCloses
#+end_src

The source-bound proof is a refinement of the existing receipt semantics,
not a new fixed-point engine or a public =use-composition= form.

  and "WatchdogBindingClosed"(P, C, W)
  => "ClassificationSupported"(K, P)
  and "RuntimeAnomalyObserved"(W) $

$ "RuntimeAnomalyObserved"(W)
  => not "SemanticClassDeterminedByWatchdog"(W)
  and not "RetryAuthorizedByWatchdog"(W) $

$ "Closed"(Q, G, H, F, P, C^*) =
  "RegistryValid"(H_"registry", G)
  and "WitnessValid"(H)
  and "FixedPointReceiptValid"(F)
  and "ProgressReceiptValid"(P)
  and (forall C in C^*: "CycleValid"(C))
  and F_"registry" = H_"registry"
  and F_"roots" = H_"roots"
  and F_"effects" = H_"effects"
  and F_"stable" = "True"
  and F_"pending" = ()
  and "UniqueSubject"(G)
  and "FixedPoint"(F_"visited", F_"roots", G)
  and (forall x in F_"visited":
    "ObjectBindingValid"(x)
    and "SourceResolutionReceiptValid"(x)) $
#+end_src

The finite-capacity statement is conditional on an owner-valid
sub-permutation witness over complete subjects.  A raw list with
duplicate string identities does not establish termination and can
collapse distinct revisions.  =Registered= is independent from
=Minimal=: a selected root is reachable even when no registry object
materializes it.

* Owner boundaries

- =gerbil-poo= remains the unique Scheme POO implementation and the
  implementation substrate for pure objects and prototype composition.
- POO Flow defines the mix-module evidence contract and composes
  owner-valid objects; it does not reimplement a generic fixed-point
  library.
- The composition owner binds the finite registry, worklist state, and
  least-closure receipt.
- The progress owner classifies convergence, advance, stall,
  incomparability, regression, oscillation, and budget exhaustion.
- The scheduling owner settles dequeue and dispatch work.
- The runtime watchdog owns time and runtime-anomaly observations.
- The recovery coordinator consumes evidence but cannot resume without
  the runtime-local =RetryCapability=.
- Lean owns countermodels and abstract implications, not runtime
  authenticity.
