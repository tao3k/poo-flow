* Ownership boundary

The provider returns a parser-native projection.  It does not construct the
final exact-selector identity packet.

#+begin_src mermaid
flowchart LR
  Request["ASP exact-selector request"] --> Snapshot["ASP source snapshot and owner bytes"]
  Request --> Provider["GSLPH provider"]
  Provider --> Native["provider-native exact projection"]
  Native --> Builder["ASP build_exact_selector_projection_packet_v1"]
  Snapshot --> Builder
  Builder --> Packet["typed exact-selector packet"]
  Packet --> Merkle["Merkle validation and persistence"]
  Merkle --> Output["cold or warm projection output"]
#+end_src

The boundary is intentional:

- GSLPH parses Gerbil source and returns the selected projection plus normalized
  parser facts.
- GSLPH does not read or validate the ASP source-snapshot envelope.
- GSLPH does not implement BLAKE3.
- GSLPH does not invent =sourceBlobDigest= or =parserFactDigest=.
- ASP derives the canonical item identity from the structural selector.
- ASP computes source and parser-fact digests with the content-identity crate.
- ASP performs the final request identity, source digest, proof identity,
  Merkle, persistence, and warm-hit checks.

* Provider-native projection contract

The version-1 provider-native JSON projection contains:

- =schemaId=:
  =agent.semantic-protocols.provider-native-exact-projection=
- =schemaVersion=: =1=
- =languageId=
- =providerId=
- =ownerPath=
- =structuralSelector=
- =projectionMode=
- =normalizedParserFacts=
- =projectionText=

It deliberately does not contain:

- =digestAlgorithm=
- =canonicalItemSelector=
- =sourceBlobDigest=
- =parserFactDigest=
- =projectionEncoding=
- =projectionPayloadBase64=

Those fields belong to the final ASP-owned
=ExactSelectorProjectionPacketV1=.

* Dispatcher construction rule

The ASP dispatcher accepts either:

1. an already valid final exact-selector packet from a provider with a native
   implementation of the complete content-identity contract; or
2. a version-1 provider-native projection.

For the second route, the dispatcher:

1. validates the native schema and activated request identity;
2. parses =structuralSelector= into =CanonicalItemSelectorV1=;
3. serializes =normalizedParserFacts= deterministically;
4. calls =build_exact_selector_projection_packet_v1= with the ASP-owned source
   bytes, parser identity, query-pack identity, owner, selector, and mode;
5. applies the existing final-packet validation, enrichment, persistence, and
   warm-hit path.
