* Approved POO prototype direction

The POO prototype model is the sole semantic kernel of this RFC suite.
Profile, Mix, Module, Capability, and Submodule are roles or projections of
POO prototype objects; they are not parallel object systems and do not form a
second nominal class hierarchy.

In Scheme, =gerbil-poo= is the core implementation and the only POO library.
The root =gerbil.pkg= identifies it as
=github.com/mighty-gerbils/gerbil-poo@1c3225637525400341a09e958296962c10184ead=.
Every POO object, prototype operation, slot behavior, recursive-object
primitive, and general POO extension used by this RFC suite is owned by that
library.  POO Flow is a consumer that defines higher-order roles and governance
with =gerbil-poo= objects; it is not another POO implementation.

The conceptual and paper lineage is
[[https://github.com/metareflection/poof][metareflection/poof]], “Prototypes: Object Orientation, Functionally”.
=gerbil-poo= is the Gerbil Scheme implementation of that POO direction.
General semantic reasoning is grounded in the paper lineage; executable Scheme
semantics and reusable POO extensions are grounded in the exact =gerbil.pkg=
dependency revision.

All public composition forms MUST lower to ordinary POO prototype operations.
The result of composition MUST remain a POO prototype and MUST therefore be
available as an input to later composition, extension, inheritance, or a
Submodule boundary.

Any mechanism that is meaningful for an arbitrary POO program independently
of Profile, Mix, governance, or runtime handoff belongs to =gerbil-poo=.  This
includes generic prototype linearization, recursive-object and fixed-point
machinery, demand cells, memoization, dependency-cycle detection, and
continuation-aware evaluation.  POO Flow owns only the higher-order roles,
staged authoring surface, governance policies, runtime boundaries, and
qualification projections built with those mechanisms.

Within one composition boundary, the expander MUST normalize all profile and
refinement contributions into one ordered, flat lineage.  It MUST NOT emit a
tree of nested binary composition calls.  A nested Submodule establishes a
new composition boundary with its own flat lineage; it does not introduce a
different merge language.

The approved public surface is owned by [[file:45-07-user-composition-and-mix-module-interface.org][45-07]].  Prototype closure, identity,
and capability refinement are owned by [[file:45-06-gerbil-poo-api-alignment.org][45-06]].  Demand cycles and recoverable
control are owned by [[file:45-05-lineage-and-cycle-detection.org][45-05]] and [[file:45-03-runtime-context-and-recovery.org][45-03]].  The three-plane
observability contract is owned by [[file:45-04-observability-and-debugging.org][45-04]].

* Cross-module invariants

- Public composition remains POO-native and functional-first.
- Public syntax remains =user-composition=, =use-composition=, =profiles=,
  =compose=, and canonical =use-module MODULE as ALIAS=.
- POO Flow reuses pinned =gerbil-poo= fixed-point and prototype composition.
- POO Flow does not implement another fixed point or replace arbitrary =.ref=.
- The parent owns =poo-flow-core=; a child package does not repeat parent G0.
- =gerbil.pkg=/=gxpkg= own package management only.
- Gerbil-Bazel owns build execution only.
- GSLPH is a development policy/build/test harness only.
- Condition, observability event, and DecisionReceipt remain distinct.
- No implementation begins until the modular RFC contracts are approved.
