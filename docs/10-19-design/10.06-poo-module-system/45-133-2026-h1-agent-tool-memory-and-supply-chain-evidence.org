* Tool discovery is not authority

** ENT-TOOL-2026-001: browser content enters agent context

- Date: 2026-03-21.
- Source kind/status: closed issue report in Microsoft Playwright MCP.
- Source:
  [[https://github.com/microsoft/playwright-mcp/issues/1479][indirect prompt injection through accessibility snapshots]].
- Reported claim: attacker-controlled accessibility text may enter the same model
  context as instructions, while a multi-page browser session retains earlier data.
- Confidence boundary: the issue is a reported attack path, not a POO Flow reproduction.
- Candidate obligations:
  - every tool response carries origin, trust, tenant, session, and sensitivity labels;
  - untrusted response content cannot become authority;
  - page/session transitions preserve noninterference;
  - later actions retain causal lineage to the untrusted observation.
- State: open.

** ENT-TOOL-2026-002: code-valued tool arguments

- Date: 2026-03-30.
- Source kind/status: closed issue report in Microsoft Playwright MCP.
- Source:
  [[https://github.com/microsoft/playwright-mcp/issues/1495][reported browser_run_code sandbox escape and RCE]].
- Reported claim: a string-valued code argument was reported to escape the intended
  VM boundary through a host object and reach process-level command execution.
- Confidence boundary: the catalog records the reporter's claim and reproduction
  description; it does not assert independent exploit verification.
- Candidate obligations:
  - tool schemas describe semantic effects, not only transport types;
  - code-valued arguments require an explicit high-risk capability;
  - sandbox identity and implementation identity are certificate inputs;
  - a tool cannot claim a weaker effect class than its reachable implementation.
- State: open.

** ENT-TOOL-2026-003: discovery-to-execution gap

- Date: 2026-04-27.
- Source kind/status: open Hermes Agent feature/security issue.
- Source:
  [[https://github.com/NousResearch/hermes-agent/issues/16462][first-invoke approval for MCP tools]].
- Reported claim: discovered MCP tools were dynamically registered and immediately
  callable through a dispatch path that did not share terminal approval gates.
- Confidence boundary: this is an upstream issue report and proposal.
- Candidate obligations:
  - discovery and registration do not issue execution authority;
  - first use requires a capability whose identity includes server and tool;
  - equivalent effects receive equivalent admission independent of dispatch path;
  - approval lifetime and reset events are explicit.
- State: open.

** ENT-TOOL-2026-004: archived provider and network authority

- Date: 2026-03-21.
- Source kind/status: issue closed as not planned against an archived MCP server.
- Source:
  [[https://github.com/modelcontextprotocol/servers/issues/3662][reported SSRF, prompt injection, and sandbox bypass in server-puppeteer]].
- Reported claim: an archived but still consumed server accepted broad navigation
  targets and exposed evaluation paths; the reporter described internal-network
  and cloud-metadata attack chains.
- Confidence boundary: download counts and exploitability are reporter claims.
- Candidate obligations:
  - archived or unmaintained provider identity fails admission unless explicitly waived;
  - network targets are resources governed by scheme, host, address class, and purpose;
  - no legacy provider fallback is implicit;
  - provider lifecycle state participates in every execution certificate.
- State: open.

** ENT-TOOL-2026-005: per-call governance is not sequence governance

- Date: 2026-04-22.
- Source kind/status: official Microsoft developer research/blog; toolkit in public preview.
- Source:
  [[https://developer.microsoft.com/blog/securing-mcp-a-control-plane-for-agent-tool-execution/][Securing MCP with an agent tool control plane]].
- Reported claim: deterministic per-call enforcement is placed between discovery
  and execution; the stated limitation is that individually allowed calls are not
  yet correlated into workflow-level policy.
- Confidence boundary: vendor benchmark and performance numbers are not adopted as
  POO Flow proof evidence.
- Candidate obligations:
  - every action is admitted before runtime handoff;
  - sequence safety is not derived from pointwise authorization;
  - workflow intent and cumulative effects are explicit state;
  - Cedar dual-engine results are bound to the exact action and sequence prefix.
- State: open.

* Persistent memory is a temporal authority surface

** ENT-MEM-2026-001: recommendation and memory poisoning in the wild

- Date: 2026-02-10.
- Source kind/status: Microsoft Defender Security Research report.
- Source:
  [[https://www.microsoft.com/en-us/security/blog/2026/02/10/ai-recommendation-poisoning/][AI Recommendation Poisoning]].
- Reported claim: over 60 days the team identified 50 prompt-based attempts from
  31 companies across more than a dozen industries to influence assistant memory.
- Candidate obligations:
  - external content cannot authorize a memory write;
  - memory writes bind user intent, provenance, purpose, and affected scope;
  - retrieved memory is requalified for freshness, trust, and tenant scope;
  - memory revocation removes future authority while retaining a redacted audit witness.
- State: open.

** ENT-MEM-2026-002: delayed activation

- Date: 2026-06-22.
- Source kind/status: Microsoft Security architecture/research blog.
- Source:
  [[https://www.microsoft.com/en-us/security/blog/2026/06/22/guarding-ai-memory/][Guarding AI memory]].
- Reported claim: memory may shape behavior and tool calls after the original
  context has disappeared; memory events may be asynchronous to user interaction.
- Candidate obligations:
  - memory exposure, persistence, retrieval, and action are separate transitions;
  - every delayed action retains causal lineage to the originating observation;
  - an approval cannot be replayed across a changed context or stale memory version;
  - erasure and revocation invalidate dependent future actions.
- State: open.

* Agentic supply-chain identity

** ENT-SUPPLY-2026-001: compromised package publication

- Date: 2026-03-24.
- Source kind/status: open LiteLLM incident issue with maintainer updates.
- Source:
  [[https://github.com/BerriAI/litellm/issues/24518][LiteLLM PyPI compromise timeline]].
- Reported claim: malicious versions =1.82.7= and =1.82.8= were published outside
  the stated GitHub release path; maintainers deleted packages, rotated accounts,
  and investigated blast radius.
- Confidence boundary: this catalog does not independently establish every affected
  consumer or credential.
- Candidate obligations:
  - source revision, build receipt, package digest, and runtime artifact identity
    are distinct and must correspond;
  - an unrecognized publication path fails closed;
  - compromise revocation invalidates every certificate depending on the artifact;
  - rotation closure records affected principals, secrets, builds, and deployments;
  - aliases such as “latest” cannot discharge exact artifact identity.
- State: open.

** ENT-SUPPLY-2026-002: updated agentic failure taxonomy

- Date: 2026-06-04.
- Source kind/status: Microsoft AI Red Team research blog.
- Source:
  [[https://www.microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us/][updated failure-mode taxonomy]].
- Reported claim: the update adds agentic supply-chain compromise, inter-agent trust
  escalation, session contamination, MCP/plugin abuse, and capability disclosure;
  it reports human-in-the-loop bypass through incremental escalation.
- Confidence boundary: aggregate incident and vulnerability counts remain the
  publisher's research claims.
- Candidate obligations:
  - delegation claims are independently verified at every agent boundary;
  - session context has provenance-preserving accumulation;
  - tool definitions are supply-chain inputs, not trusted instructions;
  - cumulative low-risk actions cannot bypass high-risk workflow authorization.
- State: open.

* Mathematical obligations

#+begin_src typst
$ "Discovered"(t) and not "CapabilityIssued"(t) => not "Authorized"(t) $

$ "Content"(c) and "Untrusted"(c)
  => not "CanCreateCapability"(c) $

$ "PointwiseSafe"(x_1, dots, x_n) <=>
  "AllAuthorized"(x_1, dots, x_n) $

$ "PointwiseSafe"(x_1, dots, x_n) and "UnsafeCumulativeEffect"(x_1, dots, x_n)
  => not "WorkflowSafe"(x_1, dots, x_n) $

$ "MemoryAction"(m, x) =>
  "Valid"("WriteProvenance"(m))
  and "Fresh"("Version"(m))
  and "SameTenant"(m, x)
  and "CausalLineage"("Write"(m), "Read"(m), x) $

$ "ArtifactValid"(a) =>
  "SourceId"(a) = "CertifiedSource"(a)
  and "BuildId"(a) = "CertifiedBuild"(a)
  and "Digest"(a) = "CertifiedDigest"(a)
  and "RuntimeId"(a) = "CertifiedRuntime"(a) $

$ "Revoked"(a) and "Depends"(c, a) => not "Valid"(c) $
#+end_src

* Independent Lean owners

| Proposed module | Responsibility |
|-----------------+----------------|
| =Enterprise.ToolDiscoveryAuthority= | Discovery, registration, capability issuance, and first use |
| =Enterprise.ToolEffectRefinement= | Schema effect class versus reachable implementation |
| =Enterprise.WorkflowSequenceSafety= | Prefix state, cumulative effect, and non-pointwise authorization |
| =Enterprise.MemoryLifecycleAuthority= | Write, retrieve, use, revoke, erase, and causal lineage |
| =Enterprise.AgenticSupplyChainIdentity= | Source/build/package/runtime correspondence and revocation |
| =Enterprise.SessionContextProvenance= | Provenance-preserving context accumulation and contamination resistance |

These are proof-layer owners.  They do not make external MCP servers, Microsoft
toolkits, or LiteLLM dependencies of POO Flow.

* Evidence-quality exclusions

- The 2026-04-07 LiteLLM issue =#25295= about per-agent spend governance is not
  admitted as incident evidence: its author withdrew it as off-topic for that
  tracker.  Budget attenuation remains a valid internal research question, but
  this issue cannot support the claim that LiteLLM exposed such a defect.
- Search-result summaries without a reachable canonical issue or publication are
  not admitted.
- A closed issue is not treated as a fixed issue without a linked fix identity and
  an executable reproduction receipt.

* Proof checklist

- [ ] Formalize discovery without authority.
- [ ] Prove untrusted content cannot construct a capability.
- [ ] Prove equivalent effects share admission across dispatch paths.
- [ ] Give a minimal counterexample showing pointwise-safe actions form an unsafe workflow.
- [ ] Prove workflow-prefix authorization and cumulative-effect monotonicity.
- [ ] Formalize asynchronous memory transitions and delayed causal lineage.
- [ ] Prove memory revocation and erasure invalidate dependent future actions.
- [ ] Prove source/build/package/runtime artifact correspondence.
- [ ] Prove compromise revocation invalidates dependent certificates.
- [ ] Add executable counterexamples for every adopted source.
- [X] Run the related existing enterprise Lean and AXLE surfaces together.
- [ ] Implement and validate the new independent Lean owners proposed by this RFC.
- [ ] Attach explicit discharge or rejection certificates.
