#+title: User Composition Semantic Evidence Facet
#+status: Accepted
#+language: en

* Decision

The POO object produced for a =user-composition= has two conceptually parallel
facets:

- the ordinary business POO graph;
- a hygienically isolated semantic evidence POO graph.

The evidence facet is accessed through native =gerbil-poo= reflection and an
imported hygienic slot binding.  It is not a string-key registry, command DSL,
provider interface or nested composition layer.

Live continuations, resumption capabilities, authority handles and resource
leases are never placed in the semantic evidence facet.

* Ordinary user composition remains unchanged

The ordinary interface remains:

#+begin_src scheme
(user-composition my-system
  (compose profiles
    wendao-episteme
    production))
#+end_src

Users do not need to add:

#+begin_example
observability-profile
cache-debug-profile
explanation-provider
nested user-composition
#+end_example

Canonical semantic evidence is required for correctness and is therefore
always produced.  A Profile may control authorized projection detail,
retention, redaction or observation budgets.  It cannot disable the evidence
needed to justify composition, reuse, convergence or recovery.

* Hygienic evidence access

Conceptually, the evidence root is obtained through native slot access:

#+begin_src scheme
(.@ my-system composition-evidence)
#+end_src

=composition-evidence= denotes an imported hygienic binding established by the
module interface and macro expansion.  It is not a raw string or runtime token.

The final implementation MAY use the appropriate native lexical-slot or
binding mechanism supplied by =gerbil-poo=.  It MUST preserve these
properties:

- no collision with an industry object's own =evidence= or =receipt= slot;
- no pollution of ordinary business-shape reflection;
- no string-path dispatch;
- no hidden global evidence registry;
- no alternative object or record model;
- expansion to ordinary native POO access.

#+begin_src mermaid
flowchart LR
  U["user-composition result"] -->|"ordinary native slot demand"| V["Business POO graph"]
  U -->|"explicit hygienic binding access"| E["Semantic evidence facet"]
  E -->|"mirrors demanded object and submodule identities"| G["Evidence POO graph"]
  G -->|"native slot access selects one demand receipt"| X["Invalidation explanation"]
  X -->|"native reflection exposes causes and affected demands"| C["Causal evidence closure"]
#+end_src

* Parallel object graphs

The evidence graph mirrors the semantic identities of observed business
objects without becoming part of their industry data shape.

#+begin_example
my-system
|-- business POO graph
`-- composition-evidence
    |-- generation
    |-- semantic-receipt
    |-- wendao-episteme
    |   `-- index
    |       |-- definition
    |       |-- invalidation
    |       |-- dependencies
    |       |-- conditions
    |       `-- predecessor
    `-- production
        `-- summary
            `-- ...
#+end_example

This is a semantic topology, not a filesystem layout or registry schema.

Submodule evidence follows submodule identity recursively.  Any to-B, to-C or
deeper composition retains its own generation, capability, authority,
dependency and receipt evidence within the mirrored graph.

* Native reflection only

Conceptually, a user may traverse the evidence graph with ordinary native POO
access:

#+begin_src scheme
(def evidence
  (.@ my-system composition-evidence))

(def wendao-evidence
  (.@ evidence wendao-episteme))

(def index-evidence
  (.@ wendao-evidence index))

(.@ index-evidence invalidation)
#+end_src

The identifiers shown here represent hygienically bound semantic slots.  The
interface MUST NOT lower them to quoted string paths or raw symbol dispatch.

Native =.has?=, =.key?=, =.all-slots= or other =gerbil-poo= reflection may be
used on evidence objects according to their native semantics.  No
=explain-cache-miss= command family is required.

* Observation must not create business demand

Evidence reflection projects observations that already exist in the current
generation.  It MUST NOT force an unobserved business slot merely to produce an
explanation.

#+begin_src mermaid
flowchart TD
  Q["Evidence query for slot S"] -->|"S was demanded in this generation"| R["Return S demand evidence"]
  Q -->|"S was not demanded"| U["Return an unobserved evidence projection"]
  U -->|"does not force the business slot"| N["Dependency graph remains unchanged"]
  R -->|"projects existing receipt without reevaluation"| N
#+end_src

An unobserved projection may state:

- no demand receipt exists in this generation;
- the definition identity is known structurally, if authorized;
- no result, dependency footprint or invalidation outcome has been observed.

It must not fabricate an empty successful result.

This rule ensures that debugging does not change the fixed point it attempts to
explain.

* Generation-specific immutable object

A composed system object and its evidence facet are bound to one contribution
generation.

#+begin_example
my-system@generation-41
`-- composition-evidence@generation-41
#+end_example

Recovery, refinement or new contribution produces a successor:

#+begin_example
my-system@generation-42
|-- predecessor -> generation-41 semantic receipt
`-- composition-evidence@generation-42
#+end_example

The previous system object is not mutated to point at current evidence.  This
preserves deterministic reflection, cache identity, continuation binding and
replay.

#+begin_src mermaid
flowchart LR
  G1["System object generation 41"] -->|"owns immutable semantic evidence"| E1["Evidence facet generation 41"]
  E1 -->|"authorized recovery contributes new semantic input"| G2["System object generation 42"]
  G2 -->|"owns a new immutable facet"| E2["Evidence facet generation 42"]
  E2 -->|"links predecessor receipt without mutating it"| E1
#+end_src

* Semantic evidence contents

The semantic evidence facet may expose authorized pure POO evidence for:

- contribution generation;
- system and submodule identity;
- prototype and slot-definition identity;
- complete contribution closure;
- slot-contract and priority decisions;
- dependency footprint;
- sealed SCC identity and convergence;
- invalidation explanation;
- canonical condition closure;
- predecessor semantic receipts;
- semantic reuse and replay equivalence;
- canonical logical budgets;
- links to separate operational receipts.

Operational receipt content does not participate in semantic object identity.

* Live control remains outside the facet

The semantic evidence facet may describe a condition and its authorized
recovery classes.  It cannot carry the live control capability used to resume
execution.

#+begin_src mermaid
flowchart TD
  S["Semantic evidence facet"] -->|"contains inert condition identity and causal witness"| I["Inspectable condition evidence"]
  L["Live condition-handler extent"] -->|"holds current generation-bound authority"| R["Actual resumption capability"]
  I -->|"cannot manufacture or restore authority"| N["No implicit resume"]
  R -->|"authorized recovery creates a successor generation"| G["New system object and evidence facet"]
  G -->|"links the predecessor semantic receipt"| S
#+end_src

The following values are excluded from the semantic facet:

- continuations and resumptions;
- dynamic handler extent;
- live capability or authority handles;
- resource leases and cleanup ownership;
- runtime cancellation handles;
- mutable worker or scheduler state;
- open effect transactions.

* Conditions and recovery projection

An evidence object for a condition may include:

- condition semantic identity;
- causal demand and SCC witness;
- current generation;
- logical budget state;
- recovery classes allowed by policy;
- authority requirements;
- predecessor receipt.

The actual resumption object exists only within the live condition handler.  A
cached, serialized or later-reflected condition explanation cannot revive it.

* Human and machine projection

The evidence POO graph is the semantic interface.  Text, Org, Mermaid, JSON or
interactive views are adapters over an authorized projection.

A renderer:

- may select a concise primary cause;
- must preserve access to the complete causal closure;
- may redact sensitive values while retaining identity commitments;
- must not change evidence identity;
- must not trigger business demand;
- must not become a configuration language.

Org and Mermaid are appropriate durable and visual projections for this
project, but neither format owns the runtime semantics.

* Redaction and observability authority

Evidence access is subject to current observability authority.

- A user may know that a dependency changed without receiving its secret value.
- Binding provenance may be projected only when authorized.
- Capability and authority handles never appear.
- Operational paths, host details and cache locations remain in the operational
  plane.
- Redaction preserves causal edges and stable identity commitments.

Lack of projection authority is not reported as absence of evidence.

* Evidence retention

Retention policy may determine which predecessor projections remain locally
available.  It cannot delete evidence required by an active causal chain,
continuation, replay claim or committed receipt.

Evicting an optional human-readable projection does not alter the canonical
semantic receipt.

* Required failure conditions

Evidence access MUST fail closed or produce an authorized condition when:

- the evidence facet is addressed through a colliding raw string key;
- ordinary business reflection exposes the hidden facet unintentionally;
- evidence lookup forces an unobserved business slot;
- an unobserved slot is presented as an observed empty result;
- a predecessor generation's facet is mutated in place;
- semantic and operational evidence are conflated;
- a reflected condition mints or restores a resumption capability;
- redaction removes causal structure;
- a renderer changes semantic identity or dependency demand;
- retention deletes evidence required by an active causal chain.

* Acceptance checklist

- [X] =user-composition= syntax remains unchanged.
- [X] Correctness evidence is always produced and is not an optional debug
  Profile.
- [X] The evidence facet uses a hygienically isolated native POO binding.
- [X] Business and evidence graphs remain conceptually parallel.
- [X] Submodule evidence recursively follows submodule identity.
- [X] Evidence traversal uses native =gerbil-poo= reflection.
- [X] Evidence lookup never forces an unobserved business slot.
- [X] System objects and evidence facets are immutable and generation-specific.
- [X] Live recovery authority remains in the condition-handler boundary.
- [X] Human-readable renderers are adapters rather than semantic interfaces.
- [X] Redaction preserves causal identity and structure.
- [ ] Validate the interface with executable business-slot collision,
  unobserved-slot, nested-submodule, generation-successor, live-condition,
  redaction and renderer-independence scenarios before implementation begins.
