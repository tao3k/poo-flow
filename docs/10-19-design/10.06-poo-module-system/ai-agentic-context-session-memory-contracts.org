* Decision and evidence boundary

This contract refines [[file:agentic-ai-context-system-design.org][the system design]] and [[file:ai-agentic-context-implementation-plan.org][the implementation plan]].
Session is one independent =session= Module. Context imports its descriptor.
Memory is an optional Feature owned by =ai-agentic-context=. Org-mode and
Orgize remain the content foundation. No separate Session core is introduced.

Commit =22c4b24c3872daac782d3c836fb17369c0fe51c7= delivered the ownership
migration, finite headline projection/replay and Module dependency closure.
The protocols below are implementation contracts, not delivered lifecycle proofs.
The subsequent role alignment separates existing shapes, objects, pure functions
and configuration; it does not implement the new turn or experience protocols.

* Module source roles

Follow [[file:44-current-project-programming-style/01-module-interface-and-source-roles.org][Programming Style 01]]. Every role owns actual content. A filename alone
cannot qualify a Module, and empty placeholder files do not repair ownership.

The Context core roles above align existing implemented behavior. Memory and
Session already have role files, but their new protocol models remain work to
implement; existing files do not establish that those new contracts exist.
Session's currently empty =types.ss= must acquire real input/transition contracts
in the Session implementation slice, before claiming role qualification.

Imports follow =types -> objects -> funs/contracts -> config/provider=.
Specialized files inherit the responsibility of their role. =interface.ss=
owns imports and exports only. Runtime state/effects stay behind the explicit
Host/provider boundary. Public values use native POO prototypes and slot
composition; private runtime records may use compact =defstruct= values.
No new macro DSL, evaluator or dependency resolver is required.
The Module Interface authoring Profile must represent stable role/import rules
and emit actionable diagnostics through the existing loader admission. Semantic
transition and freshness laws remain executable test/proof obligations; a source
keyword check cannot qualify them. Adding role files alone does not close this
authoring Profile gate.

* Dependency direction and operation activation

Context composes the independent Session descriptor through the existing Module
closure. Session's lifecycle contracts must not import Context's implementation
or Memory. Context performs the adapter composition above both semantic owners.
Existing Session Memory integration files are migration inventory: their imports
must move to Context-owned adapters as the new contracts replace those operations.
Moving one descriptor does not close this broader source-dependency obligation.

| Operation | Required selected owners | Required runtime instance or receipt |
|-----------+--------------------------+--------------------------------------|
| Source projection/replay | Context core and Orgize/Query | Current source bytes; no active Session or Memory store |
| Start/disclose a turn | Context core and Session | Active Session revision, exact input and current-use fence |
| Recall retained content | Context core and Memory | Admitted catalog/source references and current Demand |
| Capture a turn experience | Context core, Memory and Session | Admitted turn receipt and explicit retention intent |
| Claim/complete revisit | Memory and qualified Temporal profile | Claim revision, clock domain and assessment cut |
| Durable publication/recovery | Owning protocol plus qualified Data adapter | Transaction receipt, expected revision and durable pending state |

The dependency descriptor is always present in Context's Module closure.
"Without a Session" means without an active Session instance/history.
Selecting Memory neither starts a Session nor creates a scheduler or store.

* Context to Session input boundary

Session owns a generic immutable =SessionInputRef= contract. Its fields are
producer identity, contract version, input identity/digest, scope digest,
source-vector digest, query/restriction/profile digests, completeness, and the
producer admission receipt reference. Session preserves these bindings without
parsing Org or deciding whether evidence is true. Context produces and admits
the corresponding projection and owns its semantic interpretation.

A caller-created object is a proposal. Neither a digest nor an =admitted?= slot
makes it trusted. The coordinator resolves the receipt against the configured
producer boundary and obtains current authorization for the exact input,
Session/turn revision, actor, destination and purpose. Provider destination and
purpose require explicit bindings beyond today's Scope fields; extending the
current six-field Context Use ABI requires separate versioned consumer work.

Immutable content/projection admission, current disclosure permission, provider
completion, result admission and durable publication have different receipts.
A provider's completion receipt does not complete an admitted Session turn.
A historical allowed receipt cannot authorize another disclosure or effect.

* Session revisions and transition contract

Session values bind identity, parent lineage, organization/epoch, project,
worktree, actor/task, policy revision, status, revision and pending obligations.
Turn values bind identity, Session revision, exact input references, provider
request identity, result proposals, outcome and cancellation observations.
Revisions use monotone owner coordinates; restoring a checkpoint cannot reuse
an earlier coordinate or make a closed Session active.

Pure transition functions return a new value and an intent/receipt proposal.
A runtime coordinator publishes it only if the expected revision and required
current-use fences match. No pure function performs provider dispatch or CAS.

| Transition | Required state and fence | Published result |
|------------+--------------------------+------------------|
| Prepare | created; expected Session revision | preparing with explicit obligations |
| Activate | preparing; obligations satisfied under current profile | active with admitted input references |
| Begin turn | active; expected Session revision; no conflicting open turn | New turn identity and disclosure intent |
| Disclose | Current turn/input revision and current source/scope/policy/lease | Exact dispatch receipt bound to request identity |
| Observe provider completion | Matching request identity | Historical completion proposal; no authority promotion |
| Admit result | Matching input/turn revision and current consumption fence | Result receipt and one terminal turn outcome |
| Request cancellation | Nonterminal turn; expected revision | Cancellation intent and durable pending obligation |
| Observe cancellation | Matching worker/request terminal observation | Acknowledged cancellation; provider receipt retained |
| Suspend/resume | Expected revision; resume re-enrolls all current fences | suspended/active with preserved pending obligations |
| Close | closing; terminal worker observations or explicit isolation receipts | closed, with unresolved external effects recorded |

A rejected result may remain historical evidence under retention policy; it
cannot become current turn content or authorize an action. =blocked= records a
terminal outcome for that turn; retry creates a new turn and input binding.
Competing completion/cancellation publications resolve at the owner CAS.
External completion after cancellation remains an observation and cannot change
the already published terminal outcome. Effectful work also needs its own
idempotency/commit protocol; a Session CAS alone cannot undo an external effect.

* Invalidation and recovery

Source correction, restriction/profile change, epoch/grant retirement and lease
expiry invalidate affected projections. Dependency coverage must be admitted;
otherwise mark the whole affected Scope dirty. Notifications schedule checks.
Current-use fences establish permission at the consumption boundary.

Invalidation before disclosure rejects dispatch. Invalidation after disclosure
requests cancellation or isolation, preserves what was already disclosed, and
rejects stale result/effect consumption. Cancellation request and acknowledged
worker termination remain separate obligations. Failure to contact a worker is
not evidence that it stopped.

Checkpoint values preserve immutable input/receipt references, owner revisions,
request identities and pending obligations. Recovery reads current source,
policy and grants, resolves durable intent/worker state, and re-enrolls at a new
owner coordinate. It never restores an old allow handle. A closed Session stays
closed; continuation creates an explicit new lineage. Uncertain external effect
state stays unresolved until its owning protocol supplies evidence.

* Memory values and pure operations

An =Experience= binds original source anchors, projection/input digests,
Session/turn receipt when applicable, observed outcome, evidence provenance,
visibility/retention policy revision, lineage and immutable experience revision.
An =Assessment= binds the experience revision, current evidence/source cut,
supported/refuted/uncertain/not-assessed outcome, competing hypotheses,
contradictions and open questions. Original experience and later assessments
remain independently addressable.

| Pure operation | Inputs | Output proposal and guard |
|----------------+--------+---------------------------|
| Capture | Admitted source/turn receipts and retention intent | Experience proposal; current visibility and capture policy checked at publication |
| Recall | Demand, catalog cut, current sources and restrictions | Fresh Context candidates with current admission; historical allow flags ignored |
| Consolidate | Exact experience/assessment revisions and policy | New derived artifact with lineage, coverage limits and retained contradictions |
| Schedule revisit | Experience revision and Temporal policy | Schedule revision with explicit due coordinate and clock domain |
| Claim revisit | Due schedule revision, worker identity and lease | CAS claim intent with generation and expiry |
| Complete revisit | Exact claim generation, current source cut and fresh assessment | New assessment plus conditional schedule publication |
| Write Org | Explicit derived-content intent and expected document revision | Org revision proposal requiring CAS and Orgize/Query roundtrip |

Evidence assessment, revisit scheduling and retention stability are separate
axes. Repeated recall or successful scheduling cannot promote truth or stability.
Missing claims cannot select a preferred hypothesis. Contradictions remain data.
A source correction produces a new assessment cut, retaining the prior record.

Expired or reclaimed revisit claims cannot publish. Different claim generations
must not alias after restart. A completion checks current claim, current policy,
source cut and expected schedule revision in one qualified publication fence.
Temporal owns due/lease clock interpretation; Memory owns experience assessment
and scheduling intent. Data owns durable conditional storage.

Deletion, expiry, visibility denial and source correction produce distinct
receipts. Derived artifacts preserve dependencies for invalidation and retention
handling. Local deletion cannot assert erasure of already disclosed provider
content; that requires evidence from the provider's retention boundary.

* Ownership of fences and durable publication

POO Context owns projection and use semantics. Session owns interaction revision
and terminal outcomes. Memory owns retained experience/assessment lineage.
Orgize owns syntax/source mapping; Query owns result admission; Authority and
Temporal own grants and clock interpretation. MRR owns its fact/query/receipt
admission and runtime coordination. Data owns durable CAS and history/outbox.

Where selection, receipt, history and outbox share a qualified transaction,
recheck their expected revisions and publish together. A cross-owner fence
requires an explicit coordinator protocol; independent point-in-time reads do
not make an atomic transaction. External provider dispatch/effects require
idempotency, pending intents and reconciliation beyond a database commit.
The existing Context Use observation is insufficient to claim this full fence.

* Implementation and Quint obligations

First qualify source-role alignment against existing native projection and
Module activation tests. Then implement Session contracts and the Context input
adapter; add Memory experience/recall, followed by revisit and durable recovery.
Extend the consumption envelope and downstream ABI/pins with their consumers.

| Invariant | Matched negative control | Required native replay |
|-----------+--------------------------+------------------------|
| Exact input disclosure | Ignore actor/destination/profile/input binding | Cross-scope dispatch rejected |
| Current result consumption | Ignore correction/retirement between dispatch and result | Historical result retained, current use rejected |
| One terminal outcome | Ignore expected turn revision | Completion/cancellation race admits one outcome |
| Recovery preserves obligations | Restore old allow or drop pending worker | Re-enrollment required; unknown effect remains pending |
| Terminal Session cannot resume | Permit closed-to-active or reused generation | Closed Session refusal after checkpoint |
| Recall has current provenance | Reuse stored allow or omit source lineage | Fresh source admission and dependency invalidation |
| Revisit claim is exclusive | Ignore claim CAS/generation/expiry | Stale or competing completion rejected |
| Feature containment | Disable Memory to bypass Context guards | Core checks remain mandatory |

New finite Quint profiles must state bounded domains, safety assertions and each
matched control. Counterexample traces map to real native inputs and expected
rejections. Existing Session/WorkTree models and their passed controls are
baseline evidence; they do not prove these new combined protocols or unbounded
liveness. Provider/clock/storage assumptions remain named obligations.

* Session identity and subagent scheduling refinement

[[file:session-org-id-subagent-scheduling-design.org][Session IDs, Org Property Anchors and Subagent Scheduling]] specifies stable
Session identity, admitted many-to-many Org ID bindings, per-child Context
projections, task DAG/claim/join semantics and bounded incremental scheduling.
Session owns scheduling semantics; Context owns Org binding and projection
admission. The scheduling runtime and new property-ID source profile are
proposed implementation slices, not covered by existing headline replay tests.

* Scheduling granularity refinement

Follow [[file:session-scheduling-granularity-design.org][Scheduling Granularity and Incremental Context]] for independent Task
acceptance, Attempt/Turn routing, admitted output-port release and Context slices.
Implement pure readiness/routing before runtime reuse or delta transport. A
fresh Session per Attempt is not the default allocation rule; compatible reuse
requires scope/history admission and preserves each Attempt's exact receipts.
