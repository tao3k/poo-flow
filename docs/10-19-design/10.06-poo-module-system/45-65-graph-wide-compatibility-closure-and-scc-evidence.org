#+title: Graph-Wide Compatibility Closure and SCC Evidence
#+startup: overview

* Status

This RFC records the accepted graph-wide compatibility closure semantics for
POO module and submodule composition.

It extends directional persistent-state compatibility. It does not define
compatibility as a permanent property of a package or an isolated module.

* Central decision

Compatibility is a proof over one exact semantic cut consisting of:

- a canonical composition root;
- selected module revisions;
- a resolved POO definition graph;
- an immutable external observation cut;
- a compatibility policy.

Pairwise compatibility of dependency edges does not prove graph-wide
compatibility.

The closure result is scoped to its complete input identity. It must not be
reused as a global claim that a module is compatible forever.

* Why pairwise checks are insufficient

Graph-wide failure may still occur when:

- two modules satisfy isolated contracts but violate a shared-writer
  invariant;
- a priority-resolved slot changes a transitive reader or effect contract;
- an effect receipt cycle combines incompatible old and new assumptions;
- one submodule is instantiated under different prototype contexts;
- a cyclic strongly connected component requires joint resolution;
- different B2B2C scope paths produce different identities or capabilities;
- a local resource observation is inconsistent with the admitted global cut.

Compatibility evidence must retain these graph relationships.

* Typst formalization: cut-scoped graph compatibility closure

Compatibility closure is a proof over one exact semantic cut.  The input binds
the canonical root, selected revisions, resolved POO graph, immutable
observation cut, and policy identity.  It is not a permanent package property.

#+begin_src typst
$ I = (
  canonical-root,
  selected-revisions,
  resolved-nodes,
  resolved-edges,
  observation-cut,
  policy-id,
  cut-id,
) $

$ ClosureProof(I) not=> ClosureProof(I') quad "when" quad I != I' $
$ PairwiseCompatible(edges) not=> GraphCompatible(I) $

$ cut-id_1 != cut-id_2
  => ClosureIdentity(cut-id_1, policy)
  != ClosureIdentity(cut-id_2, policy) $
$ policy_1 != policy_2
  => ClosureIdentity(cut, policy_1)
  != ClosureIdentity(cut, policy_2) $
#+end_src

Each strongly connected component is proven as one closure unit.  Its required
edges carry RFC 45-64 directional evidence.  Missing evidence suspends the
decision; it is neither a proof nor a compatibility violation.

#+begin_src typst
$ SCCEvidence(S)
  := ClosureRelation(S.nodes, S.internal-edges)
  and forall edge in S.required-edges:
    exists evidence: DirectionalEdgeEvidence(edge, evidence) $

$ CompatibilityProof(I)
  => forall scc in SCCs(I): exists evidence: SCCEvidence(scc) $

$ Authority(CompatibilityProof) = true $
$ Authority(PairwiseSummary) = false $
$ Authority(CompatibilityViolation) = false $
$ Authority(CompatibilitySuspension) = false $

$ MissingEvidence != emptyset => CompatibilitySuspension $
$ CompatibilitySuspension not=> CompatibilityViolation $
#+end_src

  Graph["Resolved POO module/submodule graph"] --> Cut
  Observation["Immutable observation cut"] --> Cut

  Cut -->|"decompose graph"| SCCs["Strongly connected components"]
  Directional["RFC 45-64 directional edge evidence"] -->|"required edge witness"| SCCs
  SCCs -->|"closure witness for every SCC"| Proof["CompatibilityProof"]

The three outcomes remain distinct.  Suspension preserves uncertainty instead
of converting missing evidence into a false violation or an unsafe proof.

** Proof obligations

- [X] =pairwiseSummaryDoesNotAdmitGraphActivation=: pairwise checks cannot
  authorize graph-wide activation.
- [X] =violationFailsClosed= and =suspensionDoesNotAdmitGraphActivation=: only
  a proof admits activation.
- [X] =suspensionIsNotDefinitiveViolation=: incomplete evidence is not a proven
  incompatibility.
- [X] =exactCutProofAdmitsGraphActivation=: exact-cut proof is the sole admitted

- [X] =graphProofCarriesExactSemanticCut=: every proof carries the complete

- [X] =graphProofCoversEverySCC=: every SCC has a closure witness.
- [X] =sccClosureCoversEveryRequiredEdge=: every required SCC edge carries RFC

* POO semantic ownership

Compatibility closure is represented by ordinary higher-order POO objects.
Native object and prototype semantics are owned by the canonical dependency:

#+begin_example
github.com/mighty-gerbils/gerbil-poo@1c3225637525400341a09e958296962c10184ead
#+end_example

POO Flow supplies demand evaluation, cycle evidence, budgets, caching, and
observability over those objects.

The project must not implement a second POO library, a second independent
fixed-point evaluator, a package compatibility registry, or a boolean
compatibility DSL.

The exact public Scheme operations remain subject to verification against the
native =gerbil-poo= API.

* Compatibility closure input

A pure =CompatibilityClosure= object receives an immutable input containing:

- canonical composition-root revision identity;
- definition-graph identity;
- strongly connected component digest;
- selected revision for every definition anchor;
- prototype composition and slot-resolution evidence;
- import, identity, and capability edges;
- generation contract set identity;
- resource observation-set identity;
- consumer, publication, and migration scopes;
- compatibility policy identity.

The input is complete only when every declared scope and dependency edge has an
identified evidence source.

An absent observation is not a neutral value and must not be interpreted as a
compatible resource.

* Evidence result roles

Closure evaluation produces one of three evidence object roles:

- =CompatibilityProof=;
- =CompatibilityViolation=;
- =CompatibilitySuspension=.

A proof records a closed set of satisfied obligations.

A violation records at least one contradicted obligation and its causal graph
path.

A suspension records an open evaluation caused by missing evidence, exhausted
budget, unresolved dependency, or non-stabilized cycle.

Suspension is not compatibility and is not incompatibility.

These are POO evidence roles, not enum tokens in a user-facing macro language.

* Structural closure

Structural closure precedes semantic compatibility closure.

It proves:

- module and nested submodule graph completeness;
- definition-anchor and revision selection;
- import-edge resolution;
- provider identity for every capability requirement;
- prototype priority and slot-conflict resolution;
- scope-path identity for every module instance;
- graph identity and SCC partition identity.

Failure to close structure prevents semantic compatibility evaluation.

A source package identity alone does not identify a module instance. The same
submodule under different composition roots, tenants, industry scopes, or
prototype contexts has a distinct scoped instance identity.

* Semantic compatibility closure

Semantic closure evaluates the complete structural cut against:

- directional reader and writer compatibility;
- effect request and receipt compatibility;
- continuation and persistent-data compatibility;
- shared-resource aggregate invariants;
- rollout and activation obligations;
- migration, contract, and reversion constraints;
- capability scope non-escalation;
- lifecycle transition obligations.

Every obligation links an exact consumer projection to an exact provider or
resource projection.

Local tests and provider receipts may contribute evidence. They do not replace
the graph-wide closure.

* Strongly connected components

A cyclic SCC is evaluated as one joint compatibility obligation.

The implementation must not resolve a cyclic component by source-file order,
module declaration order, hash traversal order, or the most recently evaluated
node.

For each SCC:

- internal obligations form one higher-order POO object;
- external incoming evidence is fixed for one evaluation attempt;
- fixed-point demand records exact causal edges;
- monotone refinement is used only when the policy proves the required
  monotonicity;
- a stabilized result receives an SCC closure identity;
- oscillation, non-monotonicity, missing evidence, and budget exhaustion remain
  explicit evidence.

The last observed value of an unstable cycle must not be published as a stable
result.

* Cycle and budget observability

Cycle evidence identifies:

- SCC identity;
- demanded slot or contract projection;
- causal dependency path;
- evaluation generation and attempt identities;
- repeated value or evidence identities;
- monotonicity proof status;
- evaluation budget consumed;
- stabilization, violation, or suspension result.

Performance budget exhaustion is a suspension unless policy separately proves
an incompatibility.

The observability plane must distinguish productive recursive refinement from
non-productive recursion and oscillation.

* Continuable evaluation conditions

Recoverable closure conditions may expose constrained restart roles for:

- supplying a new immutable observation;
- increasing an evaluation budget under authority;
- suspending evaluation;
- selecting an already admitted alternative proposal.

A restart may continue the same closure identity only when it supplies evidence
or resources without changing the semantic input cut.

Changing a prototype, priority, contract, definition revision, composition
root, or compatibility policy creates a new closure input and therefore a new
composition or generation proposal.

Continuable exceptions must not mutate the meaning of an existing closure in
place.

* Cache identity and invalidation

Compatibility caching is keyed by the complete semantic cut:

#+begin_example
composition-root revision
+ definition-graph and SCC identities
+ resolved slot evidence
+ generation contract-set identity
+ resource observation-set identity
+ compatibility policy identity
#+end_example

Package names and source repository identities are insufficient cache keys.

An unchanged SCC may reuse its closed result when all incoming evidence
identities remain unchanged. A changed incoming edge invalidates the dependent
SCC closure, not unrelated graph regions.

Cached suspension must retain its missing-evidence or exhausted-budget cause.
It must not be reused as a proof.

* Explanation receipts

Every proof, violation, and suspension can be traced to exact graph evidence.

An explanation receipt identifies:

- consumer instance and scope path;
- provider instance or resource;
- slot, capability, resource, or effect contract;
- expected and provided contract identities;
- observation identity;
- module and submodule path;
- SCC identity;
- priority and prototype resolution evidence;
- causal reason for proof, violation, or suspension.

Explanation is derived from canonical evaluation evidence. It must not be a
separate best-effort diagnostic reconstruction.

* Admission boundary

Only a graph-wide =CompatibilityProof= may contribute compatibility authority
for:

- consumer activation;
- migration execution;
- destructive contract;
- generation reversion;
- continuation migration.

A violation or suspension fails closed at these admission boundaries.

Other policy may still authorize evidence acquisition, evaluation resumption,
or construction of a new generation proposal.

* Failure taxonomy

The implementation must distinguish at least:

- structural graph incomplete;
- anchor or revision unresolved;
- capability provider unresolved;
- slot conflict unresolved;
- scoped module identity collision;
- resource observation cut incomplete;
- directional contract violation;
- shared-resource aggregate violation;
- SCC monotonicity unproven;
- SCC oscillation;
- recursive demand budget exhausted;
- compatibility evidence suspended;
- stale closure cache entry;
- explanation evidence incomplete.

* Required invariants

1. Compatibility is scoped to one complete semantic cut.
2. Pairwise edge checks do not substitute for graph-wide closure.
3. Structural closure precedes semantic closure.
4. Nested instances retain composition scope-path identity.
5. SCCs are evaluated jointly and independently of traversal order.
6. Unstable cycle values never become compatibility proofs.
7. Suspension remains distinct from proof and violation.
8. Missing observations never imply compatibility.
9. Restarts cannot mutate semantic closure inputs in place.
10. Cache keys include graph, SCC, contract, observation, and policy identity.
11. Explanation evidence is produced by canonical evaluation.
12. Only a graph-wide proof crosses compatibility admission boundaries.
13. Native POO semantics remain owned by =gerbil-poo=.
14. Public semantic extension remains POO-native.
