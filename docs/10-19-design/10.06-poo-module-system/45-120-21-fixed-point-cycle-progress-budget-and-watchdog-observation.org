#+title: Fixed-Point Cycle, Progress, Budget, and Watchdog Observation
#+author: POO Flow
#+language: en

* Status

Accepted.

* Context

A recursive dependency is not automatically an error.  A cyclic Module graph
may converge productively, stabilize immediately, stall with unresolved
obligations, oscillate among values, grow without a proof of convergence,
re-enter through a continuation, or repeatedly invalidate a cache without
semantic progress.

Waiting for stack overflow, wall-clock timeout, or process-memory exhaustion
loses the first causal point at which the evaluator knew that a dependency path
had closed.

POO Flow needs immediate structural evidence and domain-specific progress
proofs without reimplementing the upstream =gerbil-poo= fixed-point algebra.

* Decision

This RFC stabilizes =poo-flow.lean-declaration-closure.v1= only.
Runtime-watchdog binding, memory attribution, phase timing, and bounded proof-root
selection are backward-compatible v1 refinements.  They do not authorize a v2
schema, a second closure identity, or a competing proof-transport path.

Cycle detection, progress proof, deterministic structural budget, and runtime
watchdog evidence are four separate responsibilities.

- Cycle detection records the first dependency edge that closes a path.
- A POO-native =ProgressContract= classifies semantic change.
- Deterministic structural budgets define reproducible evaluation limits.
- Runtime watchdogs report machine-dependent time, CPU, allocation, and
  retention evidence.

A cycle observation is a structural fact.  It is not itself a failure.

* Oscillation is a structural v1 progress claim

An =oscillating= classification MUST NOT be justified only by the domain
=semanticOscillation= hook.  POO Flow first requires a canonical fingerprint
history that returns to the same fingerprint after at least one intervening
different fingerprint.  The domain hook then confirms the industry- or
workflow-specific meaning of that structural return.

This split is normative: progress, deterministic budget, runtime watchdog, and

The progress enum is not itself evidence of deterministic classification.

The raw fingerprint list is a receipt projection, not a history evidence owner.

Logical checkpoint-content binding, predecessor binding, canonical history-root

[[file:45-120-25-source-bound-fingerprint-content-address-closure.org][45-120-25 source-bound fingerprint content-address closure]].

This is a stable v1 refinement.  It reuses the complete existing checkpoint and
history structures; it does not introduce a v2 declaration closure or a second

* Latest-checkpoint restore authorization

Content-address integrity, current runtime epoch, latest-checkpoint target, and
the exact Cedadr authorization receipt are composed in
[[file:45-120-26-source-bound-checkpoint-restore-authorization-closure.org][45-120-26 source-bound checkpoint restore authorization closure]].

Ordinary resume is latest-only.  Rollback remains a separate explicit authority
and cannot be accepted through the ordinary resume request.

* Effect replay idempotency and retry authority

Replay-window ordering, exact ledger coverage, idempotency identity,
execute-versus-suppress planning, and exact Cedadr retry authority are composed
in
[[file:45-120-27-source-bound-effect-replay-idempotency-closure.org][45-120-27 source-bound effect replay idempotency closure]].

Restore authorization does not imply replay safety, and a raw effect trace
cannot synthesize ledger coverage or an idempotency identity.

* Upstream fixed-point boundary

The upstream =gerbil-poo= package owns the POO object, dispatch, type, Contract,
debug, and fixed-point foundations.

POO Flow owns evaluation evidence around that algebra:

- dependency discovery;
- canonical dependency edge identity;
- evaluation generation;
- SCC evidence;
- progress evidence;
- typed budgets;
- cache generation and invalidation evidence;
- structured diagnostics and recovery options.

POO Flow MUST NOT create a competing generic fixed-point implementation.

* First cycle evidence

When a new dependency edge closes an active path, the evaluator MUST emit a
=CycleDetectedObservation= before beginning another step in that cycle.

The observation MUST identify:

- the active evaluation generation;
- the closing edge;
- the canonical SCC members and edges known at that point;
- the causal evaluation path;
- source, slot, and provider provenance;
- the structural budget already consumed;
- any active continuation option identity involved in re-entry.

This observation does not stop evaluation unless policy, authority, or budget
requires it.

** Source-bound structural refinement

RFC 149-07 makes the previously informal terms “canonical SCC identity,”
“causal path,” and “closing edge” precise.

- Every node is a complete object subject: package, revision, source-tree
  digest, object-content digest, and effect-contract digest.
- The closing edge is explicit and exists in the exact composition registry.
- Every SCC member and causal-path node belongs to the fixed-point visited set.
- Every adjacent causal-path pair is a real source-bound composition link.
- The causal path is closed and its final pair is the named closing edge.
- Every pair of SCC members is mutually reachable through links whose
  intermediate subjects remain inside that SCC.
- Canonical SCC members are duplicate-free.

A registry digest and generation alone do not establish these properties.
Lean countermodels in
=PooFlowProof.Enterprise.SourceBoundCycleObservationClosure= preserve the
same-name revision and ghost-cycle failures.  This refinement adds evidence
semantics only; it does not introduce a second fixed-point runtime.

* Progress Contract

A value-domain prototype participating in recursive evaluation supplies a pure
=ProgressContract=.

The Contract MUST provide evidence for:

- semantic equivalence;
- monotone improvement or refinement;
- canonical progress fingerprint;
- remaining obligations;
- an optional domain-specific bound.

The Contract MUST NOT:

- force additional lazy slots merely to classify progress;
- execute runtime effects;
- capture or invoke a continuation;
- re-enter the SCC under inspection;
- infer equality from pointer identity or printed representation;
- use machine-dependent elapsed time as semantic progress.

** Source-bound progress evidence refinement

RFC 149-07 also makes the Progress Contract input precise.  Registry digest
and generation are coordinates, not the semantic owner of a classification.
The progress receipt MUST bind the exact cycle-observation identity and cover
its canonical SCC with one =SubjectProgressEvidence= per complete subject.

Each entry records:

- package, revision, source-tree digest, object-content digest, and
  effect-contract digest through the complete subject;
- previous and current semantic fingerprints;
- canonical fingerprint history needed by oscillation evidence;
- previous and current remaining-obligation digests.

The subject projection MUST equal the canonical SCC member sequence and MUST
be duplicate-free.  A pure, owner-valid =SourceBoundProgressContract= then
supplies the relations for semantic equivalence, monotone improvement,
regression, incomparability, oscillation, and obligation completion or
remainder.

A =ProgressClass= value without those relations is only an assertion.
=converged= requires equivalence plus completed obligations for every governed
subject.  =advancing= requires no governed violation and at least one
monotone improvement.  =stalled= requires equivalence while obligations
remain.  The remaining classifications likewise require their distinct
contract evidence or an exhausted deterministic structural budget.

** Source-bound runtime watchdog refinement

An optional =watchdogObservationId= is a reference, not evidence.  When the
reference is present, RFC 149-07 requires an independently owner-valid
=SourceBoundRuntimeWatchdogObservation= with:

- the same registry and generation as the progress receipt;
- the exact cycle-observation identity and continuation identity;
- runtime owner and evaluation-phase identities;
- a typed metric and compatible unit;
- observed and threshold values with a strict exceedance relation;
- metric-specific attribution and a provenance digest.

For process-tree RSS, one scalar is insufficient.  Shared pages can be counted
multiple times and the sum does not identify the implementation phase or
largest process.  The memory attribution therefore records tree RSS, largest
process identity and RSS, and at least one proportional-set-size or
platform-footprint value.

Progress semantics and runtime watchdog binding have different owners:

- =SourceBoundProgressEvidenceClosed= proves semantic classification under a
  pure domain Contract;
- =SourceBoundRuntimeWatchdogBindingClosed= proves the runtime observation
  reference, coordinates, threshold, and attribution;
- =SourceBoundRuntimeWatchdogEvidenceClosed= composes those independently
  verified relations in Lean.

A watchdog observation does not prove convergence, regression, or absence of
a fixed point.  It also cannot mint or consume retry authority.

* Observation refinements

** Fixed-point progress

=FixedPointProgressObservation= proves that at least one governed value made
monotone semantic progress and no governed value violated its progress
Contract.

** Fixed-point convergence

=FixedPointConvergedObservation= proves semantic equivalence with the prior
generation and completion of the governed obligations.

It is success evidence, not an anomaly.

** Fixed-point stall

=FixedPointStalledObservation= proves that governed obligations remain while no
semantic improvement occurred.

** Fixed-point oscillation

=FixedPointOscillationObservation= proves a repeated sequence of canonical,
non-equivalent progress fingerprints.

** Fixed-point budget exhaustion

=FixedPointBudgetExhaustedObservation= records that the evaluator could not
prove convergence or terminal failure within an authorized deterministic
structural budget.

Budget exhaustion is not proof that the semantic fixed point does not exist.

** Continuation re-entry

=ContinuationReentryObservation= records that an admitted continuation
invocation re-entered an evaluation path still active in its causal ancestry.

** Cache thrashing

=CacheThrashObservation= records repeated cache invalidation or recomputation
without governed semantic progress.

* Deterministic structural budgets

Structural budgets use deterministic units, including:

- dependency edges;
- SCC iterations;
- slot evaluations;
- cache invalidations;
- continuation captures;
- continuation invocations.

These budgets define reproducible semantic stopping points and produce
canonical consumption evidence.

Closure-evaluation budgets remain distinct from recovery-action budgets.

* Runtime watchdog evidence

Runtime watchdogs may observe:

- elapsed time;
- CPU consumption;
- allocation growth;
- retained continuation handles;
- conservative retained-size estimates;
- runtime queue or process pressure.

These values depend on machine, runtime, and scheduling conditions.  They may
trigger a continuable diagnostic boundary, but they MUST NOT be the sole input
to canonical semantic identity or convergence proof.

Watchdog facts become authoritative only through a provider or runtime receipt
that identifies the measurement conditions.  Telemetry receives a redacted
projection of that evidence.

* Recovery boundary

An anomaly observation may expose bounded =ResumptionOption= values through the
exception bridge.  The observation itself does not choose or execute recovery.

Policies dispatch over the observation prototype.  Capabilities bound the
available response.  The coordinator validates and executes an admitted
=RecoveryDecision=.

* Conformance checklist

- [X] A cycle is recorded at the first closing dependency edge.
- [X] Cycle evidence is not automatically classified as failure.
- [X] Progress classification comes from a pure POO-native Contract.
- [X] Convergence, stall, oscillation, budget exhaustion, continuation re-entry,
  and cache thrashing remain distinct observations.
- [X] Structural budgets use deterministic semantic units.
- [X] Runtime watchdog evidence remains separate from semantic progress.
- [X] Define canonical SCC/path identity as complete source-bound subjects.
- [X] Require visited membership, linked path closure, and an explicit closing
  edge in the Lean refinement.
- [X] Closure-evaluation and recovery-action budgets remain distinct.
- [X] POO Flow observes rather than replaces upstream fixed-point algebra.
- [X] Recovery remains policy-selected, capability-bounded, and
  coordinator-executed.
- [ ] Concrete evaluator and progress-evidence source owners have been resolved
  through parser-owned owner discovery.
- [ ] Implementation has been admitted after owner resolution.

* Non-goals

- Treating every recursive dependency as an error.
- Reimplementing the upstream =gerbil-poo= fixed-point foundation.
- Using wall-clock timeout as a convergence proof.
- Guessing progress from printed values or pointer identity.
- Combining all anomalies into a generic recursion error.
- Defining an implementation schedule.
