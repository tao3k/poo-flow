#+title: RFC 45-120-63 — Lean Declaration-Closure Generation Performance
#+status: IMPLEMENTED
#+startup: overview

* Decision

POO Flow treats declaration-closure performance as a generation-level proof
substrate property.  One admitted generation performs one Lake build, hashes
the native exporter once, imports one union Lean environment, derives trusted
and Cedar proof-base module partitions from module metadata, and emits one
independent closure per requested root.

This RFC changes no authorization theorem, declaration identity, proof-base
role, universe normalization, source-owner rule, or AXLE timeout.  It changes
only how already required evidence is computed and observed.

* Authority invariants

- Lake build admission remains before cache use.
- Root =.olean= content and native exporter content remain cache identities.
- The Cedar boundary remains a typed proof-base interface.
- A batch generation never becomes a second declaration or source authority.
- Every root retains an independent canonical closure and digest.
- Cache hits do not authorize stale source or skip Lake freshness admission.
- A newly exported receipt enters the cache only after parsing and validation
  of its root module, declaration roots, base imports, and proof-base imports.
- AXLE operation and base limits remain =10s= and =2s=.
- User backend configuration names runtime and language identity, not Python
  scripts, Lean paths, exporter binaries, or batch protocol details.

* Generation architecture

#+begin_src mermaid
flowchart LR
  U[POO-native user composition] --> R[Requested proof roots]
  R --> L[One Lake generation admission]
  L --> H[One native exporter content digest]
  H --> E[One union Lean Environment]
  E --> M[Module metadata partition]
  M --> T[Trusted module closure]
  M --> C[Cedar typed proof-base module closure]
  T --> Q[Per-root declaration closure]
  C --> Q
  Q --> D[Independent closure digests]
  D --> K[Generation cache]
  D --> A[AXLE exact verification]
  K --> F[Reflection phase receipts]
  A --> F
#+end_src

The partition uses =EnvironmentHeader.moduleData.imports= and declaration
module indices.  It does not infer ownership from paths, namespace prefixes,
terminal names, or package strings.

* Performance model

#+begin_export typst
$
  T_"single" = T_"build" + T_"hash exporter"
    + T_"process" + T_"import root"
    + T_"closure" + T_"render"
$

$
  T_"batch"(R) = T_"build"(R) + T_"hash exporter"
    + T_"process" + T_"import"(union(R))
    + sum_(r in R) (T_"closure"(r) + T_"render"(r))
$

$
  forall r in R,
  "digest before"(r) = "digest after"(r)
$

$
  "admitted cache hit" iff
    "Lake generation current"
    and "root olean digest equal"
    and "exporter digest equal"
    and "request identity equal"
$
#+end_export

The former implementation loaded three overlapping environments: trusted
=Init=, =Init + Cedar.Spec=, and the full root.  Their measured module counts
were =599=, =1213=, and =2633=.  The implemented path loads one union
environment and derives both partitions from its module graph.

** Current requalification (2026-09-08)

The implementation and historical observations above remain historical
evidence.  The current performance gate is open; the earlier ten-run result
has not been reproduced in this checkout environment.

The cache regression fix moves publication after receipt identity validation.
Its negative tests verify that malformed or mismatched output is not cached,
that equal-size/equal-mtime content changes invalidate either artifact, and
that a warm hit still requires successful Lake admission.

The benchmark now writes a typed failure sample with the original code/detail
and observed phases, stops at the first failed generation, and returns a
nonzero exit code.  It records requested versus executed sample counts;
failed samples never enter warm percentiles.  A completed benchmark means
measurement completed, not proof or performance acceptance.

* Historical acceptance criteria

- [X] One native environment serves a compatible multi-root generation.
- [X] Trusted and proof-base membership derive from Lean module metadata.
- [X] The exporter content digest is reused inside one generation.
- [X] Every root retains an independent content-addressed cache entry.
- [X] Native and driver phase receipts are machine-readable.
- [X] Optimized closure JSON is semantically and bytewise unchanged.
- [X] Ten warm dual-root runs have p50 below =2.5s=.
- [X] Ten warm dual-root runs have p95 below =5s=.
- [X] Cold-or-mixed dual-root generation improves by more than 50 percent in
  the matched observation.
- [X] Same-tool maximum-RSS diagnostic improves by more than 50 percent in the
  matched observation.
- [X] Remote lifecycle and subject bridge verification remain accepted.
- [X] No timeout increase, source merge fallback, or mtime-only cache is added.

* Non-goals

- A resident Lean daemon before the bounded batch path demonstrates need.
- Treating one timing observation as a platform-wide SLA.
- Caching AXLE acceptance independently of its authority-bound receipt.
- Exposing Python, Lean, Lake, or executable paths in user composition.
- Replacing Cedar or source-owner evidence with namespace classification.
