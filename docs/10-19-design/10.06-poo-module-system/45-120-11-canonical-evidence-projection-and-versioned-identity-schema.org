#+title: Canonical Evidence Projection and Versioned Identity Schema
#+startup: overview

* Status

The architecture in this RFC is accepted.

This acceptance freezes semantic identity and canonical projection
responsibilities.  It does not admit an encoding format, digest
algorithm, implementation file, generic serializer, or public identity
macro.

* Scope

This RFC defines how native POO values participate in persistent
semantic evidence, cache identity, replay verification, and receipts.

It covers:

- domain, evidence, and runtime identity;
- Contract-owned canonical projections;
- computed and derived slots;
- function, macro, and closure evidence;
- cyclic graph and SCC identity;
- versioned canonical encoding and digest schemas;
- verification and fail-closed identity conflicts.

* Central decision

A native POO object is not serialized as a whole.

An admitted Contract selects and explains the semantic
responsibilities that contribute to canonical evidence.  Runtime
structure, implementation conveniences, caches, continuations, handles,
credentials, and secret values remain outside the projection.

Evidence identity is derived from a versioned canonical projection,
semantic schema identity, and dependency evidence identities.  It is
not derived from object address, traversal order, printed
representation, storage location, or runtime process state.

* Three identity layers

| Identity layer  | Meaning                                                | Persistence rule                                      |
|-----------------+--------------------------------------------------------+-------------------------------------------------------|
| domain identity | The declared identity of a Module or domain entity     | Persists as one semantic responsibility               |
| evidence identity | One immutable semantic value, generation, or derivation | Persists through canonical projection and schema      |
| runtime identity | A process-local object, closure, continuation, or handle | Never defines persistent equality or replay identity  |

One domain identity may have many evidence identities across
generations.  Two runtime objects may represent the same evidence only
when both verify against the same canonical evidence identity.

Runtime object equality neither proves nor disproves semantic evidence
equality.

* Contract-owned canonical projection

The evidence Contract declares:

- the semantic responsibilities included in the projection;
- the meaning and canonical order of projected fields;
- the expected semantic value types;
- the dependency identities replacing recursive references;
- the derivation evidence required for computed values;
- explicit exclusions;
- the canonical encoding schema identity;
- the digest schema identity.

The RFC term =EvidenceContract= is a semantic role.  It does not
automatically freeze an exported constructor, record, or macro name.

A projection fails closed when an included responsibility is missing,
ambiguous, unsupported, dynamically unbounded, or cannot provide its
required evidence.

* Computed and derived responsibilities

A computed slot is not admitted merely because it has a current value.

To enter canonical evidence, a derived responsibility identifies:

- its derivation or operation identity;
- all result-affecting dependency evidence identities;
- the semantic schema and evaluator identity;
- the derived value under its admitted value Contract;
- the derivation receipt or reconstructible proof.

If those identities are unavailable, the slot remains runtime-derived
and outside persistent evidence.

Caching a computed slot does not change whether it is semantic.  Cache
presence, absence, eviction, and storage location never enter its
evidence identity.

* Function, macro, and closure evidence

A function, macro, closure, or prototype computation cannot use a
memory address, generated symbol, object printout, procedure name alone,
or compiled-code pointer as semantic identity.

Admitted code evidence identifies, as applicable:

- source snapshot and exact source-owner identity;
- Module and exported binding identity;
- Gerbil phase and macro-expansion semantics;
- provider, compiler, or evaluator semantic identity;
- declared dependencies;
- captured semantic environment identities;
- the Contract governing inputs, results, and effects.

A closure with an opaque or runtime-only captured environment is not
persistable semantic evidence.

A macro-derived value identifies the admitted source and phase
derivation.  The hygiene of the macro does not by itself prove
persistent semantic identity.

* Canonical encoding schema

The canonical encoding schema defines one deterministic representation
for every admitted projected value.  It defines:

- field and collection ordering;
- scalar and symbolic representation;
- absence, optionality, and variant representation;
- graph node and edge references;
- schema and domain separation;
- rejection of unsupported or ambiguous values.

The schema MUST NOT depend on hash-table iteration, locale, printer
configuration, memory address, process architecture, wall-clock time,
or storage backend.

Multiple byte or structural representations for the same admitted
projection are forbidden within one schema identity.

* Versioned digest schema

The digest schema identifies the digest algorithm and the domain
separation over:

- canonical projection;
- canonical encoding schema identity;
- evidence Contract identity;
- dependency evidence identities;
- relevant derivation identities.

The evidence identity carries or unambiguously resolves the digest
schema identity.  Changing the algorithm, encoding, Contract meaning,
or included semantic responsibilities creates a new identity schema.

A digest is not accepted without canonical evidence sufficient for
verification.  If the same digest resolves to conflicting canonical
evidence, verification fails closed with collision evidence.

* Cyclic graph and SCC identity

Cyclic POO and Module graphs are represented as canonical semantic graph
evidence rather than recursively printed objects.

Graph evidence identifies:

- canonical node identities or node projections;
- typed directed edges;
- explicit roots;
- SCC membership;
- external dependency evidence identities;
- graph and SCC schema identities.

SCC identity is independent of traversal order, allocation order,
runtime object address, evaluator stack shape, and cache scheduling.

An unrooted authority SCC may have a diagnostic graph identity while
still deriving empty authority.  Graph existence and authority are
separate facts.

* Load and replay verification

Loading or replaying evidence verifies:

- identity-schema availability and exact identity;
- canonical encoding conformance;
- evidence Contract conformance;
- digest equality;
- dependency evidence availability and identity;
- derivation receipts for computed responsibilities;
- graph and SCC consistency when present.

A missing schema, ambiguous encoding, digest collision, mismatched
dependency, unsupported value, or incomplete derivation fails closed.

The verifier does not repair evidence by choosing a newer schema,
normalizing an old printer representation, retrieving a similar cache
entry, or consulting telemetry.

* Schema changes in the new architecture

This RFC defines no ambient compatibility, migration, or deprecation
path.

A schema or Contract change creates new evidence identities.  Existing
retained evidence remains under its declared schema identity.

Cross-schema derivation requires an explicit proof-producing POO
adapter with its own identity and receipt.  The adapter produces new
evidence; it does not mutate the old evidence or claim identity
equivalence implicitly.

* Public and advanced extension boundary

Ordinary Module composition does not expose serialization, digest,
graph-canonicalization, or identity clauses.

Advanced evidence projections and schema values are native POO objects
governed by Contracts and ordinary functional transformations.

No generic whole-object =serialize!= interface, raw alist encoding DSL,
printer-based identity helper, or public identity macro is admitted.

* Implementation admission checklist

- [ ] Keep domain, evidence, and runtime identities distinct.
- [ ] Permit one domain identity to have multiple generation-specific
  evidence identities.
- [ ] Prevent runtime object equality from defining persistent
  equality.
- [ ] Project only Contract-declared semantic responsibilities.
- [ ] Exclude runtime structure, caches, continuations, handles,
  credentials, and secrets.
- [ ] Require derivation and dependency identities for every persisted
  computed responsibility.
- [ ] Reject opaque runtime closures as persistent evidence.
- [ ] Identify functions and macros through source, binding, phase,
  provider, environment, and Contract evidence as applicable.
- [ ] Define one deterministic representation per admitted value and
  encoding-schema identity.
- [ ] Version digest algorithm and domain-separation semantics.
- [ ] Represent cycles through canonical node, edge, root, and SCC
  evidence.
- [ ] Keep SCC identity independent of traversal and allocation order.
- [ ] Revalidate schema, Contract, encoding, digest, dependencies, and
  derivations during load and replay.
- [ ] Fail closed on missing schemas, ambiguity, collision, mismatch,
  unsupported values, or incomplete derivation.
- [ ] Give schema changes new evidence identities.
- [ ] Require explicit proof-producing adapters for cross-schema
  derivation.
- [ ] Add no whole-object serializer, raw encoding DSL, printer-based
  identity helper, or public identity macro.
- [ ] Apply phase-aware macro expansion evidence and source-mapping
  rules in
  [[file:45-120-12-phase-aware-macro-expansion-evidence-source-mapping-and-receipt-schema.org][45-120-12]].
