#+title: Canonical POO Composition Root and Definition-Graph Identity
#+subtitle: Lazy semantic projection, directional native operations, closure identity, and cyclic definitions
#+startup: overview

* RFC status

- Status :: Accepted design
- Kind :: Normative design module
- Semantic core :: Native =gerbil-poo= objects, prototypes, and operations
- Related modules :: =45-35-macro-expanded-poo-prototype-definition-identity.org= and =45-44-semantic-generation-transition-and-execution-identity.org=

This module defines how an active POO composition becomes a canonical semantic root without serializing runtime object representations, forcing lazy slots, or reimplementing =gerbil-poo= evaluation.

* Core decision

#+begin_quote
The canonical active POO composition root is a lazy Merkle graph whose nodes have stable POO definition identities and whose labeled edges preserve native operation roles. It preserves explicit identity and direction, separates provenance, does not force slot evaluation, and represents cyclic definitions through definition-SCC projection.
#+end_quote

* Three identity domains

POO Flow distinguishes:

#+begin_src text
RuntimeObjectIdentity
POOSemanticProjectionIdentity
SourceProvenanceIdentity
#+end_src

Only =POOSemanticProjectionIdentity= participates in semantic generation identity.

=RuntimeObjectIdentity= describes allocation, address, process-local sharing, or other execution details. =SourceProvenanceIdentity= explains origin, macro call site, and diagnostics. Neither is a substitute for semantic definition identity.

* Definition graph, not evaluated object serialization

The canonical projection describes:

- the root POO definition identity;
- prototype and extension relationships;
- slot definition identities;
- native POO operation identities;
- operation operands and their semantic roles;
- captured pure dependency identities;
- imports, contracts, priorities, and capability requirements;
- active control-plane policy identities.

The projection does not serialize a printed runtime object or force a lazy slot value.

#+begin_src mermaid
flowchart LR
    R["Live gerbil-poo object graph"] -->|"project definitions without forcing slot values"| P["Canonical POO definition graph"]
    P -->|"preserve native operation roles and direction"| N["Semantic node and edge projection"]
    N -->|"apply domain-separated content addressing"| I["POOSemanticProjectionIdentity"]
    R -->|"record address and allocation only operationally"| O["Execution receipt"]
    S["Source path, line, and macro call site"] -->|"link as non-semantic provenance"| E["Provenance evidence"]
    E -->|"reference without changing semantic identity"| I
#+end_src

Identity projection must not trigger fixed-point evaluation, runtime handoff, capability use, or a demand for a business slot.

* Native operation direction

A native operation may be directional. Its canonical projection preserves:

- operation semantic identity;
- operand roles;
- operand order or edge direction where semantic;
- resulting definition identity.

Directional operands must not be sorted merely to obtain a stable digest. Sorting would erase native POO semantics.

Only an operation already proven canonical and presentation-order-independent for its operands may normalize those operands as an unordered or canonically sorted collection.

#+begin_src mermaid
flowchart LR
    B["Base prototype identity"] -->|"role: base operand"| O["Directional native POO operation"]
    X["Extension identity"] -->|"role: extending operand"| O
    O -->|"preserve operation and operand roles"| R["Result definition identity"]
    U["Order-independent native operation"] -->|"normalize only after canonicality is established"| C["Canonical operand collection"]
#+end_src

This RFC does not assign semantics to specific =gerbil-poo= operators before their real interfaces and laws are verified.

* Function and closure identity

General Scheme functions cannot be identified by extensional equivalence. A function or delayed POO computation therefore has an intensional semantic identity derived from:

#+begin_src text
expanded definition identity
+ referenced semantic dependency identities
+ captured pure value identities
+ declared semantic protocol identity
#+end_src

It excludes:

- closure memory address;
- compiler temporary names;
- printed hygienic gensym names;
- source path and line number;
- worker, compiler process, and scheduler identity.

If a semantic closure captures a mutable cell, live capability, port, thread, continuation, resumption, lease, or non-canonical host object, projection fails closed. The resource must move behind an explicit runtime boundary.

* Hygienic macro expansion and provenance

A macro call has separate projections:

- Expansion provenance :: Macro identity, phase, call site, expander evidence, and source diagnostics.
- Expanded POO semantic projection :: The ordinary POO definition graph produced by expansion.

The expanded POO graph participates in semantic identity. Source path and call-site coordinates remain provenance.

Two hygienic macro calls at different source locations may share the same semantic projection when they expand to the same ordinary POO definition graph and do not declare different semantic identities.

An explicitly declared POO identity remains semantic. Structural similarity must not collapse two definitions that intentionally carry different identities.

* Hygienic alpha normalization

Canonical projection normalizes hygienic binding identity without using unstable printed names:

- alpha-renaming of a bound identifier does not alter semantic identity;
- binding relationships remain explicit;
- a change in the referenced binding changes semantic identity;
- phase identity remains available in expansion evidence;
- expansion provenance remains linked without entering the semantic digest.

Normalization must follow Gerbil hygiene and phase semantics rather than implement an unrelated symbol-renaming scheme.

* Definition SCC projection

Cyclic definition graphs are represented without evaluating a value fixed point.

With stable definition identities as anchors, a definition SCC is conceptually projected as:

#+begin_src text
H(
  definition-SCC schema identity,
  sorted member definition identities,
  labeled internal edges between member identities,
  labeled external dependency identities
)
#+end_src

Sorting applies to stable member identities in the SCC envelope. It does not reorder directional operands inside an operation edge.

This projection:

- does not depend on runtime addresses;
- does not execute slot computations;
- does not iteratively hash evaluated values;
- preserves cyclic members and labeled edges;
- changes when the definition topology changes.

It is an identity projection over the definition graph, not a replacement fixed-point evaluator.

* Definition SCC and demand SCC separation

POO Flow distinguishes:

- Definition SCC :: A cyclic region in the canonical POO definition graph. It may participate in the composition-root projection.
- Demand SCC :: The dependency topology actually discovered while evaluating demanded slots in a particular semantic generation. It is derived evaluation evidence.

#+begin_src mermaid
flowchart LR
    D["Stable POO definition identities"] -->|"form labeled prototype and slot edges"| G["Definition graph"]
    G -->|"partition cycles without evaluating values"| S["Definition SCC projection"]
    S -->|"hash members, internal edges, and external dependencies"| I["Canonical definition-SCC identity"]
    Q["Runtime slot demands"] -->|"discover current dependency topology"| C["Current-generation demand SCC"]
    C -->|"record as derived evaluation evidence"| E["Evaluation receipt"]
    C -->|"must not enter composition-root hash"| X["Semantic identity cycle prevented"]
#+end_src

Changing a demand pattern does not by itself change the semantic generation. Changing the underlying POO definition graph does.

* Sharing and duplication

Runtime allocation sharing is not semantic identity:

- repeated references to one explicit semantic definition identity refer to one semantic node;
- different explicit identities remain distinct even when their content is structurally similar;
- sharing one runtime address does not make two semantic definitions equal;
- allocating two runtime objects does not split one semantic definition into two.

Canonicalization may collapse only references to the same semantic definition identity. It must not infer identity from structural equality alone.

* External dependencies

Imports, submodules, and external artifacts enter the canonical root through:

- package or module semantic identity;
- a content digest or verified source identity;
- declared import role;
- contract and capability-requirement projection.

A local checkout path, temporary store path, or development-only location is operational provenance, not semantic identity.

The dependency on =gerbil-poo= is identified by its package source:

#+begin_src text
github.com/mighty-gerbils/gerbil-poo@1c3225637525400341a09e958296962c10184ead
#+end_src

* Canonical projection laws

- Address invariance :: Runtime object addresses do not affect semantic identity.
- Source relocation invariance :: Moving source without semantic changes does not alter semantic identity.
- Hygienic alpha normalization :: Hygiene-preserving renaming does not create a semantic change.
- Semantic sensitivity :: Operation, operand role, priority, contract, and semantic dependency changes alter identity.
- Direction preservation :: Canonicalization does not erase directional native operations.
- Lazy projection :: Identity construction does not force slot evaluation.
- Cycle closure :: Cycles use definition-graph projection instead of evaluated fixed-point hashing.
- Explicit-identity preservation :: Structurally similar definitions with distinct semantic identities remain distinct.
- Provenance separation :: Source and runtime evidence remain linked without entering the semantic hash.
- Fail-closed projection :: A non-canonical live capture prevents construction of a pure semantic root.

* Evidence requirements

Projection evidence records:

- projection schema and domain-separation identity;
- root POO definition identity;
- node and labeled-edge counts;
- native operation identities and operand roles;
- definition-SCC member and external-edge identities;
- captured pure dependency identities;
- rejected non-projectable captures;
- expansion-provenance references;
- external package and artifact identities.

Evidence may disclose opaque identities under redaction, but it must preserve enough structure to prove why two projections are equal or different.

* Implementation checklist

- [ ] Define the canonical POO definition-graph projection schema.
- [ ] Project stable definition identities without forcing slot values.
- [ ] Preserve native operation identity, operand role, and direction.
- [ ] Normalize only operations whose order independence has been verified.
- [ ] Define intensional identity for functions and delayed computations.
- [ ] Canonicalize captured pure values and semantic dependencies.
- [ ] Fail closed on mutable or live runtime captures.
- [ ] Separate expansion provenance from expanded POO semantic identity.
- [ ] Implement Gerbil-aware hygienic alpha normalization.
- [ ] Project definition SCCs from stable member identities and labeled edges.
- [ ] Keep demand SCC topology outside the composition-root hash.
- [ ] Preserve explicit semantic identity across runtime sharing and duplication.
- [ ] Identify external dependencies by verified content rather than local path.
- [ ] Test address invariance, source relocation invariance, and direction preservation.
- [ ] Test that projection does not force lazy or recursively defined slot values.
- [ ] Validate every object and operation projection against real =gerbil-poo= primitives.

* Non-goals

- Do not serialize printed runtime POO objects as semantic identity.
- Do not prove general extensional equivalence of Scheme functions.
- Do not sort directional native-operation operands.
- Do not use source paths or line numbers as semantic identity.
- Do not hash runtime addresses, capabilities, continuations, or mutable cells.
- Do not evaluate a value fixed point to identify a cyclic definition graph.
- Do not replace =gerbil-poo= object semantics or POO Flow fixed-point evaluation.
