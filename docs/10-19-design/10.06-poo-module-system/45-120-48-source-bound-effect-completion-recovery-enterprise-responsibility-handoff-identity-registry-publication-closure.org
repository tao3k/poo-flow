* Decision

This RFC defines one v1 publication semantics for the enterprise
responsibility-handoff identity registry.

A classified snapshot is not sufficient evidence.  A registry is closed only
when every accepted transition is an exact, monotone publication backed by a
validated commit receipt.  Receipts for one registry form a single revision
chain, and the registry authority admits one committed successor for a given
registry revision.

The recovery component of a global handoff key is supplied by an execution
identity owner.  It is not an unchecked string label.

* Reused owners and ownership boundary

=SourceBoundEffectCompletionPublicationHistoryClosed= already proves a
receipt-backed publication chain for effect completion.  It establishes the
project pattern for chained publications, commit receipts, and identity
nonreuse.

=SourceBoundEffectReplayLedger= owns effect idempotency and retry behavior.
The handoff identity registry does not become another effect replay ledger.
It records responsibility-transfer execution evidence and retains its own
identity classification.

The new proof therefore reuses the established proof shape while retaining a
separate owner and separate semantic object.

* Lean-found architecture gaps

** Snapshot classification permits replay after forgetting

Let =S_0= contain handoff =k_0=.  If a later snapshot deletes =k_0= and admits
=k_1= with the same acceptance and observation identities, both snapshots can
be individually classified.  Snapshot-local injectivity never compares the
forgotten entry with the new entry.

#+begin_src typst :file ../../../.data/45-120-48-noninferability-countermodel.svg
#let K = $cal(K)$
#let T = $cal(T)$
#let Opt = $cal(O)$
#let S0 = $S_0: cal(K) -> cal(O)(cal(T))$
#let S1 = $S_1: cal(K) -> cal(O)(cal(T))$
#let A = $A$
#let Classified = $C$
#let Retained = $R$

$ not (Classified(S0) and Classified(S1)
  ==> Retained(S0, S1)) $

$ S0(k_0) = "some"(t_0), S1(k_1) = "some"(t_1),
  A(t_0) = A(t_1) $
#+end_src

The model theorem
=snapshotClassificationDoesNotPreventReplayAfterForgetting= constructs this
counterexample.

** Independently valid forks can conflict

Two writers can read the same empty revision.  One publishes =k_0= and the
other publishes =k_1= using the same acceptance identity.  Each branch is
classified in isolation.  Their union is not classified.

#+begin_src typst
#let Classified = $C$
#let Merge = $M$

$ Classified(S_L) and Classified(S_R)
  and not Classified(Merge(S_L, S_R)) $
#+end_src

The theorem =separatelyClassifiedForksCanConflictWhenMerged= proves that local
validation is not a substitute for one committed successor.

** Reused recovery labels collapse different executions

The previous RFC used =(recoveryId, position)= as the global key.  Lean then
showed that two different execution values may carry the same unchecked
recovery string and therefore produce the same key.

#+begin_src typst
#let E = $cal(E)$
#let Str = $cal(S)$
#let R = $R: cal(E) -> cal(S)$

$ e_0 != e_1 and R(e_0) = R(e_1)
  ==> (R(e_0), i) = (R(e_1), i) $
#+end_src

The registry requires an owner proof that =R= is injective on recovery
executions and that every issued identity is present.

** A state relation is not a commit receipt

A proposition that relates =S_before= and =S_after= can also describe an
ephemeral in-memory mutation.  It does not identify the storage transaction,
provider, registry, revision, or committed artifact.

The proof therefore introduces an explicit publication receipt and an
owner-supplied receipt-validation relation.  The receipt is part of the Lean
closure, not an audit-only JSON convention.

* Registry semantics

** Snapshot

A registry snapshot is a partial map from global handoff key to the exact
enterprise responsibility transfer:

#+begin_src typst
#let K = $cal(K) = cal(R) times NN$
#let T = $cal(T)$
#let Opt = $cal(O)$
#let S = $S: cal(K) -> cal(O)(cal(T))$
#let Some = $S_o$

$ S(k) = Some(t) $
#+end_src

Classification requires acceptance and effective-observation identities to be
injective on all present entries.

#+begin_src typst
#let K = $cal(K)$
#let T = $cal(T)$
#let Opt = $cal(O)$
#let S = $S: cal(K) -> cal(O)(cal(T))$
#let A = $A$
#let O = $O$
#let Some = $S_o$

$ forall k_1, k_2, t_1, t_2,
  S(k_1) = Some(t_1) and S(k_2) = Some(t_2)
  and A(t_1) = A(t_2) ==> k_1 = k_2 $

$ forall k_1, k_2, t_1, t_2,
  S(k_1) = Some(t_1) and S(k_2) = Some(t_2)
  and O(t_1) = O(t_2) ==> k_1 = k_2 $
#+end_src

** Exact monotone publication

A publication from =S= to =S'= for key =k= and transfer =t= requires:

- =k= was absent in =S=;
- =S'(k) = some(t)=;
- every entry in =S= is unchanged in =S'=;
- every entry in =S'= is either the new =k= entry or an entry from =S=;
- the new acceptance identity is fresh against every entry in =S=;
- the new effective-observation identity is fresh against every entry in
  =S=.

#+begin_src typst :file ../../../.data/45-120-48-registry-extension.svg
#let Extends = $subset.eq$
#let K = $cal(K)$
#let T = $cal(T)$
#let S = $S: cal(K) -> cal(O)(cal(T))$
#let Some = $S_o$
#let None = $N_o$

$ S Extends S' := forall k, t,
  S(k) = Some(t) ==> S'(k) = Some(t) $

$ Delta(S, S', k, t) :=
  S(k) = None and S'(k) = Some(t)
  and S Extends S'
  and forall k', t',
    S'(k') = Some(t') ==> k' = k or S(k') = Some(t') $
#+end_src

This is an insertion contract.  Reading an existing key is not a second
publication.

** Commit receipt

Each transition carries:

- publication receipt identity;
- registry identity;
- provider identity;
- before and after revisions;
- before and after snapshot digests;
- exact global handoff key;
- exact responsibility transfer;
- storage transaction digest.

The closed receipt proves that validation succeeded, all identities and
digests are present, the revision advances by exactly one, and the receipt key
and transfer equal the semantic publication step.

** Single committed successor

The registry authority proves:

#+begin_src typst
#let Closed = $C$
#let Registry = $G$
#let BeforeRevision = $B$

$ Closed(r_L, S, S_L) and Closed(r_R, S, S_R)
  and Registry(r_L) = Registry(r_R)
  and BeforeRevision(r_L) = BeforeRevision(r_R)
  ==> S_L = S_R $
#+end_src

It also proves that equal publication-receipt identities determine the same
registry, before revision, and handoff key.

** Receipt chain

A receipt chain is indexed by:

- publication count;
- registry identity;
- initial and final revisions;
- initial and final snapshots.

The zero chain preserves one snapshot.  Each successor is constructed only
from a closed receipt whose registry and before revision equal the current
chain endpoint.

Lean proves that every such chain:

- preserves identity classification;
- retains every initial entry exactly;
- advances through receipt-bound revisions;
- cannot silently replace a previously published transfer.

* Semantic handoff bridge

The closure binds one publication to:

- the owner-issued recovery execution identity;
- the recovery identity carried by the handoff witness;
- the global handoff classification from RFC 45-120-47;
- the exact global transfer;
- the before-snapshot projection into the semantic handoff domain;
- the receipt-closed registry transition.

The after snapshot is therefore both operationally committed and semantically
classified.  Every after entry projects to a real global handoff and its exact
transfer.

* POO boundary

The Scheme interface remains the existing POO-native responsibility-transfer
object and owner relations.  Registry publication is a runtime effect boundary
behind that object.  This RFC introduces no public alist protocol, no second
composition form, and no raw compute hook.

The runtime owner supplies:

- the recovery execution identity object;
- the immutable registry snapshot view;
- the publication receipt validator;
- the single-successor authority;
- the receipt chain.

Lean consumes those relations and proves their consequences.  JSON is only an
AXLE or audit transport.

* Theorem surface

The model proves:

- snapshot classification does not prevent replay after forgetting;
- separately classified forks can conflict when merged;
- distinct executions can collapse to one unchecked string key.

The core proves:

- exact publication preserves snapshot classification;
- publication and receipt chains retain prior entries;
- receipt chains preserve classification;
- one authority rejects divergent committed successors;
- equal receipt identities determine registry revision and key;
- injective recovery identities produce distinct global keys.

The closure proves:

- the before and after snapshots are classified;
- the newly published handoff entry is exact;
- the commit receipt closes the exact transition;
- every after entry projects to the semantic handoff domain;
- the new entry survives every following receipt chain;
- classification survives every following receipt chain;
- one registry revision cannot commit a divergent successor.

* Open proof obligation

Exact retention makes deletion impossible.  A production registry cannot use
unproved eviction merely to bound storage.  The next proof boundary is
proof-carrying archival or compaction: any compact representation must preserve
membership, nonmembership, evidence-identity nonreuse, revision continuity,
and recovery availability without weakening the v1 registry semantics.

* Cedar authorization and responsibility-handoff binding closure

** Requirement

RFC 45-120-44 remains the sole owner of the exact Cedar authorization subject.
This RFC MUST consume that subject projection without redefining it and bind it
to the enterprise responsibility transfer published by this registry:

- the Cedar exact authorization subject equals =transfer.asset=; the
  enterprise specialization of =ResponsibilityTransfer.Transfer= uses
  =AuthorizationSubject= as its asset type;
- =transfer.asset= equals both the before and after responsibility observation
  subjects;
- the Cedar decision evidence identity equals the transfer authority-evidence
  identity;
- both planes use the same owner-audit commitment;
- successor acceptance remains independent evidence carried by the handoff;
  it is not collapsed into Cedar decision evidence and is not equated with the
  predecessor or successor principal.
- the exact responsibility-handoff registry publication is already closed;
  subject/evidence binding cannot authorize an otherwise invalid publication.

The authorization subject is therefore not required to equal the successor
principal.  The closure binds the authorized asset and its authority evidence,
while the existing handoff contract separately proves successor acceptance.

** Observation and countermodel

The Cedar subject bridge and responsibility registry publication can each be
locally valid under the same owner-audit commitment while referring to
different authorization subjects and different authority-evidence identities.
The registry key and commit receipt do not derive the missing equalities.

The Lean countermodel chooses Cedar subject =1= with decision evidence =101=
and a locally closed responsibility handoff whose asset is =2= with authority
evidence =202=.  Both local closures and the shared commitment remain true.
Thus local closure composition alone permits subject/evidence substitution.

** Mathematical contract

- =SourceBoundEffectCompletionRecoveryCedarAuthorizationResponsibilityHandoffBindingClosure=
  is a composition owner, not a second authorization-subject authority.
