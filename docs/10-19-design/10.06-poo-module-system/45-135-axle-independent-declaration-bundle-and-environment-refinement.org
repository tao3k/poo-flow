#+title: AXLE Independent Declaration Bundle and Environment Refinement
#+startup: overview

* Status

Accepted.

This RFC resolves the architecture fork exposed by
[[file:45-134-enterprise-axle-final-source-validation-receipt.org][45-134]]:

- primary proof artifact: an exact, content-addressed declaration bundle;
- optional acceleration artifact: a versioned project-aware AXLE environment;
- proof authority: the bundle and its verification receipt, never the environment
  name alone.

Implementation is authorized only within the boundary defined by this RFC.

The first isolated manifest implementation is recorded in
[[file:45-136-independent-declaration-bundle-manifest-implementation-receipt.org][45-136]].

* Evidence

The uv-resolved =axiom-axle 1.4.0= client reported that every currently
available public AXLE environment from Lean 4.21 through 4.32 has:

- a fixed Lean toolchain;
- =import Mathlib= as its available import header;
- no =repo_url=, =revision=, or =subdir= identifying a POO Flow project image.

Consequently, preserving =import PooFlowProof...= cannot work in the public
environment.  The focused request in 45-134 was rejected with
=unknown module prefix 'PooFlowProof'=.

AXLE itself already supplies the right downstream semantic operations:

- [[https://axle.axiommath.ai/v1/docs/tools/extract_decls/][=extract_decls=]]
  returns self-contained declaration documents with local dependency metadata;
- [[https://axle.axiommath.ai/v1/docs/tools/merge/][=merge=]] combines documents
  in dependency order and resolves duplicate declarations;
- [[https://axle.axiommath.ai/v1/docs/tools/verify_proof/][=verify_proof=]]
  validates a candidate proof against a formal statement;
- [[https://axle.axiommath.ai/v1/docs/configuration/][AXLE environments]]
  identify a Lean toolchain and fixed dependency/import surface.

These operations require input that can already elaborate in the selected AXLE
environment.  AXLE therefore cannot discover missing POO Flow project
dependencies from an unresolved leaf.  The local Lean project must first
project the exact dependency closure.

* Decision

The POO Flow proof harness must construct an =IndependentDeclarationBundle=
before invoking AXLE.

The bundle is a proof-source projection, not a package manager:

- Lake remains the owner of Lean dependency resolution, versions, and package
  layout;
- the Lean compiler environment remains the owner of declaration identity and
  dependency reachability;
- the POO Flow projector consumes the already-resolved graph and emits the
  minimal exact source closure required by the selected declarations;
- AXLE remains the owner of remote semantic extraction, merge, checking, and
  strict proof verification;
- POO Flow remains the owner of the final evidence receipt and explicit
  certificate.

The projector must not resolve Git repositories, invent dependency versions,
replace =lake-manifest.json=, or become a general
=dependency-source-identity= subsystem.

* Why the project-aware environment is secondary

A project-aware AXLE environment is useful when many requests share the same
large dependency base, especially Mathlib, Cedar Spec, and stable POO Flow proof
foundations.  It is not the primary certificate artifact because:

- an environment name does not expose the exact reachable declarations used by
  one proof;
- environment drift could change verification without changing the leaf source;
- publication and cache availability would become correctness preconditions;
- external contributors could not independently reconstruct the proof input
  from the repository alone.

A custom environment may accelerate the same bundle only when it refines a
content-addressed environment manifest and produces the same declaration and
type identities as the independent bundle route.

* Mathematical contract

#+begin_src typst
$ C(r) = "LeanReachableDeclarationClosure"(r) $

$ B(r) = "CanonicalTopologicalBundle"(C(r)) $

$ "BundleIdentity"(B) =
  H(
    "LeanToolchain",
    "AxleEnvironment",
    "ResolvedSourceIdentities",
    "CanonicalBundleBytes",
  ) $

$ "FinalSourceVerified"(r, B) <=>
  "Root"(B) = r
  and "LocalLeanCompiles"(B)
  and "AxleChecks"(B)
  and "AxleExtracts"(r, B)
  and "AxleVerifiesProof"(r, B)
  and "TypeIdentityPreserved"(r, B) $

$ "EnvironmentAccelerates"(e, B) =>
  "EnvironmentManifestPinned"(e)
  and "BundleIdentityPreserved"(e, B)
  and "VerificationOutcomePreserved"(e, B) $

$ "EnvironmentAvailable"(e) and not "BundleIdentityPreserved"(e, B)
  => not "ExplicitCertificate"(r) $
#+end_src

=H= is a cryptographic content digest selected by the proof receipt schema.  It
does not mean that a package alias, branch name, or environment label is a
source identity.

* Bundle contents

An =IndependentDeclarationBundle= must record:

| Field | Contract |
|-------+----------|
| Root selection | Exact module plus declaration identities being verified |
| Lean toolchain | Exact toolchain identity used for local elaboration |
| AXLE environment | Exact environment identity used for remote verification |
| Resolved package sources | Lake-resolved revision and source digest for every contributing package |
| Declaration closure | Compiler-owned reachable declaration identities |
| Source mapping | Declaration identity to owner file and source digest |
| Canonical order | Dependency-topological order with deterministic tie breaking |
| Canonical bytes | The actual self-contained Lean source submitted to AXLE |
| Bundle digest | Digest over identities, mappings, order, and bytes |
| Root type identity | Local and AXLE type hashes or an equivalent checked correspondence |
| Verification receipt | AXLE request, executor, image, artifact, messages, and outcome |

Mathlib may remain supplied by the selected AXLE environment only when its
environment identity and toolchain are pinned.  Dependencies not present in
that environment, including current POO Flow and Cedar project declarations,
must be projected into the bundle or supplied by a separately pinned
project-aware environment that satisfies the refinement contract.

* Construction pipeline

#+begin_src mermaid
flowchart LR
    R["Selected Lean root declarations"] -->|"resolve with Lake-owned graph"| L["Local Lean environment"]
    L -->|"compiler-owned reachability"| C["Exact declaration closure"]
    C -->|"map owner plus source digest"| M["Closure manifest"]
    M -->|"canonical topological projection"| B["Independent declaration bundle"]
    B -->|"local compile under pinned toolchain"| LC["Local bundle receipt"]
    LC -->|"AXLE check and extract_decls"| X["AXLE declaration identities"]
    X -->|"verify_proof for selected roots"| V["AXLE verification receipt"]
    V -->|"compare type and bundle identities"| Q{"Correspondence complete?"}
    Q -->|"yes; all identities match"| E["Eligible explicit certificate"]
    Q -->|"no; missing, stale, or drifted"| F["Fail closed: open obligation"]
    A["Optional project-aware AXLE environment"] -->|"acceleration only; manifest pinned"| X
    A -->|"environment result differs from bundle"| F
#+end_src

The local compile and AXLE verification remain separate evidence surfaces.
Neither absorbs the other.

* Correspondence requirements

The projector must prove or test:

- reachability completeness: every external identifier used by a root is either
  in the bundle or in the pinned AXLE environment;
- reachability minimality: removing any included project declaration breaks at
  least one selected root or its type/proof closure;
- deterministic order: the same resolved sources and root set produce identical
  canonical bytes;
- namespace preservation: bundling does not rename a declaration without an
  explicit identity mapping;
- theorem preservation: the bundled root type is definitionally equal to the
  locally elaborated root type;
- proof preservation: no =sorry=, new axiom, or weakened statement is introduced
  by projection;
- failure monotonicity: missing or ambiguous dependency identity can only move
  the receipt to open/rejected, never to verified;
- environment refinement: an accelerated environment cannot change type,
  dependency, or verification outcome.

* Cedar boundary

Cedar remains a dependency behind the POO Flow =CedarAdapter= proof boundary.
The bundle projector may include exact Cedar Spec declarations required by a
POO Flow proof, but it does not take ownership of Cedar semantics, Rust
implementation, or upstream package publication.

The bundle receipt must distinguish:

- upstream Cedar Spec source identity;
- POO Flow Cedar adapter declaration identity;
- POO Flow dual-engine arbitration declaration identity;
- the selected root theorem;
- the AXLE environment and executor identity.

This separation prevents a passing upstream Cedar theorem from being reported
as a proof of the POO Flow adapter correspondence.

* Failure behavior

The harness must fail closed when:

- a root is an import-only aggregate with no declaration;
- a required project declaration is not in the bundle;
- a package source or owner digest is ambiguous;
- local bundle compilation fails;
- AXLE =check= or =extract_decls= reports a Lean error;
- the AXLE extracted root differs from the local root identity;
- =verify_proof= does not return a successful receipt;
- the environment manifest or executor identity is missing;
- an environment-accelerated result differs from the independent bundle result.

It must not silently fall back to:

- local =lake build= as a substitute for AXLE;
- =--preserve-imports= against an environment that lacks the project;
- a broader or newer AXLE environment;
- an earlier cached certificate with a different bundle digest.

* Implementation boundary

The first implementation slice should change only the Python proof harness and
its tests.  It must consume Lean/Lake-produced closure evidence rather than
parsing Lean imports with regular expressions.

The implementation should initially target the seven failed leaves in 45-134.
The seven already passing independent leaves remain regression controls.

No Gerbil runtime, =use-composition= interface, Cedar runtime adapter, Gerbil
Bazel rule, Nix module, or =gerbil.pkg= behavior belongs in this change.
