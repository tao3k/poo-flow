#+title: Recursive Module Import Reachability, Fixed-Point Dispatch, and Cycle Observability Contract
#+author: POO Flow
#+language: en

* Status

This RFC is an accepted semantic contract.

It defines recursive Module import reachability as the first concrete derived
responsibility of =DispatchEvaluation=.  It does not admit an implementation,
create a project-owned fixed-point engine, or reinterpret imports as package,
source, build, or runtime dependencies.

Implementation remains blocked until every consumed upstream operation path is
=ADMITTED= by RFC 45-120.

* Scope

This RFC owns:

- the =reachable-responsibilities= derived responsibility;
- Module reachability node and import-edge identity;
- demand-driven to-B-to-C traversal;
- fixed-point composition through upstream prototype operations;
- productive, suspended, unproductive, divergent, denied, and terminal cycle
  classifications;
- capability attenuation along import edges;
- node, edge, depth, dispatch, refinement, and observation budgets;
- multi-path provenance and exactly-once logical reconciliation;
- local partial values, stable cache publication, and invalidation;
- ProfileBundle reachability projection and explanation.

It does not own:

- upstream prototype or fixed-point primitives;
- a global eager graph evaluator;
- package dependency resolution;
- Git submodule traversal;
- build graph evaluation;
- runtime continuation invocation;
- capability-closure semantics beyond edge attenuation;
- a public graph or fixed-point DSL.

* Upstream fixed-point evidence

The pinned upstream identity is:

#+begin_example
github.com/mighty-gerbils/gerbil-poo@1c3225637525400341a09e958296962c10184ead
#+end_example

Pinned =proto.ss= source proves:

- =instantiate-proto=;
- =identity-proto=;
- =compose-proto=;
- =compose-proto*=;
- =proto-bottom=;
- =instantiate-protos=.

POO Flow uses these as upstream prototype and recursive-instantiation
semantics.  It must not create a separate =poo-fixed-point= implementation.

Source proof is not project-adapter admission.

* Central decision

=reachable-responsibilities= is evaluated by one =DispatchEvaluation= whose:

- receiver is a Module POO value;
- responsibility is recursive import reachability;
- context carries authority, lineage, active path, budgets, cache identity,
  redaction, and fixed-point suspension information.

Each reachable Module responsibility is one semantic equation.  Upstream
prototype composition and recursive instantiation provide the POO fixed-point
mechanism.  POO Flow supplies only the responsibility algebra, explicit
evaluation context, capability attenuation, cycle classification, provenance,
budgets, and structured outcomes.

* Reachability responsibility

=reachable-responsibilities= derives:

- reachable Module identities;
- reachable exported Profile identities;
- import-edge identities;
- capability attenuation evidence;
- ProfileBundle contributions;
- conflict and provenance inputs;
- cycle and convergence evidence.

It does not return a raw list of package names or filesystem paths.

The semantic result is suitable for later ProfileBundle composition and
=ResolvedCompositionReceipt= derivation.

* Node identity

A reachability node is identified by:

- Module semantic identity;
- requested responsibility identity;
- selected Profile or export identity when selection affects reachability;
- immutable prototype graph or generation identity;
- narrowed capability identity;
- semantic evaluation-context projection;
- cache namespace.

Repository revision, package identity, checkout path, runtime process identity,
wall-clock time, and secret value are not Module node identity.

Two paths reaching the same complete node identity share one logical
evaluation.  They preserve distinct provenance witnesses.

* Import-edge identity

An import edge records:

- source Module identity;
- imported Module identity;
- responsibility or Profile selection;
- capability requirements and attenuation;
- source prototype generation;
- declaration provenance.

An edge is not:

- a =gerbil.pkg= dependency;
- a Git submodule edge;
- a Bazel or Nix build edge;
- a runtime process relation.

Repeated declarations with the same semantic edge identity reconcile as one
logical edge with multiple provenance witnesses.  Conflicting declarations
remain distinct conflict evidence.

* Demand-driven traversal

Traversal begins only from a selected root ProfileBundle responsibility.

The evaluator:

1. registers the root node;
2. projects its =imports= responsibility;
3. attenuates capability context for each edge;
4. dispatches each reachable Module responsibility lazily;
5. memoizes complete node outcomes;
6. classifies active-path re-entry;
7. projects one reachability outcome and explanation.

Construction of a Module does not traverse its imports.  Unselected branches do
not consume evaluation or observation budgets.

* Responsibility algebra

A recursively evaluated responsibility may participate in fixed-point
refinement only when it declares:

- a bottom or initially unresolved semantic value;
- a deterministic refinement operation;
- a monotonicity relation;
- a composition or join operation;
- a convergence relation;
- an explanation delta.

=proto-bottom= may supply the upstream prototype bottom.  It does not prove
that every project responsibility is monotonic.

=compose-proto= and =compose-proto*= compose prototype transformations.  They
do not automatically define Profile conflict resolution or capability closure.

An arbitrary cyclic dispatch is never classified as productive by the mere
presence of a prototype cycle.

* Strongly connected dependency groups

Active-path re-entry identifies a candidate strongly connected dependency
group.

The group is evaluated as one logical refinement unit when:

- every participating responsibility supplies a compatible refinement algebra;
- capability context does not widen around the cycle;
- prototype and contribution identities remain stable;
- budgets permit another refinement step.

The evaluator records group membership and refinement deltas.  It does not
recurse through the host stack until overflow.

* Cycle classifications

** Productive cycle

A cycle is productive when each refinement step is monotonic and the group
reaches its declared convergence relation.

The converged value may enter the stable cache.

** Suspended dependency

A dependency is suspended when progress requires an admitted semantic value
that is not currently available, but the dependency and resume boundary are
well-defined.

The outcome carries an opaque suspension reference.  It does not expose a raw
continuation.  Coordinator resumption creates a new execution identity under
RFC 45-108.

** Unproductive cycle

A cycle is unproductive when no responsibility produces a refinement delta and
no admissible external dependency can enable progress.

The result is a structured condition with the group, dependency path, last
partial identities, and budget evidence.

** Divergent refinement

A group is divergent when it continues to change without reaching the declared
convergence relation before its refinement budget is exhausted.

The result is a structured budget or convergence condition.  The evaluator
does not publish the last partial value as complete.

** Denied or invalid cycle

A cycle is denied or invalid when:

- capability attenuation rejects an edge;
- contribution admission cannot form a valid prototype graph;
- precedence is invalid;
- a responsibility lacks the required refinement algebra.

The evaluator returns structured evidence without fallback traversal.

* Capability attenuation

Capability authority may only narrow along an import edge.

For each edge, the evaluator records:

- incoming capability identity;
- edge requirements;
- admitted provisions;
- attenuated outgoing capability identity;
- denied requirements and redacted explanation.

A later path cannot widen a node evaluation already admitted under narrower
authority.  A wider authority context produces a distinct evaluation identity
or must reuse only evidence proven safe under the narrower projection.

Full capability satisfaction and closure remain a successor contract.

* Budgets

The reachability context may bound:

- distinct logical nodes;
- distinct import edges;
- traversal depth;
- dispatch evaluations;
- fixed-point refinement steps;
- cache lookups and publications;
- observation items or bytes;
- explanation expansion.

Wall-clock deadlines are runtime observations and do not enter pure semantic
identity.

Budget reservations and consumption are reconciled exactly once per logical
node, edge, and refinement step.  Duplicate provenance paths do not repeat node
evaluation charges, but discovering and explaining a distinct edge may consume
edge and observation budgets.

* Exactly-once logical reconciliation

The same node may be reached through multiple import paths.

The evaluator:

- creates at most one active logical evaluation for one node identity;
- shares its terminal or suspended outcome;
- attaches every admitted provenance witness;
- reconciles node budgets once;
- reconciles each distinct semantic edge once;
- does not confuse duplicate delivery with retry, replay, or resumption.

Exactly-once is a semantic reconciliation property.  It is not a claim of
exactly-once runtime execution.

* Cache publication and invalidation

Only converged or terminal semantic outcomes may enter the stable
cross-evaluation cache.

Partial strongly connected group values remain local to one evaluation context.
They are not published as complete ProfileBundle reachability.

A stable cache entry is invalidated by changes to:

- Module or selected Profile identity;
- import-edge identity;
- prototype or contribution generation;
- responsibility algebra;
- capability attenuation identity;
- semantic context projection;
- redaction boundary when the cached explanation is not reusable.

Cache hits preserve provenance attachment, budget reconciliation, and
explanation semantics.

* ProfileBundle projection

Reachability projects first-class Module and Profile responsibilities into one
ProfileBundle closure.

The projection:

- preserves Module and Profile ownership;
- records every admitted import path;
- keeps capability evidence attached;
- does not activate runtime behavior;
- does not create package dependencies;
- remains input to pure =compose profiles=.

Conflict resolution, contribution priority, and final application selection are
separate semantic relations.

* Observability

The explanation may project:

- root demand and normalized node identity;
- discovered and reused nodes;
- import-edge identities;
- capability attenuation;
- cache hit, miss, local-partial, and publication decisions;
- active-path and strongly connected group membership;
- refinement steps and semantic deltas;
- convergence, suspension, denial, divergence, or unproductive-cycle evidence;
- budget reservation, consumption, and reconciliation;
- ProfileBundle contributions and provenance.

Observation is demand-driven, budgeted, capability-scoped, and redacted.
Unbounded graph dumping is not the default.

* Dispatch, =super=, and resumption boundary

Dispatch =super= advances inside one responsibility's upstream C3 path.

Fixed-point refinement advances one strongly connected dependency group.

Coordinator resumption continues a suspended evaluation under a new execution
identity.

These are three distinct continuations.  None may be substituted for another.

* Failure and outcome boundary

The reachability evaluation returns the outcome algebra accepted by RFC 45-107.

It may return:

- semantic value;
- structured condition;
- suspended;
- denied;
- cancelled.

Runtime effects are not required to traverse pure Module imports.  If a
responsibility requests an effect, dispatch projects an EffectIntent and the
pure reachability evaluation suspends or returns a structured condition
according to admitted policy.

* Public-interface boundary

This RFC adds no public graph, cycle, or fixed-point syntax.

The ordinary composition surface remains:

#+begin_src scheme
(use-composition production-system
  (compose profiles
    (use-module wendao-episteme production)
    application-production))
#+end_src

Recursive reachability is derived behind =use-module= and =compose profiles=.

Advanced extension uses native upstream POO objects, prototypes, and admitted
responsibility algebras.

* Ownership

- Upstream =gerbil-poo= owns prototype composition and recursive instantiation
  primitives.
- =poo-flow-core= owns Module reachability identity, responsibility algebra,
  evaluation context, capability attenuation boundary, cycle classification,
  budgets, cache identity, outcomes, provenance, and explanation.
- =wendao-episteme= owns its domain Module imports and exported Profiles.
- The final application owns root Profile selection and contribution admission.
- Runtime/deployment adapters own admitted effect execution and coordinator
  resumption.
- GSLPH remains a development policy harness and building/testing dependency.

* Admission checklist

** Upstream correspondence

- [X] Prove =instantiate-proto= and =instantiate-protos= identities.
- [X] Prove =compose-proto= and =compose-proto*= identities.
- [X] Prove =proto-bottom= identity.
- [X] Reject a project-owned fixed-point implementation.
- [ ] Admit every consumed upstream operation path in RFC 45-120.

** Reachability identity

- [X] Freeze node and import-edge semantic identities.
- [X] Separate imports from package, source, build, and runtime relations.
- [X] Require one logical evaluation per node identity.
- [X] Preserve multiple provenance witnesses.
- [ ] Define exact internal POO prototypes after adapter admission.

** Fixed-point semantics

- [X] Require explicit bottom, refinement, monotonicity, composition,
  convergence, and explanation delta.
- [X] Group active-path re-entry into strongly connected dependencies.
- [X] Distinguish productive, suspended, unproductive, divergent, denied, and
  invalid classifications.
- [X] Prevent publication of incomplete partial values.
- [ ] Prove at least one productive cyclic responsibility algebra.
- [ ] Prove unproductive and divergent cycle conditions.

** Capability, budget, and cache

- [X] Require capability attenuation on every import edge.
- [X] Freeze node, edge, depth, dispatch, refinement, cache, and observation
  budget dimensions.
- [X] Require exactly-once logical reconciliation.
- [X] Publish only converged or terminal cache entries.
- [ ] Prove cache-key sufficiency and invalidation.
- [ ] Prove budget reconciliation across duplicate provenance paths.

** Integration

- [X] Preserve ProfileBundle ownership and provenance.
- [X] Keep reachability behind =use-module= and pure =compose profiles=.
- [X] Separate =super=, fixed-point refinement, and coordinator resumption.
- [ ] Implement =reachable-responsibilities= through =DispatchEvaluation=.
- [ ] Prove A-to-B-to-C traversal and multi-path convergence.
- [ ] Run focused GSLPH development checks without adding a product dependency.

* Rejected alternatives

- A new =poo-fixed-point= package or engine.
- Eager traversal of every Module at construction time.
- Imports represented as package or build dependencies.
- Treating every prototype cycle as productive.
- Host-stack recursion without active-path observability.
- Publishing the last partial value after divergence or budget exhaustion.
- Re-evaluating one node for every provenance path.
- Widening capabilities along a cycle.
- Wall-clock time as pure fixed-point identity.
- Using =super= as fixed-point refinement or coordinator resumption.
- Exposing raw continuations or a public graph DSL.

* Successor contract

The next RFC should define capability satisfaction and closure over the
reachable Module graph.

It must specify:

- requirements and provisions as POO semantic values;
- attenuation and withdrawal;
- monotonic and non-monotonic capability contributions;
- denial and conflict explanations;
- interaction with productive cycles;
- cache identity and invalidation;
- the boundary between semantic capability evidence and runtime handles.

It must remain an RFC semantic contract until its upstream adapter paths are
=ADMITTED=.
