* Ownership and language strengths

This refines [[file:63-scheme-marlin-runtime-boundary.org][the Scheme / Runtime boundary]] and
[[file:150-runtime-language-abi-lane-rfc.org][the Contract-derived ABI lane]].

| Concern | Owner | Python responsibility |
|---------+-------+-----------------------|
| Composition, policies, scope, admissible graph intent | Scheme POO objects and pure functions | Project admitted values |
| Pure semantic transition decisions, reasoning and proof checking | Scheme semantic modules | Marshal input and preserve typed outcomes |
| Macros, prototype/slot composition, specialization | Scheme authoring and compilation | Consume compiled artifact; no Python evaluator |
| Versioned transport, byte ownership, status, feature negotiation | POO shared C ABI / generated projections | CFFI API bindings, release/lifetime handling |
| Async work, cancellation, timeouts, storage, model/tool/network IO | Python Runtime now; Rust Runtime later | Execute admitted effects and report observations |
| Source truth, completeness, lineage and clock authority | Explicit source/provider owner | Bind immutable source identity, never infer authority from LLM text |

Scheme does not absorb an async scheduler or durable store. Runtime execution
must consume admitted semantic decisions; a Python graph dict or custom JSON
dispatch must not establish a second semantic contract.

* Foundation gates

1. Select one vertical slice using existing POO-native values and pure functions:
   finite temporal candidate evaluation against an immutable source snapshot,
   with receipt verification. Reuse the current Scheme verifier. Do not add a
   second inference engine or generic arbitrary Scheme evaluation entrypoint.
2. Define a module-selected, versioned semantic call through the POO ABI.
   Specify canonical source/lens/root/scope identity, explicit complete/partial/
   unknown/rejected outcomes, supported operation IDs and byte limits. Derive
   foreign projections from the Scheme contract. Global =scheme_native_v1=
   validation alone is insufficient.
3. Qualify the AOT package and initialization boundary. No hidden VM in the
   ordinary pure-C SDK. Define thread affinity/reentrancy, borrowed input and
   owner-released output, failure/close behavior, snapshot lifetime and stale
   generation rejection before enabling production Python calls.
4. Compare the same candidate/source through the persistent worker and AOT
   in-process boundary. Record cold startup, warm p50/p95, payload bytes,
   allocations/copies, status and receipt equality. The experiment worker is a
   baseline until matched receipts and packaging evidence justify replacement.
5. Implement Python CFFI marshaling, resource ownership and typed errors for the
   qualified operation. Assert no semantic fallback on unavailable capability,
   rejected input, callback failure, stale handle or closed session. Retain
   Python scheduling, actual model/tool IO and durable operations at explicit
   runtime handoffs.
6. Qualify synchronous/async calls, cancellation, cleanup, concurrency contract,
   duplicate mediation, checkpoint/recovery, source drift, malformed data and
   evidence tampering. Separately record unit, real-native, isolated-wheel and
   exact-head CI results. Skips are not completion.

The native graph guard may be removed only by an implemented, qualified
semantic handoff. An open session, a Python callback, a green reference suite
or a matching plan digest does not satisfy this gate.

* Real LLM evaluation after foundation qualification

Freeze corpus, source snapshots, gold labels, model ID/config, prompts,
tool permissions, equal token/call budgets, stopping rule and evaluator version
before provider calls. Native verification checks candidate validity; it does
not establish external source truth or completeness.

| Paired workload | Independent correctness check | Expected benefit to measure |
|-----------------+------------------------------+-----------------------------|
| Exact source extraction and bounded joins | Gold rows/fields and source IDs | Precision/recall; unsupported claims |
| Valid-time window, knowledge-time cut and intervals | Enumerated finite source oracle | Correct answers and correct uncertainty |
| Withdrawal and generation changes | Frozen before/after gold sets | Stale-answer rejection; preserved old snapshot |
| Missing source, contradictory evidence, open cut | Explicit unknown/partial gold labels | Calibration and appropriate abstention |
| Model proposes valid/invalid candidates | Independent candidate oracle plus Scheme verifier | Detection rate and false rejection rate |
| Model/tool failure, timeout, cancellation and recovery | Event/effect/checkpoint records | No unauthorized or duplicate effects; recovery correctness |

Use the same model and task in paired arms: model with plain source access and
model with the qualified POO/Scheme capabilities. Keep sources, permissions and
budgets equal; include control cases where no benefit is expected. Randomize
arm order and run multiple seeds; select sample counts and budget before calls.
Do not use the same LLM as the sole judge of data accuracy.

Record final task accuracy, field precision/recall, source attribution,
uncertainty outcomes, verifier acceptance/rejection, latency, tokens, cost,
tool calls and effect safety separately. Archive raw model output, call IDs,
usage, exact Runtime/native heads, artifact digests and receipts. Report paired
deltas and uncertainty; a green Runtime suite is not an LLM benefit result.

The earlier four-call study observed identical candidates across its paired
arms and did not demonstrate a correctness benefit. It does not qualify this
new Runtime ABI or a broader task corpus. Its approved call budget is exhausted.
Prepare the runnable study and bounded budget before requesting new paid calls.

* MRR Rust admission

After these gates, Rust consumes the same C contract, immutable artifact pins
and qualification vectors. Admission must bind generation/source/clock/cut and
preserve status, lifetime and proof/evidence semantics. Record integration cost
against the already-qualified Python slice; lower cost is a hypothesis until
measured. This gate remains deferred and open.
