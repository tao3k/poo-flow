* Design correction: no preset Prompt and real-time teaching

The primary acceptance target is now specified in
[[file:model-scheme-understanding-validation.org][model Scheme understanding, reasoning and real computation validation]].
It explains why the historical Prompt was produced, prohibits preset semantic
guidance and answer supply, and requires direct validation of the model's own
Scheme/logic understanding and reasoning. Native-only correctness cannot close
that model gate.

The user prohibits preset Prompts and requires semantic guards to teach in real
time. The historical 48-call experiment violates that criterion: both arms
received preset natural-language RULES, and the native arm additionally received
the solved answer before model generation. Its 25% to 91.67% difference is an
answer-supply/rendering measurement, not evidence of the requested architecture
or model learning. It is withdrawn as an acceptance or benefit receipt for that
design. Raw paid records remain immutable; the prompted live producer is retired.

The implemented final gate recomputes and rejects contradictions. It does not
teach the model, update model weights, or demonstrate learning; 100% accepted
accuracy with abstention is not a learning benefit. No-Prompt integration,
current-execution feedback, and learning effectiveness remain unimplemented and
unqualified. The meaning of real-time teaching must be resolved before choosing
an execution-feedback interface or online parameter-training architecture.

ABI, native ownership, packaging and Runtime regression receipts remain bounded
engineering evidence. RFC model/teaching closure and MRR admission remain open.

* Delivery order and owners

User-directed order: Python/Scheme foundation -> Runtime qualification -> real
LLM accuracy and benefit -> architecture correction and scoped RFC closure ->
MRR Rust integration. No Rust integration is included in this delivery.

| Responsibility | Owner | Implemented boundary |
| Pure finite temporal reasoning and answer verification | Existing ASCENT Scheme lens | POO semantic ABI temporal.solve / temporal.verify |
| Graph objects and topology admission | POO Scheme graph types and algorithms | POO semantic ABI graph.admit / graph.targets |
| Artifact and native lifetime | POO C ABI host | One process lifetime, one owner thread, terminal cleanup |
| Scheduler, cancellation, action IO, reducers, checkpoints, stores | Python production Runtime | Dedicated semantic thread plus existing Python executor |
| Model proposal and text rendering | LLM | Inert candidate JSON; final Scheme consistency gate |
| Source authenticity and effect authority | Existing authority/control lanes | Not granted by labels, consistency or topology admission |

This extends the actual C ABI/FFI capability. Python does not reimplement the
finite temporal solver. The semantic entrypoint calls existing Scheme semantic
owners and has no arbitrary Scheme eval operation. JSON is a versioned internal
byte projection; Scheme objects remain inside the native boundary.

* Implemented interface and package

=bindings/runtime-c/include/poo_flow/semantic.h= defines owned result bytes,
borrowed bounded input, explicit release, open/call/close and typed errors.
=src/ffi/semantic.ss= owns descriptor and projections. Operations:

- =temporal.solve=: result status, rows, frontier, source/lens/root-bound digest,
  native verification and evidence verdicts.
- =graph.admit=: bounded POO graph construction, valid topology and bindings,
  successors and full projection SHA256 receipt. This is topology admission,
  not effect authorization or a claim of Scheme-owned scheduling.
- =graph.targets=: resolve conditional labels and validate control/send targets
  in Scheme against an immutable, digest-bound graph projection. The scheduler
  consumes Scheme-produced static successors, including START.
- =temporal.verify=: recompute the source-bound native answer and compare the
  candidate's exact canonical status/rows. Returns consistent or contradicted.
- =temporal.observe=: compute a source-bound status/row counterexample after
  model IO, with candidate validity and an exact request digest. No tutorial
  or native answer is supplied to the model before this computation.

Temporal requests are bounded to 128 events/members, 256 parent edges and
horizon 1024. The C host rejects wrong-thread calls, malformed UTF-8, NUL, depth >64, input
>1 MiB and invalid result ownership before Scheme. Cleanup is terminal. CFFI
loading is mutex protected. Python serializes native work on an owner thread,
limits pending calls to 64, releases every result, and discards canceled queued
calls. A second runtime instance cannot replace the active process lifetime.

The AOT builder queries the Gerbil compiler's runtime module closure. It does
not parse Scheme source or interpret compiler IR. The manifest binds artifact,
Scheme projection, C host/header, compiler and module closure hashes. Build
caches bind compiler/header/options/platform as well as module source.

=SemanticRuntime.bundled()= loads the optional wheel artifact after digest
verification. Native graph programs require this semantic context and an actual
runtime-v0 session before action execution. Reference mode remains explicit.
Mac local packaging uses a local C control artifact; Linux CI owns the Bazel
control artifact handoff. Local evidence does not establish hermetic Bazel or
clean-host portability. External system dylibs remain packaging dependencies.

Exact-answer gain: +66.67 percentage points. Post-hoc case-cluster bootstrap

This is finite temporal answer rendering with supplied native assistance. It
measures neither autonomous tool selection nor general agent/business accuracy.
The corpus is small and curated. Lower provider-stream latency in this run is
not a general performance guarantee or combined Runtime+provider latency.

* Direct prediction and computed observation

=predict_temporal_answer= and =apredict_temporal_answer= give a detached task
to Python-owned model IO. They do not compute or supply a native answer before
the model's prediction. After IO, =temporal.observe= recomputes the caller's
current source through the existing Scheme temporal owner and produces the
first status or row difference. Invalid candidate shapes remain contradictions.
The receipt binds the current semantic projection and exact request bytes.
Python transports the candidate and receipt; Scheme owns the comparison.

These APIs return contradictions as observations without retries or effect
authorization. A downstream consumer can carry the receipt into a later task.
There is no claim of model learning or business benefit from this plumbing.
The direct Scheme study separately measures actual provider behavior.

* Existing rejection gate: not real-time teaching

Both native-assisted failures fabricated three rows when the correct native
answer was empty. Correct tool output alone did not guarantee correct model
output. The historical correction used =temporal.verify= and answer-rendering
entrypoints. Those rendering entrypoints have now been removed from the active
Runtime: supplying a solved answer does not qualify direct comprehension.
=SemanticRuntime.validate_model_answer= remains available for inert archived
responses; direct model IO uses the task-first prediction/observation APIs.

[[file:evidence/python-scheme-runtime-20261003/final-gate.json][Offline final-answer gate]]
replays all 48 archived answers without a provider call. The gate records
accepted accuracy separately from coverage and retains every rejection. It
must not report abstention as a correct full-task answer. A source withdrawal
changes the binding and invalidates the old model answer.

* Executable qualification

[[file:evidence/python-scheme-runtime-20261003/qualification.json][Qualification receipt]]
and accompanying logs bind the final artifact to actual tests:

- Full Python Runtime suite: 325 passed, zero skips and zero failures. Testing
  package suite: 25 passed.
- Native descriptor, temporal status/evidence, generation rebinding, malformed
  inputs and operation, owner thread, repeated release, lifecycle, bounded queue
  and cancellation tests.
- Actual native topology admission followed by Python action IO, using a real
  runtime-v0 session; invalid topology and bindings reject before IO.
- Python scheduler, streams, checkpoints, stores, control-lane and evidence
  regression tests.
- Installed wheel invokes native semantic solve, graph execution and final verification without
  a Gerbil executable on PATH. This is local installed packaging evidence.
- 60 matched Scheme receipts over worker and native ABI, with alternating call
  order in the final measurement. Includes full binding and evidence equality.

The final alternating-paired run found native median 20.75 ms versus worker
12.54 ms (0.60x warm speedup), while native process setup was 0.0410 s versus
the full test worker harness startup 3.266 s. Filesystem and shared-library
caches were warm; these are process startup measurements. The final receipt
is authoritative.
The current native warm median is about 66% slower; there is no proven
warm-throughput gain. Cold figures compare these particular
harnesses; they do not establish the minimum possible worker startup cost.

All required local checks use real-output watchdogs. Silence beyond five
seconds is a failed attempt; failed builds are not successful receipts.
Remote CI must be checked on the submitted exact head independently.
