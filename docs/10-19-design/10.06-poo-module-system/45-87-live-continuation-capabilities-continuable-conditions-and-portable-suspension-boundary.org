#+title: Live Continuation Capabilities, Continuable Conditions, and Portable Suspension Boundary
#+author: POO Flow
#+language: en

* Status

This RFC records an approved control-plane boundary.

- [X] A live continuation is process-local and opaque.
- [X] A portable suspension descriptor contains no callable continuation.
- [X] A resumption capability is distinct from a suspension descriptor.
- [X] Continuable conditions communicate control decisions, not implicit
  Profile values.
- [X] Live resumption is one-shot by default.
- [X] Portable resumption reconstructs a semantic demand at an explicit safe
  point.
- [X] Remote workers receive pure demand envelopes, never live continuation
  authority.
- [X] Suspension cannot hide an unresolved external side effect.
- [ ] Verify the exact Gerbil and Gambit continuation, dynamic-context, and
  continuable-exception APIs before freezing implementation names.

This document specifies semantics.  Conceptual names in this RFC are not
public API names.

* Formal continuation and suspension surface

The formal surface distinguishes process-local execution authority from a
portable semantic description.

#+begin_src typst
#let CapabilityState = (
  fresh: "Fresh",
  consumed: "Consumed",
)

#let consume = state => {
  if state == CapabilityState.fresh {
    CapabilityState.consumed
  } else {
    none
  }
}

$ "consume"("Fresh") = "Consumed" $
$ "consume"("Consumed") = none $

$ "serializable"("live-continuation") = false $
$ "remote-delegable"("live-continuation") = false $
$ "Profile-operand"("live-continuation") = false $
#+end_src

One-shot authority is a control invariant even when an underlying Scheme
continuation could technically be invoked more than once.

#+begin_src typst
#let portable-safe-point = (
  demand-known
  and immutable-root-known
  and stable-frontier
  and not partial-profile-value
  and not unresolved-external-effect
  and replay-or-checkpoint-present
)

$ "callable-continuation" in "portable-descriptor" = false $
$ "descriptor" != "resumption-authority" $
$ "resumed-root" = "suspended-root" $
$ "resumed-revision" = "suspended-revision" $
$ "resumed-generation" = "suspended-generation" $
$ "resumed-demand" = "suspended-demand" $
$ "raw-VM-continuation-identity-preserved" = false $
#+end_src

Portable reconstruction preserves semantic coordinates, not a VM stack or
continuation identity.  A descriptor may be copied without copying authority;
an independent one-shot resumption capability is required.

* Central decision

The exact Gerbil and Gambit continuation, handler, catcher, cleanup, and
diagnostic API correspondence is owned by
[[file:45-88-gerbil-gambit-continuation-and-condition-runtime-correspondence.org][45-88]].
This document owns the control semantics; 45-88 owns the verified runtime
projection and its executable admission probes.

POO Flow distinguishes live control capture from portable semantic suspension.

A Scheme continuation may support efficient same-process suspension and
resumption.  It is not a portable representation of a POO semantic demand.

Portability is obtained by projecting an execution at an explicit safe point
into a pure suspension descriptor that identifies how the same semantic demand
can be reconstructed or deterministically replayed.

No raw VM continuation, control stack, closure environment, dynamic handler,
port, lock, or transaction context may be serialized as a portable
suspension.

* Three control objects

The following names describe semantic roles.  They do not freeze constructors,
types, slots, or macro syntax.

** Live continuation capability

A live continuation capability is an opaque, process-local POO control object
that encloses authority to resume one captured evaluator continuation.

It is fenced by:

- evaluator instance;
- process identity;
- immutable composition-root identity;
- Profile revision;
- generation identity;
- semantic demand identity;
- dynamic control context;
- capability lifetime; and
- one-shot consumption status.

It cannot be serialized, cached, delegated to a worker, inserted into a
Profile, or used after its fence changes.

** Portable suspension descriptor

The POO-native condition, decision, capability, and later-resumption admission
object algebra is owned by
[[file:45-89-poo-native-control-condition-decision-and-capability-algebra.org][45-89]].
This section owns descriptor purity and safe-point projection, not the control
object family definitions.

A portable suspension descriptor is a pure POO control value.  It describes a
reconstructible semantic demand and contains no callable continuation.

Its semantic contents are limited to:

- composition-root identity;
- Profile revision;
- generation identity;
- demand identity and demand path;
- explicit safe-point identity;
- evaluator semantic revision;
- consumed budget position;
- checkpoint or deterministic-replay reference; and
- required resumption authority.

These fields are semantic requirements, not a frozen serialization schema.

** Resumption capability

A resumption capability authorizes a coordinator to resume one suspended
demand.

It binds:

- a suspension descriptor;
- an authorized principal or capability;
- any additional budget;
- expiration and revocation;
- one-shot consumption; and
- the permitted evaluator target.

Copying a portable descriptor does not copy resumption authority.

* Why call/cc is not a serialization format

A continuation captured by a Scheme runtime may close over:

- VM stack and instruction state;
- dynamic exception handlers;
- =dynamic-wind= context;
- process-local closures;
- ports and locks;
- pending transactions; and
- evaluator-private objects.

Those values are implementation state, not the semantic identity of a POO
demand.

This RFC permits a live continuation capability to hold an opaque continuation
inside the same runtime fence.  It prohibits treating that opaque value as
portable data.

* Safe points

Suspension is portable only at an explicit evaluator safe point.

A portable safe point requires:

- a known semantic demand identity;
- a known immutable root and revision;
- a stable fixed-point or slot-demand frontier;
- no unrecorded partial Profile value;
- no unresolved external side effect;
- a deterministic replay path or admitted checkpoint; and
- a coordinator-owned resumption boundary.

Arbitrary instruction addresses, arbitrary exception sites, and arbitrary
foreign-function frames are not portable safe points.

* Continuable condition boundary

A continuable condition communicates between the evaluator and an authorized
control handler at a safe point.

The condition may expose:

- the suspension reason;
- semantic demand identity;
- root, revision, and generation context;
- current budget position;
- permitted control decisions; and
- a live continuation capability when local resumption is possible.

The handler may select an explicit control decision:

- continue;
- suspend;
- deny;
- cancel; or
- resume under newly authorized control resources.

Returning from a handler MUST NOT inject an arbitrary Profile domain value.
A recovery value is valid only when the native POO computation explicitly
defines a recovery protocol that admits it.

The exact Gerbil or Gambit condition API remains an implementation-verification
question.

* Local suspension and resumption

* Portable suspension and reconstruction

Portable resumption restores semantic continuity.  It does not preserve raw VM
continuation identity.

* One-shot authority

A live continuation or resumption capability is consumed atomically on its
first admitted use.

Default one-shot behavior prevents:

- duplicated budget consumption;
- repeated external effects;
- duplicate evidence;
- duplicate candidate-result submission; and
- concurrent completion of one demand through the same authority.

Although an underlying Scheme continuation may support multiple invocation,
that implementation property does not grant multi-shot POO Flow authority.

Pure branching requires an explicit operation that creates distinct demand
branches with distinct identities and budgets.  It does not reuse one
continuation capability.

* Root and revision fence

Resumption requires the root, Profile revision, generation, and demand identity
recorded at suspension.

If module reload, Profile upgrade, active-head transition, or generation
reversion changes that context, the old suspension cannot resume against the
new root.

The caller may submit a new demand to the new root.  That submission is not a
resumption.

* Side-effect fence

The POO semantic core remains pure, but runtime handoff may involve external
effects.

A portable suspension may cross an effect boundary only when:

- the effect has not started;
- the effect has an admitted commit or abort receipt; or
- an explicit idempotency protocol makes replay safe.

An uncommitted port write, lock mutation, transaction, message send, or foreign
call MUST NOT be hidden inside a portable descriptor.

This RFC does not define effect protocols.  It requires the suspension owner to
respect their existing handoff and receipt boundaries.

* Control rejection is not a native failure

The following are control-plane rejections:

- stale root or revision;
- evaluator mismatch;
- expired or revoked authority;
- already consumed continuation capability;
- missing checkpoint;
- non-portable live continuation;
- unresolved side effect; and
- replay incompatibility.

They do not replace a native POO value or native failure.  They indicate that
the requested control transition was not admitted.

* Distributed evaluator boundary

[[file:45-68-distributed-evaluator-delegation-fencing-and-portable-suspension.org][45-68]] owns the immutable demand envelope, coordinator ownership, worker
delegation, attempt lease and fence, budget ledger, cancellation tree, dynamic
demand admission, and candidate-result admission.

A remote worker receives a pure demand envelope.  It never receives:

- a live continuation capability;
- a resumption capability;
- coordinator cancellation authority;
- generation-publication authority; or
- an unresolved external-effect context.

The coordinator may use a worker result to reconstruct or continue local
evaluation under a fresh local continuation context.

* Conservative-extension relationship

[[file:45-86-poo-conservative-extension-criterion-and-cross-module-obligations.org][45-86]] owns the erasure law and requires resumed completion to match the native
POO result.

This RFC owns the control objects, fences, and transition rules used to satisfy
the resumption-continuity obligation.

* Revision and governance relationships

- [[file:45-83-profile-revisions-live-upgrade-and-module-reload-boundaries.org][45-83]] owns immutable Profile revisions and reload boundaries.
- [[file:45-74-governance-decisions-quorum-revocation-and-break-glass.org][45-74]] owns governance decisions, revocation, and break-glass authority.
- This RFC requires those owners when validating resumption fences; it does not
  reproduce their mechanisms.

* Evidence boundary

Evidence may record:

- safe-point entry;
- local continuation capture;
- descriptor projection;
- resumption authorization;
- capability consumption;
- reconstruction or replay;
- fence rejection; and
- completed native-equivalent result.

Evidence cannot invoke a continuation, grant resumption authority, or become a
Profile slot.

* Prohibited designs

The following designs violate the approved boundary:

- serializing a raw Scheme or VM continuation;
- sending a live continuation to a remote worker;
- treating a descriptor as execution authority;
- resuming against a different root or revision;
- invoking one capability more than once;
- using handler return as an implicit Profile override;
- suspending across an unresolved external effect;
- caching a callable continuation;
- reconstructing an evaluator without a safe point; or
- reporting a control rejection as a native POO failure.
