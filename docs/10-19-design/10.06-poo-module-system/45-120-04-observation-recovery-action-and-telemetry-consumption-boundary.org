#+title: Observation Recovery Action and Telemetry Consumption Boundary
#+startup: overview

* Status

The architecture in this RFC is accepted.

Implementation is not admitted by this acceptance.  Concrete source
owners, exported identifiers, and runtime adapters still require
separate evidence and admission.

* Scope

This RFC freezes the semantic lineage between immutable evaluation
generations, observation evidence, authorized recovery decisions,
coordinator-executed recovery actions, and one-way telemetry
consumption.

It does not define a new public recovery DSL, an event-log subsystem, a
mutable trace store, or a fifth Module responsibility slot.

* Central decision

An =ObservationEvent= is immutable evidence derived from one evaluation
generation.  It is not an operational command and it is not ordered by
wall-clock time.

A =RecoveryDecision= is a pure, authorization-bearing POO value.  It
describes a permitted transition without executing that transition.

Only the recovery coordinator may resolve an authorized decision to an
effectful recovery action.  Every executed recovery action produces a
new evaluation generation and preserves the complete parent evidence
lineage.

Raw continuation handles are ephemeral runtime capabilities.  They are
never fields of =ObservationEvent=, =RecoveryDecision=, Module, profile,
telemetry, or a persistent receipt.

* Semantic observation lineage

Observation identity follows semantic evidence, not log position.
Every observation MUST identify:

- the evaluation source;
- the evaluation generation;
- the evidence from which the observation was derived;
- the parent generation or parent evidence relationship when one
  exists.

Wall-clock timestamps, process identifiers, thread identifiers, and
telemetry sequence numbers MAY appear in a redacted runtime projection.
They MUST NOT define semantic parentage, equality, or evaluation order.

A debug view is a pure projection over immutable observations and their
lineage.  Replaying a mutable trace buffer MUST NOT become the source of
semantic truth.

* RecoveryDecision responsibility

A recovery decision MUST carry enough evidence to answer:

- which observed generation is the transition source;
- which recovery action is requested;
- which capability or Contract authorizes that action;
- which budget or bounded policy constrains it;
- which semantic outcome is expected if the action is admitted.

The decision remains inert until the coordinator validates its
authorization against the current generation.  A decision for a stale
generation MUST fail closed or be reconsidered as a new decision; it
MUST NOT silently act on a newer generation.

The RFC nouns =ObservationEvent= and =RecoveryDecision= are semantic
names.  They do not automatically freeze exported constructor,
function, or macro identifiers.

* Recovery action algebra

The minimum semantic actions are:

| Action     | Authorized meaning                                      | Required successor evidence                         |
|------------+---------------------------------------------------------+-----------------------------------------------------|
| retry      | Re-evaluate under an explicit bounded retry authority   | A new generation linked to the failed generation   |
| substitute | Replace an admitted input, responsibility, or result    | A new generation linked to the substituted evidence |
| resume     | Continue from an admitted recovery point with evidence  | A new generation linked to the suspended generation |
| abort      | Produce an explicit terminal semantic outcome           | A terminal generation linked to the aborted generation |

No action overwrites, deletes, or mutates its source generation.  Even
an =abort= action produces terminal successor evidence so that the
failure and the authorized response remain independently inspectable.

Project extensions MAY add recovery actions only as native POO values
with explicit capability, Contract, lineage, and coordinator execution
semantics.  They MUST NOT add host-language conditionals to the ordinary
composition interface.

* Continuation ownership

First-class continuations and continuable exceptions are runtime
mechanisms for realizing an admitted recovery action.  They are not the
semantic representation of that action.

The coordinator owns every raw continuation handle and MUST enforce an
explicit invocation bound.  A policy may admit one-shot or bounded
multi-shot behavior, but unbounded or ambient continuation reuse is
forbidden.

Persistent semantic evidence refers to a recovery-point identity and
its generation.  It never serializes, prints, hashes, compares, or
publishes the raw continuation handle.

If a continuation is unavailable, expired, already exhausted, or no
longer matches the current generation, execution fails closed with an
actionable recovery receipt.  The coordinator MUST NOT silently restart
or substitute another continuation.

* Telemetry consumption boundary

Telemetry consumes a redacted projection of semantic observations and
coordinator receipts.  It does not consume raw continuations or
unredacted capability evidence.

Telemetry delivery MAY be delayed, duplicated, dropped, batched, or
reordered.  None of those runtime behaviors may change semantic
generation identity, lineage, dispatch, fixed-point evaluation, or a
recovery authorization decision.

* Public and advanced extension boundary

Ordinary composition remains:

#+begin_src scheme
(use-composition production-system
  (compose profiles
    (use-module wendao-episteme production)
    application-production))
#+end_src

The ordinary interface does not expose continuation handling, recovery
conditionals, trace mutation, or telemetry publication.

Advanced recovery extension uses native =gerbil-poo= objects,
prototypes, slots, composition, and dispatch.  A hygienic macro may be
admitted only when a later RFC proves that it projects necessary syntax
or phase semantics onto this native POO model.

* Implementation admission checklist

- [ ] Keep every =ObservationEvent= immutable and owned by exactly one
  evaluation generation.
- [ ] Express parentage through generation and evidence identity rather
  than timestamps or log order.
- [ ] Keep every =RecoveryDecision= pure, inert, and explicitly
  authorization-bearing.
- [ ] Validate the decision against the current generation before
  execution.
- [ ] Produce a new successor generation for =retry=, =substitute=,
  =resume=, and =abort=.
- [ ] Preserve the complete source generation and evidence lineage.
- [ ] Keep raw continuation handles coordinator-owned, ephemeral, and
  invocation-bounded.
- [ ] Never store, serialize, print, hash, compare, or publish a raw
  continuation handle.
- [ ] Fail closed with an actionable receipt when authorization,
  generation identity, budget, or continuation availability is invalid.
- [ ] Redact semantic evidence before telemetry publication.
- [ ] Prevent telemetry delivery behavior from feeding back into
  semantic evaluation.
- [ ] Keep Module at exactly four responsibility slots.
- [ ] Add no public recovery DSL or host-language conditional surface.
- [ ] Apply the profile-policy, capability-authority, and coordinator
  execution boundary in
  [[file:45-120-05-profile-policy-authority-bounds-and-coordinator-execution.org][45-120-05]].
