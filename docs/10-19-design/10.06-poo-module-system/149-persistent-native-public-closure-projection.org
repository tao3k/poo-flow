#+title: Rejected persistent native public-closure projection
#+date: 2026-09-14

* Decision

POO Flow rejects a persistent cache for the mapping from public entry modules
to the ordered local source closure. The experiment accelerated the isolated
=spec= projection, but it did not accelerate the complete unchanged
=build.ss -> std/make= path. ASP, POO Flow, and contributor repositories retain
the direct Gerbil-native closure projection and the standard
=:std/build-script#defbuild-script= entrypoint.

No ASP replacement build script, empty-spec shortcut, second freshness receipt,
or downstream scheduler is admitted. Gerbil =std/make= remains the sole owner
of module dependency contexts, currentness, scheduling, and compilation.

* Why the local result was misleading

The receipt experiment compared forced native closure projection with receipt
admission in separate processes. It produced large local improvements:

| Projection fixture | Native p50 | Receipt p50 | Local reduction |
|--------------------+------------+-------------+-----------------|
| POO Flow, 112 modules | 24.682 s | 0.984 s | 96.0 percent |
| Contributor repository, 39 modules | 9.601 s | 0.534 s | 94.4 percent |

Those figures measure only the PackageSpec projection. A fresh native
projection also constructs Gerbil module contexts in the same process. The
subsequent =std/make= imports can reuse that expander state. A receipt hit
returns only file names; =std/make= must then reconstruct the contexts itself.
The experiment moved work across the =spec-projected= boundary instead of
removing it.

* Complete warm-build comparison

Both lanes below used the same POO Flow checkout, 114 targets, the same
=GERBIL_PATH= and =GERBIL_LOADPATH=, zero =compile= lines, and the native
=std/make= executor. Runs containing delayed recompilation waves were excluded
before sampling.

| Lane | Zero-job samples | p50 |
|------+------------------+-----|
| forced native projection | 51.68 s, 38.24 s, 28.63 s | 38.24 s |
| content-bound receipt hit | 31.73 s, 47.97 s, 39.80 s | 39.80 s |

The receipt-hit median was 1.56 seconds, or about 4.1 percent, slower. It fails
the acceptance requirement that the complete build improve by at least 20
percent. The production cache, policy slot, receipt functions, CI timing gate,
and downstream opt-ins were therefore removed.

* Observable boundary

The verbose handoff remains useful:

#+begin_example
[asp-gerbil-scheme-build] phase=spec-projected target-count=114 executor=std/make
#+end_example

Any silent time after this event belongs to native =std/make=. On the observed
zero-job builds, that interval imports Scheme/SSI module contexts, constructs
completion state, checks source and output timestamps, resolves dependency
library timestamps, and waits for coordinators. Official Gerbil prints compile
events only after currentness decides that work is needed, so a zero-job
planning interval has no native progress messages.

* Remaining owner and acceptance gate

Further optimization must use an existing supported Gerbil interface or be
delivered by the Gerbil owner. POO Flow may add read-only scenarios and receipts,
but it must not modify vendored/upstream Gerbil code or reproduce =std/make=.

A future candidate is accepted only when all conditions hold:

1. the ordinary top-level =defbuild-script= remains unchanged;
2. three alternating complete warm builds preserve the same ordered 114-target
   spec and emit zero compile jobs;
3. candidate p50 improves by at least 20 percent over native =std/make=;
4. one source edit rebuilds exactly the native affected closure;
5. no new scheduler, currentness oracle, or persistent dependency graph is
   introduced in ASP or POO Flow;
6. the relevant upstream owner supplies useful progress events for long native
   planning, or the absence remains explicitly visible in qualification output.

Until such a candidate exists, the correct implementation is the unmodified
native closure plus =std/make=, despite its remaining warm latency.
