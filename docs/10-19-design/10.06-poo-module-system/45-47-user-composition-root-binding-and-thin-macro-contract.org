#+title: User Composition Root Binding and Thin Macro Contract
#+subtitle: Hygienic module definition, root identity, single evaluation, and ordinary Gerbil module boundaries
#+startup: overview

* RFC status

- Status :: Accepted design
- Kind :: Normative user-interface and macro contract
- Semantic core :: Native =gerbil-poo= objects and ordinary functional composition
- Related modules :: =45-40-10-poo-constrained-gerbil-macro-governance.org= and =45-46-poo-definition-anchor-and-revision-identity.org=

This module defines the narrow responsibility that justifies =user-composition= as a public hygienic macro. It is a module-definition boundary for a stable composition root, not a composition DSL.

* Core decision

#+begin_quote
=user-composition= is a module-definition-only thin hygienic macro. It derives a root anchor from the public binding context and binds one ordinary composition value as a stable POO root. It owns no composition, revision, export, registry, or runtime semantics.
#+end_quote

The public interface remains:

#+begin_src scheme
(user-composition my-system
  (compose profiles
    base
    wendao-episteme
    production))
#+end_src

* Conceptual expansion

The macro is conceptually equivalent to:

#+begin_src scheme
(def my-system
  (make-user-composition
    root-anchor-descriptor
    source-provenance
    (compose profiles
      base
      wendao-episteme
      production)))
#+end_src

This is a semantic sketch, not a commitment to an unverified Gerbil API.

- =root-anchor-descriptor= comes from hygienic package, module, binding-role, and definition-kind context.
- =source-provenance= belongs to evidence and diagnostics.
- =compose= is an ordinary function.
- =make-user-composition= is an ordinary function or native POO constructor.
- Macro expansion does not traverse or interpret the operands of =compose=.

Concrete expansion primitives must be selected only after verification against real Gerbil macro, hygiene, and module interfaces.

* Root anchor derivation

The default root anchor is derived from:

#+begin_src text
package semantic namespace
+ module semantic namespace
+ public hygienic binding role
+ user-composition-root definition kind
#+end_src

Consequences:

- The same binding name in different packages has different anchors.
- The same binding name in different modules has different anchors.
- Moving source within the same semantic module does not change the anchor.
- Changing composition operands changes the revision, not the anchor.
- Renaming the public binding changes the public root anchor.
- Compiler gensyms, runtime addresses, and local checkout paths do not participate.

Package and module namespaces come from declared Gerbil package and module identity. They do not come from a checkout path, a =.data= directory, a Nix store path, or a temporary build location.

* =compose= does not allocate root identity

=compose= has the ordinary functional role:

#+begin_src text
composition-strategy POO object
+ Profile operands
-> pure composition value
#+end_src

It must not:

- allocate a global root identity;
- derive identity from operand order;
- infer a name from call stack or source location;
- register the composition;
- export a binding;
- rewrite operand anchors;
- acquire implicit module authority.

Each Profile operand retains its own anchor and revision. =user-composition= binds the resulting composition value under one stable root anchor.

#+begin_src mermaid
flowchart LR
    B["Hygienic public binding my-system"] -->|"derive package, module, role, and kind"| A["Root DefinitionAnchorIdentity"]
    P["Profile operands with existing identities"] -->|"pass as ordinary values"| C["compose ordinary function"]
    S["profiles POO strategy"] -->|"provide composition semantics"| C
    C -->|"produce a pure value without root registration"| V["Unsealed composition value"]
    A -->|"bind the stable root role"| M["make-user-composition"]
    V -->|"provide canonical POO composition projection"| M
    M -->|"derive the root revision through ordinary projection"| R["Bound composition root"]
    Q["Source call site"] -->|"record only as provenance"| E["Expansion evidence"]
    E -->|"reference without changing semantic identity"| R
#+end_src

* Macro and revision boundary

The macro captures an anchor descriptor. It does not compute the root revision.

The root revision is derived through ordinary identity projection:

#+begin_src text
RootDefinitionRevisionIdentity =
H(
  root DefinitionAnchorIdentity,
  canonical composition-value projection,
  profiles strategy semantic identity,
  active control-plane policy identities
)
#+end_src

The macro does not need to understand priorities, contracts, imports, capabilities, resolvers, fixed-point evaluation, or SCC topology. Those semantics enter through the ordinary POO composition projection.

* Module-definition-only placement

=user-composition= is valid only where a module definition may establish a long-lived composition root.

It is not an arbitrary expression macro:

- its purpose is to bind a stable root;
- package and module namespaces are explicit at the definition boundary;
- binding lifetime and export identity are well-defined;
- local temporary composition does not require a public root anchor.

Local and higher-order composition use the ordinary function directly:

#+begin_src scheme
(compose profiles
  base
  experimental)
#+end_src

An ordinary local binding may hold such a value:

#+begin_src scheme
(def local-profile-set
  (compose profiles
    base
    experimental))
#+end_src

That binding does not become a formal user-composition root unless the program makes a separate explicit root-definition decision.

* Ordinary Gerbil module boundaries

=user-composition= produces an ordinary Gerbil binding:

- export remains controlled by the normal Gerbil module system;
- import remains controlled by the normal Gerbil module system;
- package management remains controlled by =gerbil.pkg=;
- the macro does not create a composition registry;
- the macro does not create a discovery side channel;
- the macro does not auto-publish a runtime root;
- the macro does not transfer child build, test, or publication ownership to a parent repository.

A Git submodule relationship and a Gerbil package relationship remain distinct.

* Single evaluation and hygiene

Macro expansion guarantees:

- the composition expression is evaluated exactly once;
- operand construction is not duplicated;
- user bindings are not captured;
- internal temporary bindings do not escape;
- surface syntax errors are projected to the =user-composition= call site;
- source provenance remains separate from semantic identity;
- expansion reduces to ordinary binding, function calls, and POO values.

Semantic failures inside =compose= are not converted into macro-expansion errors. They remain structured POO composition evidence and, where authorized, continuable recovery conditions.

* Public rename and explicit object identity

Renaming the public binding changes the public root anchor by default.

An explicitly stable POO object identity may remain stable across source refactoring, but the changed export binding receives separate interface-identity evidence. The macro does not infer continuity from structural similarity and does not create compatibility aliases.

* Expansion evidence

Expansion evidence records:

- macro semantic identity and version;
- package and module semantic namespaces;
- public hygienic binding role;
- root definition kind;
- derived root anchor identity;
- source call-site provenance;
- the ordinary expansion projection;
- single-evaluation proof or check;
- any surface-shape diagnostic.

The call-site path and line remain evidence only. They do not enter the root anchor or revision.

* Macro admission closure

=user-composition= remains admitted only while its responsibilities cannot be expressed by an ordinary function:

- establishing a hygienic definition binding;
- observing the module-definition context;
- deriving the public binding role;
- projecting syntax errors to the call site.

If these responsibilities move into an ordinary language binding mechanism without losing hygiene or provenance, macro admission must be reevaluated.

The macro must not grow clauses for priority, resolver, observability, submodule, capability, retry, or runtime configuration. Such growth would violate the POO-constrained macro-governance principle.

* Implementation checklist

- [ ] Verify the real Gerbil definition-context and hygiene APIs.
- [ ] Define package, module, public-binding-role, and root-kind anchor projection.
- [ ] Exclude source path, line, gensym, runtime address, and checkout location.
- [ ] Implement a thin expansion that evaluates the composition expression once.
- [ ] Keep =compose= an ordinary function.
- [ ] Keep =profiles= a first-class POO strategy object.
- [ ] Derive the root revision through ordinary POO semantic projection.
- [ ] Reject use of =user-composition= outside the admitted definition context.
- [ ] Preserve ordinary Gerbil export and import behavior.
- [ ] Verify that no registry, discovery side channel, or auto-publication is created.
- [ ] Project macro-shape errors to the call site.
- [ ] Preserve semantic composition failures as POO evidence.
- [ ] Generate expansion evidence without hashing source coordinates.
- [ ] Test package and module namespace separation.
- [ ] Test source relocation, public rename, single evaluation, and hygiene.
- [ ] Confirm that future domain features do not add clauses to the macro.

* Non-goals

- Do not turn =user-composition= into a composition DSL.
- Do not parse or rewrite =compose= operands.
- Do not compute priority, fixed-point, capability, resolver, or SCC semantics in the macro.
- Do not use =user-composition= as an arbitrary expression macro.
- Do not allocate a generation or composition registry entry.
- Do not auto-export or auto-publish the bound root.
- Do not duplicate Gerbil module or =gerbil.pkg= behavior.
- Do not add domain-specific clauses or nested composition syntax.
