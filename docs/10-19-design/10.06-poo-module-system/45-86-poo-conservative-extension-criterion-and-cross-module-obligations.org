* Status

This RFC records an approved cross-module semantic criterion.

- [X] Native POO semantics remain the baseline.
- [X] Control and evidence are separate from the POO semantic plane.
- [X] Correctness is defined by an erasure law.
- [X] Allowed completion preserves native values and failures.
- [X] Budget restriction cannot fabricate a semantic result.
- [X] Resumption continues the same root and demand.
- [X] Cache and incremental execution remain equivalent to native
  reevaluation.
- [X] Observation is non-interfering.
- [X] One generation retains one composition root.
- [X] Live continuation and portable suspension semantics are delegated to
  [[file:45-87-live-continuation-capabilities-continuable-conditions-and-portable-suspension-boundary.org][45-87]].
- [ ] Produce cross-module conformance witnesses before implementation
  admission.

This RFC defines a criterion.  It does not re-prove POO and does not absorb the
implementation ownership of the referenced modules.

* Formal conservative-extension surface

The formal surface distinguishes a completed native outcome from an
operational state that has not produced semantic meaning.

#+begin_src typst
#let NativeOutcome = (
  value: value => ("Value", value),
  failure: error => ("NativeFailure", error),
  diverges: ("Diverges",),
)

#let ExtendedOutcome = (
  completed: native => ("Completed", native),
  suspended: control => ("Suspended", control),
  denied: control => ("Denied", control),
  cancelled: control => ("Cancelled", control),
)

#let erase = outcome => {
  if outcome.at(0) == "Completed" {
    outcome.at(1)
  } else {
    none
  }
}

$ "erase"("Completed"(n)) = n $
$ "erase"("Suspended"(c)) = none $
$ "erase"("Denied"(c)) = none $
$ "erase"("Cancelled"(c)) = none $
#+end_src

Only =Completed= has a semantic erasure.  Suspension, denial, and cancellation
are control outcomes, so none can be reclassified as a native value or native
failure.

* Central decision

POO Flow is a conservative operational extension of the adopted POOF and
=gerbil-poo= semantics.

POO Flow may observe, restrict, suspend, resume, cache, incrementally
reevaluate, govern, publish, or revert execution.  After control and evidence
are erased, every allowed completed execution MUST expose the same native POO
value or native failure.

An operational layer may decide whether and when a computation proceeds.  It
MUST NOT decide what value native POO means.

* Three planes

** POO semantic plane

The semantic plane is owned by the adopted POO implementation:

- objects and prototypes;
- slots;
- final =self=;
- inherited computation through =super=;
- fixed-point instantiation;
- object precedence; and
- native values and failures.

** Control plane

The control plane may contain:

- budgets;
- admission decisions;
- suspension;
- authorized resumption;
- retry and cancellation;
- continuation capabilities;
- cache admission; and
- incremental scheduling.

Control values are not Profile operands and are not implicit slots.

** Evidence plane

The evidence plane may contain:

- demand paths;
- observations;
- provenance;
- cache-hit or recomputation facts;
- suspension and resumption receipts;
- governance decisions; and
- generation context.

Evidence records what occurred.  It does not become a source of POO values.

* Plane relationship

The control and evidence planes may change execution availability and
operational traces.  They cannot redefine native POO meaning.

* Outcome model

The native outcome domain is:

#+begin_example
Value(value)
NativeFailure(error)
Diverges
#+end_example

The extended operational outcome domain may additionally contain:

#+begin_example
Suspended(continuation, reason, evidence)
Denied(reason, evidence)
Cancelled(reason, evidence)
#+end_example

=Suspended=, =Denied=, and =Cancelled= are not semantic values and are not
replacement native failures.  They indicate that no completed semantic result
is available from that execution.

* Erasure law

For a Profile program =P=, demand =D=, and an operational policy that allows
completion:

#+begin_example
erase-control-and-evidence(Extended(P, D, policy))
  approximately-profile
Native(P, D)
#+end_example

=approximately-profile= compares admitted Profile projections and native
failure meaning.  It does not require identical timing, event count, cache
behavior, continuation identity, object address, or receipt encoding.

The erasure relation is partial for suspended, denied, cancelled, or diverging
executions because those executions do not produce a completed semantic
outcome.

* Seven cross-module obligations

** Native-result preservation

When native POO returns =Value(v)= and the operational policy allows
completion, the extended execution MUST return the same admitted Profile value
=v= after evidence is erased.

No observer, scheduler, cache, or governance decision may substitute another
domain value.

** Native-failure preservation

When native POO produces a native failure, POO Flow may attach root revision,
operand identity, demand path, generation context, and causal evidence.

The contextualized result MUST retain the native failure category and semantic
meaning.  Observation or governance cannot turn the failure into a successful
Profile value.

** Budget restriction

Budgets restrict the set of executions allowed to continue:

#+begin_example
allowed executions are a subset of native executions
#+end_example

Budget exhaustion may suspend, deny, or cancel work.  It MUST NOT publish a
partial object, partial fixed point, guessed value, or replacement failure as a
completed Profile result.

** Resumption continuity

An authorized resumption continues the same semantic demand:

- the same immutable composition root;
- the same Profile revision;
- the same generation;
- the same slot demand;
- the same =self=/=super= relation; and
- the same accumulated control history.

A stale continuation MUST NOT attach to a newer root or re-resolve a lexical
Profile name.  A changed root requires a new demand.

Continuable exceptions and first-class continuations are control mechanisms.
They do not authorize arbitrary value injection.  A supplied recovery value is
valid only when the native POO computation explicitly defines such a recovery
protocol.

** Cache and incremental equivalence

A cache hit and a full native reevaluation for the same admitted semantic key
MUST expose equivalent Profile values or native failures.

Cache hits and misses may produce different evidence and performance.  They
cannot produce different domain meaning.

Incremental reevaluation uses full native reevaluation as its semantic oracle.
It does not define a second fixed-point semantics.

** Observation non-interference

An observer MUST NOT project an additional slot merely to describe a demand.
It records only demands, decisions, values, and failures that already occur.

An observation handler MUST NOT:

- call =.ref= on an otherwise undemanded slot;
- force a delayed slot early;
- change final =self=;
- change the inherited =super= chain;
- insert a hidden Profile contribution; or
- expose a receipt as an implicit domain slot.

Feedback from evidence to execution is permitted only through explicit control
decisions such as continue, suspend, deny, cancel, or resume.

If a policy must change a Profile value, that policy must enter the semantic
plane as an explicit Profile or prototype contribution.

** Single-root preservation

Control and evidence MUST NOT instantiate a second composition root inside one
generation.

The following are prohibited:

- re-instantiation for debugging;
- copying a new root at suspension;
- resolving a newer Profile revision at resumption;
- creating a distinct fixed point on a cache miss; and
- attaching an old continuation after module reload.

* Continuation boundary

A continuation capability is bound to the demand and immutable root context
that created it.

The control layer may expose a POO-native suspension or resumption object, but
that object is not a Profile and cannot participate in =compose profiles=.

Live continuation capabilities, continuable conditions, one-shot resumption,
safe points, and portable descriptor projection are owned by
[[file:45-87-live-continuation-capabilities-continuable-conditions-and-portable-suspension-boundary.org][45-87]].  Distributed delegation and worker fencing remain owned by
[[file:45-68-distributed-evaluator-delegation-fencing-and-portable-suspension.org][45-68]].  This document requires only semantic continuity.

* Cache boundary

This document does not define cache keys, invalidation algorithms, distributed
admission, storage, or poisoning resistance.

It requires only:

1. a cache hit is semantically equivalent to full reevaluation;
2. a stale or unverifiable entry is not admitted as a semantic result; and
3. cache evidence cannot become a Profile input unless explicitly modeled as a
   Profile contribution.

* Governance boundary

Governance may control authority to execute, suspend, resume, retry, cancel, or
publish.

Governance does not own native POO result construction.  A decision receipt is
not a slot override.

* Evidence boundary

Cross-module evidence demonstrates only the applicable conservative-extension
obligation.

It MUST NOT become:

- a package closure;
- a new runtime registry;
- a second Profile contract;
- an active evidence input to every slot demand; or
- a substitute for the specialized owner's tests.

An obligation may cite evidence produced by its owner.  This RFC does not
require copying those suites.

* Prohibited designs

The following designs violate the approved criterion:

- an observer that forces additional slots;
- a budget handler that publishes a partial value;
- a resumption attached to a different root;
- a cache hit that differs from native reevaluation;
- an incremental evaluator with a second fixed-point meaning;
- a receipt injected as a hidden slot;
- governance that substitutes a domain value;
- re-instantiation for debugging;
- converting a native structural failure into success; or
- treating operational denial as a native POO failure.
