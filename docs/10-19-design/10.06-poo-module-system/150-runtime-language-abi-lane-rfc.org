* Status

Normative owner rule: the *POO Contract is the sole canonical semantic owner*. Org, JSON, AST data, ABI vectors, C headers, language types, and Lean propositions are sources or projections; none is a semantic co-owner.

The Runtime Language ABI Lane is the contract-derived representation,
qualification, and transport boundary. Marlin, Python, and future runtimes
concretize the lane. The ABI does not own POO Contract semantics, Contract
admission, or execution truth; the concrete runtime owns the effect it performs
and the execution receipt it emits.

This RFC corrects an architectural naming error in RFC 149's next-step prose.
The *Runtime Language ABI Lane* is the contract-artifact projection and
cross-language qualification boundary, not an effect owner. Marlin, the Python
runtime, and future language runtimes concretize this lane and own the effects
they perform; none owns or redefines POO Contract semantics.

The first implementation tranche covers the Contract-derived promotion
projection, implementation-owned execution receipt, capability qualification,
epoch fence, idempotency identity, injection receipt, rollback receipt, and
cross-language qualification vector. It does not claim that a Marlin adapter
has landed.

* Decision

The authority stack is:

1. The POO Contract is the sole canonical semantic owner.
2. Org is a durable authoring, governance, and audit source. Org parser / AST
   queries may emit JSON or AST data into Runtime Language admission; neither
   Org nor its emitted representation becomes a semantic co-owner.
3. POO Flow admits source data against the POO Contract and lowers approved
   semantics into canonical subjects, commitments, promotion
   intents, and validation receipts.
4. Cedar decides whether the principal may authorize the promotion.
5. Lean checks the invariant-bearing proof obligations.
6. Runtime Language ABI projects an admitted Contract artifact into a
   versioned language lane and qualifies that projection. It neither performs
   Contract admission nor owns execution effects.
7. Marlin, Python, or another runtime is a concrete ABI-lane implementation and
   proves conformance
   using the same qualification vectors.

Memory is therefore a temporal role carried by protocol subjects.  It is not
the owner of identity, authority, proof, materialization, or execution truth.

* Owner boundary

The two causal chains below are non-interchangeable and must not share a receipt:

#+begin_example
Org -> AST -> query -> JSON / AST data -> Runtime Language -> POO Contract admission
  => SourceQueryReceipt
  => RuntimeLanguageAdmissionReceipt

POO Contract -> ABI vector / C header / JSON schema / language type / Lean proposition
  => ContractArtifactProjectionReceipt
#+end_example

The artifact-projection receipt has no source-query dependency. The chains may refer to the same content identity, but each receipt identifies only its own owner, inputs, projector/admission identity, version, and output digest.

| Concern | Canonical owner | Forbidden substitution |
|-
| Organization source and amendment | Org + Contract | mutable Markdown/JSON as authority |
| Subject, commitment, promotion semantics | POO Flow | runtime-local policy objects |
| Authorization | Cedar evidence | adapter boolean without decision identity |
| Invariant proof | Lean evidence | runtime assertion as proof |
| Wire and effect contract | Runtime Language ABI | Marlin- or Python-specific protocol |
| Execution | qualified runtime implementation | POO Flow pretending to execute effects |
| Audit and cutover | receipts + qualification vectors | logs without content identity |

* Promotion state machine

Normative ownership: =approved= is a POO Contract policy decision produced by
the POO Flow + (Cedar + Lean) dual engine. Submitted states belong to runtime
execution receipts; approval remains upstream.

ABI qualification states describe projection compatibility only. Runtime
execution states are implementation-owned and may not redefine either Contract
admission or ABI qualification.

The canonical state machine is:

#+begin_example
candidate -> approved -> submitted -> materializing -> materialized
                                                |             |
                                                v             v
                                             failed       injected -> active
                                                |             |
                                                +--> rolled-back <-+
#+end_example

=approved= and every semantic admission state belong to the POO Contract plus
the Cedar + Lean decision chain. ABI qualification states describe projection
compatibility only. Marlin/Python execution states belong to
implementation-owned receipts and cannot redefine semantic admission or ABI
qualification.

* Contract-derived ABI request projection

The ABI request is a deterministic projection of an identified and versioned
POO Contract artifact. Its fields and bytes are not a second canonical request
and cannot confer admission. The projection binds Contract identity and
version, source Contract digest, projector identity and version, and the
Contract artifact-projection receipt.

The request schema is =poo-flow.runtime-language.promotion-request.1=.  It must
carry:

- ABI major/minor and required capability bits;
- promotion, subject, commitment, candidate, and materialization identities;
- source role, target role, scope, injection target, and rollback target;
- Bundle, authority, proof, and evaluator epochs;
- evidence root, validation receipt schema, approval code, and checked gates;
- an implementation-independent idempotency identity.

The idempotency identity excludes the runtime implementation.  Otherwise a
failover from Python to Marlin could materialize the same promotion twice.

#+begin_src typst
#let K(p) = (
  p.promotion-id,
  p.materialization-id,
  p.candidate-digest,
  p.injection-target,
)

$ K(p, "python") = K(p, "marlin") = K(p) $
#+end_src

* Capability negotiation

Capability negotiation qualifies one Contract-derived projection for one
runtime implementation. A runtime reports =ABI-qualified= only when its
advertised capabilities dominate the required set and the independent
admission receipt is valid. Capability qualification is not Contract
admission.

Runtime ABI minor version 3 adds these capability bits:

| Bit | Capability |
|-
| 7 | =PROMOTION_MATERIALIZE= |
| 8 | =INJECTION_RECEIPT= |
| 9 | =ROLLBACK= |
| 10 | =EXACTLY_ONCE= |
| 11 | =LANGUAGE_QUALIFICATION= |

A runtime may accept a request only when its advertised capabilities dominate
the request's required set.

#+begin_src typst
$ Accept(r, p) => Required(p) subset.eq Supported(r) $
#+end_src

* Epoch fence

The ABI request repeats all four epochs already checked by POO Flow.  The
runtime compares them again immediately before committing an effect.  This is
an execution-time fence, not a second policy decision.

#+begin_src typst
$ Commit(r, p, w) =>
  p.bundle-epoch = w.bundle-epoch and
  p.authority-epoch = w.authority-epoch and
  p.proof-epoch = w.proof-epoch and
  p.evaluator-epoch = w.evaluator-epoch $
#+end_src

A stale request must produce =rejected-stale-epoch= and no materialization,
injection, or rollback side effect.

* Transported exactly-once execution obligations

The ABI carries idempotency and causal-link projections and defines conformance
vectors for them. Actual materialization, injection, rollback, replay, and
commit ownership belongs to the runtime implementation. Source-query,
admission, and Contract artifact-projection receipts never claim an execution
commit.

For one idempotency identity, at most one receipt may claim a committed
injection.  Replay receipts refer to the original causal receipt and do not
constitute a second commit.

#+begin_src typst
$ forall k: card({r | r.key = k and r.outcome = "injected"}) <= 1 $

$ Active(k) <=> card({r | r.key = k and r.outcome = "injected"}) = 1 $
#+end_src

An =injected= receipt is complete only when it includes both the materialized
content digest and the injection receipt digest.

#+begin_src typst
$ Complete(r) <=>
  r.outcome = "injected" =>
  r.materialization-digest != none and
  r.injection-receipt-digest != none $
#+end_src

* Runtime implementation execution receipt

This receipt is emitted by the concrete runtime that attempted the effect. The
ABI specifies its cross-language representation and qualification rules; the
ABI itself is not the causal owner. This receipt is independent of, and may
only causally reference, the source-query, Runtime Language admission, and
Contract artifact-projection receipts.

The receipt schema is =poo-flow.runtime-language.promotion-receipt.1=.  It must
carry:

- request idempotency identity and canonical request digest;
- implementation id, implementation version, and language;
- supported capabilities and attempt/fence number;
- observed Bundle, authority, proof, and evaluator epochs;
- outcome, materialization digest, injection receipt digest, rollback receipt
  digest, and causal receipt digest;
- =runtime-executed=true= only for an actual runtime-produced receipt.

Allowed outcomes are =accepted=, =materialized=, =injected=,
=replayed-active=, =rejected-stale-epoch=, =rejected-capability=, =rolled-back=,
and =failed=.

* Cross-language qualification

POO Flow derives the shared qualification vector from the identified POO
Contract and its artifact-projection receipt. Consumers compare normalized
Contract semantics first; byte equality qualifies only that representation.
Adapter-specific fixtures cannot replace this shared contract-derived vector.

POO Flow emits one deterministic line-oriented qualification vector.  Python,
Marlin, and future runtimes must consume the same vector and return a normalized
receipt satisfying this RFC.  Adapter-specific test fixtures cannot replace
the canonical vector.

For any conforming implementations =a= and =b=:

#+begin_src typst
$ Qualifies(a) and Qualifies(b) =>
  Normalize(a(p)).semantic = Normalize(b(p)).semantic $
#+end_src

Timing, allocation, and implementation-private diagnostics may differ.  The
idempotency identity, epoch decision, outcome semantics, and receipt completeness
may not differ.

* Human Audit boundary

Ordinary promotions may proceed automatically when Cedar permits, Lean
verifies, epochs are current, and the runtime qualifies.  Human Audit is
mandatory when a proposal changes any of the following owners:

- ABI schema or capability meaning;
- Bundle/authority/proof/evaluator epoch semantics;
- Cedar policy authority or Lean theorem obligations;
- the definition of committed injection, rollback, or exactly-once behavior;
- the qualification vector itself.

The audit result is an Org amendment plus a new content identity, Cedar grant,
Lean evidence, and Runtime Language admission receipt. If execution follows,
the concrete runtime emits a separate injection receipt. A runtime cannot
approve its own contract change.

* Approved clarification: canonical ownership and data ingress

** Sole semantic owner

The POO Contract is the only canonical semantic owner.  Field identity, state
transitions, compatibility, provenance requirements, epoch invalidation,
deduplication, exactly-once materialization, and receipt validity are Contract
semantics.

Neither Org nor a serialization format is a co-owner.  A change to an Org
document, JSON object, AST record, ABI vector, C header, or language-native type
cannot change runtime meaning unless it is admitted by the identified and
versioned POO Contract.

** Two independent projection chains

The Contract projection chain is:

#+begin_example
POO Contract
  -> Runtime Language ABI
  -> Gerbil POO | Rust type | Python type | C ABI
#+end_example

The source-data ingress chain is:

#+begin_example
Org source
  -> Org parser
  -> Org AST
  -> AST query
  -> JSON | AST data
  -> Runtime Language adapter
  -> language-native typed value
  -> POO Contract admission
#+end_example

These chains meet only at Contract admission.  Successful Org parsing, AST
selection, JSON decoding, or language adaptation does not grant semantic or
execution authority.

** Derived representations

The checked-in =*.vector= qualification data is an ordered ABI projection, not
a canonical contract.  JSON and AST data are also projections or ingress
representations.  Each must identify the governing POO Contract and produce a
projection receipt; qualification compares normalized Contract semantics before
it compares the bytes of a particular representation.

** Receipt split

An AST query receipt binds source content identity and version, parser identity
and version, query identity and version, selected AST node identities,
representation, provenance root, and result digest.

All receipt version identities are non-empty strings across Runtime Languages;
numeric host representations are rejected before semantic normalization so that
JSON, AST-data, Gerbil, Python, and Rust adapters cannot hash the same version
with different scalar types.

A Runtime Language admission receipt binds that result digest to adapter
identity and version, target language, POO Contract identity and version,
normalized semantic digest, and admission outcome.  An admitted projection must
carry both receipts; neither receipt alone authorizes materialization.

A Contract artifact-projection receipt is independent of source-data ingress.
It binds projection identity, POO Contract identity/version and source digest,
projector identity/version, artifact kind and identity, and output digest.  It
is the receipt used for ABI vectors, C headers, JSON schemas, language-native
types, and Lean propositions; requiring an Org query receipt here would mix the
two projection chains again.

** Typst admission equations

#+begin_src typst
$
Q(q) := id_s(q) and ver_s(q) and id_p(q) and ver_p(q)
        and id_query(q) and nodes(q) != emptyset
        and provenance(q) and digest(q)
$

$

  and p.query-digest = q.result-digest
  and p.contract-id = c.id
  and p.contract-version = c.version
  and p.semantic-digest != none
  and p.outcome = admitted
$

$
P(c, a) := a.contract-id = c.id
  and a.contract-version = c.version
  and a.source-contract-digest = digest(c)
  and a.projector-id != none
  and a.output-digest != none
$

$
semantic(q[representation := json])
  = semantic(q[representation := ast-data])
$

$

  = semantic(p[adapter := a_2, language := l_2])
$
#+end_src

The last two equalities state non-ownership: representation and runtime
implementation identity may change projection mechanics, but cannot change the
Contract semantic identity.
