* Decision

RFC 45-120-45 proves that one owner-audit commitment selects one Cedar
authorization subject, one human-authority closure, and one atomic
materialization commit.

That result does not prove that a crash can be recovered safely.

This RFC adds the missing bridge to the existing
=PromotionTransactionRecovery= owner model.  The bridge requires:

- a durable canonical transaction request;
- an exclusive fenced recovery claim;
- a terminal recovery receipt with complete effect observation;
- exact equality between the recovery base receipt and the RFC 45-120-45
  commit receipt;
- a new Cedar lifecycle admission evaluated at recovery time;
- exact epoch and fence bindings across the recovery authorization,
  source-recovery expectation, and recovery claim;
- explicit request, identity, provider-worker, authority-accountability, and
  provenance relations.

The result is one current architecture.  The RFC does not introduce an
alternative execution path.

* Owner boundary

This RFC does not define another transaction protocol.

The authoritative owners remain:

| Concern | Authoritative Lean owner |
|-
| Atomic promotion admission and commit | =PromotionTransactionAtomicity= |
| Human authority and accountability | =HumanAuthorityAccountability= |
| Transaction registry, durable intent, fence, recovery receipt, and effect observation | =PromotionTransactionRecovery= |
| Cedar lifecycle admission | =SourceBoundEffectCompletionRecoveryCedarAuthorizationLifecycleCore= |
| Canonical authorization subject and evidence bundle | RFC 45-120-44 |
| Human-authority atomic materialization | RFC 45-120-45 |
| Cross-owner recovery bindings | RFC 45-120-47 |

The bridge owns relations between these domains.  It does not duplicate their
objects or internal validity predicates.

* Lean-discovered logical gaps

** Atomic commit does not provide durable intent

An atomic commit receipt contains the transaction result.  It does not prove
that a durable record existed before an external effect began.

The independent theorem
=atomicCommitDoesNotProvideDurableIntent= constructs a closed atomic commit
for which the durable-intent owner relation is empty.

#+begin_src typst
#let A(c) = $ "AtomicCommitClosed"(c) $
#let D(c, d) = $ "DurableIntentOwned"(c, d) $

$ exists c . A(c) and not exists d . D(c, d) $
#+end_src

** Recovery closure does not identify the RFC 45-120-45 commit

=RecoveryEvidenceClosed= validates its own atomic effect receipt.  Without a
bridge equality, it can close over a different commit receipt that merely
shares transaction fields.

The independent theorem =recoveryClosureDoesNotIdentifyAtomicCommit=
constructs exactly that counterexample.

#+begin_src typst
$ "RecoveryClosed"(q, r)
  arrow.not
  r."effectReceipt"."base" = c_"45-120-45" $
#+end_src

** Commit authorization does not authorize a recovery worker

Authorization at commit time and authorization at recovery time occur at
different runtime epochs and fence tokens.  A valid commit admission cannot
be reused as authority for a later recovery action.

The independent theorem =commitAuthorizationDoesNotAuthorizeRecoveryWorker=
contains an admitted commit lifecycle and a rejected recovery lifecycle.

#+begin_src typst
$ "Admitted"(a_c, e_c, f_c)
  arrow.not
  "Admitted"(a_r, e_r, f_r) $
#+end_src

** A stale recovery epoch must reject the bridge

The recovery Cedar lifecycle and the source-recovery expectation must name the
same current runtime epoch.

The theorem =staleRecoveryEpochRejectsAuthorization= proves the fail-closed
case.

#+begin_src typst
$ a_r."runtimeEpoch" != x."runtimeEpoch"
  arrow.not "RecoveryAuthorizationFresh"(a_r, x) $
#+end_src

** Equal fence numbers do not bind provider to worker

The source-recovery provider identity and the promotion recovery worker are
different identity domains.  Equal fence tokens alone do not establish their
assignment.

The independent theorem =matchingFenceDoesNotBindProviderToWorker= makes the
provider-worker relation false while preserving fence equality.

#+begin_src typst
$ x."activeFenceToken" = q."acquiredFenceToken"
  arrow.not
  "ProviderWorkerBindingValid"(x."providerIdentity", q."workerId") $
#+end_src

** Equal transaction identity does not bind the source request

The source recovery request and the promotion commit request have different
types and different owners.  Transaction identity cannot replace their
explicit semantic projection.

The independent theorem =matchingTransactionIdentityDoesNotBindSourceRequest=
proves this separation.

#+begin_src typst
$ q."transactionId" = c."transactionId"
  arrow.not
  "ExpectationRequestBindingValid"(x."request", c."request") $
#+end_src

** Recovery evidence does not bind owner provenance by itself

=RecoveryEvidenceClosed= closes transaction recovery.  It does not state that
the expectation provenance digest, durable record, claim, and receipt were
derived from the same owner-audit commitment.

That cross-domain statement is owned by
=SourceBoundEffectCompletionRecoveryRecoveryProvenanceBindingValid=.

#+begin_src typst
$ "RecoveryProvenanceBindingValid"(c_i, p_i, d_i, q_i, r_i) $
#+end_src

* Canonical mathematical model

** Recovery-required states

Only a state whose effect may already have happened enters transaction
recovery.

#+begin_src typst
#let State = $ { "notExecuted", "executedUncommitted", "committed", "indeterminate" } $

$ "NeedsRecovery"(s) :=
  s = "executedUncommitted" or s = "indeterminate" $
#+end_src

=notExecuted= remains outside transaction recovery.  This prevents a durable
applying record from being required before execution has started.

#+begin_src typst
$ "NeedsRecovery"(s) arrow s != "committed" $
#+end_src

The Lean theorem =transactionRecoveryRequiredIsNotCommitted= proves this
disjointness.

** Fresh recovery authorization

Let =a_i^r= be a separate Cedar lifecycle evidence value for the recovery
action.

#+begin_src typst
$ "RAuth"_i :=
  "Admitted"(
    a_i^r,
    "recoveryAuthority"_i,
    c_i,
  ) $
#+end_src

=Admitted= is the existing RFC 45-120-43 predicate.  Therefore the recovery
decision is an exact Cedar reference response, is =allow=, has no erroring
policies, uses a current policy snapshot, uses an active credential, and
satisfies authority-path and separation-of-duty relations.

** Epoch and fence closure

The recovery authorization, source expectation, and exclusive claim form one
epoch-fence chain.

#+begin_src typst
$ a_i^r."runtimeEpoch"
  = x_i."runtimeEpoch" $

$ a_i^r."activeFenceToken"
  = x_i."activeFenceToken"
  = q_i."acquiredFenceToken" $
#+end_src

The recovery owner still proves that the receipt fence equals the acquired
claim fence.

** Request and action closure

Two explicit relations bind the source expectation and Cedar request to the
promotion request and claim.

#+begin_src typst
$ "ExpectationRequestBindingValid"(x_i."request", d_i."request") $

$ "AuthorizationRequestBindingValid"(
  a_i^r."snapshot"."request",
  d_i."request",
  q_i,
) $
#+end_src

The first relation binds source recovery to promotion recovery.  The second
proves that Cedar authorized the exact promotion recovery action rather than
an unrelated request.

#+begin_src typst

** Responsibility scope closure

The recovery lifecycle scope must cover the exact materialization plan stored
in the durable request.

#+begin_src typst
$ "ResponsibilityScopeCoversPlanValid"(
  a_i^r."responsibilityScopeDigest",
  d_i."request"."subject"."materializationPlanDigest",
) $
#+end_src

** Canonical transaction and receipt equality

Field similarity is insufficient at the two most important identity
boundaries.  The bridge requires full equality.

#+begin_src typst
$ d_i."request" = "request"_i $

$ r_i."effectReceipt"."base" = "commitReceipt"_i $
#+end_src

The first equality identifies the durable request with RFC 45-120-45.  The
second identifies the recovery outcome with the exact atomic commit receipt.

** Owner provenance closure

#+begin_src typst
$ "RecoveryProvenanceBindingValid"(
  c_i,
  x_i."provenanceDigest",
  d_i,
  q_i,
  r_i,
) $
#+end_src

This relation is intentionally separate from request equality.  Provenance is
an evidence-domain statement and cannot be inferred from physical =String=
aliases.

The bridge is the conjunction of the prior human-atomic proof, fresh recovery
authorization, cross-domain bindings, exact identities, and existing recovery

* Elaboration performance

The trace evidence structure already generates canonical field projections for
the RFC 45-120-45 evidence and per-index recovery bindings.  Handwritten
forwarding theorems repeated more than fifty dependent parameters and caused
unboundedly poor elaboration behavior during development.

Those redundant theorems were removed.  The closure retains only the semantic
convergence theorem; callers use the generated field projections for direct
access.
