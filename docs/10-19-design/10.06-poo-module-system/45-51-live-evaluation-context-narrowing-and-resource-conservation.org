#+title: Live Evaluation Context Narrowing and Resource Conservation
#+subtitle: Pure policy, affine runtime capability, child derivation, cancellation, and continuation lifetime
#+startup: overview

* RFC status

- Status :: Accepted design
- Kind :: Normative runtime evaluation-context protocol
- Semantic core :: POO-native policy and capability objects with explicit pure/live separation
- Related modules :: =45-42-poo-conflict-recovery-generation-resumption.org= and =45-50-pure-slot-demand-identity-projections-and-cache-isolation.org=

This module separates a pure evaluation-context policy from its live realization during one runtime execution. It defines monotonic child-context narrowing, budget conservation, hierarchical cancellation, and bounded continuation use.

* Core decision

#+begin_quote
Evaluation policy is a pure, identity-addressed POO object. LiveEvaluationContext is a non-persistent affine runtime capability object for one execution. A child context is derived only through an admitted narrowing proposal and cannot enlarge authority, resources, disclosure, or lifetime.
#+end_quote

The two layers are:

#+begin_src text
PureEvaluationContextPolicy
LiveEvaluationContext
#+end_src

POO-native does not imply that a live context belongs in the pure semantic composition graph.

* Typst formalization: context narrowing preorder

Let =Narrow(child, parent)= mean that the child context contains no authority,
resource, disclosure, or lifetime not already admitted by the parent.

#+begin_src typst
$
  "Narrow"(c, p) & equiv
    A_"cap"(c) subset.eq A_"cap"(p)
    and A_"adapter"(c) subset.eq A_"adapter"(p) \
  & quad and D_"disclosure"(c) subset.eq D_"disclosure"(p)
    and B(c) <= B(p) \
  & quad and T(c) <= T(p)
    and K(c) <= K(p) \
  & quad and ("Cancelled"(p) => "Cancelled"(c)) \
  "Narrow"(c, c) & \
  "Narrow"(c, m) and "Narrow"(m, p)
    & => "Narrow"(c, p) \
  "Narrow"(c, p) and "Admitted"(c, d)
    & => "Admitted"(p, d) \
  B(c) & <= B(p) \
  K(c) & <= K(p)
$
#+end_src

Here =A_cap= is capability authority, =A_adapter= is runtime-adapter
authority, =D_disclosure= is disclosure authority, =B= is remaining budget,
=T= is the absolute deadline, and =K= is remaining continuation capacity.

The admission theorem fixes the variance direction.  A child-admitted demand is
also parent-admitted because the parent is at least as permissive and
resourceful.  A parent-admitted demand need not be child-admitted.

* Pure evaluation-context policy

A pure policy may describe:

- budget policy;
- retry policy;
- cancellation policy;
- deadline class;
- allowed runtime-adapter classes;
- cache-use policy;
- evidence-materialization policy;
- capability requirements;
- child-context narrowing rules.

The policy:

- is canonicalizable;
- may participate in =DemandExecutionPolicyIdentity=;
- may be cached, compared, and extended through native POO operations;
- contains no live token, counter, clock, worker, portal, or handle.

Changing only execution policy does not manufacture a new business semantic value.

* Live evaluation context

A live context may hold:

- =EvaluationExecutionIdentity=;
- live capability tokens and leases;
- mutable budget ledger;
- absolute deadline and clock;
- cancellation scope;
- scheduler and worker handles;
- cache and materialization client;
- evidence sink;
- condition and recovery handler;
- runtime and Marlin adapter capabilities;
- one-shot recovery portals.

It is:

- non-serializable;
- non-cacheable;
- excluded from composition-root and semantic-generation identity;
- invalid as a Profile operand;
- unable to regain authority from a provenance or recovery receipt;
- bounded by one root-evaluation lifetime.

* Explicit evaluator boundary

The public semantic boundary is:

#+begin_src text
evaluate(
  PureSlotDemand,
  LiveEvaluationContext
)
#+end_src

The evaluator does not obtain authority from:

- a global current-context registry;
- a hidden ambient process token;
- a cached receipt;
- a dynamic variable unrelated to the explicit context;
- a composition value that captured runtime handles.

An implementation may use Gerbil or Scheme dynamic parameters, conditions, and continuations internally. Such dynamic scope must be established from the explicitly supplied live context.

* Child-context narrowing proposal

A dependency demand first produces a pure POO =ContextNarrowingProposal= describing:

- child demand identity;
- requested authority subset;
- budget reservation;
- deadline restriction;
- runtime-adapter delegation;
- evidence-disclosure restriction;
- cancellation-parent relationship.

The parent live context validates the proposal before creating a child context.

#+begin_src mermaid
flowchart LR
    D["Dependency demand"] -->|"derive a pure requested scope"| P["ContextNarrowingProposal"]
    P -->|"submit to the parent live context"| V["Validate authority and resource conservation"]
    V -->|"request exceeds parent scope"| F["Fail closed with derivation evidence"]
    V -->|"scope is admitted"| C["Live child context"]
    C -->|"execute dependency demand"| E["Child evaluation"]
    E -->|"return unused reservation with receipt"| R["Parent budget ledger"]
    C -->|"child cancellation affects only this branch"| X["Child scope closed"]
#+end_src

The proposal is pure and identity-addressed. The resulting child context is live and affine.

* Monotonic narrowing

Every admitted child satisfies:

#+begin_src text
child authority is a subset of parent authority
child allocated budget is no greater than its parent reservation
child deadline is no later than parent deadline
child disclosure scope is a subset of parent disclosure scope
child runtime adapters are a subset of explicitly delegated adapters
child lifetime is no longer than parent lifetime
#+end_src

A child cannot obtain missing authority from ambient process state. A dependency that requires additional authority must return to an explicit higher authorization boundary.

Missing authority is classified as:

- semantic or admission failure when capability changes candidate participation;
- operational authorization failure when the semantic target is unchanged but execution access is unavailable.

The classification must be explicit and evidence-backed.

* Budget conservation

The mutable budget ledger enforces:

- each child receives an explicit reservation;
- the parent cannot spend the same reservation while the child owns it;
- unused reservation may return to the parent with a receipt;
- continuation capture does not copy budget;
- resumption does not reset consumed budget;
- worker retry consumes operational retry budget;
- semantic recovery consumes generation-transition budget;
- budget exhaustion remains operational failure evidence.

#+begin_src mermaid
flowchart LR
    B["Parent budget ledger"] -->|"reserve a bounded allocation"| C["Child budget lease"]
    C -->|"consume during child evaluation"| U["Recorded resource use"]
    C -->|"return unused allocation on close"| B
    C -->|"continuation capture cannot duplicate lease"| X["Double-spend prevented"]
    U -->|"budget exhausted"| F["Operational fail-closed receipt"]
#+end_src

Budget identity and policy are pure. Remaining counters and reservations are live operational state.

* Authority monotonicity

Context derivation preserves:

- only explicitly delegated capability reaches a child;
- lease lifetime does not exceed parent lifetime;
- recovery-portal authority does not propagate automatically;
- evidence-disclosure capability is separate from business-access capability;
- cache hit does not grant capability;
- a recovery or authorization receipt cannot become future authority;
- priority =force= cannot enlarge context authority.

An explicit authorization boundary is required to add authority. Narrowing alone can never do so.

* Hierarchical cancellation

Cancellation forms a scope tree:

- parent cancellation cancels its children;
- child cancellation does not cancel parent or siblings;
- closing a child invalidates its live handles and portals;
- detaching one subscriber does not cancel shared work required by other subscribers;
- cancellation is operational evidence, not a semantic result.

Cancellation handles remain outside pure demand and composition identity.

* Concurrent demand coalescing

Live contexts are not unioned when callers share a semantic target.

- Different semantics-affecting admission scopes produce different semantic targets and cannot coalesce.
- Equal semantic targets may share pure computation and result materialization.
- Each subscriber retains separate access authorization.
- Each subscriber retains separate evidence and disclosure requests.
- Each subscriber retains separate cancellation and operational receipts.
- A shared worker uses only the minimum authority required by the computation.
- Result delivery revalidates each subscriber independently.

The runtime must not union caller capabilities. A union could manufacture authority that no caller possesses individually.

* Continuation and context lifetime

Continuation machinery obeys:

- capture does not extend an expired capability lease;
- resumption does not revive a closed context;
- multi-shot invocation does not copy budget, leases, or runtime effects;
- a consumed one-shot portal cannot be reconstructed through an older continuation;
- closing a context invalidates related portals and child handles;
- recovery against a new semantic generation still requires a currently valid live context.

The ordinary public interface exposes bounded POO recovery and context objects, not raw continuation replay authority.

* Cache and runtime adapter boundary

A live cache client may retrieve an inert pure candidate. Retrieval:

- does not grant authority;
- does not prove current generation admission;
- requires semantic-target and evidence revalidation;
- keeps cache handles outside the result projection.

Runtime and Marlin adapters are explicit delegated capabilities. A child receives only adapters admitted by its narrowing proposal. Runtime effects produce operational receipts and do not enter the pure composition value.

* Live-context identity and evidence

=LiveEvaluationContextIdentity= is operational. It may identify:

- root execution;
- parent context identity;
- admitted narrowing proposal;
- live resource-allocation receipt;
- cancellation scope;
- capability and adapter evidence permitted for disclosure.

It does not enter semantic cache keys.

Context evidence records:

- pure policy identity;
- narrowing-proposal identity;
- parent and child operational identities;
- admitted authority subset;
- budget reservation, use, and return;
- deadline and cancellation relationship;
- delegated adapter classes;
- context close or expiry;
- recovery portal creation and consumption;
- redacted capability evidence.

* Implementation checklist

- [ ] Define pure =EvaluationContextPolicy= as a POO object.
- [ ] Define live affine =LiveEvaluationContext= outside the pure composition graph.
- [ ] Pass the live context explicitly to the evaluator.
- [ ] Define pure POO =ContextNarrowingProposal=.
- [ ] Validate authority, budget, deadline, disclosure, adapters, and lifetime before child creation.
- [ ] Prove child authority and disclosure are subsets of parent scope.
- [ ] Implement reservation-based budget conservation.
- [ ] Prevent continuation capture and resumption from duplicating budget.
- [ ] Implement hierarchical cancellation.
- [ ] Invalidate child portals and handles on close.
- [ ] Separate semantic admission failure from operational authorization failure.
- [ ] Coalesce only equal semantic targets.
- [ ] Prevent capability union across subscribers.
- [ ] Revalidate authorization independently at result delivery.
- [ ] Keep cache, worker, clock, logger, continuation, and adapter handles out of pure values.
- [ ] Generate narrowing, resource, cancellation, and lifetime evidence.
- [ ] Validate context objects and operations against real =gerbil-poo= and Gerbil runtime primitives.

* Non-goals

- Do not place live evaluation context inside a Profile or composition value.
- Do not serialize, cache, or content-address live capability handles as semantic state.
- Do not derive authority from a global current-context registry.
- Do not let a child enlarge authority, budget, deadline, disclosure, adapters, or lifetime.
- Do not union subscriber capabilities for shared work.
- Do not let continuation replay duplicate budget or revive expired context.
- Do not treat cancellation or budget exhaustion as a semantic slot value.
- Do not create a context DSL or raw callback table.
