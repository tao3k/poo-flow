* Lean-discovered logical defect

RFC 45.120.51 required equality between the proof-base receipt digest and the
increment's =proof_base_interface_digest=.  Digest equality alone is not a
mathematical proof of canonical interface equality.

A digest function may collide.  In the smallest countermodel, the digest type
has one value while the interface type has two values.

#+begin_src typst
#let H = $cal(H)$
#let C = $cal(C)$

$ H = {unit} $
$ C = {"false", "true"} $
$ "Bind"("unit", "false") $
$ "Bind"("unit", "true") $
$ "false" != "true" $

$ "DigestEqual"("unit", "unit") $
$ "CanonicalInterfaceEqual"("false", "true") = #false $
#+end_src

Lean proves this countermodel as
=digestEqualityAloneDoesNotCloseCanonicalInterface=.  Consequently, a receipt
validator cannot promote =digest_a = digest_b= directly into semantic identity.

* Binding model

Let =Bind(h, c)= state that digest =h= faithfully binds canonical interface
payload =c=.

#+begin_src typst
$ "DigestBindingInjective"("Bind") :=
  forall h, c_1, c_2;
    "Bind"(h, c_1) and "Bind"(h, c_2)
      ==> c_1 = c_2 $

$ "ReceiptDigestBound"(B, D) :=
  B.h = D.h $

$ "CanonicalInterfaceBound"(B, D) :=
  B.c = D.c $

$ "DigestBindingInjective"("Bind")
  and "Bind"(B.h, B.c)
  and "Bind"(D.h, D.c)
  and "ReceiptDigestBound"(B, D)
  ==> "CanonicalInterfaceBound"(B, D) $
#+end_src

The runtime realization MUST NOT merely assume injectivity.  It MUST carry the
complete canonical typed interface in the bundle, recompute its digest, and
compare canonical interface bytes when joining independently produced
receipts.  Cryptographic collision resistance remains a trust assumption only
at the content-addressing boundary; it is not silently converted into a Lean
theorem.

* Assume-guarantee theorem

For world =w=, base semantics =P_B=, interface semantics =P_I=, and increment
semantics =P_D=:

#+begin_src typst
$ (forall w; P_B(w) ==> P_I(B.c, w))
  and (forall w; P_I(D.c, w) ==> P_D(w))
  and "CanonicalInterfaceBound"(B, D)
  ==> (forall w; P_B(w) ==> P_D(w)) $
#+end_src

The Lean theorem
=receiptBoundAssumeGuaranteeComposition= additionally requires:

- the proof-base receipt is accepted;
- the increment receipt is accepted;
- root-kind obligation dispatch is satisfied;
- proof-base and source declaration ownership are disjoint;
- digest binding is injective;
- both receipts bind their canonical interfaces.

The result is a first-class =VerifiedComposition= value carrying receipt
acceptance, canonical identity, and the semantic implication.

** Runtime v1 receipt-DAG closure

The runtime algebra accepts one complete typed schema:
=poo-flow.proof-base-receipt-graph.v1=.  Every source identity,
independent bundle digest, provided interface, named interface assumption,
acceptance receipt, edge, and terminal node is required.  There is no
alternate interpretation for absent fields or another schema identifier.

An accepted node binds the acceptance receipt to the same canonical source
identity, independent bundle, and provided interface used by the graph.  An
edge closes exactly one named consumer assumption and succeeds only when the
supplier's canonical interface bytes are identical to the assumed bytes.

#+begin_src typst
$
  G = (V, E), quad
  "Closed"(G, t) =
    "Acyclic"(E)
    and "Sink"(t)
    and "Resolved"(E)
    and "ExactBytes"(E)
    and "BoundReceipts"(V)
$

$
  "LocalStep" + "WellFounded"(E)
  arrow.r
  (forall v in V: "Accepted"(v))
$
#+end_src

The second implication is the key mathematical boundary.  Local
assume-guarantee steps do not close a cycle: a two-node cycle can satisfy every
local implication while neither node is accepted.  Well-founded dependency is
therefore a proof obligation, not an implementation convenience.

*** Canonical audit-transport closure

JSON is an audit transport only.  It does not define receipt-DAG meaning.
The adapter must be a reversible projection of the canonical typed graph:

#+begin_src typst
$
  "decode"("encode"(G)) = G
$

$
  "decode"(B) = G
  arrow.r
  "encode"(G) = B
$

$
  "LeftInverse"("decode", "encode")
  arrow.r
  "Injective"("encode")
$
#+end_src

This obligation exposed a runtime defect.  The graph digest and audit encoder
sorted nodes and edges, but the typed graph originally retained caller tuple
order.  Two structurally unequal typed values could therefore encode to the
same audit bytes.  The fix is to canonicalize nodes, edges, root declarations,
and named assumptions at typed-object construction, before hashing or JSON
projection.

A digest-only audit projection cannot satisfy the left-inverse law:

#+begin_src typst
$
  G_l != G_r, quad
  "digest"(G_l) = "digest"(G_r)
  arrow.r
  "decode"("digest"(G_l)) != G_l
  or
  "decode"("digest"(G_r)) != G_r
$
#+end_src

The v1 audit decoder therefore requires the complete canonical graph,
acceptance bindings, and verified composition receipt.  It rejects unknown or
missing fields, duplicate JSON keys, non-canonical JSON bytes, non-lowercase
hexadecimal bytes, graph failures, and any declared receipt that differs from
the recomputed result.
