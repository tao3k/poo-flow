#+title: Programming Style 07 - Formal Assurance Correspondence

* Authority

Scheme owns the admitted POO Contract and its stable identity/revision.  Formal
languages consume named projections of that Contract.  They do not publish a
second user-facing model or feed proof-engine records back as semantic owners.

* TLA+ three-part closure

POO Flow calls a TLA+ model closed only when three independent artifacts agree:

1. native =.tla/.cfg= source declares the bounded transition system and
   invariants;
2. the parser produces a syntax-contract and byte-roundtrip receipt;
3. TLC explores the configured state space and produces a model-check receipt.

Parser acceptance is not model checking.  TLC success is not source ownership.
The aggregate qualification may join the three receipts, but no component may
stand in for another.  Terminal lifecycle states must be modeled explicitly;
do not disable deadlock checking merely to hide an undeclared terminal state.

* Lean correspondence

Lean proves structural and refinement laws that should not depend on a bounded
TLC state space.  A Lean theorem binds the same Contract identity, semantic
revision and projection digest as the TLA+ receipt.  A TLA+ source change makes
the downstream proof-impact gate stale until that binding is refreshed.

* Current native semantic Query obligations

- Entity roles preserve native Object identity.
- Relations close over one Element space.
- admitted Queries select declared Elements.
- Query evaluation preserves semantic revision and never grants action
  authority.
- Provider results bind Query, Provider and revision identities.

The focused owners are =packages/proof/tla/NativeSemanticQuery.tla= and
=PooFlowProof.PooC3.NativeSemanticQueryModel=.
