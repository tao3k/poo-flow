#+title: Programming Style 03 - Functional Kernel And Runtime Projection

* Functional kernel

Selection, filtering, routing, validation summaries, graph algorithms and
projection are named pure functions.  Use Gerbil iteration, SRFI folds and
standard hash/set operations when they improve clarity or complexity.  Keep
explicit recursion where accumulator order or hot-path allocation is clearer.

Private positional traversal state may use a small =defstruct=.  Public
extension state remains POO-native.  Alists are allowed only at a final wire,
receipt or diagnostic projection after the owning object is known.

* Runtime boundary

The direction is fixed:

#+begin_export mermaid
flowchart LR
    O["Admitted POO object"] -->|"pure policy or composition"| D["Decision"]
    D -->|"named receipt"| R["Receipt"]
    R -->|"explicit projection"| W["JSON / ABI / runtime row"]
    W -->|"handoff"| X["Runtime executor"]
#+end_export

Scheme owns semantic composition, policy, diagnostics and handoff values.
Rust, Python, Marlin or another runtime executes.  A runtime adapter that must
understand private Scheme state indicates a broken projection.  Scheme code
that directly performs provider execution indicates a broken handoff.

Receipts carry schema, producer, source identity, object kind, revision and
provenance.  Human stdout is observability, not a machine decision input.
