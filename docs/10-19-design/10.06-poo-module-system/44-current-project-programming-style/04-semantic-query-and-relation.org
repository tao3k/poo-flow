#+title: Programming Style 04 - Semantic Query And Relation

* One model

=Object= is the native POO carrier.  =Entity= is an identity-bearing domain
role of that Object.  =Element= is membership in a Contract or Scenario
observation space.  These are not parallel registries.  Relations reference
stable Element identities and do not embed mutable copies of endpoints.

* Query law

A Query is an immutable, bounded, read-only POO object.  Its program is a
GQL-aligned POO AST.  Public Query slots do not contain raw strings, lists,
vectors or anonymous lambdas.

The Query Module exposes supported languages through one inheritable
=languages= noun slot.  The graph-read model currently exposes only =gql=.
Scheme is its elegant =scheme-poo= authoring surface, not another semantic
language.  A pure projector renders standard GQL, and =gerbil-parser= validates
the byte-exact source independently.  A raw GQL string and the parser's
internal alist are boundary values, never the public =program= slot.

GQL execution returns a receipt
bound to Query identity, provider identity and semantic revision.  The result
is evidence, never action authority.  Python adapters and MRR/Rust consumers
consume the same receipt boundary and do not define another Query model.

When standard GQL is sufficient for candidate discovery but not the final
domain predicate, use the staged pipeline =GQL candidate set -> typed native
refinement -> result admission=.  The refinement must be named, bounded and
Schema-owned.  Higher-order reasoning such as ASCENT sits above admitted facts;
it does not become a custom GQL clause.

* Executable rule

The Module authoring Contract rejects raw initializers in =query=, =queries=,
=query-predicate=, =query-predicates=, =*-query= and =*-queries= slots with
=poo-query-must-be-native-object=.  Named pure functions and named Provider
projections remain open.  Full correspondence is specified by
[[file:../165-native-semantic-element-relation-query-model.org][RFC 165]].
