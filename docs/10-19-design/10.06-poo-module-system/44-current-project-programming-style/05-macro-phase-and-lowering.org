#+title: Programming Style 05 - Macro Phase And Lowering

* Admission

Use a macro only when repetition is structural, the call site names domain
facts, expansion produces ordinary POO/functional code, errors retain source
locations, and no effect or authority is hidden.

Use the smallest tier: =defrules= for direct frames; =defsyntax= for validated
shape/default generation; syntax-time metadata only for shared static facts;
macro objects only when the expander itself has classed behavior.

* Phase law

Syntax owners preserve syntax objects, lexical context and binding-aware
identifier comparison.  Runtime owners construct POO values and perform
policy behavior.  Import syntax support with =for-syntax=; never load source or
maintain a mutable runtime registry during expansion.

Parse each declaration once and lower once.  Work and generated form count
should be =O(n + m)= for =n= declarations and =m= clauses.  Repeated scans,
=map= plus =apply append=, temporary runtime objects and source evaluation in
the expander are forbidden.

* Static lowering exception

A bounded static declaration may lower directly to =object<-alist= when the
public result remains a native POO object and same-source A/B evidence proves
the benefit.  This does not authorize a public alist DSL.  Keep =.o= for
inheritance, dynamic composition, computed methods, =self= or =next-method=.
