#+title: Publication-Domain Registry Lineage and Rollback Closure
#+startup: overview

* Status

- State :: Proposed
- Scope :: registry trust-root replacement, lineage ordering, and current-head rollback rejection
- Depends on :: RFC 55, RFC 56, RFC 58

* Problem

RFC 58 pins one publication-domain registry object through a verifier trust
root.  It does not yet constrain replacement of that object over time.

Exact equality with the locally selected trust root is insufficient.  A
verifier can select generation zero, upgrade to generation one, then select
generation zero again.  Equality succeeds at every local selection point even
though the final selection is a rollback.

Registry replacement therefore requires both a monotonic lineage and one
explicit current-head checkpoint.

* Exact selection permits rollback

Let =T_0= be the initial registry trust root and =T_1= a valid upgrade:

#+begin_src typst
#align(center)[
  $
    "Selected"(T_0, T_0)
      and
    "Selected"(T_1, T_1)
      and
    "Selected"(T_0, T_0)
  $
]
#+end_src

Every equality check is locally true.  The sequence =T_0 -> T_1 -> T_0= still
replays an obsolete registry object.

* Versioned registry trust root

A published registry trust root carries a generation:

#+begin_src typst
#align(center)[
  $
    V_R = (g_R, T_R)
  $
]
#+end_src

A valid transition preserves the registry authority and semantic contract while
strictly increasing the generation:

#+begin_src typst
#align(center)[
  $
    "ValidTransition"(V_l, V_r)
      "iff"
    A_R(V_l) = A_R(V_r)
      and
    S_R(V_l) = S_R(V_r)
      and
    g_R(V_l) < g_R(V_r)
  $
]
#+end_src

Consequently, a prior trust root cannot equal the selected root after a valid
transition.

* Monotonic lineage

A registry trust-root lineage publishes one versioned root at each position:

#+begin_src typst
#align(center)[
  $
    i < j
      "implies"
    g_R(L(i)) < g_R(L(j))
  $
]
#+end_src

The lineage also preserves the registry authority and semantic contract across
all positions.  A candidate from an earlier position is rejected at every later
position.

The lineage orders accepted replacements; it does not itself declare which
position is live.

* Current-head checkpoint

The verifier therefore maintains a checkpoint =H_R= selecting one lineage
position:

#+begin_src typst
#align(center)[
  $
    "AcceptedAtCheckpoint"(L, H_R, V)
      "iff"
    V = L("position"(H_R))
  $
]
#+end_src

A valid checkpoint advance is strictly forward:

#+begin_src typst
#align(center)[
  $
    "position"(H_l) < "position"(H_r)
      "implies"
    not "AcceptedAtCheckpoint"(L, H_r, L("position"(H_l)))
  $
]
#+end_src

This closes historical-membership replay within one live verifier state.

* Ownership boundary

- The registry authority owns valid versioned trust-root publication.
- The publication lineage owns authority stability, semantic stability, and generation ordering.
- The verifier owns the current-head checkpoint.
- Evidence may reference a versioned trust root, but it cannot select the current checkpoint.
- A backward, equal-position, cross-authority, or cross-semantic transition is rejected.

* State machine

#+begin_src mermaid
stateDiagram-v2
  [*] --> CurrentHeadLoaded: load registry trust-root checkpoint
  CurrentHeadLoaded --> CandidateCompared: compare candidate with lineage head
  CurrentHeadLoaded --> AdmissionRejected: checkpoint missing or ambiguous
  CandidateCompared --> TransitionChecked: candidate is a proposed replacement
  CandidateCompared --> AdmissionAccepted: candidate equals current head
  TransitionChecked --> CheckpointAdvanced: authority and semantics stable generation increases
  TransitionChecked --> RollbackRejected: generation or position does not increase
  TransitionChecked --> AdmissionRejected: authority or semantic contract changes
  CheckpointAdvanced --> PriorHeadRejected: previous root is historical
  PriorHeadRejected --> AdmissionAccepted: new head is live
  RollbackRejected --> [*]: require registry reconciliation
  AdmissionRejected --> [*]: fail closed
  AdmissionAccepted --> [*]: continue descriptor validation
#+end_src

* Architectural consequence

Registry canonicality has both object and time dimensions.  RFC 58 fixes the
object interpretation boundary; this RFC fixes the ordered live-head boundary.
A registry object is not current merely because it was once valid or remains a
member of the publication lineage.
