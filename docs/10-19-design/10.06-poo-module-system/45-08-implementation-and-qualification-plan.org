* Normative responsibility

This module exclusively owns implementation ordering, test groups, and closure
criteria.  It does not authorize implementation while any upstream contract
remains unapproved.

* Implementation order

The macro-expansion, named POO-predicate, and public
=user-composition=/=use-composition= work is one 45-07-owned tranche.  Any
separate list entries below describe internal sequencing inside that tranche;
they do not create a second macro owner or authorize implementation before
45-07 approval.

The 45-04 observability tranche and the 45-05 lineage/cycle tranche are sibling
tranches after the 45-03 runtime substrate.  Neither is a semantic prerequisite
of the other.  Their implementations may proceed independently, but their
cross-layer qualification converges before 45-07 composition integration is
accepted.

* Required test groups

In this RFC, “required integration groups” means only parent-owned
=poo-flow-core= cross-layer qualification.  It never includes a
=wendao-episteme= suite, another descendant-only suite, descendant
distribution qualification, or recursively executing a child package test
graph.  A descendant may qualify its consumption of an explicitly identified
parent artifact under its own owner and completion gate.

Benchmark and performance qualification remains owned by
[[file:80-observability-performance-gates.org][80]].  Such evidence may be
scheduled after the semantic tranches are green, but it is not a first-round
45-08 semantic gate and cannot redefine the contracts owned by 45-01 through
45-07.

| Group | Required evidence |
|-
| G0 semantic | four pure cases, four live cases, two precedence boundaries, one sentinel |
| fixed point | pinned =instantiate-proto=/=compose-proto*= are used; no duplicate implementation |
| runtime | same-context sharing, cross-context isolation, close, replacement |
| continuation | multi-shot inspection, one-shot commit/recovery, stale resume |
| cycle | direct, multi-module, cross-branch, acyclic sharing, deep nesting |
| observability | event order, overflow, sink failure, snapshot isolation |
| user interface | canonical parser, Profile composition, alias isolation |
| child boundary | downstream consumes capability without repeated G0 |

GSLPH may execute these groups as the development harness.  It does not define
the semantics or issue runtime evidence.

* Completion gate

Work is not complete from source edits, a focused green check, =Ready=,
=git diff --check=, or an expected golden digest alone.

Closure requires:

- all modular RFCs approved;
- implementation mapped to the named owner;
- focused tests green;
- required integration groups green;
- runtime-produced Observation and Decision evidence where required;
- no unexpected worktree changes;
- explicit remaining blockers, if any.
