* Problem

RFC 53 closes the distinction between authority-issued evidence and a
self-reported audit object.  It does not yet prove that an authority-issued
receipt remains valid when the enterprise state used by that authority has
changed.

This is a real replay boundary.  A receipt can have been accepted by the
correct owner and can still be stale at the time a receipt graph consumes it.
The relevant change may be an authority generation, a Cedar policy snapshot,
an authorization snapshot, or a revocation snapshot.

Receipt bytes, canonical audit transport, source identity, declaration roots,
and bundle identity do not by themselves establish freshness against those
mutable enterprise states.

* Validation context

The receipt validation context is an authority-owned value:

#+begin_src typst
#align(center)[
  $
    C = (A, g, P, U, R)
  $
]

#grid(
  columns: (auto, 1fr),
  gutter: 12pt,
  [$A$], [acceptance authority identity],
  [$g$], [authority generation],
  [$P$], [policy snapshot identity],
  [$U$], [authorization snapshot identity],
  [$R$], [revocation snapshot identity],
)
#+end_src

These identities are opaque canonical identities.  They are not wall-clock
timestamps and are not values declared by audit JSON.

The source identity, independent declaration bundle, root declarations, and
provided interface remain bound by the receipt evidence defined in RFC 51–53.
The context above closes a different boundary: the mutable enterprise state
under which that evidence was accepted.

* Acceptance rule

Let =issued(r)= be the validation context captured by authority-issued receipt
=r=, and let =current= be the context supplied by the live authority when the
receipt graph is verified.

#+begin_src typst
#align(center)[
  $
    "AcceptedAt"(r, C_"current")
      "iff"
    "OwnerAccepted"(r)
      and
    "issued"(r) = C_"current"
  $
]
#+end_src

The equality is exact tuple equality.  A digest projection that omits an
enterprise state component is not sufficient evidence for this rule.

Replaying the same receipt inside the same exact context is idempotent.
Replaying it after any context component changes is stale and must be rejected
until the live owner issues evidence for the new context.

Receipt-DAG admission additionally requires a nonempty graph:

#+begin_src typst
#align(center)[
  $
    "Admit"(G, C)
      "iff"
    G != emptyset
      and
    forall r in G, "AcceptedAt"(r, C)
  $
]
#+end_src

Without the nonempty condition, a pointwise-only universal predicate accepts
the empty graph vacuously.  Empty-graph rejection is therefore part of the
admission semantics rather than a storage or transport convenience.

Exact-context admission also makes authority homogeneity explicit:

#+begin_src typst
#align(center)[
  $
    "Admit"(G, C)
      "implies"
    forall r in G,
      "authority"("issued"(r)) = "authority"(C)
  $
]
#+end_src

One receipt DAG has one authority-owned validation context.  Receipt evidence
from independent authority paths is not unioned into that DAG.  This is not a
resolver omission: it is the fail-closed anti-union invariant already required
by the composition architecture.

* Lean-discovered countermodels

** Context-free acceptance permits stale replay

Assume an owner accepted a receipt at:

#+begin_src typst
#align(center)[
  $
    C_0 = (A, 3, P, U, R)
    quad "and" quad
    C_1 = (A, 4, P, U, R)
  $
]
#+end_src

A predicate that checks only =OwnerAccepted(r)= accepts the receipt at both
=C_0= and =C_1=.  Exact-context acceptance accepts it at =C_0= and rejects it
at =C_1=.  Therefore authority issuance without context equality is
insufficient for graph acceptance.

** Policy-only projection misses authorization and revocation changes

Consider:

#+begin_src typst
#align(center)[
  $
    C_l = (A, g, P, U_l, R_l)
    quad "and" quad
    C_r = (A, g, P, U_r, R_r)
  $
]

#align(center)[
  $
    (U_l, R_l) != (U_r, R_r)
    quad "but" quad
    pi_"policy"(C_l) = pi_"policy"(C_r) = (A, g, P)
  $
]
#+end_src

Binding only the authority generation and Cedar policy snapshot cannot observe
an authorization or revocation change.  The enterprise context must bind all
five components.

* Ownership boundary

- The live acceptance authority owns =ReceiptValidationContext=.
- The AXLE adapter derives the context from owner-controlled runtime inputs.
- Cedar policy and authorization integrations supply canonical snapshot
  identities; they do not decide proof-graph structure.
- Audit JSON carries an already authority-issued context binding for
  representation and audit only.
- The receipt-DAG verifier compares the issued context with the current
  authority context before admitting a node.
- One receipt DAG admits only receipts whose authority identity equals the
  authority identity of its current validation context.
- Independent authority paths are never converted into a synthetic union
  authority by the receipt layer.
- The POO composition layer consumes the verified result and does not recreate
  freshness policy.

* State machine

#+begin_src mermaid
stateDiagram-v2
  [*] --> Declared: receipt bytes parsed
  Declared --> OwnerValidated: live owner accepts at issued context
  OwnerValidated --> ContextCurrent: issued context equals current context
  OwnerValidated --> StaleRejected: any context component changed
  ContextCurrent --> AuthorityHomogeneous: every node has current authority identity
  AuthorityHomogeneous --> GraphAccepted: graph nonempty and every node is exact
  StaleRejected --> RevalidationRequired: current owner evidence required
  RevalidationRequired --> OwnerValidated: owner issues receipt at current context
  GraphAccepted --> [*]: composition may consume verified node
#+end_src

* Lean closure

The model is implemented in:

- =PooFlowProof.Enterprise.ReceiptContextFreshnessClosure=

The proof surface contains:

- =authorityIssuedReceiptIsValidAtExactContext=
- =exactContextAcceptanceRejectsChangedContext=
- =contextFreeAcceptancePermitsStaleReplay=
- =policyOnlyProjectionMissesAuthorizationRevocationChange=
- =exactContextEvidenceClosesReceiptDagAdmission=
- =oneStaleReceiptRejectsReceiptDagAdmission=
- =pointwiseOnlyAdmissionAcceptsEmptyDag=
- =emptyReceiptDagIsRejected=
- =receiptDagAdmissionEnforcesAuthorityIdentity=
- =receiptsAcceptedAtOneContextShareAuthorityIdentity=

The first two theorems establish the positive exact-context rule.  The latter
theorems close receipt-DAG admission, reject a stale member, and expose the
empty-graph countermodel hidden by pointwise universal acceptance.

* Architectural consequence

RFC 53 authority issuance is necessary but not sufficient.  Receipt-graph
admission requires both:

1. evidence issued by the real acceptance authority; and
2. equality between the receipt's issued validation context and the current
   authority-owned validation context.

This closes stale enterprise evidence without introducing time heuristics or
allowing audit transport to become an acceptance authority.
