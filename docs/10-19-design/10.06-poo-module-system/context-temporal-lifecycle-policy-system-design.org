* Decision and evidence boundary

POO Flow owns the semantic design of Context, Temporal applicability, strategy
composition, lifecycle transitions and effect admission. Its FFI/C ABI projects
that design to Runtime adapters. MRR owns relational Context derivation and proof
admission. MRR Data owns physical scheduling, storage, resource ownership and
conditional durable publication. Each consumer qualifies the boundary it uses.
No downstream adapter becomes a second policy language or semantic lifecycle
owner. Session remains an independent Module composed by AI Agentic-context;
Memory is a Context Feature. Orgize remains the parser/source structure owner.

This contract extends [[file:agentic-ai-context-system-design.org][the Context system design]], [[file:167-temporal-revisit-evidence-design.org][temporal revisit]],
[[file:45-127-higher-order-capability-materialization-poo-lifecycle-object-and-runtime-policy-prototype-algebra.org][the lifecycle policy-prototype algebra]] and [[file:context-org-anchor-session-host-receipt.org][the local claim Host receipt]].
It declares prospective provider/Data handoffs explicitly. A local window
assessment is implemented below; the complete joint runtime is not delivered.

* Orthogonal state axes

Use a product of state machines. One scalar status cannot represent all facts.

| Axis | States or owned coordinates | Owner |
|------+----------------------------+-------|
| Source lineage | Registered authority/subject, source identity, cut, generation; live/retired | Source owner through trusted Runtime control |
| Context projection | Proposed, admitted, prepared, invalidated, superseded, retired | AI Agentic-context |
| Evidence applicability | Necessary/possible/refuted plus current/stale and required/missing obligations | Temporal and MRR |
| Strategy | Admitted graph digest, schema/implementation identities, revision; active/retired | POO Flow policy composition |
| Session | Open/closing/closed, owner revision and Turn | Session |
| Attempt | Claimed, disclosed, result-received, admitted, invalidated, recovery-pending, reconciled | Session with Context consumer gates |
| Effect | Requested, dispatched, observed, ambiguous, resolved | Runtime/provider receipts |
| Durable head | Expected generation/commitment, published or CAS-conflicted | MRR Data |
| Memory | Evidence verdict, revisit state and retention assessment | Context Memory Feature |

A stale proof can remain valid historical evidence. A completed provider request
can have a rejected current result. A cancelled waiter can leave running work
and a lease. A retained memory can be unfit for current use. Lifecycle reducers
preserve these distinctions and append immutable reason/evidence events.

* Temporal product and clock semantics

Track source event time, ingress/admission time, processing time, valid-time
interval, policy evaluation time, Attempt deadlines and revisit due conditions
separately. Source generation, Session revision and policy revision are fencing
coordinates, not timestamps. Org heading ancestry is not a clock or a C4 policy
graph. Source-vector equality is necessary for this first conservative profile;
a later dependency-complete refinement can permit explicitly proved unaffected
reuse. Similar content or unchanged Org IDs alone cannot establish that reuse.

Temporal instants retain domain, modality and provenance. A clock conversion is
an admitted evidence object with explicit uncertainty; numeric equality cannot
convert domains. Event-time observations and planning dates cannot stand in for
an observed policy clock. A lease uses a named domain and a half-open window.
For a clock observation [earliest, latest], eligibility requires the entire
closed uncertainty interval inside [start, end): start <= earliest <= latest < end.
An interval crossing either boundary is uncertain and cannot authorize use.
The restriction's information domain is separate from the temporal clock domain.

For each required Temporal admission, resolve its original source identity from
the owner registry, replay the original admission and assess against that owner's
current snapshot. Require a declared verdict profile: for example necessary-only
for a consequential use, or possible-with-explicit-disclosure for exploration.
These are explicit profiles, not a claim that every use requires necessity.
Missing evidence, incomparable clocks or unsupported demanded semantics block
the consequential operation. A historical display uses a separately authorized
purpose and preserves historical labels; it does not become current inference.

Logical ordering is a partial causal relation; a total timestamp order does not
supply causal evidence. This design applies that distinction from [[https://www.microsoft.com/en-us/research/publication/time-clocks-ordering-events-distributed-system/][Lamport's
clock paper]]. Neither Session ID nor a wall-clock timestamp proves causality.

* Core strategy composition in POO Flow

Strategy is a native POO value contributing pure named functions, immutable
policy decisions and explicit effect intents. Reuse the existing Module source
roles and contribution admission, then freeze the explicit graph and its C4
linearization before dispatch. Configuration selects qualified profiles; it does
not install a second raw record DSL or arbitrary runtime callback evaluator.
No new strategy Module is introduced merely to hold forwarding files.

| Strategy family | Decision and required evidence |
|-----------------+--------------------------------|
| Selection/coverage | Org/Query profile, dependency frontier, completeness and budgets |
| Temporal applicability | Original admissions, current owner snapshots, verdict and clock window |
| Authority/flow | Actor, purpose, resource, destination, current grant and restrictions |
| Scheduling | Ready dependencies, Join obligations, capacity, Task/Attempt revision and deadlines |
| Disclosure | Exact rendered bytes, provider/request/destination, current input and authority fences |
| Result admission | Matching Attempt, original input, provider receipt and current applicability |
| Invalidation | Changed source/evidence/policy/authority dependencies; retain unresolved effects |
| Recovery | Exact terminal/isolation proof, cancellation acknowledgement and retained resources |
| Publication | Current successor proposal, expected durable head and atomic backend fences |
| Retention/revisit | Separate evidence, due conditions, permitted readers and measurable recall/use |
| Close/cleanup | No unresolved effects/obligations/leases; immutable terminal state |

C4 chooses behavior order inside an admitted graph. It does not allow a later
permit to override a mandatory restriction or clear an inherited recovery
obligation. Narrow readers/destinations and windows, retain provenance, take the
minimum resource budget and preserve accumulated obligations. Scheduling priority
and revisit intervals have domain-specific composition laws; do not force all
policy values into numeric minimum. Conflicting strategy requirements return a
bounded typed refusal rather than silently picking one parent's value.

Authorization uses the existing Cedar owner. Bind principal/action/resource/
context together with policy, entity, schema and runtime admission identities.
Cedar's [[https://docs.cedarpolicy.com/auth/authorization.html][authorization algorithm]] uses default deny, forbid-overrides-permit and
skip-on-error. The proposed consequential lifecycle profile additionally rejects
relevant authorization diagnostics and missing mandatory policy inputs; this is
an explicit application rule, not a change to Cedar semantics. A Cedar Allow
still needs the Context/Temporal/Session/backend gates for the same operation.

* Joint immutable use envelope

The versioned envelope binds the original MRR Context contract without mutation.
It additionally contains:

- Org parser/query/projection identities, original source references and exact
  selected anchor bindings; no raw provider handle or secret;
- complete dependency and Temporal admission references, with their original
  source-owner identities and current applicability witness references;
- frozen policy graph, implementation/schema/entity set, revision and profile;
- information restriction, purpose, destination and registered authority generation;
- Session ID, Turn, Task/spec revision, Attempt ID/generation and provider request;
- trusted clock observation reference, clock domain/role and bounded window;
- expected Session owner revision, source/policy registry generations, durable
  head generation/commitment, idempotency key and semantic envelope commitment.

A digest is identity/freshness metadata. Replaying a digest is not receipt
authentication. Runtime validates referenced receipts against registered owners;
caller-supplied current digests, booleans or clock coordinates cannot replace
those owners. Capacity bounds and exhaustion are explicit per registry; no wrap,
implicit eviction or fallback to historical authority is allowed.

* Lifecycle transitions and linearization boundaries

| Transition | Pure proposal | Runtime condition and durable boundary |
|------------+---------------+----------------------------------------|
| select/derive | Source-backed Context plus required evidence | Source/Query owner qualification; preserve original producer admissions |
| prepare | Joint envelope and decisions | Observe current registered vector; preparation grants no future effect permission |
| claim | Session Attempt and obligations | Current owner CAS, input/strategy/source/grant checks; record claim |
| disclose | Exact provider/request payload intent | Recheck envelope at dispatch admission; fenced outbox/dispatch receipt |
| receive | Matching provider response observation | Retain immutable provider receipt even if current admission fails |
| accept-result | Derived candidate with producer lineage | Recheck original Attempt and current source/Temporal/strategy/authority |
| publish | Successor head proposal | Atomic expected-head and authority/source/strategy fence at backend commit |
| invalidate | New generation plus retained pending obligations | Fence undispatched claims; quarantine late responses; preserve effect ambiguity |
| reconcile | Resolve the exact old Attempt obligation | Actual matching terminal or admitted isolation receipt; resource release evidence |
| close | Terminal Session/Context intent | No unresolved effects, obligations or leases; terminal retirement cannot reopen |
| revisit | New assessment/retention/due proposal | Current evidence and policy; fresh Attempt identity rather than old-use resurrection |

Two POO Flow checks around an external operation are not a distributed atomic
transaction. For dispatch, publish an idempotent fenced outbox or an equivalent
qualified gateway intent, then obtain a provider receipt. A revocation ordered
before dispatch admission blocks that new dispatch. A payload already disclosed
cannot be withdrawn by a local state change. Provider idempotency and isolation
must be qualified; local CAS alone cannot promise exactly-once external effects.

For Data publication, the backend must atomically validate the enrolled fence
vector and expected head or an equivalent transaction-bound registered capsule.
Independent prechecks followed by a later SQL/CAS call leave a race. Any claim
about physical filesystem currency also needs a qualified source-owner snapshot
protocol; generic transactions cannot lock arbitrary WorkTree path mutations.
CAS conflict discards the stale publication proposal and rederives from current
owners. Crash ambiguity retains a pending obligation until real evidence resolves
it; timeout, a cancel request, or dropping a waiter is insufficient evidence.

* FFI/C ABI and downstream responsibilities

POO Flow implements native Types, Objects, Funs, config/profile and interface
closure for the semantic contract. Privileged control enrollment and ordinary
inert evaluation stay distinct. The ABI negotiates envelope version and profile,
rejects unknown/missing/duplicate fields and unsupported operations, and returns
bounded typed receipts. Expose no native pointer, mutable POO object or private
ledger as an ordinary wire value. Preserve the single-owner-thread native rule;
parallel workers can operate outside it with explicit lease/fence handoff.

Runtime owns process/worker/clock/source capabilities and transports owner events
back to the reducer. MRR verifies original relational derivation and consumer
bindings without reimplementing POO strategy dispatch. Data owns physical worker
leases, immutable events and conditional publication. Python remains glue and
qualification; Rust adapters own typed semantic/result admission assertions.
Downstream pins and lockfiles change only after the exact producer surface is
qualified. Producer CI does not qualify a downstream physical roundtrip.

* Delivered first implementation slice

=AiAgenticContextTemporalPolicy.= and its Type are native Context values.
=funs-temporal.ss= closes through the normal functional/interface roles and
reuses Temporal intervals, interval membership and bounded observation replay.
It admits a bounded policy revision, purpose set and clock role, copies interval
strings, and constructs a canonical policy digest. =temporal-assess= returns
eligible, not-yet-effective, expired, uncertain, incomparable, unknown,
unsupported-clock or purpose-denied relative to declared observations.

This helper is a pure proposal. Its authentication, authorization, publication
and durability flags remain false. It is not wired into the existing Session
Host or v1 ABI and does not select trusted current clocks or Temporal admissions.
Do not describe a helper pass as implementation of disclosure/result/publication.

* Formal obligations and staged qualification

The joint finite model explicitly permits source, Temporal and policy revisions
between preparation and commit, independent clock domain/uncertainty changes,
evidence refutation, terminal retirement and receipt-based recovery. Historical
commit rows retain the values at their linearization point. Later invalidation
does not rewrite those rows or make them current again. It is a prospective
protocol model with a fixed admitted scope/owner, one effect and no real provider;
existing Session models cover Attempt routing/owner CAS separately. A resolved
effect obligation remains cleared across later invalidation; a pending obligation
remains retained. Resolution and lifecycle retirement have independent terminal
semantics.

Lean proves conservative interval and exact-current-vector admission laws over
abstract owner inputs. Quint enumerates bounded interleavings and matched guard
mutations. Native tests exercise real Temporal domain/modality/bounds and POO
policy replay. These are separate evidence scopes. Source hash binding proves
metadata freshness; end-to-end refinement and automatic trace-to-native replay
remain additional work.

Delivery order:

1. Qualify the native window policy and joint bounded lifecycle obligations.
2. Add typed current source/Temporal/policy/authority registry capsules and
   Context-required receipt resolution; qualify rejection and exhaustion.
3. Route claim/disclosure/result/retirement through one native lifecycle reducer,
   retaining immutable obligations and exact Attempt lineage.
4. Qualify the versioned C ABI and MRR typed consumer on the exact producer head.
5. Qualify Data transaction fences, outbox/idempotency, crash recovery and resource
   retention with real backend/provider controls.
6. Measure dependency-indexed invalidation, ready queues and amortized replay
   after semantic parity. Preserve negative results; no throughput claim follows
   from finite model size or concurrent worker counts.

* Local qualification receipt

The normal production PackageSpec build and serial heap-fenced native entrypoints
qualify the delivered window policy. Seven new native cases exercise whole-window
membership, future/expired distinction, uncertainty across each endpoint, foreign
clock domains, declared time, wrong role/purpose and owned policy replay. Eight
existing Context core cases qualify Module composition and original source replay.
Final native acceptance requires MODULE-OK, HARNESS-OK, final OK and no harness or
heap/stack errors. Only initial test-artifact compilation uses the previously
recorded O0 setting; production modules retain the normal compiler.

=ContextTemporalPolicy.lean= proves 13 named interval/current-vector/obligation
laws; its audit inventories 30 theorems including generated declarations, using
only standard Lean axioms. =ContextTemporalLifecycle.qnt= enumerates 4,904 distinct
safe states with an empty queue. Nine independent guard mutations produce actual
invariant counterexamples: source, Temporal and policy versions; refuted evidence;
clock domain; uncertainty; missing terminal receipt; lifecycle resurrection; and
recreation of an already resolved obligation. The model initially needed explicit
action return annotations and assignment-expression parentheses; syntax/type
failures were rejected by the gate and were not accepted as counterexamples.

The terminal-resolution refinement was checked by the complete unchanged-limit
group. It retains one effect, one resolution and bounded independent revisions;
it proves neither scheduler fairness nor physical provider isolation. The native
window tests are condition-matched controls, not automated trace replay from this
prospective lifecycle model. Existing proof-gate tests, source/invariant metadata,
Just recipes and workflow syntax checks are separate local evidence. CI owns the
exact-head cross-platform/package/ABI qualifications.
