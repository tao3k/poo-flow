#+title: Source-bound fingerprint history closure
#+startup: overview

* Status

Proof-backed declaration-closure v1 refinement.

This document stabilizes =poo-flow.lean-declaration-closure.v1=.  It does not
authorize a v2 schema, a second closure identity, or a competing proof path.

* Context

=SubjectProgressEvidence.fingerprintHistory= is a raw list of semantic
fingerprint strings.  The structural oscillation witness proves that one string
occurs twice with an intervening different string, but the list itself does not
prove:

- which subject produced an entry;
- which registry and generation owned it;
- the transition sequence;
- the obligations state at each checkpoint;
- checkpoint or history provenance;
- that the last two checkpoints are the stated previous/current transition;
- that the current fingerprint appears anywhere in the list;
- that one closed history exists for every exact SCC subject.

Lean constructs a forged list that satisfies the oscillation shape while not
containing the evidence's current fingerprint.  Therefore structural
oscillation over raw strings is necessary but not sufficient.

* Decision

The raw fingerprint list remains a projection for compact progress receipts.
The evidence owner is a separate
=SourceBoundSemanticFingerprintHistory= containing typed checkpoints.

Every checkpoint binds:

- composition-object subject;
- registry digest;
- evaluation generation;
- strictly increasing sequence number;
- semantic fingerprint;
- remaining-obligations digest;
- non-empty provenance digest.

Every history binds:

- non-empty history identity and provenance;
- one subject and registry;
- source-bound checkpoints;
- strict sequence order and non-decreasing generation;
- generation bounded by the progress receipt;
- exact fingerprint projection;
- previous/current endpoint fingerprints and obligations;
- current endpoint generation equal to the progress generation.

The progress-level closure requires exact subject coverage, unique history
subjects, and one closed history witness for every progress evidence subject.
It composes with =SourceBoundProgressEvidenceClosed= rather than replacing it.

* Mathematical model

A checkpoint carries source coordinates and provenance:

#+begin_src typst
$ q_i = (s_i, R_i, g_i, n_i, f_i, o_i, p_i) $
#+end_src

Checkpoint order is strict in sequence and monotone in generation:

#+begin_src typst
$ i < j => n_i < n_j and g_i <= g_j $
#+end_src

The raw evidence history is exactly the fingerprint projection:

#+begin_src typst
$ H_e = "map"("fingerprint", Q) $
#+end_src

The final two checkpoints are the stated transition:

#+begin_src typst
$ Q = B ++ [q_"previous", q_"current"] $
#+end_src

#+begin_src typst
$ f(q_"previous") = f_"previous"
  and f(q_"current") = f_"current"
  and g(q_"current") = g_"progress" $
#+end_src

Consequently, every closed history contains the current fingerprint:

#+begin_src typst
$ "HistoryClosed"(e, Q) => f_"current" in H_e $
#+end_src

* State model

#+begin_src mermaid
stateDiagram-v2
  [*] --> RawFingerprintList: progress receipt carries string projection
  RawFingerprintList --> ForgedOscillation: repeated string with intervening change
  ForgedOscillation --> FailClosed: current fingerprint is absent
  [*] --> CheckpointMinted: subject registry generation sequence provenance
  CheckpointMinted --> SourceBound: checkpoint subject and registry match history
  SourceBound --> Ordered: sequence strictly increases and generation is monotone
  Ordered --> ProjectionExact: mapped fingerprints equal receipt history
  ProjectionExact --> EndpointBound: final two checkpoints equal previous and current
  EndpointBound --> GenerationCurrent: current checkpoint generation matches progress
  GenerationCurrent --> SubjectCoverageExact: one unique history per evidence subject
  SubjectCoverageExact --> HistoryClosed: compose source-bound progress evidence
  HistoryClosed --> OscillationEligible: structural repeat is now source-bound
#+end_src

* Ownership boundaries

| Owner | Owns | Does not own |
|-------+------+--------------|
| Raw progress receipt | compact fingerprint projection | history truth or provenance |
| Checkpoint | one source-bound semantic state | classification selection |
| Fingerprint-history closure | order, generation, projection, endpoints, provenance | domain semantic relation |
| Progress closure | exact SCC subjects and classification evidence | manufacturing checkpoint history |
| Classification coherence | relation consistency and maximal candidate | history storage or ordering |
| Runtime watchdog | runtime threshold and attribution | semantic checkpoint history |
