* Logic gap found by Lean

The existing recovery progress algebra classifies a transition by one owner
coordinate:

- runtime crash budget;
- scheduler admission;
- completion storage admission.

If the selected coordinate must decrease strictly while the other coordinates
need only be non-increasing, one transition may satisfy more than one owner
constructor.  A transition that decreases both crash and scheduling budgets can
be labeled as both runtime-crash progress and scheduler progress.

The independent model proves this counterexample as
=weakProgressAlgebraAllowsMultipleOwners=.

#+begin_src typst
$
  "Weak"(B, B', o) :=
  cases(
    o = "crash": c' < c and s' <= s and t' <= t,
    o = "scheduler": c' <= c and s' < s and t' <= t,
    o = "storage": c' <= c and s' <= s and t' < t,
  )
$
#+end_src

#+begin_src typst
$
  exists B, B':
    "Weak"(B, B', "crash")
    and
    "Weak"(B, B', "scheduler")
$
#+end_src

Therefore strict rank decrease proves progress, but it does not by itself prove
which owner is accountable for that step.

* Decision

Define an atomic owner receipt.  Exactly one coordinate decreases strictly and
the other two coordinates remain equal.

#+begin_src typst
$
  "Atomic"(B, B', "crash") :=
    c' < c and s' = s and t' = t
$
#+end_src

#+begin_src typst
$
  "Atomic"(B, B', "scheduler") :=
    c' = c and s' < s and t' = t
$
#+end_src

#+begin_src typst
$
  "Atomic"(B, B', "storage") :=
    c' = c and s' = s and t' < t
$
#+end_src

This gives both rank decrease and owner exclusivity.

#+begin_src typst
$
  "Atomic"(B, B', o)
  and
  "Atomic"(B, B', o')
  arrow.r.double
  o = o'
$
#+end_src

The independent model packages:

- an atomic progress receipt indexed by the owner kind;
- non-empty owner identity;
- non-empty owner receipt identity.

Lean also proves that an atomic progress receipt does not determine those
identities.  Owner evidence is an independent premise rather than a value
inferred from budget arithmetic.

* Binding to actual recovery owners

The actual closure defines
=SourceBoundEffectCompletionRecoveryOwnerCoveredStep=.  Its three indexed
constructors consume the already-proved owner-native transition closures.

The runtime-crash constructor requires:

It can construct only the =runtimeCrashBudget= progress owner.

** Scheduler owner

The scheduler constructor requires:

- =SourceBoundEffectCompletionRecoverySchedulingDeferralTransitionClosed=;
- =SourceBoundEffectCompletionRecoverySchedulingDeferralProgressProjection=.

It can construct only the =schedulerAdmission= progress owner.

** Completion storage owner

The storage constructor requires:

- =SourceBoundEffectCompletionPrecommitStorageDeferralTransitionClosed=;
- =SourceBoundEffectCompletionRecoveryStorageDeferralProgressProjection=.

It can construct only the =completionStorageAdmission= progress owner.

No constructor accepts a receipt owned by another branch.

* Per-step totality and exclusivity

For every non-committed trace position, owner coverage requires a current
generation, a stable provider acknowledgement, and an owner-covered transition
from the current budget to the next budget.

#+begin_src typst
$
  forall i:
    T_i != "committed"
    arrow.r.double
    exists o:
      "CoveredStep"(E_i, B_i, B_(i + 1), o)
$
#+end_src

The separate uniqueness theorem strengthens the existential to a unique owner:

#+begin_src typst
$
  forall i, o, o':
    "CoveredStep"(E_i, B_i, B_(i + 1), o)
    and
    "CoveredStep"(E_i, B_i, B_(i + 1), o')
    arrow.r.double
    o = o'
$
#+end_src

Thus each admitted non-committed step has total owner coverage and cannot be
reclassified under a second progress-owner kind.

* What is proved

- the weak progress algebra is owner-ambiguous;
- atomic owner receipts strictly decrease the shared rank;
- two atomic receipts for one transition imply the same owner kind;
- owner identity is not inferred from arithmetic;
- each actual owner branch consumes its own transition closure and projection;
- every covered step builds the existing progress receipt;
- every non-committed step has an owner-covered transition;
- two covered transitions over the same step imply the same owner kind;
- unstable provider evidence rejects aggregate coverage;
- a superseded non-committed scope rejects aggregate coverage;
- aggregate owner coverage reuses the existing convergence theorem.

* What is not yet proved

The aggregate evidence stores owner coverage as a proposition:

#+begin_src typst
$
  exists o: "CoveredStep"(E_i, B_i, B_(i + 1), o)
$
#+end_src

It does not yet expose a first-class audit value containing:

- the exact owner identity;
- the exact owner receipt identity;
- continuity between the previous after-receipt and the next before-receipt;
- non-reuse of an owner receipt identity at a later step;
- recovery identity continuity across the trace.

The current closure proves admission and convergence.  It does not claim that a
downstream audit exporter can recover the unique receipt identity from the
aggregate proposition.

* Architecture boundary

- no runtime scheduler API is introduced;
- no recovery receipt is synthesized from a progress coordinate;
- no owner is inferred from rank decrease;
- no JSON transport surface is introduced;
- no proof constructor accepts another owner's receipt kind;
- no new convergence semantics are introduced;
- Lean structures, indexed inductives, and propositions remain the proof core.
