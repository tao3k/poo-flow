* Normative responsibility

This module exclusively owns repository, dependency, package, build,
parent/child, and development-harness boundaries for the 45 RFC family.

* Ownership table

| Concern | Owner | Explicitly not owned |
|-
| pure-object fixed point, prototype composition, self/super | pinned =gerbil-poo= | POO Flow, GSLPH |
| Mix/Profile/module composition semantics | POO Flow | Gerbil-Bazel, =gerbil.pkg= |
| module import and binding behavior | Gerbil module system | POO Flow policy |
| dependency installation | =gerbil.pkg=/=gxpkg= | semantic qualification |
| build graph and build execution | Gerbil-Bazel | Mix/Profile semantics |
| policy harness and building/testing framework | GSLPH | runtime authority |
| parent core initialization | =poo-flow-core= | child packages |
| child governance semantics | =wendao-episteme= | parent reimplementation |

* Parent and child

The parent maintains and qualifies only its core dependency boundary.  The
=wendao-episteme= submodule is source identity and a downstream semantic
consumer.  It does not become a Gerbil package merely because it is a gitlink,
and it does not repeat parent G0.

* Qualification responsibility split

The parent qualification surface ends at the published =poo-flow-core=
capability contract.

| Qualification concern | Owner |
|-
| pinned =gerbil-poo= import/binding qualification | parent =poo-flow-core= |
| parent capability publication and parent-local tests | parent =poo-flow-core= |
| child consumption against an identified parent artifact | =wendao-episteme= |
| governance Profile/case behavior | =wendao-episteme= |
| downstream B-to-C embedding | the downstream consumer that owns that edge |

Parent completion MUST NOT depend on:

- =wendao-episteme= integration tests;
- =wendao-episteme= distribution tests;
- child governance fixtures;
- child Profile/case qualification;
- recursively executing descendant package suites.

The parent may test that its own published capability is complete and
consumable.  It does not enter the child checkout to prove how the child uses
that capability.

The child owns qualification against an explicitly identified published or
pinned parent artifact.  That proves the child consumed the parent contract; it
does not reopen, wrap, or rerun parent G0.

GSLPH may execute the parent and child test groups as separate development
workflows.  The harness does not merge their ownership or make the child suite
a parent completion gate.

* Name and package identity

The exact downstream project and semantic package name is
=wendao-episteme=, not =wendao=.

Its current git submodule identity does not imply:

- a =gerbil.pkg= declaration;
- =gxpkg= installation identity;
- a Gerbil import namespace;
- parent package integration;
- parent build-graph membership.

If =wendao-episteme= later chooses to become a Gerbil package, that is a
child-owned package decision with its own contract.  It does not retroactively
change the meaning of the gitlink or expand parent ownership.

* New architecture status

This RFC specifies a new architecture.  It has no legacy public contract to
preserve and therefore defines no:

- compatibility mode;
- migration adapter;
- deprecation window;
- legacy parser branch;
- fallback behavior;
- staged removal policy.

Rejected experimental drafts are design history, not deployed interfaces.
Removing them from the normative RFC requires no compatibility or deprecation
strategy.

* Forbidden boundary collapses

- No Gerbil-Bazel semantic adapter contract.
- No build receipt inside Requirement, Observation, Policy, or Decision.
- No =gerbil.pkg= dependency projection or active evidence closure.
- No GSLPH runtime probe, event, receipt, condition, or context authority.
- No child-specific parent dependency qualification.
- No parent integration/distribution gate owned by a child.
- No compatibility or migration layer for pre-implementation drafts.
- No package identity inferred from an ambient checkout.
