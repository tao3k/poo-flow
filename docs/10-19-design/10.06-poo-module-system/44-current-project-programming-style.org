* 10.06.44 Current Project Programming Style

This file is the normative router for POO Flow programming style.  It is not a
monolithic Gerbil guide and does not repeat every module rule.  An author first
classifies the source role, then follows exactly the owning style module below.

The public-surface authority remains
[[file:164-capability-gradient-and-default-expression-surface.org][RFC 164]].
The detailed Object/Entity/Element/Relation/Query correspondence is
[[file:165-native-semantic-element-relation-query-model.org][RFC 165]].

These modules refine one style contract; they are not optional profiles and do
not define competing APIs.  A vertical module may refine its authoring Profile
with stricter domain rules, but may not weaken unrelated base rules.

** Universal invariants

1. The default public surface is value-first and POO-native.
2. Native slot algebra owns default, functional refinement, nested refinement
   and override; domain verbs such as =add-*= or =remove-*= do not duplicate it.
3. Pure functions own algorithms.  Slot generics own one receiver axis.  CLOS
   owns only crossings whose axes grow independently.
4. =define-type= owns boundary contracts; it does not simulate a class system.
5. Runtime, proof and wire values are projections of admitted POO facts, never
   a second semantic authority.
6. Heavy execution stays behind an explicit runtime handoff.
7. Every claim of performance or formal closure names its executable evidence.

** Author workflow

Before editing code, identify:

- the source role being changed;
- the public POO value or pure function that owns the fact;
- whether dispatch has one open axis or several independent axes;
- the runtime/proof boundary, if any;
- the focused gate and the broader consumer gate.

If those five answers are unclear, the change is not ready to acquire a new
abstraction.  Repair the ownership boundary before adding macros, registries,
providers or generic functions.

** Agent admission rule

Documentation is not the only enforcement plane.  Stable source-shape rules
MUST be represented by the Module Interface's =authoring= Profile and produce
an actionable diagnostic.  Semantic facts that cannot be proven safely from
syntax remain test/proof obligations; the authoring gate must not pretend to
prove them by keyword matching.

The default repair vocabulary is native: =?=, ===>=, ===>.+=, ordinary slot
override, named pure functions, maintained POO objects and explicit Provider
projections.  A repair must not introduce a compatibility layer or a second
evaluator.

** Completion checklist

- [ ] The change follows the single owning style module.
- [ ] Public values remain native POO objects or named pure functions.
- [ ] Imports point from lower roles to higher composition roles, never back.
- [ ] Query and proof projections bind stable object and revision identities.
- [ ] Focused executable evidence passes.
- [ ] Affected public consumers pass without absorbing unrelated worktree edits.
