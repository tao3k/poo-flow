#+title: Publication-Domain Registry Replica Provenance Closure
#+startup: overview

* Status

- State :: Proposed
- Scope :: peer knowledge poisoning, full validation-context binding, sender authorization, and durable recovery provenance
- Depends on :: RFC 54, RFC 60, RFC 61

* Problem

RFC 61 proves that maximum is a safe join for already admitted replica
checkpoint knowledge.  The ordinary knowledge value still contains only a
minimum position and can be constructed directly.

An unverified peer may claim minimum position =100=.  Joining that claim with a
legitimate local minimum =5= raises the result to =100= and rejects legitimate
candidate position =6=.

This attack does not cause registry rollback.  It poisons availability and
admission integrity by making an unsupported high position permanent under an
idempotent maximum join.

* Self-reported peer envelope is insufficient

A peer may self-report sender identity, authorization snapshot, and checkpoint
knowledge:

#+begin_src typst
#align(center)[
  $
    U = ("sender", "authorization-snapshot", K_100)
  $
]
#+end_src

Those fields do not prove their own authority:

#+begin_src typst
#align(center)[
  $
    "Accepted"(K_5, 6)
      and
    not "Accepted"(K_5 "join" K_100, 6)
  $
]
#+end_src

The pure join cannot distinguish an authority-issued position from an arbitrary
number.  Admission must occur before projection into joinable knowledge.

* Authorization snapshot equality is insufficient

Two validation contexts may carry the same authorization snapshot while
carrying different revocation state:

#+begin_src typst
#align(center)[
  $
    "authorization"(C_l) = "authorization"(C_r)
      and
    "revocation"(C_l) != "revocation"(C_r)
      "implies"
    C_l != C_r
  $
]
#+end_src

The verifier must not project context equality down to authorization identity.
RFC 54 exact-context equality is the admission boundary.

* Verifier admission authority

For one actual lineage =L=, the verifier pins one replica-knowledge admission
authority =A_L=.  It owns:

- the exact RFC 54 validation context, including authority generation, policy,
  authorization, and revocation snapshots;
- the authorized-sender predicate;
- the RFC 60 durable recovery authority configured for each sender.

The authority is an actual verifier input.  Matching numeric identifiers do not
allow an envelope to select a replacement authorization predicate or recovery
authority.

* Authority-issued replica envelope

An admitted envelope is indexed by both the actual lineage and the actual
admission-authority object:

#+begin_src typst
#align(center)[
  $
    C_(L, A_L) =
      ("sender", "validation-context", E_L, K_L)
  $
]
#+end_src

Construction requires all of the following:

#+begin_src typst
#align(center)[
  $
    "context"(C) = "context"(A_L)
      and
    "Authorized"(A_L, "sender"(C))
      and
    "IssuedRecovery"(A_L("sender"(C)), E_L)
      and
    K_L = p_"recovered"(E_L)
  $
]
#+end_src

Sender identity and the complete validation context remain observable evidence,
while the actual authority object supplies their meaning.  An authorization
snapshot match alone does not admit an envelope when policy, revocation, or
authority generation differs.

* Durable lower bound

An admitted envelope cannot project knowledge below its sender's durable
checkpoint:

#+begin_src typst
#align(center)[
  $
    p_"durable"(A_L("sender"(C))) <= K(C)
  $
]
#+end_src

It also cannot invent a position above the authority-owned recovered checkpoint:

#+begin_src typst
#align(center)[
  $
    K(C) = p_"head"(A_L("sender"(C)))
  $
]
#+end_src

The results follow from strengthened RFC 60 authority-issued recovery and the
exact equality between projected knowledge, recovered position, and the
authority-owned checkpoint.

* Provenance-restricted join

The public admitted-join surface accepts only envelopes indexed by the same
lineage and admission authority:

#+begin_src typst
#align(center)[
  $
    "AdmittedJoin"(C_l, C_r) = K(C_l) "join" K(C_r)
  $
]
#+end_src

The joined minimum is not below either sender's durable checkpoint, and it
preserves every rollback rejection already known by either admitted envelope.

This proof does not establish that every authorized sender is non-Byzantine.
The semantic position is accepted because it carries the configured RFC 60
recovery authority's evidence, not merely because the transport authenticated a
sender name.

* Ownership boundary

- The verifier owns the actual replica-knowledge admission authority.
- RFC 54 validation context owns authority, policy, authorization, and revocation freshness.
- Each configured RFC 60 recovery authority owns durable checkpoint evidence.
- Transport authentication carries an envelope but does not create semantic provenance.
- Only admitted envelopes may be projected into the RFC 61 join.

* Architectural consequence

Semilattice laws protect only the values admitted into the semilattice.  Replica
knowledge becomes joinable after authorization and durable recovery provenance
are established, not before.  This keeps the pure RFC 61 join small while
making its trust boundary explicit and fail closed.
