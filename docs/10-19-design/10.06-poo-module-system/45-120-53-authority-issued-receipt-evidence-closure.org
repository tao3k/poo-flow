#+startup: overview

* Problem

RFC 52 proves that the audit projection is canonical and lossless:

#+begin_src typst
$
  "decode"("encode"(G)) = G
$
#+end_src

This proves representation identity.  It does not prove that a receipt claim is
true.  A forged claim can have a perfect canonical round trip:

#+begin_src typst
$
  "decode"("encode"("forged")) = "forged"
$

$
  "selfReportedAccepted"("forged") = "true"
  quad and quad
  "authorityAccepted"("forged") = "false"
$
#+end_src

The current runtime shape exposes this distinction.  An audit object can carry
=decision: accepted=, binding digests, and opaque receipt bytes.  Recomputing
the audit digest proves that these fields were transported intact; it does not
prove that the AXLE owner issued them or that the receipt bytes bind those
fields.

* Authority model

Let =A= be the acceptance authority, =R= an owner receipt artifact, and =B= the
typed binding containing source identity, independent bundle identity, and the
provided interface identity.

#+begin_src typst
$
  A."validate"(R) = "some"(B)
  arrow.r
  A."accepted"(B)
$

$
  B =
  (
    "sourceIdentity",
    "independentBundle",
    "providedInterface"
  )
$
#+end_src

A graph node is accepted only when the binding returned by the authority is
identical to the binding carried by that node:

#+begin_src typst
$
  A."validate"(R) = "some"(B_A)
  quad and quad
  B_A = B_N
  arrow.r
  "NodeAccepted"(B_N)
$
#+end_src

The acceptance authority is sound by construction:

#+begin_src typst
$
  forall R, B:
  A."validate"(R) = "some"(B)
  arrow.r
  A."accepted"(B)
$
#+end_src

* Ownership boundary

- Audit JSON may declare receipt bytes and expected identities.
- Audit decoding may establish exact shape, canonical bytes, and round-trip identity.
- Audit decoding MUST NOT create an accepted receipt value.
- The AXLE owner adapter validates the real closure artifact and derives the binding.
- The receipt-DAG core accepts only authority-issued evidence.
- Source identity, independent bundle identity, root declarations, and provided interface identity MUST be derived from the same owner artifact.
- A duplicated =decision= or digest field is not authority evidence.

* Real AXLE artifact

The current standard =poo-flow-axle-verify= closure artifact provides:

- =closure.schema_id = poo-flow.lean-declaration-closure.v1=
- =preflight.schema_id = poo-flow.axle-closure-preflight.v1=
- =exact_bundle.schema_id = poo-flow.axle-exact-declaration-closure.v1=
- =exact_bundle.verification.schema_id = poo-flow.axle-root-declaration-validation.v1=
- =exact_bundle.verification.status = accepted=
- zero failed declarations
- complete root declarations
- canonical source digest
- exact bundle digest
- =independent_declaration_bundle.schema_id = poo-flow.independent-declaration-bundle.v1=
- independent declaration bundle digest

The authority adapter must validate this chain as typed owner output.  It must
not reinterpret the RFC 52 receipt-graph audit object as an AXLE closure
artifact; the two artifacts have different owners and different schemas.

Root declarations have two distinct order semantics.  The AXLE closure request
preserves owner order because request order participates in the closure and
exact-bundle identities.  After authority validation, receipt-DAG ownership
canonicalizes the same roots as a set.  Sorting roots before owner
reverification changes the Lean closure digest and is invalid.

* Validation state machine

#+begin_src mermaid
stateDiagram-v2
  [*] --> DecodeAudit: untrusted audit bytes
  DecodeAudit --> Reject: shape or canonical transport failure
  DecodeAudit --> DeclaredEvidence: representation is exact
  DeclaredEvidence --> Reject: owner artifact is absent
  DeclaredEvidence --> ValidateAxleOwner: AXLE closure artifact supplied
  ValidateAxleOwner --> Reject: schema, root, digest, or proof status differs
  ValidateAxleOwner --> DeriveBinding: owner result is accepted
  DeriveBinding --> Reject: source, bundle, or interface binding differs
  DeriveBinding --> AuthorityEvidence: exact owner-issued binding
  AuthorityEvidence --> BuildNode: accepted evidence capability present
  BuildNode --> [*]: receipt DAG may verify
#+end_src
