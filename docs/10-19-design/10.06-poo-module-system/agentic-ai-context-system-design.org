* Decision and status

The new =ai-agentic-context= Module is the architectural owner of the Agentic AI
Content and Context System in POO Flow. Org-mode documents and their Orgize
Element graphs are its core content model. Session is an independent Module
composed as a dependency by Context. Memory is a Feature owned by Context.
Session governs scoped interaction with content over time. Memory governs
retention, recall, consolidation, and revisit. Context owns its content model.

This is a proposed redesign, refining the Context, Protocol, Authority, and
Evidence facets of [[file:91-canonical-organization-bundle-rfc.org][RFC 91]]. The design follows the source boundaries in
[[file:166-session-memory-orgize-boundary.org][166]] and the independent evidence/revisit/retention axes in [[file:167-temporal-revisit-evidence-design.org][167]]. It supersedes
the earlier proposed placement of Agentic Context under memory-core and the
standalone Memory ownership assumptions in those documents. Existing
lifecycle details remain proposed contracts. Core and source ownership have
already migrated; the next protocols are specified in
[[file:ai-agentic-context-session-memory-contracts.org][Module roles, Session and Memory contracts]].

The delivered ownership baseline is POO Flow
=22c4b24c3872daac782d3c836fb17369c0fe51c7=. Existing native Context Use checks
are a partial Library implementation, not qualification of this whole system.
All newly authored design documents and examples use English.

* System structure

#+begin_src text
Module: ai-agentic-context
  Core: Org Content, source revisions, Context contracts and consumption gates
  Dependency Module: session -- turns, branches, handoff, cancellation and recovery
  Feature: memory -- retention, recall, consolidation and temporal revisit

Org source -> Orgize graph -> POO Query -> admitted evidence
           -> scoped Context projection -> Session turn
           -> judgment/action proposal -> current consumption gate
           -> retained experience or explicit Org revision
#+end_src

Session and Memory reference Content and Context revisions. They do not own
another document grammar, parser, truth registry, or global Context head.
Organization, Authority, Temporal, and Evidence remain their existing semantic
owners; this system composes their admitted values rather than absorbing them.

The module home is =modules/ai-agentic-context/=. Its core owns Content
and Context; =features/memory/= holds the Memory Feature. Independent
=modules/session/= own the Session dependency.
One public =interface.ss= closes the Module boundary. Internal Gerbil files
provide static code ownership. Session remains independently selectable. The core interface is implemented;
new Session/Memory protocols remain proposed. Core sources follow the
=types/objects/funs/config/interface= roles in Programming Style 01. Public values are
native POO objects; named pure functions own selection, composition, replay,
and projection. Private records hold Host runtime state. C/Python values are
projections of the same Scheme contracts; MRR Rust remains a downstream adapter.

* Module and Feature contract

** Core is always present

The =ai-agentic-context= Module owns its Context identity/revision space, Org source
binding, Scope/Demand/Evidence/Restriction/Projection/Use contracts, and mandatory
admission and consumption checks. A Feature may add behavior or stricter
obligations; disabling a Feature cannot disable source, scope, or Authority
checks. Context works without retained Memory or a Session history.

** Feature composition

Use the existing [[file:137-immutable-feature-manifest-bundles.org][FeatureDescriptor/FeatureManifestBundle]] system. Each immutable
descriptor declares =ai-agentic-context= as owner, stable Feature identity,
dependencies/conflicts, option schemas, and its policy/strategy/adapter/projection
contributions. =resolve-feature-profile= remains the sole dependency resolver.
No new feature registry, merge engine, Memory facade, or module-specific DSL is
introduced.

| Owned Feature | Contributions | Dependency and activation rule |
|---------------+---------------+--------------------------------|
| memory | Retained experiences, recall, consolidation, retention and revisit policies | Requires admitted core Context; ordinary source recall does not require an active Session instance |

Memory capture of a Session turn explicitly requires the composed Session Module and
binds its turn receipt. Memory revisit explicitly requires a qualified Temporal
profile. Durable retention explicitly requires a declared Backend adapter.
These requirements belong to the selected operation/profile; activating Memory
alone cannot silently instantiate a Session, scheduler, or durable store.

The proposed authoring selection is one Module with native Feature values:
=ai-agentic-context= with its independent Session dependency and optional
=ai-agentic-context/memory= descriptor.
The final syntax must lower through the existing module/feature authoring
surface; no new macro is implied by these design names. Missing dependencies,
unsupported options, duplicate identities, cycles, and conflicting policies
produce structured rejection before runtime activation.

** Refinement and lifetime

Feature policies refine the core contracts. Context restrictions intersect;
Evidence obligations accumulate; Session protocol transitions refine; Memory
retention does not widen visibility or extend a lease. C4 lookup order cannot
select a weaker Feature policy. Feature selections and their qualified manifest
are part of the Bundle/projection identity, so changing a profile invalidates
dependent projections and requires explicit Session transition or re-enrollment.

Core source revisions, Feature configuration revisions, Session revisions,
and Memory assessment revisions remain distinct. One Module does not imply a
single mutable head. Feature activation does not grant runtime capability;
Feature deactivation cannot erase pending turns, retirement fences, history,
or unfulfilled obligations. Reject a transition with live obligations unless
the declared Protocol has completed cancellation, handoff, or closure.

* Orgize and Org-mode as the content core

** Source and structure

Orgize owns Org syntax, parsing, Elements, document-local structural selectors,
and their maintained execution projections. POO Flow consumes that model;
it must not add a Context-specific Org parser or a parallel Memory grammar.

Headings and sections provide structural scope. Properties, tags, TODO states,
timestamps, LOGBOOK entries, links, attachments, paragraphs, tables, and source
blocks enter through supported Orgize projections. A source block is content;
parsing or selecting it does not execute it. Unsupported required features
produce typed refusal rather than silent omission.

Org properties may declare task, visibility, or policy intent. Such declarations
must resolve through admitted Bundle and Authority values before controlling
access. Text, heading ancestry, TODO completion, and links do not confer grants,
authenticate evidence, or prove a claim. Evidence and controlling instructions
retain distinct roles in a model input projection.

** Identity and revision

A source anchor binds repository/Project identity, stable WorkTree identity,
document identity, exact bytes digest, and declared source cut. Path locates a
document but is not its complete identity. The cut includes relevant HEAD,
index, dirty, and untracked inputs under a stated acquisition profile.

An exported Element reference binds that anchor, graph/parser/profile revision,
Element identity, and byte span. A document-local ID or byte offset alone is
insufficient. Org ID/CUSTOM_ID links are explicit source references; resolving
them requires the target document and revision, including duplicate/unresolved
reference checks. Cross-revision relocation is an explicit resolution step,
not permission to reuse the old span or admission.

Content revisions are immutable. An Org edit creates a new source revision and
requires reparse/query. Parser, parse configuration, selector rule, and query
changes also invalidate their projections, even when selected text is unchanged.

** Qualified selection and content closure

Orgize's graph supplies POO Query's ElementSpace. POO Query owns canonical Query,
Provider, result contract, bounded rows, and completeness. A document-local
Orgize selector is a structural input to that route, not a separate semantic
Query language. MRR admits relational facts and derived Context claims where
inference is required; simple structural selection need not invent a derivation.

The qualified result retains exact query/rule identity, source anchor, scope,
selected Elements/spans, result digest, and complete/partial status. Replaying
against current bytes must reject forged rows and rule substitution.
Authentication of the file, WorkTree cut, and read grant remains a Host duty.

Links and attachments extend the content closure only under an explicit profile
and budget. Each consumed dependency contributes its own source anchor and
permission. A link is neither an automatic fetch capability nor a claim of
complete dependency coverage. Unknown closure prevents a complete result.

Non-Org inputs use explicit source adapters and retain their source identities.
They may be referenced by Org content; they must not masquerade as Orgize rows.
Promoting an experience into Org requires an authorized source mutation and a
new Orgize revision. Persisting a transient record does not perform that promotion.

* Context models

| Model | Owned facts and invariants |
|-------+----------------------------|
| Scope | Bundle/digest, tenant/organization/epoch, Project/WorkTree, actor/task, Session/turn profile, purpose and destination |
| Demand | Org/query selection, required evidence, Temporal obligations, complete/partial profile and rows/bytes/depth/tokens/work budgets |
| Evidence | Qualified Org references and original MRR admissions where applicable, source vector, proofs/supports, contradictions and missing obligations |
| Restriction | Readers, destinations, provenance and same-domain half-open leases; composition cannot widen inputs |
| Projection | Immutable selected/rendered content, scope/demand/evidence/restriction, profile/version, content digest, budget outcome and revision |
| Use | Trusted enrollment, exact projection/admission/contract binding, grant generation, allowed purposes and current owner observations |

The source-rooted models compose as POO values. Rendering, sorting, truncation,
summarization, and redaction are explicit projection steps with identities and
receipts. Summaries retain coverage and original Element references; they cannot
replace the original claim's evidence. Prompt ordering grants no precedence over
Authority or Context restrictions.

The existing finite restriction profile intersects readers/destinations and
leases, preserves provenance, and rejects incomparable domains. It does not yet
implement arbitrary reader/destination correlations, general labels, redaction,
or declassification. Unsupported demands fail closed. Declassification requires
a separate explicit Authority and Evidence operation.

MRR's original six-field contract is compared intact. Additional POO scope,
Org anchors, and projection bindings belong to an independently declared
envelope; the existing ABI must not be described as already checking them.

* Independent Session Module integration

** Session as an interaction lineage

A Session binds stable identity, parent/branch lineage, Project/WorkTree/task,
actor, Bundle epoch, policy, revision, status, and the exact Context revisions
used by its turns. A message array is one rendering of its history, not its
semantic owner. Session does not duplicate Org content or hold an unrestricted
mutable prompt as authoritative Context.

A Turn binds its input projection, model/provider profile, pending obligations,
tool proposals/results, judgment proposals, and completion or cancellation
receipt. The protocol distinguishes created, preparing, active, suspended,
closing, and terminal closed states; turn outcomes distinguish completed,
cancelled, failed, and blocked. These are proposed states, requiring a transition
contract before implementation. Every output retains the Context revision it
actually consumed, including stale outputs kept only for historical inspection.

** Branch, handoff, and merge

Branching retains parent and input revision, and derives a narrower explicit
scope. Handoff issues a new recipient projection after current Authority,
Context, and Evidence checks. Same bytes or a copied handle do not authorize a
different actor, Session, organization, provider, or turn.

Merging combines admitted proposals and their provenance under a named policy;
it does not concatenate prompts or select the latest branch as truth. Conflicts
remain explicit. Publication checks expected Session/turn revision and source
cut so competing completions cannot silently overwrite each other.

** Invalidation, cancellation, and recovery

Source correction, policy change, retirement, and expiry invalidate affected
turn inputs. Already disclosed information cannot be retracted from a model.
The runtime must cancel or isolate in-flight work and reject subsequent result
or action consumption using an invalid revision. Cancellation requests and
confirmed terminal worker states are separate protocol events.

Checkpoint stores immutable content/projection references, lineage, pending
obligations, and protocol state. Restart resolves content, replays admissions,
and rechecks current scope/source/policy/grant/clock before resuming. Process
handles and old allowed observations cannot restore authority. Closed Sessions
remain closed; a new interaction uses a new explicit Session lineage.

* Memory Feature redesign

Memory is the lifecycle of retained experiences and source references available
for later Context construction. A store catalog is a physical/policy projection.
Memory does not require every query, review, evidence assessment, or learning
operation to pass through one store or head.

| Axis | Meaning | Independence |
|------+---------+--------------|
| Evidence | Supported/refuted/uncertain/not assessed at a source cut | Retention and review completion cannot establish truth |
| Revisit | Scheduled/due/claimed/completed/deferred | A due timestamp does not invalidate or validate evidence |
| Retention | Untested/unstable/improving/stable under a policy | Repetition does not make a claim permanently valid |

Capture retains the original Session/turn, Org references, projection revision,
observed outcome, provenance, visibility, and retention intent. Recall is a new
Demand/query over permitted retained content with current admission checks.
Consolidation produces a new derived artifact with input lineage, uncertainty,
coverage, and policy; it cannot erase contradictions or replace original facts.

Revisit selects a claim or experience, records why a check is due, acquires
current source/evidence, and records a new assessment. Old assessments remain
historical. Short-to-long retention is a policy-bound judgment demonstrated by
recall/use/revalidation, not an irreversible truth or authority bit.

An authorized promotion may write an Org note, property, or linked assessment.
It uses explicit source mutation, expected revision, and the normal parse/query
cycle. Retention expiry, recall denial, source correction, and deletion have
distinct receipts. Deletion must account for derived artifacts and provider
retention contracts; deleting one index row does not prove content erasure.

* Current selection, use, and effects

Immutable revisions are separate from mutable current selection. Proposed
Context selection states are pending, available, dirty, superseded, and terminal
retired. Lease expiry is an observation at the effective Host coordinate.
Unknown owner state or dependency coverage blocks use.

| Boundary | Required check |
|----------+----------------|
| Admission | Source/Org/query binding, original semantic receipts, proof obligations, restriction and bounded completeness |
| Disclosure | Current scope/epoch, exact projection, source vector, policy/grant generation, purpose, reader/destination and Host lease |
| Result/action consumption | Exact input revision plus current Authority, Protocol, Context and Evidence; explicit effect intent/payload |

Dirty notifications schedule reevaluation; each use still observes current
owners. No event received is not proof of freshness. A multi-support claim
surviving correction still requires a proof at the new cut; absence dependencies
and coverage participate in invalidation. An unqualified dependency index causes
the entire affected scope to become dirty rather than silently missing edges.

Disclosure check and consumption need one declared Host/coordinator fence;
an allowed observation alone is only a point-in-time result. External providers
require their own consumption/lease contract. Durable publication uses Data's
held transaction to recheck fences, lease and expected pointer, then persist
selection/receipt/history/outbox atomically. Historical replay returns the
original transaction, never permission to execute another effect.

* Owners, implementation inventory, and direct migration

| Owner | Responsibility |
|-------+----------------|
| Orgize | Org syntax, Elements, document-local selectors and source projections |
| AI Agentic-context Module | Core Content/Context contracts and Session Module dependency and owned Memory Feature composition |
| POO Query | Canonical Query/ElementSpace/Provider/result admission |
| POO Authority/Temporal/Evidence | Grants, restrictions, proof/applicability and typed obligations within declared profiles |
| MRR | Original fact/query/receipt identity, semantic admission, materialization and typed rejection |
| MRR runtime | C transport, worker lifecycle and explicit native/Data consumer coordination |
| MRR Data | Immutable storage, conditional transactions, CAS, history/outbox and recovery |

Current code includes =modules/query/orgize-source.ss= (bounded source-headline
Query/replay), =modules/ai-agentic-context/features/memory/org-selection.ss=
(structural proposal), =modules/session/= (independent declarations/protocol
pieces), and =modules/ai-agentic-context/use-host.ss= (registered use,
retirement and policy clock). The new Context core separates boundary Types,
inert POO objects, pure functions, configuration and its public interface.

The ownership migration removed standalone Memory registrations and moved its
implementation under Context. The native Session descriptor is composed through
the existing Module closure. The next Session and Memory semantic changes follow
[[file:ai-agentic-context-session-memory-contracts.org][the explicit role and protocol contracts]]. Existing Session imports of Memory
helpers remain adapter-migration inventory; descriptor independence does not
establish full lifecycle source independence. Data stays the physical owner,
and Orgize stays the parser owner. Dependency pins require consumer qualification.

POO CI qualifies Scheme/C/Python. MRR CI qualifies original Rust/MRR/Data
consumers using the exact POO pin; POO does not gain a reverse MRR dependency.

* Cache and rejection contract

Content cache keys use exact source/content digests and parser/profile revision.
Query/projection keys additionally bind full rule, source closure, scope/epoch,
restriction, projection version and budget outcome. Applicable-state caches are
separate; no cached observation becomes a future disclosure/effect permit.

Typed rejection distinguishes source-unavailable, parse-failed, unresolved or
ambiguous Org reference, query-rejected, scope-mismatch, evidence-rejected,
incomplete, stale-source, contract/generation mismatch, purpose/flow denied,
expired, revoked, Session closed, budget exceeded, and fence conflict. These
proposed categories preserve owner errors; existing ABI four-state decisions
do not yet expose the whole taxonomy. Diagnostic detail is also subject to
visibility restrictions.

* Quint correspondence and acceptance

Scheme contracts own semantics. Quint projects bounded transitions; Lean retains
structural/algebraic/refinement obligations. Follow the [[file:44-current-project-programming-style/07-formal-assurance-correspondence.org][formal correspondence]]
three-part gate: qnt sources, pinned tool typecheck, and verification of the
catalogued invariants with Scheme v1 receipts bound to source/projection digests.
Existing Session/Worktree/Temporal/publication models do not individually qualify
the proposed combined system.

The proposed joint profile includes two Org documents/cuts, two scopes/actors/
destinations, bounded Session turns and revisions, finite grant generations and
lease coordinates. Actions include edit/reparse/query, admit/project/enroll,
branch/handoff, source/policy/clock advance, invalidate/disclose/consume, capture/
recall/revisit, retire/close, and checkpoint/recover. Terminal states are explicit;
capacity refusal preserves retired identities instead of evicting their fences.

| Invariant | Matched mutation and concrete replay |
|-----------+-------------------------------------|
| SourceBinding | Changed bytes/span/parser/rule/linked dependency cannot reuse the old admitted selection |
| ExactScope | Same text across Session/actor/tenant/epoch/provider cannot bypass consumption checks |
| NoWidening | Reader/destination/lease widening or removed provenance rejects |
| FeatureContainment | Disabling Memory cannot remove core guards; changing Feature profile cannot reuse an old projection or discard live Session obligations |
| NoStaleUse | Source/policy/generation/clock change between check and use fences or refuses consumption |
| TerminalLifecycle | Closed Session or retired grant cannot resurrect, including ABA and alias bypass |
| EvidenceRetentionSeparation | Revisit completed or retention stable cannot establish current truth |
| BoundedCompleteness | Truncation, unresolved closure or capacity failure cannot publish complete Context |
| SafeRecovery | Old handles, repeated outbox or historical ACK cannot restore permission or duplicate effect |

Each disabled guard must yield its matched counterexample, replayed against
native Library and original MRR/Data consumers with exact transition order and
source/scope/generation/clock/payload bindings. Finite checking, concrete trace
acceptance, and refinement are distinct evidence.

* Delivery order

The [[file:ai-agentic-context-implementation-plan.org][implementation plan]] maps these contracts to current code owners,
direct migration slices, and focused executable gates.

1. Review this system boundary and Content/Context/Session/Memory contracts,
   including Module/Feature manifests, Org examples, projection laws, partial
   outcomes and cross-turn scope.
2. Implement native POO values and pure functions around the Orgize/POO Query
   route; qualify source/query/revision correspondence before reusing selections.
3. Compose the independent Session Module and migrate Memory as an owned Feature of =ai-agentic-context=;
   qualify each Feature profile, core-only use, Session capture dependencies,
   lineage, evidence/revisit/retention independence, and typed recovery.
4. Check the combined Quint profile, guard mutations, and concrete native traces.
5. Close disclosure and result/effect fences with original MRR/Data consumers;
   qualify checkpoint/restart and source/grant races before real Agent claims.

Acceptance scenario: an Org task references two independent supports. One edit
removes a support and produces a new valid projection; the final removal makes
the claim unavailable/uncertain. A Session already using the old projection
cannot commit an action. Recall and revisit retain the original history while
checking the new source cut. Repeat with a broken Org link, changed query rule,
cross-Session handoff, policy retirement, lease expiry, and restart.

Report design acceptance, implemented Library profile, bounded model checking,
native correspondence, and exact-head consumer CI separately. The full system
is not complete until its declared consumption and recovery boundaries qualify.

projections, task DAG/claim/join semantics and bounded incremental scheduling.
Session owns scheduling semantics; Context owns Org binding and projection
admission. The scheduling runtime and new property-ID source profile are
proposed implementation slices, not covered by existing headline replay tests.

[[file:context-temporal-lifecycle-policy-system-design.org][The POO Flow joint policy system design]] defines orthogonal lifecycle states,

policy and separates its local qualification from the prospective joint protocol
