#+title: External Evidence Obligation and Certificate
#+startup: overview

* Status

Proposal.

This RFC defines how external enterprise-AI reports become research inputs for the
POO Flow proof layer.  It does not claim that an issue, blog post, benchmark, or
vendor control proves a POO Flow property.

AXLE final-source validation has been executed against the existing enterprise
proof family through the uv-managed Python harness.  The current result is
=7/14= independent leaf modules verified, so the family remains open.  See
[[file:45-134-enterprise-axle-final-source-validation-receipt.org][45-134]].

* Decision

External evidence is admitted through the existing =Reference Evidence Boundary=:

- an external observation may create one or more =candidate obligations=;
- an adopted candidate becomes an =open obligation= owned by an independent Lean
  module and an executable validation surface;
- an external source never closes its own obligation;
- closure requires POO-owned proof evidence or an =explicit certificate=;
- incomplete provenance, ambiguous scope, stale identity, or missing executable
  evidence must =fail closed=.

This RFC refines the scenario ownership in
[[file:45-128-real-world-ai-assurance-scenarios-and-adapter-governance.org][45-128]]
and the enterprise proof-family ownership in
[[file:45-129-enterprise-assurance-proof-module-family.org][45-129]].  It does not
take ownership from Cedar semantics, runtime adapters, or
[[file:45-130-enterprise-tenant-organization-isolation-proof-family.org][45-130]]
tenant/organization isolation.

* Evidence is not proof authority

An issue body is a report by its author.  A vendor blog is a statement by its
publisher.  A release note describes a product change.  A standards paper
describes a problem space.  Their claims must retain those source kinds and must
not be silently rewritten as verified incidents or POO Flow guarantees.

#+begin_src typst
$ "External"(e) => not "ProofAuthority"(e) $

$ "Adopt"(e, o) =>
  "SourceVerified"(e)
  and "CandidateObligation"(o)
  and "Traceable"(e, o) $

$ "Adopt"(e, o) and not "ExplicitCertificate"(o) => "Open"(o) $

$ "Close"(o, c) <=>
  "LeanChecks"(c, o)
  and "AxleFinalSourceChecks"(c, o)
  and "ExecutableReceipt"(c, o)
  and "StableOwner"(c, o)
  and "FreshScope"(c, o) $

$ not "Complete"(c) => "State"(o) = "open" $
#+end_src

The AXLE conjunct is intentional.  A local Lean build and AXLE validation are
separate evidence fields; neither may be reported as the other.

* Adoption state machine

#+begin_src mermaid
stateDiagram-v2
    [*] --> Discovered: URL and observation recorded
    Discovered --> SourceVerified: publisher, date, status, and scope checked
    Discovered --> Rejected: inaccessible, duplicate, promotional, or unverifiable
    SourceVerified --> Candidate: counterexample and affected boundary extracted
    Candidate --> Open: Lean owner and executable witness assigned
    Candidate --> Rejected: no POO Flow obligation follows
    Open --> Open: proof or runtime evidence incomplete
    Open --> Discharged: Lean plus AXLE plus receipt plus owner certificate
    Open --> Stale: source, artifact, identity, or scope changed
    Stale --> SourceVerified: evidence requalified
    Discharged --> Stale: certificate inputs no longer match
    Rejected --> [*]: rejection certificate retained
    Discharged --> [*]: explicit certificate retained
#+end_src

The labelled transitions are part of the RFC.  “Closed on GitHub” is not a
transition to =Discharged=.  It is only source metadata.

* Canonical evidence record

Every adopted item must carry:

| Field | Meaning |
|-------+---------|
| =evidence-id= | Stable local identity, independent of source title |
| =observed-at= | Publication or issue-open date |
| =source-kind= | Issue, release, research, standard, or incident record |
| =source-status= | Open, closed, preview, GA, draft, withdrawn, or superseded |
| =source-url= | Canonical primary URL |
| =publisher= | Repository owner, standards body, or research team |
| =reported-claim= | Narrow statement actually supported by the source |
| =confidence-boundary= | What has not been independently reproduced |
| =counterexample= | POO Flow property that could be falsified |
| =lean-owner= | Independent proof module responsible for the obligation |
| =runtime-witness= | Executable adversarial or conformance scenario |
| =certificate-owner= | Component allowed to discharge or reject the obligation |
| =state= | Candidate, open, discharged, rejected, or stale |

* Proof-family routing

| Problem family | Stable proof owner |
|----------------+--------------------|
| Agent identity, delegation, responsibility, and audit | Enterprise identity and accountability modules |
| Tenant and organization separation | Existing tenant/organization isolation proof family |
| Tool discovery, capability issuance, and execution | Tool-admission and capability modules |
| Memory provenance, persistence, retrieval, and erasure | Memory-lifecycle modules |
| Artifact, dependency, and runtime identity | Supply-chain evidence modules |
| Individually allowed actions composing into an unsafe workflow | Sequence-policy modules |
| Cedar decision correspondence | Existing Cedar adapter and dual-engine proof family |
