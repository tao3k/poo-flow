* Decision

RFC 45-120-45 establishes one canonical v1 responsibility relation for every
source-bound effect that has not reached =committed=.

Authorization and responsibility are different facts:

1. Cedar admission proves that an authority path may perform the effect.
2. A human authority grant and bound receipt prove that a principal owns the
   required capability for the canonical authorization subject.
3. A responsibility assignment proves who is accountable for the exact effect,
   which scope that accountability covers, which authority receipt supports it,
   and at which recovery epoch it is effective.
4. The audit commitment, Cedar evidence, authority evidence, and responsibility
   assignment must all identify the same operation.

The system admits no second responsibility predicate. Nonempty identity strings
are metadata, not assignment evidence. A responsibility assignment that fails
the canonical relation is rejected.

* Reused owners

This RFC adds a binding owner. It does not replace any existing owner.

| Existing owner | Reused fact |
|-
| RFC 45-120-42 | exact audit commitment and authenticity evidence |
| RFC 45-120-43 | complete Cedar response, credential, policy, and runtime freshness |
| RFC 45-120-44 | canonical authorization subject and independent decision receipts |
| =HumanAuthorityAccountability= | authority grant, bound authority receipt, capability, subject, and receipt validity |
| =ResponsibilityTransfer= | safe previous-principal to successor-principal handoff |
| =Enterprise.Assurance= | responsibility/accountability is mandatory for enterprise assurance |

The new owner is
=SourceBoundEffectCompletionRecoveryEnterpriseResponsibilityAssignment=.
It describes current responsibility. The existing =ResponsibilityTransfer=
continues to own changes in responsibility.

* Lean-found architecture gaps

** Nonempty responsibility fields do not determine an assignment

The existing commitment-authenticity predicate and Cedar admission predicate
require =accountabilityIdentity= and =responsibilityScopeDigest= to be nonempty.
They do not identify a responsibility-assignment object.

The independent model constructs two valid detached evidence values with the
same commitment and authority but different accountable principals and scopes.

#+begin_src typst
$ W(e) :=
  e.c != emptyset
  and e.h != emptyset
  and e.a != emptyset
  and e.rho != emptyset $

$ exists e_1, e_2:
  W(e_1)
  and W(e_2)
  and e_1.c = e_2.c
  and e_1.h = e_2.h
  and e_1.a != e_2.a
  and e_1.rho != e_2.rho $
#+end_src

Therefore presence cannot prove ownership, scope, acceptance, subject binding,
or effective epoch.

** Authorization does not determine accountability

An authority grant answers “who may approve this subject.” It does not answer
“who is accountable for the resulting effect.” Those principals must be
explicit and distinct.

#+begin_src typst
$ h_"authority" != a_"accountable" $
#+end_src

The canonical assignment rejects self-accountability. This is a concrete
enterprise separation-of-duty requirement, not an abstract callback result.

** An authority receipt does not bind an audit commitment by itself

=BoundAuthorityReceipt= binds principal, capability, subject, grant, acceptance,
and receipt identity. It has no audit-commitment field. The new assignment
therefore carries both the authority receipt identity and the exact commitment.

#+begin_src typst
$ A.r = R.id
  and A.c = C.c $
#+end_src

The binding closure additionally proves that the Cedar evidence and
authenticity evidence identify that same commitment.

** Subject equality without epoch equality is stale

A responsibility assignment is valid only for the recovery epoch of the
canonical authorization subject.

#+begin_src typst
$ A.s = S
  and A.epsilon = S.epsilon
  and S.epsilon = epsilon_"recovery" $
#+end_src

This prevents a previously accepted assignment from being replayed after the
recovery epoch changes.

** Current responsibility and responsibility transfer are distinct

Every active effect requires a current responsibility assignment. A
=ResponsibilityTransfer.Transfer= is required only when the accountable
principal changes.

#+begin_src typst
$ C_"current"(i) := V_"assignment"(A_i) $

$ H_"handoff"(i, i + 1) :=
  A_i.a != A_(i + 1).a $
#+end_src

When =Handoff= holds, the existing transfer owner must establish exact contract
authority, successor acceptance, a current effective observation, no
responsibility gap, and no overlapping exclusive authority. Stable assignment
does not manufacture a transfer event.

* Canonical assignment predicate

Let =A= be a responsibility assignment, =c= the exact audit commitment, =S= the
canonical authorization subject, =R= the bound authority receipt, and =V_A= the
assignment owner's validation relation.

#+begin_src typst
$ V_"assignment"(A, c, S, R) :=
  A.i != emptyset
  and A.c = c
  and A.h != emptyset
  and A.a != emptyset
  and A.a != A.h
  and A.rho != emptyset
  and A.s = S
  and A.r = R.id
  and A.epsilon = S.epsilon
  and A.xi != emptyset
  and A.q_"accepted"
  and V_A(A) $
#+end_src

=V_A= remains owner supplied because signature validation, persistence,
revocation, and organization-specific assignment issuance are external facts.
The binding closure never invents them.

* Canonical cross-owner binding

For lifecycle evidence =L=, authenticity evidence =T=, grant =G=, authority
receipt =R=, subject =S=, and responsibility assignment =A=:

#+begin_src typst
$ B_"bound"(L, T, G, R, S, A) :=
  V_"assignment"(A, T.c, S, R)
  and L.c = T.c = A.c
  and L.h = T.h = G.p = R.p = A.h
  and L.a = T.a = A.a
  and L.rho = T.rho = A.rho
  and G.s = R.s = A.s = S
  and A.epsilon = S.epsilon $
#+end_src

The actual Lean structure also embeds:

- the RFC 45-120-44 =CedarAuthorizationSubjectBound= proof;
- the existing =SourceBoundEffectCompletionRecoveryAuthorizedOwnerAssertion=;
- complete authority-receipt validity and capability approval;
- freshness checks for the exact recovery epoch;
- the current dual-decision identity relation.

* Recovery-trace closure

For each non-committed trace position =i=, the commitment selects every registry
entry used by the responsibility proof.

#+begin_src typst
$ forall i,
  T(i) != q_"committed"
  => B_"bound"(
      C(E(i).c),
      A(i),
      G(E(i).c),
      R(E(i).c),
      S(E(i).c),
      Q(E(i).c),
    ) $
#+end_src

No caller may select an unrelated assignment by position or by an unbound
identity. The commitment is the lookup key and is also re-proven inside the
assignment.

* Responsibility handoff boundary

The current closure proves a valid assignment at every active position. It does
not yet prove that two adjacent assignments with different accountable
principals are connected by an admitted =ResponsibilityTransfer.Transfer=.

That missing adjacent handoff relation is the next proof obligation:

#+begin_src typst
$ A_i.a != A_(i + 1).a
  => exists tau_i:
    T_"admitted"(tau_i)
    and tau_i.p = A_i.a
    and tau_i.s = A_(i + 1).a
    and tau_i.rho = A_i.rho = A_(i + 1).rho $
#+end_src

This is deliberately recorded as an open obligation. The present RFC must not
claim transfer continuity from two independently valid assignments.
