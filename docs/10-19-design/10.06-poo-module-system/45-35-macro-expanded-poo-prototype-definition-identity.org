#+title: Macro-Expanded POO Prototype Definition Identity
#+status: Accepted
#+language: en

* Decision

Cross-process and cross-generation reuse MUST identify the expanded native POO
definition, not merely the source file that contains it.

Prototype-definition identity is a structured, phase-aware and hygienic Merkle
identity.  It distinguishes:

- source and module input;
- macro-expansion execution;
- canonical expanded POO semantics;
- compiled artifacts;
- individual slot-result reuse.

The identity model is conservative:

#+begin_quote
Equivalent definitions may be recomputed when equivalence cannot be proved.
Different definitions must never be reused as if they were identical.
#+end_quote

* Gerbil macro basis

Gerbil provides a full meta-syntactic tower, hygienic macros through
=syntax-case= and =quote-syntax=, procedural transformers through =defsyntax=,
and explicit phase shifts through =begin-syntax=.

Consequently, the meaning of a POO definition may depend on:

- the surface syntax at the macro use site;
- the hygienic binding context;
- imported transformer bindings at =phi=+1=;
- support code at higher phases;
- compile-time inputs observed by procedural macros;
- runtime bindings referenced by the expanded form;
- native =gerbil-poo= operator semantics.

Two identical source fragments can therefore expand differently.  Two
different source fragments can also expand to the same canonical POO
definition.

* Identity layers

#+begin_src mermaid
flowchart LR
  S["Surface module and syntax"] -->|"forms the input to macro execution"| E["Expansion execution identity"]
  M["Phase-indexed transformer closure"] -->|"decides whether expansion must rerun"| E
  E -->|"produces hygienic syntax with resolved bindings"| P["Canonical expanded POO identity"]
  P -->|"splits prototype shape, supers and slots"| D["Structured definition identities"]
  D -->|"combines with compiler target and ABI"| C["Compiled artifact identity"]
  D -->|"combines with current semantic inputs"| R["Slot-result reuse identity"]
#+end_src

| Identity layer | Purpose |
|----------------+---------|
| Surface input identity | Identify module syntax and declared imports used as expansion input |
| Expansion execution identity | Decide whether macro expansion must be executed again |
| Expanded POO semantic identity | Identify the canonical native prototype and slot definitions produced by expansion |
| Compiled artifact identity | Decide whether a compiled artifact may be loaded in the current runtime and target |
| Slot-result identity | Decide whether one observed slot result may be reused under current contributions and dependencies |

No layer may be replaced by a single whole-source-file hash.

* Expansion execution identity

Expansion execution identity commits to:

- surface syntax input after removal of non-semantic formatting;
- macro-use hygienic context;
- the transitive transformer definitions used during expansion;
- phase-indexed imports at =phi=+1= and higher;
- =begin-syntax= support definitions;
- captured compile-time inputs;
- the relevant Gerbil expander identity;
- expansion policy and declared hermeticity evidence.

A change to this identity means expansion must rerun.  It does not by itself
prove that the final expanded POO semantics changed.

* Expanded POO semantic identity

Expanded POO semantic identity commits to:

- canonical expanded native POO forms;
- the hygienic binding graph;
- runtime binding identities;
- prototype supers and native precedence;
- individual slot-definition identities;
- nested POO definition identities;
- slot-contract attachments;
- native =gerbil-poo= operation identities.

If a transformer implementation changes but fresh expansion produces the same
canonical result and resolved binding graph, the expansion execution identity
changes while the expanded POO semantic identity may remain stable.

#+begin_src mermaid
flowchart TD
  O["Original transformer closure"] -->|"expands the macro use"| A["Canonical POO definition A"]
  N["Refactored transformer closure"] -->|"forces a fresh expansion"| B["Canonical POO definition B"]
  A -->|"same binding graph and native POO structure"| I["Stable semantic definition identity"]
  B -->|"same binding graph and native POO structure"| I
  O -->|"different transformer content invalidates expansion execution cache"| X["Distinct expansion execution identity"]
  N -->|"different transformer content invalidates expansion execution cache"| X
#+end_src

This permits safe reuse after a macro implementation refactor without skipping
the required re-expansion.

* Hygienic canonicalization

Canonical expanded identity MUST preserve binding meaning rather than printed
identifier spelling.

The canonicalizer:

- alpha-normalizes local and generated bindings;
- preserves which binding every identifier resolves to;
- preserves the binding's defining module and phase;
- preserves ordered prototype and slot operations;
- preserves literal data and operator identity;
- removes non-semantic formatting and comments;
- excludes ordinary source locations from semantic identity;
- retains source locations in diagnostic evidence.

Two printed identifiers with the same name but different resolved bindings are
different.  Two hygienic local bindings that differ only by generated name may
be equivalent.

Process-local syntax-object addresses, uninterned symbol printing and gensym
names MUST NOT be cross-process semantic identities.

* Structured prototype Merkle identity

A prototype root is a structured commitment, not the invalidation unit for
every slot result.

#+begin_src mermaid
flowchart TD
  P["Prototype root identity"] -->|"commits declared supers and precedence"| S["Supers identity"]
  P -->|"commits canonical slot-key structure"| K["Prototype shape identity"]
  P -->|"commits one independent definition leaf"| A["Slot A definition identity"]
  P -->|"commits one independent definition leaf"| B["Slot B definition identity"]
  A -->|"invalidates only actual reverse-demand consumers"| DA["Slot A dependency closure"]
  B -->|"does not invalidate unrelated Slot A work"| DB["Slot B dependency closure"]
  K -->|"invalidates structural reflection"| R["Shape observers"]
#+end_src

The prototype commitment contains:

- ordered supers and native precedence;
- canonical slot-key structure;
- one identity leaf per slot definition;
- nested prototype-definition identities;
- prototype-wide contract or authority declarations;
- structural reflection identity.

Changing one slot body does not automatically invalidate unrelated slot
results.  A consumer depends on the smallest semantic identity actually
observed.

* Slot-definition identity

An individual slot-definition identity includes:

- canonical expanded slot computation;
- resolved runtime bindings referenced by the computation;
- the relevant prototype lookup lineage;
- the native POO operation identities used;
- attached POO contract identities;
- nested slot-definition identities actually embedded;
- declared purity and cacheability boundary.

The reusable slot-result identity is then:

#+begin_example
canonical slot-definition identity
+ relevant prototype lookup lineage
+ current contribution closure
+ current slot-contract closure
+ current dependency footprint
+ current capability and authority requirements
#+end_example

This identity complements, rather than replaces, the current-generation
invalidation and reuse rules.

* Reflection-dependent invalidation width

Native POO reflection determines how much prototype structure a demand
observes.

| Native observation | Required definition dependency |
|--------------------+--------------------------------|
| Demand of one known slot through =.ref=, =.@= or equivalent native access | That slot's lookup lineage and definition identity |
| =.has?= or =.key?= for one key | Existence identity for that key |
| =.all-slots= | Complete prototype-shape identity |
| =.mix= or inherited lookup | Ordered supers and relevant native precedence |
| Nested object access | Every traversed nested identity and final slot definition |
| Structural diagnostic projection | The explicitly projected structural identity, not semantic success |

Reflection does not automatically make every slot result depend on the whole
prototype.  The observed operation defines the dependency width.

* Invalidation rules

| Change | Required invalidation |
|--------+-----------------------|
| Comment, formatting or ordinary source location | Diagnostic identity only |
| Hygienic local alpha rename | No semantic invalidation |
| Macro transformer body or phase import | Expansion execution identity |
| Transformer change with identical canonical expansion | No expanded POO semantic invalidation after re-expansion proves equality |
| Expanded slot computation changes | That slot and its reverse demand closure |
| Slot is added or removed | Prototype shape and relevant structural observers |
| Slot existence changes | Corresponding =.has?= and =.key?= observers |
| Supers or native precedence changes | Every affected lookup lineage |
| Referenced runtime binding changes | Slot definitions that resolve to that binding |
| Nested prototype changes | Consumers of the changed nested identity path |
| Relevant native =gerbil-poo= operation semantics change | Definitions using that operation |
| Compiler code generation or target ABI changes | Compiled artifact identity |

The implementation MAY conservatively invalidate a wider closure when a
narrower proof is unavailable.  It MUST NOT reuse a narrower closure without
evidence.

* Procedural macro dependency classes

Gerbil procedural macros are full Scheme programs.  Expansion may observe
inputs outside ordinary module imports.

#+begin_src mermaid
flowchart TD
  M["Procedural macro expansion"] -->|"all compile-time dependencies are identified"| H["Hermetic expansion"]
  M -->|"external inputs are captured with canonical identities"| C["Captured expansion"]
  M -->|"reads untracked dynamic or ambient state"| O["Opaque expansion"]
  H -->|"supports cross-process definition identity"| R["Reusable expanded definition"]
  C -->|"supports reuse only while captured inputs match"| R
  O -->|"macro remains valid but reuse fails closed"| N["Fresh expansion and current-process evaluation"]
#+end_src

** Hermetic expansion

All transformer definitions, phase imports and compile-time inputs are part of
the expansion execution closure.

** Captured expansion

External compile-time inputs are permitted when their values and provenance are
canonically captured.  Reuse requires the current inputs to match.

** Opaque expansion

If compile-time dependencies cannot be completely identified, the macro
remains usable.  Its result is not authorized for cross-process definition
reuse.

This classification preserves Gerbil's macro power while making reuse
fail-closed.

* Toolchain and semantic substrate identities

Toolchain identity is layered rather than indiscriminately mixed into POO
semantics.

- Gerbil expander changes invalidate expansion execution artifacts.
- A fresh expansion that canonicalizes identically may preserve expanded POO
  semantic identity.
- Compiler, backend, target and ABI changes invalidate compiled artifacts.
- Native =gerbil-poo= operation semantic changes invalidate definitions using
  those operations.
- Platform-dependent runtime behavior makes the affected result non-portable
  unless the platform identity is an explicit semantic input.

The canonical Gerbil package dependency for the POO substrate is:

#+begin_example
github.com/mighty-gerbils/gerbil-poo@1c3225637525400341a09e958296962c10184ead
#+end_example

The fixed dependency identity is an input to the substrate closure.  It does
not make package management responsible for POO semantic evidence.

* gerbil.pkg boundary

=gerbil.pkg= remains Gerbil's package-management mechanism.  It resolves and
installs package dependencies.

POO Flow MAY use the resolved fixed package identity as one input to a
definition closure.  It MUST NOT ask =gerbil.pkg= to provide:

- prototype-definition identity;
- slot-result identity;
- cache receipts;
- macro-expansion evidence;
- replay equivalence;
- capability or authority proof.

Package resolution and semantic identity remain separate responsibilities.

* Definition receipt

A prototype-definition receipt SHOULD commit to:

- surface module identity;
- expansion execution identity;
- phase-indexed transformer closure;
- compile-time dependency classification;
- canonical expanded POO semantic identity;
- prototype shape and ordered supers;
- individual slot-definition identities;
- runtime binding closure;
- native POO substrate identity;
- compiled artifact identities where produced;
- diagnostic source-location projection;
- predecessor receipt and invalidation relation.

The receipt is a POO evidence object, not a raw compiler depfile or package
manifest.

* Required failure conditions

Cross-process reuse MUST fail closed when:

- phase-indexed transformer dependencies are incomplete;
- hygiene is reduced to printed identifier names;
- generated binding addresses or gensym printing enter semantic identity;
- an opaque procedural macro is treated as hermetic;
- a changed expansion is hidden by an unchanged source hash;
- a runtime binding changes without invalidating consumers;
- a prototype-wide hash unnecessarily becomes the only slot invalidation key;
- =.all-slots= reuse omits prototype-shape identity;
- ordered supers or =.mix= precedence is canonicalized as an unordered set;
- compiled artifacts are reused across incompatible target or ABI identity;
- a package pin is presented as complete semantic proof.

* Acceptance checklist

- [X] Definition identity is based on expanded native POO semantics rather than
  whole-source hashes.
- [X] Expansion execution identity and expanded POO semantic identity are
  distinct.
- [X] Transformer refactoring forces re-expansion but may preserve semantic
  identity when canonical output is equal.
- [X] Hygienic binding graphs are preserved across alpha-normalization.
- [X] Source locations belong to diagnostics rather than semantic identity.
- [X] Prototype roots contain independently addressable slot-definition
  identities.
- [X] Reflection operations determine dependency width.
- [X] Procedural macros are classified as hermetic, captured or opaque for
  reuse.
- [X] Toolchain, compiled artifact and POO semantic identities remain layered.
- [X] Native =gerbil-poo= operation identity participates in affected
  definitions.
- [X] =gerbil.pkg= remains package management rather than semantic evidence.
- [ ] Validate the model with executable phase-import, transformer-refactor,
  hygienic-alpha-rename, runtime-binding, slot-local-change, shape-reflection,
  opaque-macro, substrate-change and target-ABI scenarios before
  implementation begins.
