#+title: 10.06.167 Revisiting Evidence Across Time

* Status and decision

Design draft for POO Flow PR #34. It does not claim a running review scheduler,
source authenticator, verified Memory head, or durable learning engine.
[[file:43-session-memory-recovery-rfc.org][RFC 43]] and [[file:166-session-memory-orgize-boundary.org][166]] describe the earlier store-centered Memory design. Their
Session recovery and source-bound selection work remains relevant, but their
assumption that a Memory head is the principal unit of knowledge is under
reconsideration here.

The design unit is a *revisit of a claim or experience at a later time*. The
question is what should be checked again, why, against which current source
and evidence, and what that check changes. Stored text is an input, not the
outcome. This keeps the full temporal-causality, Session, and Orgize
capabilities available instead of making every case fit a Memory store.

Orgize's =languages/org/v1/modules= collection is the source capability home:
agenda/planning, notes/ID/links/attachments, LOGBOOK, and review facts share
one Org source identity. Emacs packages such as =org-super-agenda= show how to
compose a view over already selected agenda entries; the wider Org notes
ecosystem shows capture, association, and revisit as cooperating operations.
POO Flow should consume these source-grounded capabilities for policy, not
require each one to become a Memory head. The proposed Orgize module map is
=languages/org/v1/modules/README.org= on the Orgize design branch.

The design should be judged by observable outcomes: whether a regression
still passes on a stated cut, whether a person can retrieve and use an idea,
how often a stale claim reaches a decision, and how much needless review work
is created. The short-to-long trajectory is valuable precisely because it
requires observed recall, use, revision, and linked provenance. It is not a
storage-class change or automatic promotion. Retention and factual validity
require different evidence.

Three states must remain independent:

| Axis | Question | Example value |
|------+----------+---------------|
| Evidence | Does current evidence support this claim at this source cut? | supported, refuted, uncertain, not assessed |
| Revisit | Is another check due or already being performed? | scheduled, due, claimed, completed, deferred |
| Retention | Can the intended reader reliably recall or apply it later? | untested, unstable, improving, stable under a stated policy |

=DONE=, =CLOSED=, an old test pass, a due timestamp, and a repeated reading are
different observations. None implies the other. "Long-term knowledge" is a
policy-bound judgment about stable recall or repeatedly revalidated evidence;
it is never an irreversible truth bit.

* Current seams and ownership

Orgize PR #21 has Scheme-owned Element queries and
=memory-headline-state=, while its wider =AgentMemorySnapshot= authority
classification is still partly in Rust. The proposed Orgize document
=docs/10_architecture/10.08_temporal_revisit_projection.org= makes the
document-local temporal projection Scheme-owned and requires parity before
generated Rust execution can replace independent Rust classification. The
current POO Flow =modules/memory-core/org-selection.ss= calls an Orgize
Scheme selector on a supplied graph; it cannot attest that the graph came
from the declared current bytes. This selector is document-local, whereas
=modules/query= owns POO Flow's canonical Query and ElementSpace contracts.

The Orgize event fold yields Scheme-owned parse events, then its generated
Rust/Rowan path projects the Elements graph. The Scheme graph-query view
accepts caller-provided records and accessors; its structural checks do not
bind those records to the event stream or exact bytes. A prototype Orgize
=OrgAotDocument::query_named_source_observation= binds a maintained AOT
query result to one parser-owned document, including source digest, parse
configuration, full query rule, scope, IDs and spans. At Orgize PR #21 head
=1fd3c44972902545e13e80568f397789c717c785=, the observation also
retains the base parse configuration and can reparse current bytes and rerun
the Scheme-AOT named query. A changed rule body with the same ID is refused
even when it happens to select the same records. The [[https://github.com/tao3k/orgize/actions/runs/37254770472][exact-head CI]] records
the focused test and cross-platform gates. This in-process recheck does not
authenticate a file, WorkTree cut or grant, or connect to POO Flow's separate
Scheme graph view. The proposed
bridge must project parser-owned Elements into POO Flow's ElementSpace and
bind qualified Query rows to the same source before Session or temporal use;
comparing a caller-supplied graph with a caller-supplied digest is insufficient.

The optional POO Flow Rust runtime =orgize-source= feature now starts that
host-side bridge. It reads a bounded UTF-8 file under a host-supplied WorkTree
root, runs the maintained Orgize named query, and holds the parser-owned
observation privately. A later use must recheck the declared key, resolved
root and file, current bytes, parse configuration, and query rule. The key's
WorkTree identity and cut are still host premises; this adapter cannot prove
Git state, grants, stable filesystem access under concurrent path mutation, or
Session policy. It remains a read-side observation and cannot publish a
Memory/Session head.

The Scheme =modules/query/orgize-source.ss= adapter takes supplied Org text,
asks Orgize's =org-elements/source-interface.ss= for a bounded source-derived
headline projection, builds a canonical POO Flow ElementSpace and GQL-aligned
POO Query, then runs one supported query for open TODO headlines. Canonical
scalar result rows carry source SHA-256, byte span, title, and TODO state.
Replay reparses current supplied text and reruns the fixed Query, rejecting a
changed source, predicate, or row even when a forged row has a valid internal
digest. It does not read a WorkTree itself or establish host source-cut/grant
identity, Session admission, temporal evidence qualification, Impact, or
publication. Those handoffs remain separate work.

POO Flow already has temporal instants/axes, evidence retrieval/use/assessment,
impact frontiers, and pure Session/Memory policy receipts. Reuse those owners:

| Owner | Decision |
|-------+----------|
| Orgize Scheme | Preserve source-local Org identity, spans, planning/repeater and LOGBOOK events; project document-local candidates with reasons |
| POO Flow Query | Admit the canonical Query over an explicit ElementSpace; bind Provider and bounded result contracts to source-backed rows |
| POO Flow temporal-causality | Evaluate evidence against current cuts, valid time, changes, contradiction and affected claims |
| POO Flow Session and policy | Scope, grants, explicit C4 policy order, attempt budget, when to request a revisit and which actor may do it |
| MRR Query/Content/Context | Admit derived semantic claims when a revisit uses relational inference; direct test receipts do not need a fabricated MRR derivation |
| Wendao or a caller's index | Search and rank across documents; preserve Orgize anchors in results |
| runtime and MRR Data | Execute scheduled checks, retain immutable artifacts, conditionally publish the accepted head and reconcile effects |

Neither Org heading nesting nor Git ancestry defines C4 policy inheritance.
Matching heading titles also do not prove that one historical claim supersedes
another; they only nominate a comparison to assess with source evidence.
Project -> WorkTree -> Task -> Session is containment; a request selects a
finite explicit policy graph. A WorkTree may share a current review history
among its Tasks and Sessions, while cross-WorkTree reuse requires publication,
target authorization, source-cut validation, and an independent target head.

* Proposed pure contract

A revisit target is an Orgize source anchor or an explicitly named claim:
document identity, exact bytes digest, Element ID and span, source cut, and
purpose. A bare heading title or Element ID is insufficient. The purpose is
one of =verify= (e.g. rerun a regression), =recall= (e.g. answer from a diary
without looking), or =reflect= (e.g. compare an old interpretation with new
evidence). Policies may extend this finite vocabulary after defining an
observable outcome.

One revisit intent binds target, purpose, scope, trigger, due condition,
required evidence, current capability, expected head revision, attempt ID,
budget, and policy revision. Triggers may be elapsed time, a new source cut,
dependency change, contradictory evidence, or an imminent use of the claim.
Time merely makes the check eligible; it does not attest the outcome.
An Orgize named selector can nominate Elements within the document; a POO Flow
Query result determines which source-backed candidates a downstream consumer
may use. The result must retain the document cut and anchor. Query admission
and receipt metadata alone do not authenticate execution or result rows.

One attempt records the selected current source cut, actor, start/end time,
method and actual outcome. Its assessment cites the evidence used, the
assessor, the claim validity interval or source cut, and a verdict
(supported/refuted/uncertain). A human recall attempt may instead record
whether the person could reconstruct or apply the idea; that result updates a
retention policy, not the truth of the diary's factual claims. Failed and
uncertain attempts remain visible. Repeating an attempt with the same
idempotency key cannot manufacture a second success.

The next due decision is a pure function of policy, last admitted attempts,
source/evidence changes, and an explicit evaluation time. The runtime may
schedule it, but cannot make the assessment true by scheduling it. Publication
requires current grant/source checks and expected-head CAS. A lost CAS must
re-evaluate current inputs, not replay a stale assessment as current.

Track at least source event time, source admission/knowledge time, attempted
review time, claim valid interval, and next due time separately. Existing
temporal axes cover event/ingress/processing instants; a due time is a policy
target rather than proof of valid time or causality. No one timestamp may be
used as a substitute for all of these.

* From a short observation to a durable insight

For a fleeting idea, capture an Org note with source context and time. A
Session later queries Orgize Elements at an explicit cut for that note, its
linked observations, and recorded review events. It creates a bounded revisit
attempt; the resulting recall, application, or contradiction changes the
assessment and next review decision. A new Org claim or procedure links back
to the original episodes. This is how a compact agent memory summary could be
derived from Org evidence. A literal Markdown =MEMORY.md= requires an explicit
source-preserving import or separate adapter before Orgize Element queries can
address it.

The current Orgize query DSL provides bounded document-local predicates and
lineage, without cross-document joins, temporal ordering, or aggregation.
Therefore the multi-note chain and short-to-long assessment are proposed, not
an implemented single-query operation.

Consolidation creates a *new versioned claim or usable procedure* with links
to the episodes that motivated it, the scope where it applies, its supporting
and contrary evidence, and a way to check it again. It is not a Boolean
upgrade on an old note. Repeated retrieval can increase confidence that a
person can recall a diary insight; independent successful use and explicit
assessment can support a broader practical lesson. Neither justifies
claiming universal truth. MRR admits a derived relational claim when that
form of inference is used; POO Flow retains the temporal and source authority
for its future use.

For a fixed bug, the durable product could be a regression test, a scoped
failure rule, and a note explaining the root cause, all linked to the original
failure and later passing runs. For a diary, it could be a revised insight
linked to the entries and reviews that changed the person's understanding.
Both can be reopened when a new counterexample appears. Keep the old episodes
available so a later agent can inspect why the abstraction was formed.

* Acceptance cases

** Was the bug fixed?

An Org heading says =DONE= and links a passing regression from WorkTree A at
cut C1. At C1, the assessment may say "supported by test T on C1". A source,
dependency, or relevant policy change to C2 makes that old assessment
historical for C2 and schedules a new check. If T fails at C2, preserve both
receipts and mark the current C2 claim refuted or uncertain. The heading does
not silently revert to =TODO=, and an old =DONE= does not suppress the new
finding. A reviewer can tell exactly which cut was tested.

** Did the diary become usable knowledge?

A diary entry has a stable Org ID, a review schedule, and timestamped review
notes. On each due date the human or agent attempts retrieval before reading
the entry, records the outcome, then may reflect and revise the note. One
re-read is exposure only. Success across spaced reviews can justify a longer
next interval or a scoped "stable for this learner and use" judgment; it
does not establish that every assertion in the diary is true. A contradiction
or failed later recall may shorten the interval or reopen review.

** Did fleeting ideas become a reusable insight?

Several timestamped Org notes are captured during a Task. A later Session
queries their Element anchors and linked evidence at the current source cut,
groups the candidates, and writes a new insight only after a review can state
its scope, supporting episodes, contrary examples, and a way to test its use.
The original notes remain individually addressable. A repeated search hit or
one elegant summary is not a successful consolidation receipt. Later failed
application reopens the insight without erasing the episodes.

** Cross-WorkTree and concurrent checks

Two Tasks in A may consume the same current WorkTree history with separate
Session overlays. B cannot directly read A private notes or inherit A's
"fixed" verdict. A published claim carries the original cut, evidence and
grant; B checks applicability at its own cut and performs an independent
assessment. Two workers finishing one due attempt against the same revision
cannot both publish a head transition.

* Proof and implementation gates

1. In Orgize, keep document-local parsing, Elements, selectors and temporal
   Org facts Scheme-owned. Preserve source spans, repeaters and LOGBOOK events;
   compare generated Rust with Scheme on the same fixtures. This gives POO Flow
   source-backed Elements, not an independent general Query authority.
2. In POO Flow =modules/query=, project those Elements into an explicit
   ElementSpace and bind one canonical Query to bounded, source-backed result
   rows. Qualify a forged graph, changed source, changed selector rule,
   mismatched row digest and incomplete result as refusals. The existing
   Provider receipt binding checks declared metadata, not execution or rows;
   add the missing evidence at this boundary before temporal use.
3. Define pure revisit intent/assessment POO values using Query results,
   temporal evidence and Session policy owners. Reuse the finite C4
   certificate. Impact requires typed, scope-compatible trajectories; an Org
   Element match alone is insufficient. Keep the current =memory-core= catalog
   report-only until the migration decision.
4. In Lean, prove that a due signal cannot imply evidence support, a prior
   cut cannot certify a new cut, and a retention verdict cannot imply truth.
   In Quint, explore source change, revocation, two workers, stale assessment,
   and lost CAS. Scheme tests prove the actual projection and policy behavior;
   Python coordinates these native gates only.
5. Only after source authentication, semantic evidence and runtime CAS exist,
   consider moving a visible head. The current Orgize query selector and pure
   Session intent do not establish that path.

Compare three policies on controlled fixtures: time-only revisit, change-only
revisit, and combined time/evidence-triggered revisit. Report missed stale
claims, unnecessary checks, human recall success, and conflicting evidence
retention separately. The spaced-repetition literature informs the human
recall schedule ([[https://arxiv.org/abs/1602.07032][Reddy et al., 2016]]), while the
memory-stream/reflection design of [[https://arxiv.org/abs/2304.03442][Generative Agents]] and
temporal graph work such as [[https://arxiv.org/abs/2501.13956][Zep]] are comparison cases, not
proof that a particular POO Flow policy is better. The official
[[https://orgmode.org/manual/Repeated-tasks.html][Org repeat/log semantics]] remain the source syntax contract.
