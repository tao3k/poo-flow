* Refined environment identity

=AxleEnvironmentIdentity= must bind:

#+begin_src text
AxleEnvironmentIdentity
  name
  lean_toolchain
  required_imports
  environment_resolution_receipt_digest
#+end_src

=required_imports= must be projected from the exact canonical source, not from
the Lean exporter's base environment alone.

The current exporter base import =Init= and the AXLE-independent source import
=Mathlib= are different concepts and must not share one field.

* Environment resolution receipt

The environment provider must supply:

#+begin_src text
EnvironmentResolutionReceipt
  environment_name
  lean_toolchain
  provided_imports
  environment_content_digest
  provider_id
  provider_receipt_digest
#+end_src

For a repository-backed project-aware environment, the content identity may
also include repository URL, revision, and subdirectory. Those fields do not
replace =environment_content_digest=.

The AXLE executor artifact digest identifies the verifier implementation. It
does not identify the environment content and must remain a separate field.

Matching the receipt fields is not provider evidence. The provider-specific
=ProviderValid= relation must validate the canonical receipt and its digest.

* Acceptance rule

Before proof verification is accepted:

1. extract the exact required imports from canonical source;
2. compare them with =AxleEnvironmentIdentity.required_imports=;
3. verify the environment receipt matches name and toolchain;
4. prove every required import is in =provided_imports=;
5. validate the receipt through the provider authority;
6. bind the environment receipt digest into the verification subject defined
   by RFC 45-135-02; and
7. reject a missing or changed content digest.

* Required rejection rules

The proof boundary must reject:

- a required import missing from the identity;
- a required import absent from the provider receipt;
- an identity/receipt environment name mismatch;
- a Lean toolchain mismatch;
- a missing environment content digest;
- a changed environment content digest under the same public name;
- an unsupported environment provider;
- a field-matching receipt that fails provider authority validation;
- an executor artifact digest presented as an environment digest; and
- a verification subject that omits the environment receipt digest.
