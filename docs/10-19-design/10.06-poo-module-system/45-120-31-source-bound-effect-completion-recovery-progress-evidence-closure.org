#+title: Source-bound effect completion recovery progress-evidence closure
#+startup: overview

* Status

This RFC closes the next v1 proof boundary after
[[file:45-120-30-source-bound-effect-completion-recovery-convergence-closure.org][45-120-30]].

The previous RFC proves that a strictly decreasing natural-number recovery rank
implies convergence.  It does not yet explain which runtime owners construct
that rank or which evidence justifies every decrease.

This continuation keeps the proof layer free of schedulers, journals, package
managers, and persistence systems.  It models only proof-valued receipts over
existing owners.

* Lean-discovered gap: weak fairness is not a rank

Weak scheduler fairness says that a continuously enabled recovery action is
eventually scheduled.  Eventual storage acceptance says that some valid
publication is eventually accepted.  Neither claim supplies a finite bound on
the number of preceding deferrals.

The strict rank required by 45-120-30 is stronger:

#+begin_src typst
$ forall n,
  tau(n) != "committed"
  => rho(n + 1) < rho(n) $
#+end_src

An unbounded but fair wait may preserve the same rank for arbitrarily many
steps.  Therefore weak fairness alone cannot construct this witness.

The v1 architecture must state one of two contracts explicitly:

1. bounded progress: existing runtime owners provide finite budgets and a
   receipt for every decrease, so convergence is promised;
2. unbounded progress: the system promises safety and fail-closed recovery, but
   does not promise convergence.

This RFC formalizes the bounded contract without turning its proof budgets into
stored runtime counters.

* Decision

Use three finite proof budgets:

#+begin_src typst
$ B = (c, s, a) in NN^3 $

$ rho(B) = c + s + a $
#+end_src

where:

- =c= is the remaining finite crash budget owned by the runtime;
- =s= is the remaining bounded scheduling-deferral budget owned by the
  scheduler;
- =a= is the remaining bounded completion-storage deferral budget owned by the
  existing completion storage authority.

Every non-committed transition must carry exactly one proof receipt whose
owner strictly decreases its component and whose other components remain
equal.  A physical event that consumes two owner budgets is represented by
two atomic proof steps, never by one ambiguously owned step.

For a runtime crash receipt:

#+begin_src typst
$ c' < c
  and s' = s
  and a' = a $
#+end_src

For a scheduler-admission receipt:

#+begin_src typst
$ c' = c
  and s' < s
  and a' = a $
#+end_src

For a completion-storage admission receipt:

#+begin_src typst
$ c' = c
  and s' = s
  and a' < a $
#+end_src

Each constructor proves:

#+begin_src typst
$ op("OwnerReceipt")(o, B, B')
  => rho(B') < rho(B) $
#+end_src

The budgets are proof measures.  They do not create a recovery journal, a
second completion ledger, or a mutable counter API.

* Owner-indexed proof receipts

The receipt is a proposition indexed by its owner:

- =runtimeCrashBudget=;
- =schedulerAdmission=;
- =completionStorageAdmission=.

It is not a data record from which the proof layer extracts a runtime owner.
Lean rejected that design: a proof-valued evidence bundle cannot project a
non-proof owner value.

The original non-increasing formulation was also too weak.  For
=B = (1, 1, 0)= and =B' = (0, 0, 0)= it admitted both a crash receipt and a
scheduler receipt for the same transition:

#+begin_src typst
$ op("WeakReceipt")("crash", (1, 1, 0), (0, 0, 0))
  and op("WeakReceipt")("scheduler", (1, 1, 0), (0, 0, 0)) $
#+end_src

The atomic equality constraints remove that overlap:

#+begin_src typst
$ op("AtomicReceipt")(o_1, B, B')
  and op("AtomicReceipt")(o_2, B, B')
  => o_1 = o_2 $
#+end_src

The corrected family fixes =before= and =after= budgets and lets each
constructor determine its owner index.  Existing owners remain responsible for
producing their external receipts; Lean only checks the algebra.

An unchanged budget cannot carry any owner receipt:

#+begin_src typst
$ not exists o,
  op("OwnerReceipt")(o, B, B) $
#+end_src

This theorem prevents a safe retry self-loop from being relabeled as progress.

* Evidence-composition graph

#+begin_src mermaid
flowchart LR
    Scope["Current epoch + fence"] -->|"scope is current"| Evidence["Closed progress evidence"]
    Provider["Stable provider acknowledgement"] -->|"same receipt remains observable"| Evidence
    Runtime["Runtime crash authority"] -->|"crash receipt: c' < c"| Receipt["Owner-indexed decrease receipt"]
    Scheduler["Scheduler authority"] -->|"admission receipt: s' < s"| Receipt
    Storage["Existing completion storage"] -->|"admission receipt: a' < a"| Receipt
    Receipt -->|"non-owner budgets remain equal"| Evidence
    Evidence -->|"construct rho(n) = sum(B(n))"| Ranked["Strictly ranked recovery trace"]
    Transition["Existing safe transition closure"] -->|"no invalid state edge"| Convergence["Committed and absorbing"]
    Ranked -->|"reuse 45-120-30 theorem"| Convergence
    Scope -->|"epoch/fence superseded"| Superseded["Old obligation rejected"]
    Superseded -.->|"never count as rank decrease"| Evidence
#+end_src

The graph has two independent gates:

- scope and provider evidence determine whether the recovery obligation remains
  valid;
- an owner-indexed decrease receipt determines whether the step is progress.

Neither gate replaces the existing transition relation or completion history.

* Provider acknowledgement is a scope condition

Stable provider acknowledgement is required at every non-committed step, but it
is not a decreasing budget component.

Provider stability prevents the world from regressing from an acknowledged
effect to an authoritative negative observation.  It does not by itself
schedule publication or force storage acceptance.

This separation prevents the provider from being incorrectly treated as the
owner of scheduler or storage liveness.

* Supersession closes the old obligation

If the epoch or fence is superseded while the old trace is non-committed, the
old closed progress evidence is rejected:

#+begin_src typst
$ tau(i) != "committed"
  and op("Scope")(i) = "superseded"
  => not op("ClosedProgressEvidence")(tau, i) $
#+end_src

Supersession is not a successful rank decrease and does not prove that the old
effect committed.  A newer generation must establish its own recovery
obligation and evidence.

* Convergence theorem

Closed progress evidence constructs the existing strict-rank predicate:

#+begin_src typst
$ op("ClosedProgressEvidence")(tau, B)
  => op("StrictlyRanked")(tau, n => rho(B(n))) $
#+end_src

Together with the existing safe transition closure:

#+begin_src typst
$ op("TransitionClosed")(tau)
  and op("ClosedProgressEvidence")(tau, B)
  => op("Converges")(tau) $
#+end_src

The theorem reuses
=rankedTransitionClosedRecoveryTraceConverges=.  It does not introduce a second
convergence implementation.

The existing infinite =executed-uncommitted= retry trace cannot carry closed
concrete progress evidence.  Otherwise that evidence would construct the
strict natural-number rank already proved impossible for the stalled trace.

* Authority separation

| Concern | Existing owner | Proof role |
|-
| Finite crash bound | runtime recovery authority | decrease =c= |
| Bounded scheduling admission | runtime scheduler | decrease =s= |
| Bounded storage deferral | existing completion storage | decrease =a= |
| Stable acknowledgement | effect provider | keep the recovery world valid |
| Current epoch and fence | runtime generation authority | keep the obligation in scope |
| Safe state transition | existing core proof | reject invalid state edges |
| Commit uniqueness | existing publication history | keep committed keys pairwise distinct |

No row assigns storage, scheduling, provider, or generation ownership to the
proof layer.

* Proof findings

Lean exposes and closes these v1 design defects:

1. Weak fairness and eventual acceptance do not imply a per-step natural-number
   decrease.
2. A convergence promise therefore requires bounded evidence, not only a
   fairness slogan.
3. Proof receipts must be propositions indexed by existing owners; they must
   not become runtime data owned by Lean.
4. One owner component must strictly decrease while every other component is
   equal, making owner attribution unique.
5. An unchanged budget has no progress receipt.
6. Stable provider acknowledgement is a scope condition, not scheduler or
   storage progress.
7. Supersession invalidates the old obligation instead of manufacturing
   convergence.
8. Concrete evidence must reuse the existing strict-rank convergence theorem.

* Next proof gap

The remaining v1 gap is binding these abstract owner propositions to current
runtime evidence without inventing new authorities:

- the runtime receipt that establishes the finite crash budget;
- the scheduler receipt that establishes bounded admission;
- the storage receipt that establishes bounded deferral or acceptance;
- the existing provider acknowledgement receipt and monotonicity theorem;
- the current epoch/fence authority;
- policy authorization for the actor permitted to assert each bound.

That binding must reuse current runtime, provider, storage, authentication,
evidence, and Cedar-policy owners.  The proof layer may compose their evidence
but must not issue those receipts itself.
