#+title: Minimal User Composition and Three-Layer Extension Surface
#+startup: overview

* Status

This RFC records the accepted public-interface projection for the POO module
system after the preceding semantic contracts.

It consolidates the user-composition, compose-function, profiles-strategy, and
macro-governance boundaries. It does not introduce a new clause language.

* Typst formalization: minimal projection over first-class POO values

The public syntax is a single flat module-definition macro whose composition
expression is evaluated exactly once.  The expression uses the pure
=compose= function with one first-class strategy and zero or more ordinary POO
profile values.

#+begin_src typst
#let user-composition(binding, expression) = (
  binding: hygienic(binding),
  value: evaluate-once(expression),
  provenance: composition-provenance(expression),
)

#let compose(strategy, profiles) = (
  strategy.apply(profiles),
)

$ public-composition(root, expression)
  ==> root = user-composition(root, expression).value
  and evaluation-count(expression) = 1
  and hygienic(root) $

$ compose(profiles-strategy, profile-values)
  ==> pure(compose)
  and canonical-composition-root(result)
  and forall(p in profile-values, first-class-poo-value(p)) $
#+end_src

The macro and the function stay deliberately small.  They do not evaluate the
fixed point, execute effects, register providers, select adapters, parse policy
clauses, read a hidden registry, or create another object system.

#+begin_src typst
$ user-composition-boundary(macro)
  ==> not evaluates-fixed-point(macro)
  and not registers-providers(macro)
  and not selects-runtime-adapters(macro)
  and not executes-effects(macro)
  and not builds-hidden-registry(macro)
  and not creates-second-object-system(macro) $

$ public-syntax(form)
  ==> form = "flat-user-composition"
  and not nested-user-composition(form)
  and not clause-dsl(form) $

$ strategy-a != strategy-b or profiles-a != profiles-b
  ==> root-id(strategy-a, profiles-a)
  != root-id(strategy-b, profiles-b) $
#+end_src

* Central decision

The ordinary user interface remains:

#+begin_src scheme
(user-composition my-system
  (compose profiles
    base
    wendao-episteme
    production))
#+end_src

The public surface has three layers:

1. user composition;
2. package author construction;
3. advanced native POO extension.

The complexity of governance, rollout, migration, caching, distributed
evaluation, event ingress, evidence retention, and federation remains behind
ordinary first-class profile values.

* User-composition macro

=user-composition= is the admitted module-definition hygienic macro.

It is responsible only for:

- defining the composition-root binding;
- evaluating the composition expression once;
- recording source and module provenance;
- integrating with normal Gerbil module, export, and import boundaries;
- reporting bounded compile-time syntax diagnostics.

It is not responsible for:

- evaluating the POO fixed point;
- parsing profile-policy clauses;
- registering providers;
- executing effects;
- selecting runtime adapters;
- building a hidden registry;
- creating a second object system.

Nested =user-composition= forms are not part of the public design.

* Compose function

=compose= is an ordinary pure function.

It receives:

- one first-class composition-strategy object;
- zero or more ordinary POO profile values.

It returns one canonical composition-root value.

=compose= is not a macro, package manager, effect runner, provider registry, or
configuration clause parser.

The empty and single-operand behavior remains defined by the selected
composition strategy rather than by special macro syntax.

* Profiles strategy

=profiles= is a first-class POO composition-strategy object.

It owns profile-composition semantics such as:

- prototype lineage;
- slot contributions;
- contribution-priority resolution;
- imports;
- identity;
- capability requirements;
- graph construction;
- conflict evidence.

=compose= does not contain special knowledge of governance, caching, migration,
federation, rollout, or evidence policy.

Those semantics enter as ordinary POO contributions carried by profile values.

* Ordinary profile values

Package surfaces may export concise named profile values such as:

- =base=;
- =wendao-episteme=;
- =production=;
- =strict-governance=;
- =b2b2c-federation=;
- =durable-evidence=.

Every exported name denotes an ordinary Scheme value backed by POO objects.

A profile may contribute:

- module imports;
- identity;
- capability requirements;
- rollout policy;
- migration contracts;
- governance policy;
- cache policy;
- retention policy;
- federation requirements.

The ordinary user composes values without learning every internal evidence
object.

* No secondary clause language

The ordinary user interface must not expose forms such as:

#+begin_example
(initial ...)
(use-composition ...)
(poo-compose ...)
(fixed-point-observability ...)
#+end_example

It also must not grow a clause vocabulary such as:

#+begin_example
#:atomic
#:retry
#:governance
#:cache
#:migration
#+end_example

These concepts already belong to POO objects and profile contributions.

Adding a clause for every subsystem would create a second semantic language and
make macro expansion order an accidental source of meaning.

* Priority and operand order

Contribution priority belongs to the exact slot contribution.

The established priority model remains:

- normal priority is =0=;
- larger numeric priority is stronger;
- =default= is below normal contributions;
- =force= is above ordinary contributions.

Operand order must not become a hidden arbitrary conflict winner.

Equal-priority resolution is permutation-invariant or fails closed with
conflict evidence.

Package authors define explicit priorities and contracts. Ordinary users do not
repair ambiguous conflicts through positional ordering.

* Higher-order profile selection

Optional and variant behavior is expressed through higher-order POO profile
construction.

The composition root must not use host-language =if=, =cond=, or =case= to
select semantic variants at runtime.

A package author constructs a new profile value through native POO prototype
extension and ordinary functional composition. The user then places that value
in =compose profiles=.

The exact native operator names remain deferred until verified against the real
=gerbil-poo= API.

The RFC must not invent an alternative =poo-object= language or unverified
extension operation.

* Package author layer

Package authors construct and export ordinary profile values.

They may use constrained Gerbil macros and functional helpers for:

- repeated internal POO object families;
- contract projection boilerplate;
- manifest and schema declaration;
- generation of ordinary profile definitions;
- bounded compile-time validation.

Every helper expands or evaluates to ordinary POO-native or functional code.

Package-author helpers do not create a second runtime registry, patch language,
effect channel, or capability system.

* Advanced semantic layer

The advanced extension interface is the native object and prototype semantics
of the canonical dependency:

#+begin_example
github.com/mighty-gerbils/gerbil-poo@1c3225637525400341a09e958296962c10184ead
#+end_example

Advanced users may work with verified native operations for:

- object extension;
- prototype composition;
- slot contribution;
- higher-order objects;
- contract projection;
- capability requirements;
- profile construction.

Exact operation spelling is fixed only after verification against
=gerbil-poo=. Conceptual RFC examples must not be presented as an implemented
API.

* Macro governance

Admitted macro roles include:

- the =user-composition= root binding;
- package-internal repeated POO object generation;
- contract projection boilerplate;
- manifest or schema declaration;
- bounded compile-time work producing ordinary POO-native code.

Macros must not:

- invent runtime semantics;
- establish hidden registries;
- turn every policy into a keyword clause;
- bypass POO prototypes;
- hide effects, capabilities, or authority;
- use expansion order as semantic priority;
- make ordinary values inaccessible to functions and tools.

Macro expansion remains inspectable and hygienic.

* Simplicity without macro proliferation

The design adopts the lesson that an ordinary user interface should be small
and readable.

It does not copy an unconstrained macro-heavy package configuration model.

The governing principle is:

#+begin_quote
Every convenience macro is constrained by POO core semantics and expands to
ordinary POO-native or functional code.
#+end_quote

Interface simplicity comes from curated first-class values, not from adding a
macro keyword for every internal concept.

* Diagnostic projection

Ordinary diagnostics identify:

- profile operand;
- exported contract;
- conflicting slot;
- missing capability;
- explanation receipt identity.

Advanced evidence may expand:

- object and prototype path;
- contribution priority;
- module and submodule scope;
- SCC identity;
- evidence cut;
- causal dependency path.

The user does not need to understand the entire fixed-point evaluator to
diagnose a profile conflict.

Diagnostic summaries are projections from canonical evidence. They are not a
separate best-effort explanation system.

* Three stable public surfaces

** User composition layer

This layer exposes:

- =user-composition=;
- =compose=;
- =profiles=;
- named first-class profile values.

** Package author layer

This layer uses constrained Gerbil macros and functional helpers to construct
ordinary POO profile objects.

** Advanced semantic layer

This layer uses verified native =gerbil-poo= object and prototype operations
directly.

Movement to a more advanced layer is explicit. Ordinary users are not required
to understand the advanced layer to compose profiles.

* Failure taxonomy

The implementation must distinguish at least:

- user-composition syntax invalid;
- composition expression evaluated more than once;
- profile operand is not an admitted value;
- strategy identity invalid;
- hidden clause language attempted;
- ambiguous equal-priority conflict;
- host-language semantic branch attempted;
- macro expansion introduced runtime semantics;
- package helper produced non-POO extension;
- unverified native operation exposed as implemented;
- diagnostic projection incomplete;
- module binding or provenance incomplete.

* Required invariants

1. The ordinary user interface remains =user-composition= plus
   =compose profiles= and named values.
2. =user-composition= remains a thin module-definition macro.
3. =compose= remains an ordinary pure function.
4. =profiles= remains a first-class POO strategy object.
5. Internal subsystem semantics remain profile contributions.
6. No secondary clause language is introduced.
7. Operand order does not hide ambiguous slot conflicts.
8. Higher-order POO profiles replace host-language semantic branching.
9. Package-author macros expand to ordinary POO-native or functional code.
10. Native =gerbil-poo= operations are the only advanced semantic interface.
11. Unverified conceptual operations are not exposed as implemented APIs.
12. Diagnostics project from canonical evidence.
13. Interface simplicity does not justify macro proliferation.
