#+title: Event Ingress, Causal Cuts, Deduplication, and Acknowledgement
#+startup: overview

* Status

This RFC records the accepted semantics for external event and message ingress
into POO Flow.

It extends explicit time, entropy, compatibility, effect, backpressure, and
distributed evaluation contracts. Transport arrival order does not become POO
semantic order implicitly.

* Typst formalization: admitted immutable causal cuts

Transport delivery is an arrival candidate, not pure input.  Admission requires
identity, integrity, schema, provenance, causal coverage, and confidentiality
checks before the event can enter an immutable causal cut.

#+begin_src typst
#let ingress-checks(event) = (
  valid-identity(event)
  and valid-integrity(event)
  and valid-schema(event)
  and trusted-provenance(event)
  and causal-coverage(event)
  and confidentiality-allowed(event)
)

$ transport-arrival(delivery) ==> candidate(delivery) $

$ pure-event-input(event)
  ==> ingress-checks(event)
  and event in immutable-causal-cut(event.cut) $

$ missing(causal-parent(event))
  ==> suspend(causal-closure)
  and not evaluate(event.cut) $
#+end_src

Event, delivery, and processing-attempt identities are distinct.  Repeated
delivery preserves the event identity.  Watermarks are source-scoped coverage
evidence, acknowledgements state an exact processing stage, and late events
never silently mutate a closed cut.

#+begin_src typst
$ duplicate-delivery(delivery-a, delivery-b)
  ==> event-id(delivery-a) = event-id(delivery-b) $

$ closes-cut(watermark)
  ==> coverage-established(
    watermark.source,
    watermark.covered-through,
    watermark.coverage-identity,
  ) $

$ ack-stage(ack) = "transport-received"
  ==> not claims-effect-commit(ack) $

$ ack-stage(ack) = "effect-committed"
  ==> claims-effect-commit(ack) $

$ late-event(event, closed-cut)
  ==> outcome(event) in ("new-cut", "quarantined", "rejected", "suspended")
  and not silently-mutate(closed-cut) $

$ replay(cut, time-observation, entropy)
  = evaluate(cut, time-observation, entropy) $
#+end_src

* Central decision

A transport delivery is an arrival candidate.

An event becomes input to pure POO evaluation only after identity, integrity,
schema, provenance, causality, coverage, and confidentiality admission.

Pure fixed-point evaluation consumes an immutable causal event cut. It does not
consume a live transport stream directly.

* POO semantic ownership

Ingress, deduplication, causal closure, watermark, acknowledgement, and replay
policy are ordinary higher-order POO objects.

Native prototype composition defines:

- admitted event identities;
- schema and provenance requirements;
- deduplication scope;
- causal ordering requirements;
- sequence and watermark policy;
- acknowledgement obligations;
- replay and late-event policy.

The public extension interface remains POO-native. Delivery modes,
exactly-once claims, ordering, and acknowledgement must not become an
unstructured macro token DSL.

* Identity roles

At least three identities remain distinct:

- event identity identifies one domain fact;
- delivery identity identifies one transport delivery;
- processing-attempt identity identifies one evaluator execution.

One event may have multiple deliveries and multiple processing attempts.

A delivery or retry must not manufacture a new event identity unless a new
domain fact was actually produced.

* Event envelope

An immutable =EventEnvelope= contains:

- event identity;
- producer and source identities;
- stream and partition identities;
- source sequence or offset;
- payload digest;
- schema and contract identities;
- causal parent or version-vector evidence;
- event-time observation and uncertainty;
- ingestion-time observation;
- idempotency scope;
- provenance;
- confidentiality domain;
- envelope receipt identity;
- envelope schema identity.

The envelope is candidate evidence. Its producer claims are independently
validated by ingress admission.

* Deduplication

Deduplication evaluates event identity, payload identity, scope, and retention
evidence.

The default rules are:

- same event identity and same payload digest converge as duplicate delivery;
- same event identity and different payload digest produce producer
  equivocation or identity-collision evidence;
- different event identities with identical payload converge only when an
  explicit domain policy proves semantic equivalence.

A deduplication record identifies:

- event identity;
- payload digest;
- producer and source scope;
- deduplication policy;
- retention window;
- authoritative storage version;
- admitted processing and acknowledgement receipts.

Once deduplication evidence is reclaimed, the system must not continue to claim
permanent duplicate suppression.

* Ordering domains

Ordering evidence is scoped.

- producer sequence orders events only within the producer sequence domain;
- partition offset orders transport delivery only within that partition;
- causal-parent edges express domain dependency;
- version vectors express partial order;
- authoritative sequencer receipts may provide a declared total order;
- arrival and worker completion order are operational by default.

Concurrent events without a causal or authoritative order must not be ordered
by arrival time, hash traversal, worker identity, or completion speed.

If domain policy requires total order, it identifies the ordering authority,
sequence domain, gap policy, and receipt.

* Causal event cut

An immutable =CausalEventCut= contains:

- exact source and partition coverage;
- admitted event identities;
- causal closure identity;
- source sequence evidence;
- known gaps;
- watermark evidence;
- schema-version set;
- confidentiality projection;
- cut identity;
- cut-construction receipt.

Missing events, causal parents, source scopes, or sequence coverage remain
explicit.

An incomplete cut may produce =CausalSuspension=. Incompleteness must not be
interpreted as absence of domain facts.

* Event, ingestion, and processing time

The following time roles remain distinct:

- event time states when the producer claims the domain fact occurred;
- ingestion time states when ingress observed the delivery;
- processing time states when evaluation ran;
- watermark time states an authority's bounded claim about future earlier
  arrivals.

Every temporal value identifies its clock domain, uncertainty, source, and
receipt.

Arrival time must not replace event time. Processing time must not repair
missing causal order.

* Watermarks and late events

A watermark contains:

- source and partition scope;
- covered sequence range;
- time and clock domain;
- uncertainty interval;
- issuing authority;
- late-event policy;
- watermark identity and receipt.

A watermark is bounded evidence, not absolute truth.

If watermark uncertainty crosses a decision boundary, the event cut remains
suspended.

A late event is admitted according to explicit policy. It may produce a new
event cut, correction proposal, reconciliation obligation, or violation
evidence. It must not silently rewrite a prior immutable cut.

* Exactly-once boundary

Transport exactly-once does not imply end-to-end exactly-once.

A transactional exactly-once claim is scoped to one proven transaction
boundary covering:

- input cursor or acknowledgement;
- persistent state mutation;
- emitted output event or effect;
- idempotency receipt.

If no common transaction boundary exists, the contract is:

- at-least-once delivery;
- idempotent processing;
- content-addressed result;
- explicit partial and unknown effect outcomes;
- reconciliation;
- acknowledgement after processing obligations close.

Sequential operations followed by retries do not prove exactly-once.

The exact transaction adapter and resource set appear in the claim evidence.

* Acknowledgement sequencing

Acknowledgement or cursor commit closes a transport delivery obligation.

It occurs only after:

- event admission;
- pure evaluation;
- required effect commit or reconciliation;
- processing receipt publication;
- current transport ownership and fencing checks.

The system must not acknowledge first and then perform an effect whose outcome
cannot be reconstructed.

Duplicate deliveries may share pure semantic evaluation. Every delivery
obligation still closes under its exact transport scope and ownership.

* Backpressure and rebalance

Ingress obeys bounded admission and processing capacity.

- ingress queues are bounded;
- unavailable capacity reduces pull or transport credit;
- backpressure does not trigger premature acknowledgement;
- cancellation preserves unacknowledged delivery obligations;
- consumer rebalance fences the prior cursor owner;
- a stale owner cannot commit a cursor after fencing;
- repeated delivery may reuse admitted pure results under cache policy.

Transport pressure is execution evidence, not semantic incompatibility.

* Continuation obligations

A suspended event-handler continuation binds:

- semantic generation identity;
- causal event-cut identity;
- delivery and processing-attempt identities;
- pending effect identities;
- pending acknowledgement obligation;
- transport lease and fencing observations.

Resumption must not silently select a new generation or event cut.

If transport ownership is lost, the old continuation may complete pure
computation, but it cannot commit effects or acknowledgements under the stale
lease. Its result enters the new owner's admission or reconciliation path.

* Replay

Replay uses the recorded causal event cut, time observations, entropy
observations, generation identity, and policy identities.

It does not rebuild semantics from current transport arrival order.

Live effects are suppressed by default during replay. If effect reconciliation
is required, it uses the original idempotency identities and receipts.

Replay must not emit a second external effect merely because the event is
processed again.

* Completion boundaries

The following completions remain distinct:

- delivery received;
- event admitted;
- causal cut closed;
- pure evaluation completed;
- effects committed or reconciled;
- delivery acknowledgement or cursor committed.

No earlier completion implies a later completion.

Only acknowledgement or cursor commit closes the transport obligation.

* Failure taxonomy

The implementation must distinguish at least:

- envelope malformed;
- payload digest mismatch;
- schema rejected;
- provenance rejected;
- duplicate delivery converged;
- event identity equivocation;
- sequence gap;
- causal parent missing;
- causal cut incomplete;
- watermark uncertainty unresolved;
- late event admitted;
- transaction boundary unproven;
- effect outcome unknown;
- premature acknowledgement attempted;
- transport owner fenced;
- ingress capacity suspended;
- replay effect duplication attempted;
- acknowledgement receipt incomplete.

* Required invariants

1. Transport delivery is only an arrival candidate.
2. Event, delivery, and processing-attempt identities remain distinct.
3. Same event identity with different payload fails closed.
4. Arrival order does not define semantic order.
5. Ordering evidence remains scoped to its authority and domain.
6. Pure evaluation consumes an immutable causal event cut.
7. Missing coverage never means absence.
8. Event, ingestion, processing, and watermark time remain distinct.
9. Watermarks retain uncertainty and late-event policy.
10. Exactly-once claims identify one proven transaction boundary.
11. Acknowledgement follows required effect commit or reconciliation.
12. Backpressure does not cause premature acknowledgement.
13. Rebalance fencing prevents stale cursor commit.
14. Continuations preserve generation, cut, and acknowledgement obligations.
15. Replay does not duplicate live effects.
16. Public ingress policy extension remains POO-native.
