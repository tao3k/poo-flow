#+title: Authoritative Evidence, Disposable Cache, Telemetry, Handle Registry, and Pure Replay
#+startup: overview

* Status

The architecture in this RFC is accepted.

This acceptance freezes persistence and replay ownership.  It does not
admit implementation files, storage engines, serialization formats,
schema migrations, or public storage macros.

* Scope

This RFC separates four data ownerships:

- authoritative immutable semantic evidence;
- disposable derived caches;
- redacted lossy telemetry;
- ephemeral runtime handles.

It also defines pure semantic replay, effect execution receipts,
indeterminate materialization, retention roots, and evidence garbage
collection.

* Central decision

The semantic evidence store is the authoritative durable lineage.

Semantic and projection caches are replaceable acceleration layers.
Telemetry is a purpose-bound redacted operational projection.  The
runtime handle registry is ephemeral and nonserializable.

Pure replay reconstructs semantic derivations from complete immutable
evidence.  It does not repeat retry, substitute, resume, abort, external
I/O, telemetry publication, or any other effect.

No storage backend, cache, log, telemetry sink, or handle registry may
become an alternative source of semantic truth.

* Four distinct ownerships

| Ownership                    | Durability             | Semantic authority                         | Loss behavior                                  |
|-----------------------------+------------------------+--------------------------------------------+------------------------------------------------|
| semantic evidence store     | durable by policy      | authoritative immutable lineage            | missing required evidence fails closed         |
| semantic or projection cache | disposable             | no independent authority                   | recompute from complete evidence               |
| telemetry                   | lossy and purpose-bound | no semantic authority                      | drop, delay, duplication, and reorder allowed  |
| runtime handle registry     | ephemeral               | no persistent semantic authority           | expiry requires explicit recovery or denial    |

The four ownerships require distinct types, contracts, identities, and
adapters.  A generic store or cache implementation may be reused
internally, but it cannot erase their semantic distinctions.

* Authoritative semantic evidence store

The evidence store retains immutable semantic values and their
dependencies, including:

- Module, generation, capability, profile, Contract, and delegation
  evidence;
- evaluation, SCC, cache-disposition, observation, diagnostic,
  authorization, and recovery evidence;
- budget allocation and consumption evidence;
- execution and redaction receipts;
- semantic schema and derivation identities required for
  reconstruction.

Semantic identity is independent of database keys, file paths, table
layouts, object-store locations, compression, encryption, replication,
and storage-engine version.

An adapter MUST preserve immutable read-after-write identity and detect
missing, conflicting, truncated, or corrupt evidence.  It MUST NOT
return a nearest, partial, or newer value for an exact semantic
identity.

* Storage adapters

SQLite, Turso, files, object stores, memory stores, and future providers
are adapters behind the evidence-store Contract.

An adapter may choose physical indexing, transactions, compression,
encryption, replication, and locality.  It may not choose semantic
identity, lineage, authority, replay equivalence, retention roots, or
garbage-collection reachability.

Adapter failure produces an actionable storage receipt.  Silent
fallback to a cache, telemetry, log, or another generation is
forbidden.

* Disposable caches

A semantic cache stores derived evaluation results under the semantic
cache rules.  A projection cache stores audience-safe projections under
the visibility rules.

They are both disposable, but they are not the same cache:

- semantic cache identity follows evaluation evidence;
- projection cache identity additionally follows consumer, visibility
  capability, policy, schema, purpose, and generation evidence.

Eviction needs no semantic reachability proof.  A cache miss triggers
derivation from complete authoritative evidence.  If that evidence is
missing, the result is a fail-closed evidence denial rather than a
fallback to logs or telemetry.

* Telemetry and handle registry

Telemetry may be delayed, duplicated, dropped, sampled, aggregated, or
reordered.  Those properties make it unsuitable for reconstructing
semantic lineage.

The handle registry holds runtime continuation and provider handles only
for their admitted lifetime.  Persistent semantic evidence stores
recovery-point or provider-handle identities and bounds, never the raw
handle.

Loss or expiry of a handle is an explicit materialization condition.
It does not corrupt historical semantic evidence and does not authorize
an implicit restart or replacement.

* Pure semantic replay

Pure replay requires exact identities for:

- root semantic inputs;
- every result-affecting dependency;
- semantic schema and evaluator semantics;
- Module and generation;
- capability, Contract, profile, delegation, and budget evidence;
- prior derivation evidence when the replay is a verification.

Replay recomputes or verifies pure semantic results and emits a replay
receipt.  The receipt identifies whether the result:

- matches the recorded semantic identity;
- differs with complete counter-evidence;
- cannot be reconstructed because named evidence is missing or invalid.

Replay MUST NOT infer missing evidence from source logs, rendered
diagnostics, telemetry, cache remnants, wall-clock order, or runtime
handles.

* Effect execution and idempotency receipts

An effectful action is materialization, not semantic replay.  It
requires a current authorized action and an effect execution identity
bound to the target generation and adapter Contract.

Before execution, the coordinator checks for a terminal receipt with
the same effect identity:

- a successful terminal receipt returns the recorded outcome without
  repeating the effect;
- a denied terminal receipt returns the recorded denial;
- an absent receipt permits execution only under the adapter's admitted
  idempotency Contract;
- an indeterminate receipt or crash window fails closed for
  reconciliation.

The architecture does not claim universal exactly-once effects.
Provider and transport failures can leave materialization indeterminate.
Blind retry is forbidden when duplicate effects cannot be excluded.

Reconciliation is a separately authorized operation that gathers
provider evidence and produces a new receipt.  It is not an implicit
replay fallback.

* Retention roots and evidence garbage collection

Evidence garbage collection starts from explicit immutable retention
roots.  A root identifies the semantic generations, audit obligations,
execution receipts, schemas, and policy evidence that must remain
reconstructible.

Before deletion, garbage collection produces a reachability proof that
the candidate evidence is not required by any retained:

- semantic generation or lineage;
- dependency or fixed-point derivation;
- capability or visibility delegation;
- budget allocation or consumption;
- execution, replay, diagnostic, or redaction receipt;
- schema or Contract obligation.

Cache eviction is not evidence garbage collection and requires no such
proof.

If reachability, retention policy, or legal ownership is ambiguous,
evidence collection fails closed.  Telemetry retention does not
substitute for semantic evidence retention.

* Schema evolution in the new architecture

This RFC defines no legacy compatibility migration or deprecation
strategy.

A semantic schema change creates a new schema identity and therefore new
semantic evidence identities.  Retained old evidence remains
interpretable only through its declared schema.

Cross-schema reuse or derivation requires an explicit proof-producing
adapter.  There is no ambient compatibility fallback and no silent
mutation of old evidence.

* Implementation admission checklist

- [ ] Give evidence store, caches, telemetry, and handle registry
  distinct types, contracts, identities, and adapters.
- [ ] Keep the semantic evidence store authoritative and immutable.
- [ ] Keep storage-engine details outside semantic identity.
- [ ] Fail closed on missing, conflicting, partial, or corrupt exact
  evidence.
- [ ] Keep semantic and audience-safe projection caches distinct and
  disposable.
- [ ] Recompute cache misses only from complete authoritative evidence.
- [ ] Keep telemetry lossy, redacted, purpose-bound, and
  non-authoritative.
- [ ] Keep raw runtime handles ephemeral and nonserializable.
- [ ] Make semantic replay pure and effect-free.
- [ ] Require exact schema, generation, dependency, and authority
  evidence for replay.
- [ ] Prevent replay from reconstructing truth from logs, telemetry,
  cache remnants, or runtime order.
- [ ] Bind effect execution receipts to authorized action, target
  generation, and adapter Contract.
- [ ] Return completed receipts without repeating known effects.
- [ ] Fail closed on indeterminate effects rather than blindly retry.
- [ ] Require explicit authorization and evidence for reconciliation.
- [ ] Require explicit retention roots and reachability proof before
  evidence deletion.
- [ ] Keep cache eviction separate from evidence garbage collection.
- [ ] Give schema changes new identities without legacy compatibility
  fallback.
- [ ] Add no public storage, cache, replay, or migration macro.
- [ ] Apply canonical evidence projection and versioned identity-schema
  rules in
  [[file:45-120-11-canonical-evidence-projection-and-versioned-identity-schema.org][45-120-11]].
