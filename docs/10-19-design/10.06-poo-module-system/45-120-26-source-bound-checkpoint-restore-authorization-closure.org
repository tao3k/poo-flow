* Status

Proof-backed v1 refinement.

This document stabilizes latest-checkpoint restore authorization on top of the
existing source-bound fingerprint history and content-address closure.  It does
not authorize a v2 schema, a second checkpoint identity, or an implicit
rollback path.

* Context

A content-addressed checkpoint proves integrity and history position.  It does
not prove that the current runtime may restore that checkpoint.

Two invalid implications must be rejected:

1. the same canonical history root does not imply the same current runtime
   epoch;
2. closed content-address evidence does not imply a policy authorization.

Without an explicit restore boundary, a valid but stale request could cross a
runtime restart, lease replacement, or recovery epoch while retaining the same
checkpoint root.  Likewise, treating a nonempty policy digest as authorization
would repeat the provenance mistake closed in 45-120-25.

* Decision

Ordinary v1 resume is latest-only.

A closed restore operation composes three independent owners:

1. the existing content-address closure proves checkpoint/history integrity;
2. a runtime frontier binds the latest checkpoint identity, current runtime
   epoch, and active fence token;
3. a policy authorization receipt binds an allow decision to the exact request
   identity, canonical root, target checkpoint identity, runtime epoch, and
   active fence token.

Rollback is not an alternative spelling of ordinary resume.  Restoring an older
checkpoint requires a separate explicit rollback authority, epoch transition,
and replay analysis.  Those obligations cannot be silently satisfied by this
latest-only request.

* Mathematical model

Let the current frontier be:

Let a latest-checkpoint restore request and its authorization receipt be:

#+begin_src typst

#+begin_src typst

$ f_Q = f_F $

The policy closure requires:

#+begin_src typst
$ "PolicyValid"_"cedadr"(A) $

$ q_A = q $

$ R_A = R_Q $

$ I_A = I_Q $

$ e_A = e_Q $

$ f_A = f_Q $

The full v1 restore obligation is:

#+begin_src typst

  "ContentAddressClosed"
  and "LatestRequestClosed"

#+end_src

The counterexamples are:

The dashed rollback edge is a rejection boundary.  It does not mean that a
rollback receipt can be supplied where a latest-checkpoint request is expected.

* Proof findings

The Lean model found and closes these v1 defects:

1. canonical content identity lacks runtime freshness;
2. a current frontier must own runtime epoch and active fence independently
   from persisted history;
3. root equality alone permits a stale epoch request;
4. content integrity cannot manufacture an authorization decision;
5. root and epoch equality still do not determine the active fence token;
6. authorization must bind the request identity as well as root, target, epoch,
   and active fence;
7. ordinary resume must reject an older checkpoint rather than interpreting it
   as an implicit rollback.

The concrete counterexamples are executable Lean theorems rather than prose
warnings.

* Ownership boundaries

| Owner | Owns | Does not own |
|-
| Content-address/history proof | Checkpoint content, chain, canonical history root | Current runtime epoch or restore authority |
| Runtime frontier | Current epoch, active fence, and latest restorable checkpoint | Policy allow decision |
| Cedadr policy owner | Validity of the exact allow receipt | Checkpoint integrity or runtime execution |
| Restore executor | Fail-closed consumption of all three closed owners | Inventing missing authorization or treating rollback as resume |
| Rollback authority | A future explicit rollback decision and epoch transition | Ordinary latest-checkpoint resume |

The policy surface is an abstract Cedadr-owned validity predicate.  This RFC
does not introduce a Rust owner, a Cedar semantic adapter, or a policy engine
inside POO Flow proof core.

* Related effect replay refinement

This closure authorizes a latest-checkpoint restore request.  It does not by
itself authorize replaying effects emitted after that checkpoint.

Replay-window ordering, exact effect-ledger coverage, idempotency identity,
execute-versus-suppress planning, and Cedadr retry authority are closed in
[[file:45-120-27-source-bound-effect-replay-idempotency-closure.org][45-120-27 source-bound effect replay idempotency closure]].

That proof reuses the active fence token added here and the existing
source-bound effect trace.  Runtime replay completion receipts and explicit
rollback epoch rotation remain separate proof boundaries.
