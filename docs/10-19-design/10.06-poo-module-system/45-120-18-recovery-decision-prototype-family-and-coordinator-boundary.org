#+title: Recovery Decision Prototype Family and Coordinator Boundary
#+author: POO Flow
#+language: en

* Status

Accepted.

* Context

An observation describes immutable semantic facts.  A recovery policy
interprets visible facts and chooses a possible response.  The chosen response
must remain pure until an authorized runtime coordinator validates current
authority, budget, generation, and idempotency evidence.

A central action tag and =case= statement would close the recovery model around
one registry.  It would also encourage decisions, authority, runtime handles,
and effects to collapse into one command object.

POO Flow instead uses an open prototype family and native POO dispatch.

* Decision

=RecoveryDecision= is an independent =ObjectType= prototype family.

The base prototype owns:

- authoritative observation evidence basis;
- policy provenance;
- authority requirement;
- typed budget request;
- successor Contract.

The base prototype does not own authority, budget state, a raw continuation, an
executable runtime handle, or effect execution.

Concrete recovery responses refine the base prototype:

- =RetryDecision=;
- =SubstituteDecision=;
- =ResumeDecision=;
- =AbortDecision=.

The prototype lineage expresses the recovery response.  A central action tag is
not the ordinary dispatch mechanism.

* Base responsibility contracts

** Evidence basis

A decision MUST identify every authoritative =ObservationEvent= on which it
depends, including the relevant evaluation generation.

The coordinator MUST reject a decision whose evidence basis is unavailable,
redacted beyond validation, invalidated, or stale relative to the active
generation.

** Policy provenance

Policy provenance MUST identify the profile-selected policy and dispatch
derivation that produced the decision.  Provenance is evidence; it does not
grant execution authority.

** Authority requirement

An authority requirement describes the capability and delegation conditions
that execution requires.

It MUST NOT:

- grant a capability;
- widen the active capability closure;
- replace delegation evidence;
- infer authority from an observation or decision prototype.

The coordinator validates the requirement against the current rooted,
non-widening capability closure.

** Typed budget request

A typed budget request describes the recovery-action resources that execution
would consume.  It does not reserve or consume them.

Recovery-action budgets remain distinct from closure-evaluation budgets.
Budget accounting occurs only at the coordinator admission boundary and MUST
produce evidence that prevents double spending.

** Successor Contract

The successor Contract describes the permitted relation between the originating
generation, the selected response, its effect receipt, and the successor
=ObservationEvent=.

It does not construct or mutate the successor event.

* Decision refinements

** Retry decision

=RetryDecision= refines the base decision with the semantic retry target,
strategy, and attempt-specific budget request.

It does not execute the target, increment a counter, consume budget, or mutate
the originating observation.

** Substitute decision

=SubstituteDecision= carries or references a first-class POO value satisfying
the declared successor Contract.

It MUST NOT use an alist patch, raw record patch, or ad hoc compute hook as the
ordinary substitution interface.

** Resume decision

=ResumeDecision= identifies a bounded resumption option published by the
exception bridge.

It MUST NOT contain a raw continuation, continuation serialization, process
address, or executable handle.  Only the coordinator may resolve the option
identity through its ephemeral handle registry.

** Abort decision

=AbortDecision= identifies the terminal scope and the evidence that justifies
terminalization.

Abort still produces successor terminal evidence.  It does not erase, rewrite,
or mutate the failed generation.

* Coordinator boundary

Before executing a decision, the coordinator MUST:

- verify the decision identity and evidence basis;
- verify that the active generation still matches the decision basis;
- recompute or validate the current rooted capability closure;
- verify non-widening delegation evidence;
- verify and account for the typed recovery-action budget;
- detect an existing effect receipt for the same decision identity;
- resolve runtime-only handles only after admission succeeds;
- execute through the decision prototype's bounded runtime handler;
- publish an effect receipt;
- emit a successor =ObservationEvent= or fail closed with indeterminate outcome
  evidence.

The coordinator performs effectful dispatch over recovery decision prototypes.
That dispatch remains behind the explicit runtime boundary.  It is not a
general user composition interface.

* Idempotency and generations

A decision identity is stable for one evidence basis, policy derivation,
authority requirement, budget request, and successor Contract.

Submitting the same decision identity again MUST NOT:

- consume the same budget twice;
- execute an already-receipted effect twice;
- create unrelated successor generations;
- replace an indeterminate outcome with an assumed success.

Every accepted, rejected, failed, or indeterminate execution attempt produces
new immutable evidence.  Prior observations and decisions remain unchanged.

* Module and profile boundaries

=RecoveryDecision= MUST NOT inherit =ModuleType=.

Profiles select or restrict recovery policy.  They do not execute decisions,
grant capabilities, consume budgets, or own runtime handles.

The Module invariant remains:

#+begin_example
ModuleType
  = ObjectType(identity, imports, capabilities, profiles)
#+end_example

* Conformance checklist

- [X] =RecoveryDecision= is an independent =ObjectType= refinement.
- [X] Decision variants use prototype refinement rather than a central action
  tag.
- [X] Evidence basis includes authoritative identity and generation.
- [X] Authority requirements do not grant authority.
- [X] Budget requests do not reserve or consume budget.
- [X] =ResumeDecision= carries no continuation or runtime handle.
- [X] =SubstituteDecision= uses a first-class POO value.
- [X] Profiles select policy but do not execute recovery.
- [X] Coordinator execution produces immutable successor evidence.
- [X] Duplicate decision identity cannot double-spend budget or repeat a
  receipted effect.
- [ ] The concrete recovery decision source owner has been resolved through
  parser-owned owner discovery.
- [ ] Implementation has been admitted after owner resolution.

* Non-goals

- Treating decisions as Modules.
- Combining policy selection, authority, budget state, and effects in one
  command object.
- Creating a central recovery action registry.
- Serializing continuations or runtime handles.
- Using alist substitution patches.
- Claiming exactly-once execution for arbitrary external effects.
- Defining an implementation schedule.
