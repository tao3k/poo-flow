* Rejected alternatives

** Replacing the upstream session with an adaptive downstream controller

Rejected.  Worker scheduling, dependency completion, and incremental validity
are =std/make= responsibilities.  POO Flow observes a single upstream session
and may stop an actual RSS-rate anomaly; it does not pre-limit ordinary worker
capacity or create a second scheduler.

** Fixed chunk sizes or a global spec ceiling

Rejected.  They encode one host's behavior and cannot explain changes from
receipts.

** Concurrent std/make coordinators

Rejected.  They duplicate scheduling ownership and make the hard RSS cap more
difficult to enforce.

** Per-spec child gxi scheduling

Rejected.  Prior process multiplicity imposed dominant startup overhead and
duplicated Building Framework currentness, topology, and receipt ownership.

** Parsing Scheme source headers to infer the build graph

Rejected.  Textual import scanning cannot safely reproduce =cond-expand=,
macro-generated imports, preludes, includes, custom readers, or expander
registry semantics.  Missing one edge can make parallel compilation incorrect.
Only the Gerbil expander is the dependency authority.

** Package-local stamps as a freshness oracle

Rejected.  A receipt can report what an upstream build did, but it cannot
replace =std/make='s answer about whether generated Scheme, SSI, macro, and
native units are current.  Mtime retouching and output enumeration must not be
used to manufacture a warm result.

** Python-owned build policy

Rejected.  The Scheme build and its safety policy are Gerbil-owned.  Python may
remain a validation runtime below other interfaces, but it is not the owner of
this build controller.
