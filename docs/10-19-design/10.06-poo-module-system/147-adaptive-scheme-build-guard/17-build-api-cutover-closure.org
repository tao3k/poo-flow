* 2026-09-12 native PackageSpec and guard convergence

The current root =build.ss= no longer uses the retired ASP package profiles,
profile projectors, or =defbuild-script= compatibility surface.  It declares
one POO-native =PackageSpec= with an explicit =all-gerbil-modules= catalog and
the POO Flow native-spec projector, then gives the resulting =spec= procedure
to =clan/building#init-build-environment!=.  The whole native call is supervised
by the public
=call-with-framework-native-build-memory-anomaly-guard= composition.

That composition reads ASP's canonical positive override-or-host-capacity
selection for its observation receipt.  PackageSpec remains the only owner
that publishes the value into =GERBIL_BUILD_CORES= and Gerbil's compiler
capacity immediately before =std/make= constructs settings.  POO Flow neither
hardcodes a worker count nor implements a second scheduler, sampler, classifier,
or receipt schema.

The nested Cedar conformance build uses the same public PackageSpec and guard
surface.  Its specialized Cargo artifact staging remains downstream-owned, but
the old =parallelize: #f= override is removed so native Gerbil scheduling keeps
the caller or machine capacity.

The sections below are retained as the historical 2026-09-01 cutover record;
their former profile names are not current APIs.

* 2026-09-01 downstream Build API cutover closure

POO Flow now consumes the public ASP Gerbil Scheme package-spec macro and the
gerbil-bazel project execution capability directly.  The root =build.ss=
declares one POO package object with =asp-gerbil-scheme-package-spec!=, projects
its native =std/make= value, and hands that value to the ASP
=defbuild-script= entrypoint.  POO Flow no longer owns a CLI build supervisor,
an adaptive execution-window scheduler, or a project compile guard.

The cutover deliberately provides no compatibility path.  The deleted

code.  Their tests were removed rather than redirected to aliases.  Build-core
selection has one external input, =GERBIL_BUILD_CORES=; requested and effective

** 2026-09-04 dependency-facade correction

POO Flow imports only =:asp-gerbil-scheme/src/package-build-api= from its
=gerbil.pkg= dependency.  It does not import ASP's CLI, provider server, HTTP
runtime, testing framework, or product-native build plan.  The facade exposes
the declarative package macro, builder profiles, source discovery, profile
projection, and the native =std/make= bridge.

The package macro captures one module owner catalog.  Profile admission parses
that declared catalog once, then the accepted native-spec is passed to the one
upstream =std/make= session.  This shares ownership without pretending that the
policy parser AST can replace Gerbil's compiler AST.

#+begin_src mermaid
flowchart LR
  Dep[gerbil.pkg dependency] --> API[package-build-api facade]
  API --> Package[POO package object]
  Package --> Catalog[one declared module catalog]
  Catalog --> Policy[one policy projection]
  Catalog --> Spec[native std/make spec]
  Policy --> Admission[profile admission]
  Admission --> Make[one upstream std/make session]
  Spec --> Make

  Product[ASP CLI / provider / HTTP / tests] -. excluded from dependency facade .-> API
#+end_src
* Project Root and Runtime Closure Correction

The downstream Package Spec has one source catalog boundary.  For a customary
Gerbil repository that boundary is =roots: ["."]=; =t/= is a Builder Profile
test convention, not a second runtime catalog.  POO Flow may retain an explicit
=native-spec= while its specialized FFI ownership is being projected, but it
must not reintroduce =runtime-roots=.  A Provider executable owns its static
closure separately through =runtime-modules=.

#+begin_src mermaid
flowchart LR
  ROOT["Package Spec\nroots"] --> CATALOG["One module catalog"]
  PROFILE["Build API Profile\nGit ignore + fixture exclusions"] --> CATALOG
  CATALOG --> POLICY["Policy admission\none scan"]
  TESTS["Profile test-roots: t/"] --> NATIVE["Native build projection"]
  CATALOG --> NATIVE
  PROJECTOR["POO Flow named projector\nSSI + Nono FFI + UI ownership"] --> NATIVE
  NATIVE --> RUNTIME["Production library units"]
  PROVIDER["Provider runtime-modules"] --> CLOSURE["Static executable closure"]
#+end_src
