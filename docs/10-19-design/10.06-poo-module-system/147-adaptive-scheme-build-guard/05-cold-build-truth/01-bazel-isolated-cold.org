* Bazel-declared isolated cold receipt

The Bazel outer layer now declares the complete Scheme action without replacing
=build.ss= or Building Framework.  The action receives only declared project
sources, compiled =clan= and =gslph= dependencies, host Gerbil tools, and the
host-system receipt.  It produces an isolated tree artifact, a complete build
log, and the Scheme-owned canonical JSON receipt.

| Metric | Accepted Bazel cold receipt |
|--------+-----------------------------|
| Target | =//scheme:compile= |
| Bazel execution | Darwin sandbox; exit 0 |
| Bazel wall time | 161.694 s, approximately 2.69 minutes |
| Scheme guard elapsed | 155,837 ms |
| Scheme process-tree peak RSS | 3,359,752,192 B |
| Detected physical memory | 34,359,738,368 B |
| Scheme-derived maximum RSS | 17,179,869,184 B |
| Build stages | 3 of 3 compiled |
| Output tree | 73 MiB; no temporary tool symlinks |
| Receipt | =poo-flow.project-compile-guard.v1=; =completed= |

The Bazel wall time is 41.176 seconds below the previous 202.87-second accepted
reference, an improvement of approximately 20.3%, and 410.016 seconds below
the historical 571.71-second ceiling, an improvement of approximately 71.7%.
The result is not a second build implementation: Bazel owns declared inputs,
host-tool projection, sandboxing, caching, and outputs; =build.ss= and Building
Framework still own topology, scheduling, compilation, guards, and receipts.

The first isolated attempt also exposed two bootstrap defects that a populated
workspace had hidden: =build.ss= imported its own installed package for the
observability helper, and the source declaration omitted tracked =.ssi=,
=.scm=, and =.inc= inputs.  The accepted action removes the self-import cycle
and declares those inputs.  It cannot read =.gerbil/lib/poo-flow=.
