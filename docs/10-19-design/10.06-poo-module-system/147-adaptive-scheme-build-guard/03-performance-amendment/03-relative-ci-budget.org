* Identity-scoped relative CI performance budget

An absolute duration is not a portable performance budget.  The previous
=480-second= CI comparison mixed three different concerns: a GitHub Actions
runaway timeout, one runner generation's expected duration, and a performance
regression decision.  These concerns now have separate owners:

1. GitHub Actions retains an absolute timeout only to terminate a lost or
   wedged action.  Its receipt names the field =runawayTimeoutSeconds= and does
   not claim =withinBudget=.
2. The Scheme control plane owns
   =poo-flow.scheme-compile-performance-budget-receipt.v1=.
3. A performance decision compares equal-size, odd sample sets containing at
   least three observations per side.  It uses each side's median and an
   explicitly supplied maximum regression in basis points.
4. The baseline and candidate must share one runner, one host session, one
   Gerbil/GSLPH toolchain identity, one execution policy, one detected logical
   CPU count, one effective worker count, one spec count, one coldness class,
   and one dependency-cache state.
5. Revision and source digest must be stable within each side but may differ
   between baseline and candidate.  Otherwise a source change could never be
   measured.
6. A mismatched identity produces =incomparable=, never a pass.  A comparable
   median above the relative ceiling produces =regressed=.

For baseline median \(B\) milliseconds and a policy allowance \(P\) basis
points, the integer ceiling is:

#+begin_example
ceiling_ms = ceil(B * (10000 + P) / 10000)
#+end_example

The policy contains no machine-specific CPU count or duration.  Machine
capacity is observed and becomes part of the comparison identity.  The
implementation is POO-native: observations and the comparison receipt are
immutable =.o= objects, while sorting, projection, and identity comparison use
the shared functional combinators from =src/utilities/functional.ss=.

The dependency-source contract also has an executable Bazel action-input
boundary.  CI queries both action graphs: the contract source must be present
in =//scheme:dependency_source_contract_compile= and absent from
=//scheme:compile=.  This proves that editing the contract-only source cannot
invalidate the runtime compile action merely because both files live in the
same repository.
