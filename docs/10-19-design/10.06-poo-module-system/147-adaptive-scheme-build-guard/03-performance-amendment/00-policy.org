* 2026-07-23 performance amendment

The accepted cold receipts already establish the performance boundary:

- canonical guarded cold build: =202.87 s= wall time;
- Bazel-declared isolated cold build: =161.694 s= wall time.

The dependency-source integration later observed =549.087 s= wall time with a
=534.76 s= critical path, followed by a =1154.91 s= compile critical path on a
host whose total wall time was contaminated by executable-startup stalls.  The
first approximately nine-minute observation is itself a regression; it is not
a new baseline.

The root policy defect was that the outer project guard always materialized a
positive =POO_FLOW_BUILD_MAX_RSS_BYTES= value, while the build planner treated
the mere presence of that observation limit as permission to activate adaptive
execution windows.  That coupling converted the established single upstream
=std/make= topology session into repeated sequential coordinator sessions.

This amendment restores the semantic split:

1. topology is the default compile-graph policy;
2. the process-tree RSS guard remains active and produces its own receipt;
3. =adaptive-window= is an explicit policy requiring an explicit positive cap;
4. a point-in-time runnable-process count is advisory evidence and cannot
   silently reduce the configured native worker count;
5. future adaptive concurrency work must tune native worker admission or use
   historical calibration receipts; it must not infer graph-rewrite authority
   from an observation value.

The performance acceptance target remains the pre-regression known-good
envelope, not the =534.76 s= comparison point.  POO Flow issue =#13= owns the
healthy-host reproduction and CI regression budget.
