* Canonical receipt contracts

Build and resource receipts are upstream-owned.  POO Flow does not define a
parallel process-memory or project-compile receipt schema.

#+begin_src mermaid
flowchart LR
    A["gerbil-bazel action"] --> R["gerbil-bazel typed receipt"]
    R --> B["Bazel output group / CI artifact"]
    B --> Q["poo-flow.qualification-gate-receipt.v1"]
    Q --> V["Pure revision and declaration verification"]
#+end_src

The accepted upstream resource schema is:

- =gerbil-bazel.resource-guard-receipt.v1=

It owns admission outcome, available resources, effective build core count,
elapsed milliseconds, process-tree peak memory, child exit code, termination
outcome, and hard-limit enforcement.

POO Flow projects that evidence without copying its process-control semantics:

- =poo-flow.qualification-gate-receipt.v1= binds an opaque evidence value to a
  gate id, owner, source revision, declaration digest, artifact identity,
  installed-consumer claim, and acceptance decision.
- =poo-flow.qualification-run-receipt.v1= aggregates gate receipts for one
  source revision and mode.
- =poo-flow.qualification-verification-receipt.v1= records the pure completeness
  and freshness verdict.

JSON is produced by the action owner.  POO Flow Scheme verification keeps the
evidence value opaque and never turns a diagnostic text stream, printed alist,
or locally sampled process table into a competing build receipt.
