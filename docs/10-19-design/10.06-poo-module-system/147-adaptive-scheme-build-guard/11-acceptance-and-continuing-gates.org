* Acceptance outcome and continuing gates

The bounded implementation phase and the full-cold gate are complete.  The
accepted 161.694-second Bazel receipt establishes that the canonical Building
Framework topology policy is healthy inside a declared Darwin sandbox after
the toolchain and source-bootstrap boundaries are corrected.  The earlier
202.87-second direct receipt remains the previous accepted reference.

The following continuing rules remain normative:

1. default builds use Building Framework topology and one upstream
   =std/make= session when the caller declares no tight memory cap;
2. a positive =POO_FLOW_BUILD_MAX_RSS_BYTES= activates adaptive windows, and
   every completed window must retain canonical JSON evidence; safe growth is
   capacity-capped and geometric, while native concurrency remains bounded by
   the detected worker count;
3. any invalid receipt, cap breach, timeout, or non-completed outcome fails
   closed before the next adaptive window;
4. =571.71= seconds remains the historical regression ceiling, =202.87= seconds
   is the previous direct reference, =161.694= seconds is the accepted local
   Bazel host reference, and run =29633871888= is the accepted constrained
   hosted reference at =230= seconds for the Scheme phase and =5 min 41 s= for
   the complete macOS job;
5. the Bazel host-toolchain rule must classify the host explicitly as =darwin=
   or =linux=, reject every unsupported system, preserve valid custom selectors,
   never project a Nix Apple SDK into a Homebrew Gerbil compile, register an
   execution-platform-constrained implementation, and keep consumer rules on
   native toolchain resolution rather than repository-internal labels; and
6. no accepted path may introduce a second executor or concurrent
   =std/make= coordinators;
7. =//scheme:tests= is the ordinary serial acceptance suite, while
   =//scheme:performance_tests= remains an explicit separate gate until its
   native fixture-contract drift is repaired; and
8. =build.ss= must cold-start without importing =:poo-flow= from an installed
   output tree, and Bazel actions must declare every =.ss=, =.ssi=, =.scm=,
   =.inc=, user-interface, and native-header input they consume; and
9. the root =justfile= must remain a declarative catalog of Bazel targets and
   recipe dependencies; it must not acquire platform detection, native tool
   discovery, direct Scheme execution, receipt parsing, or output ownership;
   and
10. Scheme and runtime-C Starlark consumers must resolve
    =GERBIL_TOOLCHAIN_TYPE= through the shared capability helper; runtime-C
    BUILD declarations must not name =@local_gerbil= or expose individual
    Gerbil/native tool attributes.

Phase-level overlap remains an upstream proposal.  The next performance path
is to change the upstream expansion/import and native-job flush behavior so
native compilation can overlap earlier with Scheme expansion.  That work must
remain inside the canonical =std/make= coordinator; it must not introduce a
second executor in POO Flow.
