* Measured bounded A/B evidence

The bounded comparisons use the same owners, source sets, and host.  The
optimized lane merges unnecessary Building Framework barriers while retaining
the single upstream executor.

** User-interface batch

| Metric                    | Baseline       | Optimized      | Delta    |
|---------------------------+----------------+----------------+----------|
| Specs                     | 8              | 8              | 0        |
| Outer wall time           | 12.06 s        | 11.58 s        | -3.980%  |
| Control-plane wall time   | 10.587950 s    | 9.996911 s     | -5.582%  |
| Control-plane allocation  | 11.317668112 GB| 8.700916696 GB | -23.121% |

The UI result establishes a real but secondary barrier-merging gain.  It does
not establish that one unbounded session is safe for a full cold project.

** Runtime target-cold 16-spec batch

| Metric                    | Baseline       | Optimized      | Delta    |
|---------------------------+----------------+----------------+----------|
| Specs                     | 16             | 16             | 0        |
| Outer wall time           | 18.48 s        | 16.39 s        | -11.310% |
| Control-plane wall time   | 17.009764 s    | 14.741602 s    | -13.334% |

The runtime result improves wall time and average core use, but allocation and
RSS increase.  This is the evidence that makes an always-one-window cold policy
unsafe: the wall-time win cannot be generalized without a hard memory bound.

** Pre-acceptance runtime target-cold 48-spec calibration

Gerbil libraries through =GERBIL_LOADPATH=, 12 workers, a
=2,147,483,648=-byte hard RSS cap, and =268,435,456= bytes of reserved
headroom. FFI and UI stages were excluded. The current empty-root topology
contains 39 dependency-closed groups and 377 specs; its group widths are:

The maximum observed process-tree RSS was =1,396,244,480= bytes, about 65%
of the hard cap. The first window paid the largest cold compiler cost; the
latest two transient estimates converged to approximately 26 MiB per spec.
Because 12 is also the configured worker ceiling, retaining =12 + 12= is the
expected adaptive decision rather than evidence of a fixed-width scheduler.

This historical run covers 48 of 377 runtime specs (12.7%) and 48 of the widest
group's 58 specs.  It authorized the bounded adaptive path at that stage.  The
later strict A/B and full-cold receipts below supersede its then-blocked
acceptance state without changing the receipt.

** Strict same-Framework topology versus adaptive A/B

The decisive comparison does not compare Building Framework against a raw
=std/make= script.  Both lanes use the same Building Framework declaration,
the same upstream =std/make= executor, the same non-Nix Gerbil installation,
fresh output roots, 12 workers, and a 2,147,483,648-byte hard cap.  Only the
Building Framework execution policy changes:

- =topology= flattens every dependency-ordered topology group into one ordered
  upstream =std/make= session;
- =adaptive= divides that same ordered spec stream into guarded sessions when
  the caller supplies an explicit memory budget.

| Cold slice | Policy | Windows or sessions | Guard elapsed | Process-tree peak RSS | Outer wall time |
|------------+--------+---------------------+---------------+-----------------------+-----------------|
| 24 specs | adaptive | =12 + 12= | 29,792 ms | 1,420,820,480 B | 32.72 s |
| 24 specs | topology | one session | 24,059 ms | 1,665,728,512 B | 26.44 s |
| 58 specs | adaptive | =12 + 13 + 25 + 8= | 48,341 ms | 1,411,432,448 B | 51.34 s |
| 58 specs | topology | one session | 41,159 ms | 1,885,782,016 B | 43.65 s |

For 24 specs, topology is approximately 19.2% faster and uses approximately
17.2% more process-tree peak RSS.  For 58 specs, topology is approximately
14.9% faster and adds 474,349,568 bytes of peak RSS.  The 58-spec topology run
is below the hard cap but exceeds the cap minus the reserved 256-MiB headroom
by approximately 6.7 MiB.  This confirms the existing policy boundary:
topology is the performance default when the caller does not declare a tight
cap, while adaptive windows are the safety path under an explicit cap and
headroom contract.

A bounded continuation compiled the next topology groups of 38, 35, and 30
specs in 23,058 ms, 24,144 ms, and 19,161 ms.  Together with the first
58-spec group, the first 161 specs completed in approximately 107.5 seconds
without a superlinear topology anomaly.

An experimental pending-native-queue flusher reduced the 58-spec guard time
from 41,159 ms to 39,822 ms, only 3.25%, while retaining essentially the same
memory peak.  It is not productized: a polling wrapper around an upstream
queue is not a sufficient gain and would duplicate coordinator policy.
