declared dependency chain rather than a synthetic Gerbil package.

The =gslph_package= action is =20,044 ms=, or =18.3%=, below the previously
recorded macOS package hotspot of =109,604 ms=.  This is a package-action
improvement, not an end-to-end two-minute result.  The four Gerbil project
actions remain dependency-ordered, and the root runtime stage alone consumed
=213,495,326 elapsed jiffies= for 379 modules.  The root receipt already reports
=worker-count=12= on a 12-logical-CPU host, so increasing the worker count is not
the next root-cause fix.

The next performance owner is the downstream compile/AOT graph and its cache
partitioning.  Gerbil-Bazel must continue to expose one declared project action,
one Scheme guard, and one upstream =build.ss=/=std/make= executor; it must not
introduce a second scheduler to hide downstream graph cost.

The first normal-pin replay later observed host contention and one transient
child exit 10 while reporting only =678,264,832 bytes= peak RSS against a
=13,657,996,001 bytes= cap.  A focused retry of the identical pinned
=gerbil_utils_package= succeeded in =63.959 s=.  Therefore neither run is mixed
into the fresh-root performance comparison.  The normal pin remains a
correctness/reproducibility gate, while performance comparisons require the
identity and coldness tuple defined above.
