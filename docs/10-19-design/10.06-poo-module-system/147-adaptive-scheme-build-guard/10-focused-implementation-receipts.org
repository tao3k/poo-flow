The original toolchain failure was not a Scheme algorithm result.  =gxpkg env=
injected a Nix =DEVELOPER_DIR= into a Homebrew Gerbil/Gambit compiler configured
with GCC.  GCC's =collect2= delegated to =xcrun=; the Nix =xcrun ld= wrapper then
recursively invoked an equivalent =xcrun ld= process.  That process chain
explains the earlier extreme latency and memory growth.  The Bazel repository
rule now delegates the finite =darwin | linux= choice to =host_system.bzl= and
emits a canonical JSON receipt.  On Darwin it replaces only absent, invalid, or
Nix-store Apple SDK paths and resolves =xcrun= through the active host developer
tools without hard-coding one machine's path.  Linux preserves its host
environment.  The direct wrapper mirrors this policy for invocations that
intentionally do not enter through Bazel.
