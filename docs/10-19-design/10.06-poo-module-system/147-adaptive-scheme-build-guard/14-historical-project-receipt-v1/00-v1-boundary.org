* Historical stable Gerbil project receipt v1 boundary

POO Flow pins gerbil-bazel revision
=0d5ef5362674d788e0fc9e146b8e9e1daf78f137=.  That revision preserves
=gerbil-bazel.project-receipt.v1= as the stable outer envelope for every
=gerbil_project_compile= action.  Prefix-derived producer evidence does not
replace the envelope; POO Flow's =poo-flow.project-compile-guard.v1= receipt is
nested under =buildReceipt=.  Optional Gerbil-Bazel process-guard evidence is
nested independently under =resourceGuard=.

The same revision removes the former Bazel-owned package identity/revision
graph.  =gerbil.pkg= owns package metadata, =gxpkg= owns package lifecycle, and
=build.ss= with =std/make= owns compile membership, ordering, and Scheme-level
incrementality.  Bazel owns repository pins, declared inputs, dependency tree
artifacts, sandboxing, adaptive host capabilities, caching, guards, and
receipts.  The developer-only dependency target invokes one standard
=gxpkg deps --install= command; it is not build truth inside a compile action.

The registered toolchain leaves the installed =gambuild-C= immutable:
repository discovery reads its literal =C_COMPILER= declaration and queries
=FLAGS_DYN= and =FLAGS_OBJ= without writing the installation.  =GERBIL_GSC=
uses Gambit's public =-cc=, =-cc-options=, and =-ld-options= interfaces.
Because =-cc= clears the configured mode flags, implicit or explicit dynamic
compilation restores the complete =FLAGS_DYN= value before adding a platform
extra, while =-obj= restores the complete =FLAGS_OBJ= value.  =-c=, =-link=,
and =-exe= pass through without a wrapper-added compiler override.  Final
executable-link ownership remains at Gerbil's public =GERBIL_GCC= boundary.
Darwin appends =-Wl,-undefined,dynamic_lookup= for dynamic compilation and
selects Xcode Clang for the final link; Linux restores the producer mode flags
without the Darwin extra or a separate final link driver.

No =project-receipt.v2= is introduced.  A future additive requirement must
first demonstrate that it cannot be represented by the two explicitly reserved
v1 extension fields.  A breaking v2 proposal requires its own migration RFC,
producer and consumer vectors, and dual-version transition evidence; it cannot
be created as a convenience rename.

The Bazel target =//scheme:compile_receipt_v1_test= is the executable contract
gate.  It resolves =gxi= through the registered Gerbil toolchain, applies the
upstream Scheme validator to the formal v1 schema and the actual
=//scheme:compile= receipt, and then applies a POO Flow Scheme validator to the
nested build receipt.  CI executes the target immediately after the Scheme
compile and before publishing the artifact evidence.

This receipt gate proves the stable envelope and POO Flow consumer contract;
it does not substitute for compiler-mode normalization evidence.  Upstream
provider and toolchain probes separately prove complete =FLAGS_DYN= and
=FLAGS_OBJ= restoration, the =-c/-link/-exe= pass-through boundary, and final
executable-link ownership by =GERBIL_GCC=.
