** Baseline-correct adaptive worker admission

A subsequent full downstream gate exposed a dimensional error in POO Flow's
own compile guard.  The guard converted host-available memory directly into an
absolute process RSS ceiling, even though host-available memory is an
incremental allocation and the compiler process tree already has a non-zero
RSS baseline.  Under transient host pressure the old formula admitted all 12
configured workers beneath a =2738041651-byte= absolute ceiling.  The build
correctly failed closed with exit 70 when the process tree reached
=2741518336 bytes=, only =3476685 bytes= beyond that ceiling.

The corrected admission model preserves units and couples CPU concurrency to
the admitted memory allocation:

#+begin_src mermaid
flowchart LR
  Available["Live host-available bytes"] --> Allocatable["allocatable = available - host headroom"]
  Headroom["Host headroom bytes"] --> Allocatable
  Requested["Requested absolute RSS cap"] --> Admitted["admitted = min(allocatable, requested - baseline)"]
  Baseline["Current process-tree baseline RSS"] --> Admitted
  Allocatable --> Admitted
  Baseline --> Cap["hard max = baseline + admitted"]
  Admitted --> Cap
  Admitted --> Capacity["memory worker capacity = floor(admitted / 768 MiB)"]
  Configured["Configured CPU workers"] --> Workers["effective workers = min(configured, memory capacity, runnable capacity)"]
  Capacity --> Workers
  Runnable["Observed runnable processes"] --> RunnableCap["runnable capacity = max(1, 2 x logical CPUs - runnable)"]
  RunnableCap --> Workers
  Workers --> Environment["GERBIL_BUILD_CORES + initial adaptive window"]
  Cap --> Guard["Outer process-tree guard"]
  Environment --> Guard
  Guard -->|"within cap"| Receipt["Unit-bearing buildReceipt"]
  Guard -->|"over cap"| Exit70["Fail closed: exit 70"]
#+end_src

The regression suite is now owned by the executable root rather than an
import-time =run-tests!= side effect, so its result determines the =gxtest=
and Bazel exit status.  The composition-writer suite follows the same root
ownership for the changed Bundle v1 path and compares compact IDs through

legacy import-time test-suite migration remains a separate compatibility
cleanup; this gate does not claim that unmodified legacy suites have already
been rewritten.

Runnable saturation is observable as an advisory and reduces the effective
worker count; it is not by itself a hard admission failure.  Only a missing
host-memory floor or a requested RSS cap that cannot cover the measured
baseline plus the 768 MiB minimum allocation produces a typed hard reason.
