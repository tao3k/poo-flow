* Native compiler failure evidence boundary

Revision =efcbff933107c9beb04510aa4d745e74c9966714= adds failure-only evidence to
the generated =GXC=, =GERBIL_GSC=, and =GERBIL_GCC= wrappers.  Any nonzero
Gerbil compile-driver, GSC mode, or final executable-link stage now produces a
typed receipt with its driver, mode, exact NUL-delimited argument vector, and
whitelisted compiler environment, plus byte-size and SHA-256 receipts for
existing input files.  The project runner exports an action-local receipt
channel; parallel compiler wrappers publish valid JSONL with a no-clobber
same-filesystem handoff, and the runner restores typed log prefixes before its
bounded failure tail.  Successful compiler invocations do not hash inputs or
emit receipts, and the runner removes the empty channel.

This boundary deliberately does not retry =gsc=, reduce adaptive parallelism,
or replace =gxpkg=, =build.ss=, or =std/make=.  It turns the deterministic
macOS CI failure into evidence that can distinguish incomplete link inputs
from a compiler/runtime configuration difference without changing upstream
package semantics.
