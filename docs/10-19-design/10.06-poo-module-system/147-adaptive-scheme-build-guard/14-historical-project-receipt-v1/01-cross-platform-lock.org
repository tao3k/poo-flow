A stale-lock Linux run exposed the failure only after the external-module
compile and receipt gate had already completed successfully in =469.304 s=.
Regular CI and =runtime-wasm-package= therefore run
=mod deps --lockfile_mode=error= immediately after Bazel setup and before
their heavyweight external-module or dependency-build steps.  This preserves
fail-closed lock ownership while moving the stale-lock decision to the front
of both pipelines.  It does not mask artifact transport failures or relax any
later build and receipt gate.

The full Linux external-consumer scenario is therefore an independent peer job
with its own 15-minute budget and cache namespace.  Native Linux retains a
36-second analysis-only external check and all root build, receipt, and
acceptance gates.  There is exactly one full external-module owner, but it runs
in parallel instead of consuming the native job's serial critical path.
