* Upstream-owned build control flow

The single executor is upstream =std/make=.  ASP Build API can set a declared
profile, preserve or resolve portable host capabilities, validate the package
declaration, and observe the process.  Observation is not admission control:
an RSS-rate anomaly may terminate the running build and identify its owner, but
normal worker capacity is not reduced pre-emptively to hide a suspected leak.

POO Flow scenarios own workload shape and thresholds.  They do not call =gsc=
directly, create per-module =gxi= processes, parse imports, retouch currentness
stamps, or overlap multiple coordinators.  Bazel uses the same package entry
through =gerbil-bazel=; it is a reproducibility and cache adapter, not an
alternative Gerbil build engine.
